# 상태 변화에 따른 과업 분해

2026-10-07 사용자 합의: 이후 과업도 원목의 탐색→접근→채굴→수집처럼 의미 있는 단위로 분해한다.
이는 새로운 전체 연구 설계가 아니라 현재 장기 RM/skill 구조의 적용 원칙이다.

현재 후속 항목은 [작업 단위와 완료 근거](next-task-units.md)에 연결한다.

## 두 수준

상위 RM은 사용자 목표의 약속과 완료를 관리한다. 예: 원목 확보→작업대 확보→곡괭이 제작.
각 skill 내부 RM은 현재 조작 단계와 관측 증거를 관리한다. 예: 대상 탐색→접근→채굴→회수.
달리기·웅크리기·시점 회전·인벤토리 슬롯 조작은 여전히 하위 행동 공간이다.
같은 기능의 독립된 상태 기계를 중복 구현하지 않고 기존 과업/레시피/학습 모듈에 연결한다.

| 과업 | 내부 단계 예시 | 완료 근거 | 현재 범위 |
|---|---|---|---|
| 원목 수집 | 탐색→접근→채굴→수집→확인 | 서버 원목 증가 | RM 입력·shaping·소규모 RL 연결됨 |
| 흙 수집 | 대상 확인→접근→채굴→수집→확인 | 서버 흙 증가 | 기존 수집 가능, 단계 RL 연결은 별도 구현 필요 |
| 제작 | 재료 확인→적합한 그리드 열기→레시피 배치→출력 회수→확인 | 서버 인벤토리와 커서, 레시피 일치 | 기존 명시적 GUI 보조, 자율 RL 제작으로 해석 금지 |
| 작업대 사용 | 보유 확인→설치 위치 확인→설치→열기→작업→정리 | 실제 블록/3×3 화면/인벤토리 | 기존 보조 경로 사용, 단계별 학습은 별도 |
| 새 이동/전투 등 | 대상·위험 확인→접근→상호작용→결과 확인 | 과업별 서버 이벤트 필요 | 미지원 의미를 실행 vocabulary에 자동 추가하지 않음 |

## 단계 계약

새 단계를 추가할 때 다음을 함께 명시한다.

1. 진입 조건과 이용 가능한 증거: 관측 범위·timestamp·source, privileged 여부.
2. 완료 조건: 상태가 실제로 바뀌었는지. 채굴 입력을 보냈다는 사실만으로 블록 파괴를 인정하지 않는다.
3. 재탐색/복구/시간 초과: 목표 소실, 접근 불가, 커서에 남은 물품, 재료 부족 등에 대응한다.
4. 정책 및 value 입력: stage와 목표를 기록만 하지 않고 학습·실행에 전달한다.
5. 보상 분리: 실제 과업 성공, 진행도 shaping, 시간 비용, 실패 비용, human prior를 각각 기록한다.
6. 중단: 완료/취소/실패의 우선순위, 전송 중 행동과 이후 행동의 경계를 정의한다.
7. 검증: 정상 전이, 이미 충족된 단계 건너뛰기, 소실/복귀, 중복 보상 방지, 종료/시간 초과를 시험한다.

현재 상태에 맞게 단계를 건너뛰거나 되돌아갈 수 있다. 이미 나무 앞이면 탐색을 강제하지 않고,
채굴과 동시에 주워지면 수집 대기 없이 완료한다. 완료 이력과 현재 재료 보유는 별도로 관리한다.
상위 목표 수량을 늘린다고 단일 획득 reward latch를 임의 재무장하지 않는다. 반복 과업에는
소모/버리기/다시 줍기까지 고려한 별도 계약이 필요하다.

## 검증과 개선 순서

관측/단계 판정→보상·종료 계산→정책/학습 입력→실제 skill 실행→동일 조건 대조→다중 세계 평가 순으로 확인한다.
스크립트는 시험 배치의 비용 측정이나 재현에만 명시적으로 사용하며 learned policy 결과와 합산하지 않는다.
성능 기준은 실제 목표 획득과 시간/틱이다. 높은 shaping 합만으로 성공을 선언하지 않는다.
단계 수를 늘리는 것 자체가 학습 개선 증거는 아니며, 학습 가능한 성공·실패·복구 경험이 함께 필요하다.

현재 원목 수집의 수집 거리는 실제 아이템 entity가 아닌 파괴 위치를 사용한다. 다른 과업으로
일반화할 때 이 근사를 복사하지 말고 필요한 관측을 먼저 구현·검증한다.
