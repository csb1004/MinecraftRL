# 조합 정지 경계 원인 분석 및 재검증

원본 연구 명세와 목표를 유지한다. 기존 두 실험의 실제 로그를 재계산한다.
수집 RM의 완료 후 dispatch 여부와 craft-probe의 별도 실행 경로를 구분한다.

확인된 원인:

- 최초 무정지 실험은 과업 RM 없이 180초 정책 평가를 했다. 회수 증거가 있어도 계속했다.
- 후속 정지 실험도 task_session=false인 별도 경로다. 인벤토리 4개와 제작 통계를 함께
  기다려, 성공 세 시행에서 인벤토리 4개 이후 정책 행동이 각각 4번 추가됐다.
- 실패 두 시행은 전체 인벤토리 4개를 관측하지 못했다. 커서·조합 입력 칸은 기존
  인벤토리 집계에서 빠지고, 정책이 버튼/막대기 조합으로 진행했다.
- 설치된 Minecraft의 Container.onContainerClosed는 커서 물품을 드롭한다.
  창 닫기만으로 커서 회수를 보장할 수 없다.

이번 실험의 상태 경계는 crafting → recovering → completed/failed다. 커서·실제 조합
입력·플레이어 인벤토리의 판자 합이 4개가 되면 제작 정책 dispatch를 금지한다.
결과 미리보기는 합산하지 않는다. 읽기 전용 모니터는 게임 물품을 변경하지 않는다.
필요 시 일반 MineRL 마우스 이동·클릭으로 커서 물품을 빈 인벤토리에 놓고 창을 닫는다.
서버 통계는 최대 8개 중립 스텝에서 기다린다. 이후 실제 인벤토리 4개·통계 증가 4·
커서 비움·GUI 닫기를 확인해야 completed다. 저장 NBT를 추가로 대조한다.

이것은 STEVE-1 단독 회수 성공과 다른 **정책 제작 + 명시적 회수 보조** 조건이다.
정책 성공과 정리 후 과업 성공을 별도로 집계한다. 일반 대화/RM 제작 지원으로 확대하지 않는다.
원래 RM에 문제가 있다고 가정해 수집 런타임을 변경하지 않는다. 완료 후 다음 추론·행동 0회
회귀 검사를 추가하고 기존 상태 전이를 확인한다.

기존 원목 1개 저장 세대·prompt·guidance·고정 시드 5개·제어 상한 180초를 유지한다.
원본은 보존하고 복사본만 사용한다. API 0회. 초기화/정리/저장 시간과 정책 제어 시간을
구분한다. 관측·빌드 실패는 기술 실패로 기록하고 미실행은 과업 표본에 넣지 않는다.

## 첫 실행 후 확인한 추가 조건

첫 실행 results/craft-recovery-20261004T065808018475Z에서 104729는 저장까지 일치했으나
130363은 클라이언트 판자 4개와 저장 NBT의 판자 0개가 불일치했다. 뒤의 155921은
초기화 중 중단했고 나머지 2개는 미실행이다. 이 실행을 5회 성공 결과로 합산하지 않는다.
클라이언트 커서 비움만으로 저장을 보장한다는 가정을 폐기한다.

후속 수정 실험은 로컬 통합 서버의 인벤토리·커서·제작 통계를 읽기 전용으로 관측한다.
커서 배치 후 서버 인벤토리 판자 4·커서 0·제작 증가 4를 최대 12개 중립 스텝에서
기다린다. 확인 전에는 GUI 닫기를 거부한다. 이후 닫힌 GUI와 서버/클라이언트 상태를
확인하고 저장 NBT를 다시 대조한다. 서버 확인이 되지 않으면 실패로 남긴다.
이전 실패 시드부터 130363, 262147, 104729, 155921, 196613 순서로 같은 고정 5개를
검사한다. 정책 제어 상한·원본 저장 세대·가중치·문구는 유지한다.
