# MinecraftRL 연구 명세 — 러프 요약

2026-10-08. 원문은 [연구 명세 20개 항목](research-spec.md)이며, 이 요약으로 범위를 축소하지 않는다.
아래는 목표와 요구사항이다. 모두 구현됐다는 뜻은 아니다.

## 최종 목표

사람과 계속 대화하면서 함께 Minecraft를 플레이하는 동료 에이전트.
대화와 행동에 페르소나를 유지하고, 장기 목표를 기억하며, 상황 변화에 대응한다.

## 전체 흐름

대화·월드 관측 → LLM 의미 해석 → 과업 확정 → 목표/RM 보관·우선순위 선택
→ 상위 계획 → skill 내부 RM → 사전학습 정책·모방학습·강화학습 → 실제 게임 결과 검증.

- 대화: 잡담·선호·제안·실행 요청·수정·취소를 구분한다. LLM 혼자 과업 확정/완료를 결정하지 않는다.
- 기억: 최근 대화와 요약, 사용자 선호, 월드 정보, 과거 경험을 사용한다. 실행 진행도는 구조화된 RM이 보존한다.
- RM: 장기 목표와 skill 내부 단계를 구분한다. 탐색→접근→채굴→수집처럼 검증 가능한 상태 변화로 나눈다.
- 계획: LLM이 다음 과업과 대안을 제안하고 로컬 검증기가 실행 가능성·전제·우선순위를 확인한다.
- 행동: 공개 Minecraft 사전학습 정책과 인간 시연을 활용하고, BC/미세조정/RL로 환경과 skill에 적응시킨다.
  이동·시점·채굴·설치·전투·인벤토리 조작 등을 다룬다. 명시적 GUI/API 보조와 학습 정책 결과는 구분한다.
- 인간형 플레이: 인간 행동 prior와 문화·관습 지식을 구분하고, 페르소나는 목표를 임의 변경하지 않고 행동 선호에 반영한다.
- 검증: 실제 서버 상태·인벤토리로 성공을 판정한다. 성공률, 소요 시간/행동, 지연, 메모리, 실패 원인,
  목표 유지·취소·재개·중단을 측정한다. 학습/개발/최종 평가를 분리한다.

## 추가 합의: RM을 버리지 않고 우선순위를 조정

사용자 요구: **LLM 재계획의 기본 동작은 기존 RM 삭제·교체가 아니라 기존 목표를 보존하고 실행 우선순위를 바꾸는 것**이다.

1. 각 목표/RM에 고정 ID, 버전, 현재 단계, 완료 증거, 우선순위, 대기/실행/중단/완료/취소 상태를 보존한다.
2. 새 요청이나 긴급 상황에서는 새 목표를 추가하거나 기존 목표의 우선순위를 조정한다.
   잠시 밀린 목표는 대기 상태로 남으며 진행도를 초기화하지 않는다.
3. 우선순위는 실행 순서다. 선행 조건을 건너뛰거나 RM 완료 조건·보상값을 임의로 바꾸는 수단이 아니다.
   기본 순서는 안전 대응→명시적 긴급 요청→주 과업→배경 과업→자율 행동이며, STOP은 모든 실행에 우선한다.
4. LLM은 변경 대상 ID/버전, 우선순위, 이유와 근거를 제안한다. 검증기는 오래된 제안, 미지원 skill,
   의존 관계 위반을 거부한다. 변경 전후와 사유를 기록한다.
5. 상위 과업이 끝나면 실행 가능한 대기 과업을 다시 선택한다. 명시적 사용자 pause/STOP은 자동 해제하지 않는다.
   재개 전 현재 월드·재료·도구를 확인하고 필요한 단계만 다시 준비한다. 완료 보상은 중복 지급하지 않는다.
6. 명시적 취소는 기록을 지우지 않고 cancelled로 남기며 자동 재개하지 않는다.
   목표 내용 변경은 이전 버전을 보존하고 새 버전에 연결한다. 대체된 버전을 대기 목표처럼 다시 실행하지 않는다.

예: “철 모아줘” 수행 중 “일단 집으로 와” → 철 RM의 진행을 보존하고 귀환을 우선 실행.
귀환 후에는 유효한 재개 조건에 따라 철 목표의 남은 단계부터 계속한다.
“철은 이제 필요 없어”라면 철 목표를 취소 상태로 보존하고 실행 대상에서 제외한다.

이는 [상위 플래너](llm-high-level-planner-2026-10-07.md)의 추가 요구사항이다.
원문12절의 ‘현재 RM 종료→새 RM 생성’은 자동 삭제를 뜻하지 않으며, 임시 전환은 이 보존·우선순위 규칙을 따른다.

## 현재 위치

STEVE-1 실제 실행, 원목 RM/RL·BC, 마지막 표현층 미세조정과 실제 게임 비교를 진행했다.
긴 벽 우회 일반화는 미입증이다. [기존 root RM과 임시 하위 계획의 우선순위 연결](rm-planner-validation-2026-10-10.md)은
구현했고 고정 계획에서 실제 원목+1을 확인했다. 새 형식의 실제 LLM1회는 탐색 반복과 다른 우회 하위 계획을
생성했지만 실행기가 없는 단계여서 실제 복구를 실행하지 않았다. 복수 사용자 과업 전체의 우선순위 관리와
우회 skill은 검증·확장해야 한다. 최신 근거는 [진행 기록](progress.md)을 따른다.

다음에는 우회/복구 skill을 개선하고, RM 보존·우선순위 전환·재개를 구현·검증한 뒤 장기 과업으로 확장한다.
