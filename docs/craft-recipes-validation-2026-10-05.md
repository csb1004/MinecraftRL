# 막대기·작업대 실제 독립 검증 — 2026-10-05

로컬 Windows/WSL에서 STEVE-1 고정 시드5개 × 두 조건을 완료했다. 클라우드 실행은 없다.
작업대1개 제작·저장은 **4/5**, 막대기 제작·저장은 **2/5**이나 두 번 모두8개여서
**막대기4개·판자2개 보존은0/5**다. 미실행·기술 실행 실패·추가 API는0이다.
대화/RM의 일반 제작 지원은 아직 추가하지 않았다.

## 조건과 원본

[사전 조건](craft-recipes-protocol.md). 각 회차는 판자4/흙1인 동일 저장본의 독립 복사본이다.
이 판자는 이전 정책 실험에서 자연 수집한 원목으로 제작·저장한 것이다. 아이템 지급이나
조합 API를 사용하지 않았다. 같은 월드의 정책 시드 반복이며 서로 다른 월드5개가 아니다.

- 시작 세대: `results/craft-recovery-20261004T071020156492Z/104729/worlds/sequence-20261004T025836469371Z/26ade77ecd2e4552bfa87a0d01a23ff9`
- 막대기 원자료: `results/craft-sticks-20261004T162709295721Z`
- 작업대 원자료: `results/craft-table-20261004T165122395709Z`
- 각 원자료의 `experiment.json`, `recipe-analysis.json`, 시드별 `run/events.jsonl`,
  `run/craft-cleanup.json`, `saved-inventory-verification.json`에 판정 근거를 보존했다.
- 원본 포인터와 manifest/world.zip 해시 유지. 연구 명세 SHA256도 유지했다.
- 프롬프트: `craft sticks` / `craft a crafting table`. 막대기 수량4는 제어기의 사전 조건이며
  프롬프트에는 수량을 넣지 않았다. 초과 제작을 언어 수량 지시 이해 실패라고 해석하지 않는다.

## 서버와 클라이언트 수량 차이

시드130363의 막대기 step88에서 클라이언트4/서버0을 관측해 정책을 즉시 정지했다.
새 정책 행동 없이 서버 대기 중 양쪽 모두8개가 됐고 저장 NBT도8개였다.
마지막 정책 입력은 Shift+클릭이다. Minecraft는 이 입력을 QUICK_MOVE로 처리하고,
서버에서 결과 슬롯을 갱신하며 재료가 허용하는 만큼 반복 제작한다.
클라이언트4는 최종 성공이 아니라 조기 정지 신호였고, 정확 예산 성공으로 인정하지 않았다.
[로그와 원본 코드 경로](craft-batch-click-cause.md).

따라서 서버 확정 대기는 오판을 막지만, 이미 전달한 일괄 제작의 재료 소비를 되돌리지 못한다.
다음 보완 지점은 **행동 전달 전의 레시피·재료 예산 제약**이다. 관측 뒤 정지 처리만
다시 수정해서는 이 문제를 해결할 수 없다. 이번 고정 조건 실행 도중 정책 출력을
수정하거나 API 제작으로 대체하지 않았다.

## 검증과 변경 범위

- 목표가 실제 생성된6회 모두 첫 관측 이후 새 추론/정책 전달0. 나머지4회는 목표 미생성으로
  이 검사의 성공 표본이 아니며, 모든10회에서 STOP 확인 후 새 추론/정책 전달0을 검사했다.
- 10회 입력 해제, GUI 종료, 빈 커서, 소유 자식 종료 및 저장 NBT 일치.
  종료 후 프로젝트 WSL Python/Java 잔존0, STOP 유지.
- Windows123개 통과/4개 플랫폼 제외, WSL127개 통과.
  `results/craft-recipes-windows-tests.log`, `results/craft-recipes-wsl-tests.log`.
- Java 관측 패치 빌드 성공. 별도 JAR `5378bd256926aca57f5a697f8dedb3f190834ef75c14cbb2d6e621ed58e4445f.jar`를 사용했다.
  설치된 원본 게임 JAR와 시스템 Python/Java/드라이버는 변경하지 않았다.
- 최종 근거: `results/craft-recipes-final-verification.json`, `results/craft-recipes-process-check.json`.
- 코드: 고정 레시피3종, CLI 격리 조건, 읽기 전용 목표/서버 관측 확장,
  GUI 종료 뒤 남은 판자의 서버 복귀 검사, 실행·분석 스크립트와 회귀 검사.
- 원래 craft_success 필드는 정책 실행 중 늦은 제작 통계까지 일치한 witness이다.
  조기 정지 조건에서는 false일 수 있어 이를 제작 실패율로 사용하지 않는다.
  위 성공률은 서버 확정·회수·저장까지 검사한 task_success_after_cleanup 기준이다.

아직 작업대 배치·열기, 3×3 곡괭이 제작, 제작 목표의 대화/RM 연결, 정확 수량의 행동 전
제약은 미검증/미구현이다. 우선 수량과 레시피 제약을 별도 조건으로 검증한 뒤 순차 제작으로
진행해야 한다. 이번 소규모 결과로 인간다움·문화 이해 또는 전체 생존 능력을 주장하지 않는다.
