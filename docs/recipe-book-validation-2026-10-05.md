# 레시피북 실제 검증 — 2026-10-05

레시피북 선택→자동 재료 배치→배치 검사→결과 회수 경로가 실제 MineRL Java1.16.5에서
작동했다. **막대기4·판자2 보존5/5, 작업대1 제작·보존5/5**다. 모두 자연 제작 판자4·흙1
저장본의 독립 복사본이며, 게임의 정상 마우스 입력만 사용했다.

이것은 **명시적 GUI 보조의 결과**다. 읽기 전용 내부 관측으로 버튼의 레시피 정체와
좌표를 확인하고 결정적 제어기로 클릭한다. STEVE-1/VPT 가중치를 로드하거나 LLM을
호출하지 않았다. 기존 정책의 제작 능력이5/5로 개선됐다고 해석하지 않는다.
[사전 조건](recipe-book-protocol.md), [해금 조건 조사](recipe-book-unlocks.md).

## 구현한 검사

- `--recipe-book`/`--craft-recipe-book`은 별도2×2 실험 옵션이다. 기본 정책·대화/RM은 유지한다.
- 서버와 클라이언트의 실제 해금 여부, 현재 표시된 단일 레시피 버튼, 재료 충분 여부를 확인한다.
- 책 버튼을 일반 클릭1회로 선택한다. 자동 배치 응답을 기다리며 임의로 반복 클릭하지 않는다.
- 막대기는 세로 한 열에 판자1개씩, 작업대는 네 칸에 판자1개씩 있어야 한다.
  결과 아이템·출력 수량·빈 커서도 검사하고, 결과 칸 일반 클릭1회만 전달한다.
- 목표가 커서에 생기는 첫 관측에서 새 제어 행동을 멈춘다. 기존 명시적 커서 회수 보조로
  인벤토리에 넣고 서버 확정·남은 재료·저장 level.dat/playerdata NBT를 확인한다.
- 잘못된 배치, 초과 재료, 다른 결과, 잠긴 레시피, 부족한 재료, 불명확한 그룹 버튼을
  거부하는 단위 검사를 추가했다. 이 거부 조건들을 모두 실게임으로 유발한 것은 아니다.

시작하는 분기는 이번10회로 검증했다고 주장하지 않는다.

## 해금의 실제 전후 비교

원본은 판자·막대기·작업대 레시피가 해금돼 있고 나무 곡괭이는 미해금이었다.
막대기 제작·회수 후에는5/5 저장본의 level.dat와 playerdata 모두 곡괭이 레시피가 추가됐다.
작업대만 만든5/5 저장본에서는 곡괭이가 여전히 미해금이었다. 설치된1.16.5의
`has_stick` 조건과 일치한다. 레시피 지급 명령이나 아이템 지급은 사용하지 않았다.

해금은 제작 가능과 다르다. 곡괭이에는 추가 판자3·막대기2와 작업대3×3가 필요하다.
표시 목록은 현재 칸 크기·탭·검색·페이지·재료 필터에도 영향을 받는다.
각 시행의 `unlocks.json`에 버전별 원본 조건과 저장 결과를 보존했다.
