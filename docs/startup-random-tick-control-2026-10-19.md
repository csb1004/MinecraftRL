# 시작 준비 동안의 무작위 블록 갱신 제어

2026-10-19. 구현 전 계약이다. 기존 연구 목표·정책·평가 결과는 유지한다.

같은 저장 월드를 불러와 60중립틱을 준비하는 동안 덩굴 성장 등이 달라졌다.
근거는 `results/common-block-state-20261019/comparison.json`이다. 원본 2회 사이
8블록/5픽셀이 달랐고, randomTickSpeed만 0인 대조 2회는 해당 영역과 픽셀이 같았다.
각 실행 내 서버와 클라이언트는 같았다. 단차 이동 실패와 분리한 초기 조건 문제다.

수정은 명시적으로 선택한 실험에만 적용한다. 기본 실행은 그대로 유지한다.

1. 원본 ZIP/sidecar를 보존하고 별도 시작 월드에 randomTickSpeed=0만 기록한다. 다른 NBT 값과
   ZIP 멤버의 보존을 검증한다. 원래 값·원본 해시·복사본 해시·split을 함께 기록한다.
2. 기존 60중립틱·입력·시점·이동·시간 진행은 바꾸지 않는다. 고정된 MineRL 초기화에서
   첫 정책 관측은 client_tick=80이었다. 이 경계를 검사하고 다른 경계를 조용히 허용하지 않는다.
3. 마지막 준비 화면을 캡처하는 메인 스레드에서 첫 정책 행동 이전에 원래 randomTickSpeed를 복원한다.
   복원은 추가 입력/서버 tick/클라이언트 tick/RNG 추출 없이 수행하고 실제 복원값과 경계의 증거를 남긴다.
4. 잘못된 월드 해시·미지원 split·누락/불일치한 복원 기록·경계 누락은 정책 제어 진입을 막는다.
   STOP은 계속 우선하며, 원본 월드를 변경하거나 취소된 실행을 성공으로 세지 않는다.
5. 실제 2회 이상 초기화에서 같은 초기 관측과 복원 증거를 확인하고, 그 뒤 첫 제어 틱에서도 원래 규칙이
   유지되는지 검사한다. 단위/실제 검증을 통과한 새 코드/JAR/월드로만 새 정책 비교를 동결한다.

준비 동안의 환경 제어를 새 실험 조건으로 기록한다. 실제 정책 제어 중에는 원래 성장 규칙을 사용한다.
과거 판정 null을 덮어쓰지 않는다. 일반적인 Minecraft 전체 결정론이나 모든 렌더 불일치 해결을 주장하지 않는다.
최종 5월드는 여전히 열지 않으며 기존 교정/개발 결과의 개선 수치도 소급 합산하지 않는다.

관측 진입 검사다. 실제 구현 시 기본 JAR 경로의 동작 보존과 중단/정리도 함께 확인한다.
