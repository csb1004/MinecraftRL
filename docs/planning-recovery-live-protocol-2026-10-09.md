# 실시간 LLM 복구 제안 일회 연결 — 승인용 실행 조건

상태: 실행 준비. 이 문서는 유료 자원 사용의 승인이 아니다. 이전 승인2회의 API 예산은 모두
사용했으며 새 실시간 호출은0회다. 아래 한 번의 유료 요청만 추가 승인받은 뒤 실행한다.
원문 연구 목표·원래 wood RM·완료 증거·기본 정책은 유지한다. 복수 RM 우선순위 스케줄러 전체를
구현한 것으로 해석하지 않는다.

## 검증할 상태 변화

실제 정체→입력 해제/현재 근거 고정→Windows LLM 제안→WSL 현재 상태 재검증→제한된 신경망
복구 또는 일시정지→원래 wood 조건 복귀/실제 인벤토리 판정. 과거 기록 대상 API 검사가 아니라
현재 게임의 요청 ID·월드·실행 세대에 묶인 제안이다.

LLM vocabulary는 `explore_then_resume`, `remain_paused` 두 가지다. 탐색 방향·경로·채굴 키를
직접 지정하거나 미구현 skill을 실행하지 않는다. LLM 출력은 제안이며 ReplanGuard 검토와
현재 STOP/목표 완료/시간 제한 검사를 통과하기 전에는 제어할 수 없다.

정체 시 남은 시간이 대기20초+복구30초를 확보하지 못하면 요청하지 않는다. 정체 없이 원목을
얻으면 API0회/인계 미실행이다. 응답 거절·오류·시간 초과에 고정 응답이나 API 키 조작으로
대체하지 않는다. STOP 이후 도착한 응답은 기록만 하고 제어에 쓰지 않는다. 입력 해제와 소유
자식 PID 정리를 검증한다. 게임의 종료와 네트워크 응답의 종료는 각각 기록한다.

## 데이터·기록 경계

Windows 브로커만 기존 MyWife 설정을 읽는다. 비밀키를 WSL/명령행/결과에 복사하지 않는다.
전송 데이터는 정체 근거·현재 서버 상태·RM 참조·잔여 시간 등 해당 실험 패킷과 고정 프롬프트다.
개인 대화·persona·프로젝트 전체를 전송하지 않는다. 네트워크 영수증, 응답/usage, 지연,
브로커 요청/응답, 원본 전이/화면/기억·RM, GPU/제어주기/인벤토리를 프로젝트 results에 보존한다.
API 연결이 시작된 시점부터 보수적으로 호출1회로 기록하며 네트워크 오류도 자동 재시도하지 않는다.

획득은 서버 인벤토리로 판정한다. 준비용 고정 응답 실행, 기술 오류, 취소, 인계 미실행은
LLM 복구 성능의 성공/실패 표본에 섞지 않는다. 이1회는 실행 연결 검사이며 LLM의 추가 효과,
우회 일반화, RL 개선이나 인간다움의 증명이 아니다. 이후 성능 비교는 별도 조건과 예산을 정한다.
최종 평가5시드3000017/3000029/3000047/3000061/3000073는 사용하지 않는다.

## 실행과 보존

준비 manifest: `results/planning-recovery-live-prepared-20261009/manifest.json`.
프롬프트·소스·월드·체크포인트·임베딩 해시를 확인한 뒤 전용 일회 결과 폴더를 생성한다.
완료/실패 폴더가 이미 있으면 거부한다. 중간에 소스가 바뀌면 manifest 불일치로 중단한다.
`approved:false`는 준비 문서 자체가 권한을 부여하지 않는다는 뜻이며 사용자 승인은 대화와
명시적 실행 옵션으로 별도 확인한다.

추가 승인 후 PowerShell 실행 명령:

```powershell
$env:PYTHONPATH='src'
python scripts/run_planner_exchange_pilot.py --allow-paid
```

실행 기록은 `results/planning-recovery-live-20261009/work.json`이다. 게임 summary의 유료 호출 수가
null이면 호출0으로 해석하지 않고 Windows 브로커의 `api-receipt.json`과 대조한다.
종료 뒤 `scripts/audit_planning_recovery.py`에 run, checkpoint, `--exchange`를 넘겨 실제 기록을
감사한다. 결과를 보고한 뒤 후속 유료 호출을 추가로 실행하지 않는다.
