# 같은 프로세스에서 한 번의 정책 재초기화

사용자의 다음 단계 실행 요청에 따라 이전 문구 비교의 미검증 항목을 진행한다.
일반 런타임은 기존의 명시적 resume 방식을 유지하며, 실험기만 자연 정체 뒤 재개를
한 번 발행한다. 무한 재시도나 자동 목표 변경은 없다. 유료 API 0회.

## 사전 고정 조건

- 원본 슬롯 failure-20261004T032512557525Z의 세대
  1c1415241ad44a81b6e89a1943472bf0을 각 시행의 격리 저장소에 복사한다.
  이는 이전 실제 흙 무획득 시행이 시작한 세대다. 원본 pointer/manifest/zip은 보존한다.
- 최초 설정에서 paused 과업을 dirt 1개로 교체하고 재개한다. 정책은 기존 short,
  guidance 6.0. 이후 복구 시 목표·baseline·진행도·완료 이력을 그대로 유지한다.
- 시드는 130363, 104729, 155921, 196613, 262147. 이전 실패 시드를 먼저 검사하고
  나머지 고정 시드를 수행한다. 같은 저장 월드의 난수 시드 비교다.
- 자연 무획득 60초 시 기존 resume 명령으로 **최대 한 번** 재초기화한다.
  두 번째 정체에는 저장·종료한다. 각 시행의 전체 제어 상한은 재시도 포함 180초다.
- 초기 성공, 정체 후 재초기화 성공, 재시도 후 미완료를 별도로 센다.
  초기 성공은 재초기화 성공의 분모/분자에 넣지 않는다. 자연 정체가 없으면 해당
  시행의 복구 효과는 미검증이다. 기술 오류가 나면 남은 시행을 멈춘다.
- 재개 관측만으로 완료되어 실제 policy reset 전에 끝난 경우도 따로 분류한다.

## 검증 근거

worker PID, episode 시작 횟수, 환경 reset 횟수, policy reset 이벤트를 비교한다.
재개는 recurrent state와 text prior embedding을 함께 재초기화한다. hidden state만의
효과는 분리하지 않는다. 조건 embedding 해시 변경을 기록한다.
pause부터 새 resume acknowledgment 전 및 STOP 이후의 정책 dispatch는 0이어야 한다.
모든 시행에서 중립 입력 해제, 저장 성공, 소유 자식 종료를 확인한다.

## 구현 기록

기존 런타임의 resume 동작은 이미 필요한 기능을 제공했다. 새로운 테스트에서 같은
정책 객체·월드를 유지하고 부분 진행도/완료 단계를 보존함을 확인했다. 실험기의
1회 예산과 worker PID 증거를 실패 검사로 먼저 확인한 뒤 추가했다.
일반 세션의 정책 행동/자동 재시도 설정은 바꾸지 않았다. 사용자 지침대로 단일
에이전트·현재 프로젝트에서 실행하며 자체 검토한다.
