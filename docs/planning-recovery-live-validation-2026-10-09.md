LLM은 구현된 임시 탐색/일시정지 중 하나를 제안할 수 있고, 방향성 우회나 새 탐색 skill을
직접 만들어 실행할 수는 없다. 이 한계와 LLM 전송·검토의 정상 동작을 구분한다.

기존 실패 판정기로 탐색 구간을 다시 평가하면 `recovery_budget_exhausted`, `replan_candidate=true`,
`goal_completed=false`, `task_impossible=false`다. 이동량만으로 복구 성공을 주지 않는다.
이 판정은 이번 결과 분석에 연결했으며 실행 도중 한도를 바꾸거나 두 번째 API 요청을 하지 않았다.
후속 단위는 복구 종료 근거를 실행 스케줄러에 전달하고, 실패 이력·남은 시간·호출 예산·실행 가능한
대안에 따라 다음 동작을 정하는 것이다. 다중 RM 우선순위와 목표 재획득 skill의 학습은 별도 과제다.
