# E2 실행 계약·전체 과업 학습 — 실험 완료, 후보 미승격

[고정 원래 프로토콜](specs/2026-11-03-execution-contract-e2.md), [독립 실행법](execution-contract-e2-usage.md).
본 배치 26회와 후보 학습 3회, 실제 STOP 검사, 별도 회수 비교 8회를 완료했다. 보존 후보의 일반 개발 완료는 초기2/5에서4/5로 늘었지만 탐색·회수 퇴행이 남아 가중치를 기본 정책으로 승격하지 않는다. 34회는 train6회와 개발28회이며 이를 하나의 성공률로 합치지 않는다.

## 구현 범위

| 승인한 개선 | 이번 연결 | 한계 |
|---|---|---|
| 공통 실행 계약 | 같은 v2가 작성 형식, RM 판정, 정책 입력, 실행 결과의 기준이 됨 | 등록 대상은 wood/dirt; 새 문장만으로 새 능력이 생기지 않음 |
| 전체 목표와 자원 보존 | acquire/possess/preserve, 마지막까지 이어지는 return, 실제 서버 수량 검증 | 시작 인벤토리·단계 관측은 privileged 조건 |
| 공통 능력·전환·보존 학습 | 별도 학습기, 목표별 비중, critic 보정, PPO와 분리한 공식 정책 KL 자료 | 작은 개발 실험; 일반화·지속학습 완성의 증거가 아님 |
| 실패·변경 경계 | 보수적인 실패 기록, 확정 행동 경계의 우선순위 변경, 의미 변경은 새 실행 | 자동 모니터/LLM/SQLite 루프는 아직 연결하지 않음 |

관련 WSL 회귀 118개 통과. 기존 v1/E1 실행 의미는 유지한다. 공식 STEVE-1 backbone/순환망/기본 motor를 고정하고 residual adapter와 value만 갱신한다. 새 목표 임베딩을 만들거나 observer를 재학습하지 않았다.

## 환경·고정 조건

Windows의 실제 프로젝트에서 기존 WSL Ubuntu-24.04 격리 환경을 사용했다. PyTorch2.0.1/CUDA11.7/GTX1060 3GB에서 행렬 계산을 실제 확인했다. `glxinfo`는 설치되어 있지 않아 조회하지 못했고, 중립 준비의 실제 Minecraft 렌더링 PNG와 게임 로그를 보존했다.

원래 배치 `results/execution-contract-e2-20261103`: 소스345, 입력47, 공식 모델/원문/기존 완료 영수증7의 해시를 고정했다. Git HEAD는 `de1d2f932918382dba76ab1a790b788ad00f4346`이며 작업 트리는 기존 미커밋 변경을 포함한다. 실행 시점 소스를 `source-at-game`에 복사하고, 실행에 사용하는 프로젝트 소스의 동일성을 각 실행 전후 해시로 검사한다.

추가로 후보 생성·개발 결과 전에 회수 능력 보존 비교8회를 별도 선언했다.
`results/execution-contract-e2-20261103-retention-check/plan.json`은 side(흙)와 occluded(원목) 개발 환경에서 초기/세 후보를 비교한다. 원래26회와 별도 집계하며 이 자료를 학습하지 않는다.

## 후보 학습

세 후보 모두 같은2,373행동으로 PPO150업데이트/4,746행 방문을 수행했다. 행동 확률·기존 value 재현 오차0, 기본 motor 보존, KL 조기 중단 없음. 보정 두 후보는 actor를 고정한 critic750업데이트에서 학습 자료의 가중 MSE .36445→.000934로 낮췄다. 이 학습 오차 감소가 행동 성능 향상을 뜻하지 않는다.

| 후보 | critic 보정 | 별도 보존행 | PPO 업데이트 | 기록된 PPO 구간 CUDA 최대 MiB | checkpoint SHA256 |
|---|---:|---:|---:|---:|---|
| plain | 0 | 0 | 150 | 255.84 | `901021f61496c6883dc3bb83f8a4424be8ea9df0abacd06a40ab2cc1757f4e3b` |
| calibrated | 750 | 0 | 150 | 256.14 | `6d0b00cd52cbd37391b4d17d57f013c96124579d785ded260548a3699d90fe92` |
| retained | 750 | 508 | 150 | 274.20 | `7e9b8817dd132b1c54e9985252490cee7e5503ae8fc9d71cbab09b0df5c19cda` |

E2 안에서 critic 보정과 보존 자료의 차이를 비교한다. 계약/전체 return/명시적 목표 입력/목표별 비중을 동시에 도입했으므로 이 각각의 개별 인과 효과나 E1 대비 효과를 이번 비교만으로 분리하지 않는다.

## 일반 개발 비교: 5조건 × 4정책

숫자는 실제 정책 행동 수다. 한 조건당 각 정책 한 번의 개발 관측이며, 성공률 추정이나 봉인된 최종 평가가 아니다.

| 목표 | initial | plain | calibrated | retained |
|---|---|---|---|---|
| 원목3 새 획득 | 실패 1,130: 시간 제한, 최종2 | 실패 1,000: 미회수, 최종1 | 완료 886 | 완료 356 |
| 흙3 보유 | 완료 179 | 완료 529 | 완료 558 | 완료 99 |
| 원목1→흙1, 원목 보존 | 완료 607 | 완료 388 | 실패 600: 원목 탐색 | 실패 600: 원목 탐색 |
| 흙1→원목1, 흙 보존 | 실패 600: 흙 무진전 | 실패 600: 흙 무진전 | 실패 600: 흙 무진전 | 완료 339 |
| 원목1 획득→동일 원목 보유 | 실패 810: 무진전 | 실패 769: 미회수 | 실패 595: 미회수 | 완료 258 |
| 전체 완료 | **2/5** | **2/5** | **2/5** | **4/5** |

retained의 마지막 조건은 원목2를 얻은 서버 틱340에 두 목표가 모두 완료됐다. 후속 보유 목표의 추가 정책 행동은0이며 프로그램 완료 보상은1회다. 이는 실제 서버 증거로 확인한 즉시 완료 경계이다. 첫 목표에서 실패한 나머지 실행들의 후속 목표는 미실행이며 별도 실패 표본으로 세지 않는다.

관측된 전체 완료 수는 retained가 높지만 초기 정책이 완료한 원목→흙 조건을 실패했다. 따라서 자동 승격하지 않는다.
PPO 자료의 원목search 태그는207행동(전체2,373의8.7%, 원목1,102의18.8%)이며 보존 자료는 회수 조건이었다.
이는 탐색 보존 경험의 범위가 좁다는 근거이며 퇴행의 단일 인과를 확정하지 않는다. 흙의 세부 단계는unknown이므로 raw `collect` 태그를 전부 회수 경험으로 해석하지 않는다.

원목1→흙1 실패 두 후보의 시작/최종 PNG를 확인했다. 최종 화면은 원목이 아닌 지형 블록에 접한 모습이며, 서버 인벤토리는 각각 red_sand1·원목0이었다. 목표 관련 확정 상호작용0, 요청/임베딩은 원목 탐색으로 유지됐다. 영상만으로 시각 인식 오류나 학습 퇴행의 단일 원인을 확정하지 않는다.

원목 획득→보유 조건의 initial 화면190→210→250에는 원목 옆 벌집을 부수고 상태 이상이 나타난 순서가 남아 있다. 서버 체력20→최저0.8333, 피해 분류는other였으며 정확한 피해 원인을 자동 판정할 수 없다(`posthoc-health-audit.json`). plain은 목표 관련 상호작용1회 후300틱 동안 원목0이었다.

원목3 조건의 initial은 총 증가3·감소1이었다. 감소 시점은1110행동, 직전1106에 `use`가 있었으며 GUI닫힘/커서빈 상태였다. 입력과 실제 감소 사이의 지연도 보존했다. 정확한 소비 원인을 확정하지 않고, 항목별 최고치 합계를 현재 보유량으로 잘못 세지 않는다. 근거: `flow-metrics.json`, `loss-observation.jsonl`, 원본 events/PNG.

## 본 배치 검증과 한계

- 원본 서버/행동/계약/보상 감사14,384행, 불일치0. 실제 tensor와 JSON의 계약·목표 벡터·문맥도14,384행 일치했다.
- 실행당16행, 총416행의 CPU 행동 확률 재현 최대 절대 logp 오차는0.00006390이다. 전체 행동 확률을 모두 재계산했다는 뜻은 아니다.
- 15개 초기/후보 비교 모두 시작 위치·시선이 같았다. 첫 픽셀과 특징까지 같은 비교는6/15였다. 나머지 차이의 최대 변경 채널 비율0.0060, 평균 절대 채널 차이0.652/255였다. 완전히 결정론적인 비교로 주장하지 않는다. 원목→흙은 세 후보 모두 초기와 첫 픽셀/특징이 같았다.
- 새 train seed81113003의 첫 화면은 원목/흙 실행에서 동일했고, 전체 목표 조건부 모델의 첫 행동 인자별 최대 TV는0.9141이었다. 목표 조건에 반응하는 경로는 확인했지만 MineCLIP만의 인과, 결합 행동 TV, 지시 수행 성공을 의미하지 않는다. 다른 train seed는 첫 픽셀도 달라 별도 표시했다.
- 실행별 추론 중앙값49.36–55.05ms, p95 59.90–141.76ms; 전체 제어 주기 중앙값137.30–166.12ms, p95 180.41–254.08ms. 짧은 실행의 느린 초기 추론도 제외하지 않았다. 전체 장치 VRAM 표본 최대2,729–2,956MiB. 자원 오류로 무효 처리된 실행0이다.
- 실제 STOP은10행동 뒤 요청했다. 요청 가시화 이후/확인 이후 새 dispatch0, 입력0, 소유 자식 PID0. 확인 지연24.45ms, 측정 상한87.81ms. 의도된 중단의 worker exit2는 성능 실패가 아니다.
- 본 배치 최종 영수증은 코드/입력/공식 모델/원문/기존 E1 완료 영수증 보존을 확인했다. 성능 표본에 중립 준비·STOP·오프라인 감사는 포함하지 않는다.

근거: 본 배치 `analysis.json`, `tensor-audit.json`, `stop-probe-audit.json`, `driver-completion.json`.

## 별도 회수 개발 비교: 2조건 × 4정책

후보 생성 전에 선언한 준비된 Minecraft 환경이다. 바닥은 채취할 수 없고 떨어진 목표 아이템을 실제 정책으로 회수한다. 준비용 아이템 좌표는 정책 입력이 아니며, 이 개발 자료는 학습에 사용하지 않았다. 각 조건 최대400행동·180초 제어이다.

| 조건 | initial | plain | calibrated | retained |
|---|---|---|---|---|
| 옆에 놓인 흙(side) | 완료40 | 완료376 | 완료332 | 실패400 |
| 시야가 가려진 원목(occluded) | 실패400 | 완료120 | 실패400 | 완료148 |
| 전체 완료 | **1/2** | **2/2** | **1/2** | **1/2** |

보존 후보는 초기의 원목 실패를 개선했지만 흙 성공을 잃었다. plain도 흙 회수는 초기보다 느렸다. 따라서 ‘보존 KL을 추가하면 기존 능력이 보존된다’는 결론은 이 실험으로 지지되지 않는다. 성공/실패 표본 수가 작아 통계적 효과나 보편적 우열을 주장하지 않는다.

원본과 tensor2,216행 일치, 128행 CPU logp 재현 최대 오차0.00005388. 6개 초기/후보 쌍 모두 첫 위치·시선·픽셀·특징이 같았다. 실행별 추론 중앙값49.47–56.29ms, p95 최대145.33ms, 제어 주기 중앙값131.13–146.68ms, 전체 장치 VRAM 표본 최대2,735MiB였다. 기술적 무효 실행0, 입력 해제·소유 자식 종료를 확인했고 최종 STOP을 유지했다. 정확한 실행별 수치는 보충 배치 `analysis.json`에 있다.

두 배치 합계16,600행의 원본/입력 감사, 행동 확률 표본544행을 검증했다. 중립 준비40행동과 실제 STOP10행동은 성능 집계에 넣지 않는다. 보충 완료 영수증은 입력·공식 가중치·기존 완료 기록 보존을 확인했다.

| critic 보정·분리된 보존 학습을 독립 실행 코드로 비교 | train2시드·4PPO실행·2보존시작은 범위가 좁다. 새 train 환경의 탐색/접근/회수/전환 경험과 보존 표본을 늘리고, 신선한 rollout→업데이트 주기를 대조해야 함 |
| 관측 불확실성과 실제 실패 근거를 기록 | 흙 세부 단계·떨어진 아이템 위치는unknown이다. 피해종류other 같은 제한을 새 사실로 추측하지 않음 |
| 의미 변경과 우선순위 변경의 안전한 경계를 추가 | 현재 단일 실행 소유자의 mailbox이며 자동 LLM/감시 스레드/SQLite 통합은 후속 단계 |

자연 수집의 collect는 기존 root 임베딩, 독립 pickup은 별도 pickup 임베딩을 사용한다. 이 조건·장면 차이가 학습 전이를 제한하는지는 고정 관측에서 판정 가능한 회수 의도를 공통 계약으로 묶는 별도 대조가 필요하다. 모든 단계에서 무조건 임베딩을 바꾸거나 특정 월드에 예외 동작을 넣는 수정은 이번에 하지 않았다.

다음 실험도 개발 실패 월드를 학습에 섞지 않고, 경험 범위·조건 바인딩·학습 범위의 효과를 구분해야 한다. 현재 후보는 보존하고 승격하지 않는다. 유료 API/클라우드/원격 게시0, 원본 연구 명세와 4단계 OPEN 결정은 유지한다.

## 실험 후 정리

E2의 설명용 `condition_metadata.goal`에 남아 있던 과거 `collect wood` 명칭을 실제 프로그램 목표로, `phase_context_training`의 S2 명칭을 E2 설명으로 정리했다. 실제 per-action 목표/임베딩에는 해당 오류가 없었다. 두 키를 제외한 전체 파일 AST가 실험 당시 사본과 같음을 검사했고, 관련 WSL 회귀52개가 추가로 통과했다(건너뜀0). 앞선118개 검사와 중복이 있으므로170개의 서로 다른 검사로 합산하지 않는다.

기존 실행 기록을 다시 쓰거나 게임을 재실행하지 않았다. 재현 시 실험 당시 파일은 `source-at-game`, 실험 후 설명 변경은 `postrun-metadata-receipt.json`을 구분한다. 최종 `final-review.json`에서408개 파일 중407개는 실험 시점 해시,1개는 명시한 설명 변경 후 해시와 일치함을 확인했다. 소스 사본345개 보존, 두 배치의 동일 Minecraft JAR, 최종 STOP과 가중치·월드·화면의 Git 제외도 확인했다.
