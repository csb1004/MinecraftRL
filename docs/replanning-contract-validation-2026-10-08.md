## 구현한 동작

- `src/minecraftrl/replanning.py`: 실제 관측 snapshot, 원자적 실패/요청/판정 이력 저장,
  제한된 proposal 검증. 게임 입력·네트워크 호출·TaskState 수정 기능은 없다.
- world/episode/목표, 정책 버전, 관련 관측 사실로 같은 실패를 비교한다. 표현만 바꾼 재시도는
  거부한다. 자동 정체 pause가 task revision을 올려도 같은 실패를 새 시도로 보지 않는다.
  원래 revision은 이력에 남기며 응답 최신성 검사에서는 정확한 revision/실행 세대를 요구한다.
- 오래된 목표/실행 세대/전제, STOP·사용자 pause·취소·완료·대체, 입력 해제 근거 부재,
  근거 없는 event, 미지원 skill/인자, 보상·RM 수정, 시간/tick 예산 초과를 거부한다.
  실제 인벤토리가 이미 목표를 만족하면 요청 발급과 제안 수락 모두 막는다.
- 요청은 session당 최대3회, 응답은 요청당1회다. 발급 때 예산을 소비하고 재로드 후에도
  소비 상태를 유지한다. 독립적인 현재 시계로30초 TTL과 전체180초 예산을 검사한다.
  skill 예산 상한60초/600tick은 초기 계약값이며 효과를 실험으로 최적화한 값은 아니다.
- 모든 판정은 `execution_authorized=false`, `rm_effect=preserve`다. 형식상 유효한 제안도
  실행 허가가 아니다. 우선순위 스케줄러/실행기가 별도로 필요하다.

## 실제 기록과 가상 제안의 구분

완료된 graph-stall v3 기록에서 실제 정체5건/실패4궤적을 읽었다. 각 사건에 가상 제안7종을
독립적으로 대조해35건 모두 예상 사유로 거부했다. 정상 참고10궤적은 재계획 요청0건이다.
정상 참고에는 scripted teacher가 포함되므로 정책 성공률로 해석하지 않는다.

| 원본 정체 사건 | 원본 episode 시작 후 경과 시간 |
|---|---:|
| blocked-0, step421 | 45.665초 |
| blocked-0, step721 | 77.674초 |
| blocked-1, step400 | 42.744초 |
| long_wall parent, step200 | 24.802초 |
| long_wall candidate, step200 | 25.929초 |

시간은 원본 `episode_started` 기준이다. 그래프 보고서의 첫 transition 기준 시간과 다르다.
가상 사례는 같은 실패 반복, 미지원 우회, 허구 근거, 보상 변경, 늦은 STOP/완료/만료 응답이다.
실제 기록에 없는 task/revision/실행 generation/neutral 입력 해제 증거를 만들지 않았다.
따라서 `unproven_generation`, `inputs_not_released`도 명시적으로 판정되며, 각 사례의 고유
거부 사유 역시 확인했다. 유효 제안 경로는 별도 합성 단위 검사로만 확인했다.

현재 해당 정책 조건의 실행 vocabulary는 `collect_wood`뿐이다. 같은 실패 방법을 제외하면
대안이 없어5건 모두 `no_available_alternative`로 model 호출을 생략하도록 판정했다.
특정 나무 선택이나 좌/우 우회 skill은 아직 구현되지 않았다. 새 단어를 LLM에게 제공한다고
하위 정책이 그 행동을 수행할 수 있다고 가정하지 않는다.

새 게임 행동 **0**, 학습 갱신 **0**, 실제 LLM 호출 **0**. 실제 복구 성공 표본은 추가되지 않았다.

## 남은 한계와 다음 실행 단위

관측 사실은4블록 구역·대상·선택 아이템·목표 인벤토리·생존 상태로 제한한다. 전체 지도나
블록 재질 센서가 아니므로 구역 내부의 유효한 변화까지 구분하지 못할 수 있다. 같은 실패의
재시도 제한은 보수적인 계약이며 다른 접근이 불가능하다는 증명이 아니다. 이력은 session
내에서 유지하며 episode를 넘는 일반화된 복구 기억은 구현하지 않았다. schema1 sidecar의
Windows/WSL 동시 작성은 지원하지 않는다.

실제 LLM 호출, RM 우선순위 변경/복귀, 실행 직전 재검사와 dispatch 연결은 남아 있다.
그 전에 필요한 실질적인 다음 단위는 **연속 복구 시연의 기억층 BC 학습기·체크포인트·추론
연결**이다. 기존 train/development 분리를 유지해 후보를 학습하고 실제 우회와 자연 수집을
비교해야 한다. 이전8프레임 gradient 검사나 이번 제안 거부 검사를 복구 능력 향상으로 세지 않는다.
