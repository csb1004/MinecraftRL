# STEVE-1 판자 제작·회수 검증

## 결과

**현재 STEVE-1은 조합 동작을 수행했지만, 요청한 판자를 안정적으로 남겨 두지는 못했다.**
같은 저장 월드의 고정 난수 시드 5회에서 판자 제작 통계는 모두 4 증가했다.
정책 제어 중 원목 1개 소비와 실제 인벤토리 판자 4개가 함께 확인된 시행은 **3/5**다.
두 시행은 인벤토리 판자 최대치가 각각 2개·3개로 사전 회수 기준에 미달했다.

모든 시행에서 후속 제작이 발생했고 180초 종료 시 판자는 0개였다. 따라서 이 3/5는
**중간에 제작·회수 능력이 관측된 비율**이며 “판자 4개를 만들어 보존하는 과업”의
성공률이 아니다. 자유 대화/RM에 제작 목표를 지원한다고 표시하지 않았다.

## 고정 조건

[사전 조건](crafting-probe-plan.md) 그대로 5회 완료했다. 기술 오류 0, 미실행 0,
추가 API 0회다. 원본은 자연 수집한 참나무 원목 1개와 흙 1개가 있는
`sequence-20261004T025836469371Z/28222939e73444be84ba333eedf2d4d8` 세대다.
재료 지급·명령 제작·API fallback 없이 매 시행 독립 복사본을 사용했다.
원본 current pointer/manifest/zip 해시를 보존했다. 같은 지형이지 서로 다른 5개 지형은 아니다.

기존 STEVE-1 가중치·guidance 6.0, 문구 `craft wooden planks`를 고정했다.
사용자 과업을 확장하지 않은 별도 `craft-probe` 경로다. 판자 미리보기나 LLM 발언은
완료 증거가 아니며, 인벤토리 변화와 `craft_item.oak_planks`의 baseline 대비 증가를
함께 사용했다. 종료 정리에서만 회수되면 별도 분류하도록 했으나 이번 cleanup_witness는
전부 null이었다. 초기화와 종료 정리는 제어 예산과 분리했다.

## 시행별 결과

흙 1개는 모든 최종 인벤토리에 유지돼 표에서 생략했다. 회수 시각은 episode_started부터
처음 사전 성공 조건을 충족한 관측까지다. 제작 통계 증가량은 각 시행 판자 4개다.

추가 제작 통계는 104729/196613 작업대 1, 130363/262147 버튼 4,
155921 막대기 4·버튼 2 증가였다. 이 부수 관측을 작업대·막대기 지시 성공률로

버튼 제작 통계 4지만 최종 보유는 3이다.

주요 증거:

- 104729의 `run/frames/000300.png`: 원목과 판자 결과 미리보기. 아직 회수 성공은 아님.
- 104729의 step 650: 원목 순감소 1, 판자 인벤토리 순증가 4, 제작 통계 증가 4.
- 130363의 `run/frames/001000.png`: 조합 칸에 판자를 배분한 모습.
  전체 기록에서 판자 4개 동시 보유는 확인되지 않았고 이후 버튼으로 소비했다.
- 각 시행의 `craft-before-cleanup.png`, `craft-after-cleanup.png`, `craft-cleanup.json`:
  종료 전후 화면·인벤토리·GUI 상태.
- 각 시행 `saved-nbt.json`: 저장된 level.dat와 playerdata의 슬롯 수량을 합산해
  최종 관측과 대조했다. 5회 모두 일치한다.

출력 루트는 `results/crafting-20261004T052011252355Z/`다.
`experiment.json`, `analysis.json`, `saved-inventory-check.json`에 집계와 검증을 남겼다.

## 중단·저장과 검증 경계

5회 모두 STOP acknowledgment 뒤 새 정책 dispatch 0회, 중립 입력 해제,
종료 시 열린 조합창 닫기, 복사본 월드 저장, 소유 자식 프로세스 종료를 확인했다.
조합창 닫기는 정책 행동이 아니라 종료 정리 동작으로 기록했다.
원본 보존과 종료 후 프로젝트 관련 WSL Python/Java 잔존 0개 및 STOP 유지도 확인했다.

**커서에 들린 아이템은 현재 관측 API가 직접 제공하지 않는다.** 전후 프레임과 저장
인벤토리는 확인했지만 모든 커서/조합 칸 물품이 손실 없이 반환됐다는 자동 검증은
하지 못했다. report의 cursor_item_verified=false를 유지한다. 제작한 수량과 최종
보유 수량의 차이를 숨기거나 GUI가 닫혔다는 사실만으로 물품 회수를 보장하지 않는다.

최종 Windows 113개 중 109개 통과·Linux 전용 4개 제외(1.673초), WSL 113개 통과
(30.247초). 새 제작 증거 검사 4개 및 원본 저장소로 실험을 실행하지 못하도록 하는
검사 1개를 추가했다. 스크립트 구문·분석 집계도 확인했다. 단일 에이전트 자체 검토이며
독립 에이전트 리뷰는 아니다. 연구 명세 SHA256은 기존
`4af3ad00c5bab9b9d08b2e23fe768e140944118aa85cf412c45a67bb032275ad`를 유지한다.

## 재현과 다음 보완

프로젝트 PowerShell, STOP이 유지된 상태에서 실행한다.

```powershell
$env:PYTHONPATH='src'
python scripts/run_crafting_probe.py
python scripts/analyze_crafting_probe.py results/crafting-<실행시각>
```

다음 최소 보완은 **목표 판자 회수 증거가 생긴 즉시 정책 행동을 멈추고 결과를 보존하는
제작 과업 제어**다. 현재 실험은 180초 동안 계속 행동하게 했으므로 즉시 중단의 효과는
아직 검증하지 않았다. 4개 회수 기준에 도달하지 못하는 시행에 대한 재료 배치·회수
보완도 별도 문제다. 작업대 배치/3×3 조합이나 전체 기술 트리가 해결됐다고 주장하지 않는다.
