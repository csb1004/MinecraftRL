# MineRL 월드 저장과 재개

사용자 요청(2026-10-04): 게임을 종료했다가 다시 켜도 같은 월드, 인벤토리와 과업을
이어간다. 공개 정책의 픽셀 입력·키보드/마우스 행동 경로와 180초 제어 제한을 유지한다.

## 동작

`session` 실행은 기본 `companion` 슬롯을 사용한다. 슬롯에 저장본이 없으면 새 월드를
만들고, 있으면 해시를 검증한 저장 ZIP을 MineRL `HumanSurvival(load_filename=...)`에
전달한다. 불러오기에 실패하거나 인벤토리·위치가 맞지 않으면 새 월드로 몰래 대체하지
않고 오류로 종료한다. 공식 고정 버전의 불러오기 경로를 사용한다. 아래 실제 검증에서
발견한 종료 저장 누락은 세션 전용 런타임 JAR 사본에서 수정하며 설치 원본 JAR는 보존한다.

```powershell
.\scripts\Invoke-PolicyProbe.ps1 -Policy steve1 -Operation session -WorldSlot companion -Seconds 180
```

같은 명령을 다시 실행하면 같은 슬롯의 최신 완료 저장본을 사용한다. 독립 월드가 필요하면
다른 슬롯 이름을 지정한다. 기존 `results/STOP` 재무장 절차는 그대로 적용한다.
`episode`, `suite`와 기존 과업 시나리오는 새 월드 실험을 유지하며 이 저장 기능을 쓰지 않는다.

실행 종료 시 정책 행동을 차단하고 중립 입력을 보낸 뒤, MineRL `<Quit/>` 저장·종료 응답을
받는다. 저장 월드를 ZIP으로 묶고 실제 관측과 과업 체크포인트를 함께 기록한다.
각 세대는 새 디렉터리에 쓰며 완료 후에만 `current.json`을 원자적으로 바꾼다.
이전 세대는 보존한다. 저장이 실패하면 마지막 정상 세대가 유지된다.

고정된 MineRL의 동기식 서버에서는 원래 `<Quit/>`가 최신 플레이어/청크를 저장하지 않았다.
실제 흙 2개 획득 뒤 저장 ZIP의 NBT에는 빈 Inventory와 시작 위치가 남았고 재시작 검사가
이를 거부했다. `world_save_patch.py`는 원본 JAR 해시를 확인하고 `ReplaySender.stop()`의
disconnect 직전에 실제 서버의 `saveAllPlayerData()`와 `save(false,true,true)`를 실행한다.
프로젝트 Java 8로 해당 클래스만 다시 컴파일해 `.runtime/world-save/`의 별도 JAR에 담는다.
정책 추론·행동과 일반 실험 JAR는 변경하지 않는다. 빌드 receipt에 원본/수정 해시를 남긴다.

upstream 기본 실행 이름 `Player<시간>`은 매번 다른 offline UUID를 만든다. 세션에서는
슬롯 이름으로 결정되는 고정 UUID와 고정 시작 이름을 Java 실행 옵션으로 전달한다.
같은 슬롯을 재시작할 때 플레이어별 저장 기록이 다른 UUID로 갈라지는 것을 막는다.
실제 적용 값은 결과 폴더의 `player-identity.json`에 남긴다. 일반 정책 실험에는 이 옵션을
설정하지 않는다. 기존 저장 폴더를 수동으로 다른 슬롯 이름으로 바꾸는 것은 지원하지 않는다.

복원된 실행 중 과업은 paused가 된다. 대화 콘솔에서 `다시 계속해줘` 또는 기존 resume
명령을 보내야 정책 행동을 시작한다. 모델의 순환 은닉 상태는 재생성하며 게임/정책 전체를
비트 단위로 재현하는 기능은 아니다. 모델에 게임 파일이나 인벤토리를 조작할 권한을 주지 않는다.

이미 완료·취소된 과업의 월드를 불러오면 새 요청을 기다린다. 명시적인 새 수집 요청은
그 시점 실제 인벤토리를 새 baseline으로 삼으며 이전 아이템을 새 획득량으로 세지 않는다.

## 저장 위치와 검증

- `data/worlds/<slot>/<generation>/world.zip`: 월드 파일(지형·플레이어 데이터 포함).
- 같은 디렉터리의 `manifest.json`: 월드 ID, ZIP 해시, 과업 상태와 마지막 관측.
- `data/worlds/<slot>/current.json`: 완료된 세대만 가리키는 포인터와 manifest 해시.
- `data/worlds/runtime/`: upstream ZIP 로더의 추출 디렉터리. 실제 프로젝트 경로 안에 둔다.
- 결과 폴더: `world_restored`, `world_saved` 이벤트, 요약의 `world_restore`, `world_save`.

ZIP 경로 이탈·심볼릭 링크·복수 월드·CRC·해시를 검사한다. 슬롯은 하나의 WSL worker가
독점한다. 저장된 아이템별 수량은 실제 초기 관측과 정확히 비교하고, 위치는 MineRL의
초기 중립 프레임을 고려해 거리 2블록 이내로 제한한다. 이 허용치는 동일 프레임 복원
보장을 뜻하지 않는다. 체력 등은 증거로 기록하며 초기 프레임 사이 변동 가능성이 있다.

## 한계와 검증 기록

정상 종료 시 자동 저장하는 기능이다. 전원 차단·강제 종료·초기화 실패 시에는 마지막
정상 저장 이후 진행을 잃을 수 있다. 진행 중 주기적 저장과 저장본 자동 삭제는 아직 없다.
손상된 최신 저장본은 자동으로 이전 세대로 바꾸지 않으며 오류를 보고한다.
월드 내부 GUI 상태와 정책의 과거 은닉 상태는 복원 범위가 아니다.
최신 Bukkit 서버 호환성·멀티플레이어 서버 복원을 뜻하지 않는다.

실게임 검증은 `world-scenario`로 서로 다른 worker/Java 프로세스 두 번을 사용한다.
첫 실행에서 STEVE-1으로 실제 흙 수집→pause→정상 저장, 두 번째에서 인벤토리·위치·
진행도 확인→1초간 무행동→명시적 resume→추가 수집→저장을 검사한다.
검증 결과는 별도 실게임 보고서에 기록한다. 합성 테스트 통과를 실게임 성공으로 계산하지 않는다.
