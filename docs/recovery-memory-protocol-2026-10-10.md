# 실패 이력을 사용하는 재계획 — 2026-10-10

사용자 요청: 실패 판정 → LLM의 해결 방법 검토 → 이전 시도와 결과를 입력으로 제공 → 중복 시도 방지.
기존 RM/진행도는 보존하고 이미 승인된 로컬 구현·검사 범위에서 기존 연결을 확장한다.
원문 연구 명세, 유료 호출 승인, 최종 평가 시드는 바꾸지 않는다.

현재 누락: ReplanGuard.planner_input에는 실패 목록이 있으나 실제 PlanningRecoveryController가
별도 packet을 만들어 목록을 전달하지 않는다. 탐색 실행의 전후 상태/종료 결과도 PlanHistory와 분리돼 있다.
기존 중복 키는 위치 cell/선택 슬롯에 영향을 받고 실제 조건 인자를 포함하지 않는다.

## 구현 단위

1. 기존 PlanHistory에 실행 영수증을 추가한다. method는 skill/policy/arguments로 식별하고,
   요청·전후 관측·커밋된 전이 수·결과/근거를 보존한다. 기존 schema1은 읽을 수 있게 유지한다.
   실패, 부분 진전, 실제 완료, 중단을 구분한다. STOP/미실행을 실패로 세지 않는다.
2. 같은 목표 범위에서 현재 조건의 실패/부분 진전 방법을 실행 전에 거부한다.
   문구/시간/세대/작은 위치 이동/선택 슬롯만 바꿔 우회할 수 없다. 관측된 목표·인벤토리·도달 가능성,
   실제 policy/인자가 달라진 경우는 새 조건으로 구분한다. 조건 왕복은 과거 이력을 지우지 않는다.
3. LLM 입력에 현재 관측, 최근 실패/실행 결과, 생략 건수, 중복으로 막힌 방법, 실제 가능한 대안을 넣는다.
   프롬프트는 실패 근거를 이용해 대안을 선택하도록 하고, 응답도 같은 목록에 맞춰 로컬 검증한다.
   최근 목록을 줄여도 전체 중복 검사는 유지한다. 가능한 실행 대안이 없으면 호출/행동 없이 pause한다.
4. 현재 한정된 실행기의 호출/탐색1회 한도는 유지한다. 새 API0, 새 실행 vocabulary0.
   일반 이력/검토 계약은 collect wood/dirt와 등록된 조건 전환에 공통으로 쓴다.
   live 어댑터의 지원은 여전히 wood의 explore_then_resume/remain_paused다.

## 확인

실패 먼저 재현: 실제 packet에 이력 누락, 동일 인자/문구 변경·위치 흔들림 중복, 다른 인자,
실제 상태 변화·왕복, 부분 진전/STOP/완료 구분, restart와 오래된 schema, stale/STOP/해제/예산 검사.
Windows/WSL 회귀 검사, 보존된 실제 실패 궤적의 다음 요청을 오프라인 재생한다.
새 고정 응답 실제 game은 최대1회/180초, 기존 checkpoint/corner world/seed104761/sampling9721.
이는 연결 검증이며 LLM 추론 성과·우회 학습 성공·새 RL 갱신으로 세지 않는다.
실제 게임의 이력 packet/영수증·STOP·해제·소유PID와 기존 행동/RM/확률 감사를 확인한다.
완료 배치는 재실행하지 않고 `results/recovery-memory-20261010/`에 새 근거와 변경 전 소스를 보존한다.
