# 실제 경유점 실패 뒤 목표 조건 보강

첫 후보의 fixed far 게임902전이/이동400행동에서 첫 경유점 완료0,최단거리0.671블록이었다.
첫9번 약90도 회전 후 목표가 여전히 옆90도인데 회전0/전진1로 전환했다.
이동 중 공격0/전진360/회전26이었다. 공격 해제는 됐지만 목표 방향이 행동을 충분히 제어하지 못했다.
오프라인 목표 반전 평균 TV0.01533과 일관되지만 이것만으로 단일 원인을 확정하지 않는다.
첫 조건의 far/corner 두 결과를 보존한 뒤 다음 **별도 개발 조건**을 실행한다.

- 후보1의 복사본에서 이동용 visual linear의 weight/bias를0.1배로 줄이고 동결한다.
  이것은 원래 root actor/시각·기억 backbone 변경이 아니다. 이동 때만 적용한다.
- 기존 목표 선형 파라미터만 동일한1394개 실제 teacher 이동 정답으로 추가 BC한다.
  목표 lr1e-2,batch32,24epoch,seed9921,KL0.01 고정. 개발273개는 optimizer에 넣지 않는다.
- 합성 반대 목표에 기존 행동 정답을 붙이지 않는다. 추가 게임/교사 행동을 훈련에 섞지 않는다.
- 전체 추론 특징과 구조는 그대로이며, 저장/reload·root 보존·목표 반전 효과를 다시 검사한다.
- 같은 far/corner 개발 월드·동일 sampling seed9922/9923의 새 별도 디렉터리에서 각1회.
  각 제어180초,이동400행동/60초,서버 도착0.35블록/높이차1.5,기존 RM·STOP 계약 유지.
- 첫 조건과 초기 화면/전환 prefix가 다른 경우 인과 비교를 주장하지 않는다.
  이 조건은 개발 실패를 보고 선택했으므로 최종 평가나 무편향 일반화 표본이 아니다.

기존 경유점만 입력하는 numeric 조건을 강하게 쓰는 실험이다. 영상만으로 지도를 만들거나
장애물을 이해한 성공으로 해석하지 않는다. 이번 비교가 개선되지 않아도 성공 임계값을 넓히거나
키 입력을 수식/스크립트로 교체하지 않는다. 실제 실패 원인과 남은 학습 자료 요구를 기록한다.
