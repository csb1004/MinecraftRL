**상태: 끝남. 공식 정책 대비로 미리 정한 판정을 개발·최종 모두 통과했다(최종 8/8 대 8/8, 채굴 시도 중 파괴 비율 53% 대 5%, 성공 단계 시간 중앙값 11초 대 38초).**

헤드는 공식 정책에 없는 특권 입력(fixture 좌표·서버 자세로 계산한 조준점 방향)을 쓴다(§6).

- 설계: [채굴 v3 설계](specs/2026-11-14-mining-aim-point-design.md). 앞선 실험: [채굴 v2](mining-direction-results-2026-11-14.md).

  스크립트가 시작할 때 `mining-aim`(5eb4a76)을 `jump-map`에 로컬 병합했다(7894579). push·main 병합은 없다.

- 유효 게임 38회(L11 18, 개발 4, 최종 16), 무효 0회, 다시 실행 0회, 유료 API 0회. 38판 모두 입력 해제(`neutral_command_sent`)·남은 PID 없음.

## 5. v2와 달라진 점

- v2 최종(seed 223606)은 실패 6판 모두 철광석 바로 옆에서 시선만 흔들다 180초가 지났다. 블록 중심이 위의 돌에 가린 자리다.

## 6. 밝혀 둘 점

- **특권 입력:** 학습과 평가 모두 fixture 좌표, 그때까지 부서진 블록, 서버 자세로 계산한 조준점 방향 4개(`aim_sin_yaw, aim_cos_yaw, aim_pitch, aim_dist`)를 헤드에 배율 10으로 넣는다.
  공식 정책은 이 입력이 없다. 이 정보 없이 쓰려면 조준점을 화면에서 추정하는 부분이 따로 필요하다.
- 학습 seed 수집(L11)의 성공은 평가가 아니다. 판정은 개발·최종만 쓴다.
- 이 학생은 LLM vocabulary에 넣지 않았다. main 병합은 사용자가 정한다.
- 실행 중 사건: 17:58부터 사용자 쪽 GPU 사용으로 남은 메모리가 2150MiB보다 적어 건축 배치가 멈췄고, 이 배치가 먼저 시작했다.
  데이터셋(18:29–18:35)은 CPU로 만들었고, v3-a 학습(18:35–19:00)은 GPU를 최대 2228MiB 쓰며 정상 끝났다(그때의 남은 메모리는 기록하지 않았다).
  첫 L11 게임은 19:00:46에 GPU 확인(2150MiB 이상)을 통과하고 시작했다. 이 배치의 게임 중 GPU 부족으로 멈추거나 무효가 된 판은 없다.
