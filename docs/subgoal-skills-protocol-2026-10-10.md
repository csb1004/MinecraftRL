# LLM이 선택하는 관측 기반 신경망 하위 skill

사용자 요청: 하위 skill 또는 추상 state를 확장해 LLM의 계획이 실제 실행에 영향을 주게 한다.
기존 root RM/진척/인벤토리 완료·보상은 보존한다. 승인된 로컬 구현/실험이며 새 유료 호출은 포함하지 않는다.

## 구현 범위

- `leave_stalled_area`: 기존 공식 explore 조건으로 시작 위치에서 수평3블록 이상 이동한다.
  이동 완료는 장애물 통과나 경로 확보의 증거가 아니다. 최대200tick/30초.
- `locate_wood`: 공식 wood 문구 조건으로 서버가 유효한 원목 위치를 추적할 때까지 실행한다.
  추적 중인 목표가 있으면 관측으로 충족된 단계를 생략한다. 최대200tick/30초.
- `approach_wood`: 고정된 `walk toward the tree` 문구의 공식 STEVE-1 prior embedding을 사용한다.
  원목 목표가 없으면 실행하지 않고, 실제 원목 목표 reachable이 될 때만 완료한다. 최대200tick/30초.
- root `collect_wood`는 원래 정책/완료 기준을 유지한다. 이미 목표 인벤토리를 획득하면 모든 하위 계획을 끝낸다.

세 하위 skill은 실험용 신경망 조건 실행기다. 새 이름을 추가했다는 사실을 능력 습득/성공으로 부르지 않는다.
지원 범위에 없는 벽 종류 진단·경로 지도·좌우 통로 검증을 알고 있다고 주장하지 않는다.
행동을 키 스크립트/API 제어로 대체하지 않는다. 실제 모터 행동은 동일한 사전학습 모델/동결 체크포인트에서 나온다.

## 상태와 연결

서버의 위치, 유효한 추적 목표, 거리, reachable, 채굴 상태, 인벤토리를 검증해
gui_open / unknown / tracked_unreachable / reachable / mining / collecting / completed를 구분한다.
GUI 열림은 정상 관측이며 기존 신경망 인벤토리 조작을 유지한다. 열린 동안 이동 하위 조건은 완료되지 않는다.
고정 목표 조건은 실제 policy 입력 embedding으로 들어가고 전이에 선택 skill·목표·판정 근거를 남긴다.
root 보상과 단계 특징은 바꾸지 않는다. 이번 동적 계획은 eval 전용이며 optimizer 갱신0이다.

각 노드의 실제 전후 관측/종료 원인/부분 진전을 스케줄 이력에 보존하고 다음 LLM packet에 넣는다.
이미 충족된 단계 생략과 실제 행동을 통한 달성을 구분한다. 실패한 같은 방법은 문구/우선순위 변경으로 반복하지 못한다.
전체180초·계획 요청 최대3회·STOP 우선·입력 해제·자식 PID 정리를 유지한다.

## 검증 순서

관측/완료/스키마/스케줄 회귀 → 공식 embedding 생성/해시/조건 영향 검사 → 새로운 개발 게임의 고정 계획 실행
→ 전이/인벤토리/정책 확률/입력 조건/STOP 전수 검사 순으로 진행한다.
새 실제 LLM 연결이 필요하면 실행 가능한 입력·검증 결과를 준비한 뒤 별도 유료 승인을 받는다.
원본·실패·가중치/월드를 보존하고 최종5시드를 사용하지 않는다. 고정 계획과 LLM 계획의 결과는 분리한다.

## 새 개발 실행 사전 고정

- 동결 onset-coverage 체크포인트/원래 wood embedding 유지. 새 catalogue seed9811.
- 최대180초, 고정 로컬 subgoal fixture, 응답 대기5초, 요청 최대3회, API0/학습0.
- 같은 단계에서3블록 이동 또는 목표 추적/상호작용 준비가 관측되면 즉시 다음 노드 선택.
- 원목 실제 획득 여부와 각 하위 조건 달성을 따로 기록. 실패한 조건은 다음 고정 계획에서 제외.
- 첫 실행은 성공률 평가가 아니라 실제 연결/실패 분석용이며 이전 실행과 직접 성능 비교하지 않는다.
- 첫191전이에서 인벤토리 열림을 관측 오류로 취급한 기술 오류를 보존했다. GUI 상태를 추가해 재현 검사를
  통과한 뒤 `game-gui-fixed`의 새 실행으로 검증한다. 동일 시드/범위이며 초기 실패 디렉터리는 재사용하지 않는다.
