LLM이 선택한 하위 계획이 실제 STEVE-1 조건 입력과 게임 행동에 연결됐다.
정체 이탈은 완료됐지만 나무 찾기가 예산 안에 완료되지 않아 원목 획득은0이다.

## 실제 계획과 전이

800전이에서 원목 목표/획득 진전이 없는 정체를 감지했다. 중립801에서 입력을 해제하고
현재 추상 상태`unknown`, 기존 실패 이력, 실행 가능한 스킬을 LLM에 전달했다.
LLM은 아래 의존 순서와 우선순위100→90→80→70을 제안했다.
응답 검증 후 중립802를 거쳐 계획을 설치했다. 원래 목표 RM/보상/기억은 보존했다.

계획 중지 상태를 나타내며 런타임 예외는 없다. 전체 실험 성공률을 계산하지 않는다.

## 실패 원인과 해석

행동/단계/embedding 해시와 확률을 전수 재검산해 계획 전달 누락은 관측되지 않았다.
정체 이탈은 explore 조건, 나무 찾기는 별도의 wood 조건으로 실제 전환됐다.
나무 찾기200행동 중 전진134·후진28·좌59·우27·질주53회이며 공격/인벤토리 입력은0회였다.
동시 키가 있어 각 횟수를 더하면 행동 수와 다르다. 시선 pitch는4.768~8.602도 범위였다.

서버 추적은 화면 전체의 나무 인식기가 아니다. `WorkshopObservation.java`의 시선 방향16블록
ray가 원목에 닿거나 실제 원목 채굴이 받아들여졌을 때 잠기는 관측이다.
이번에는 추적값이 계속0이었으므로 이 조건의 목표 확보 실패라고 판정한다.
화면에 나무가 전혀 없었다거나 모델이 나무를 인식하지 못했다고 단정할 수 없다.
실제925화면의 오른쪽 위에는 잎 일부가 보이지만 원목 추적은 없었다.

표본 화면802/825/875/925/975와 최종 화면을 확인했다. 기반암 벽 주변을 이동한 뒤
최종적으로 벽을 근접해서 바라봤다. **이 기록은 계획을 실행할 수 있게 만드는 것과
탐색·시선 정렬·통로 선택 능력을 확보하는 것이 별도 과제임을 보여준다.**
정확한 오경로 원인과 능력 일반화는 단일 궤적으로 확정하지 않는다.
이미 부여한200틱/30초 예산을 결과를 보고 늘리거나 원래 실패를 성공으로 바꾸지 않았다.

다음 작업 단위는 관측 가능한 목표 확보/통로 진입을 수행하는 하위 정책의 능력 검증이다.
개발 실패를 훈련 자료로 섞지 않고, 별도 훈련 세계에서 성공·실패 시연을 확보해야 한다.
실제 `approach_wood` 실행 능력도 여전히 미검증이다. 장기 연구 명세와 목표는 유지한다.

## 실패 이력의 재사용

게임/API를 추가 실행하지 않고 마지막 실제 실패 영수증을 복사해 `archived_review` 입력을 구성했다.
기존 계획 전체, 성공23행동/실패200행동 영수증, root 참조/진척을 그대로 유지한다.
같은 상태에서 `locate_wood`와 기존 실패 `collect_wood`가 차단됨을 확인했다.
실패한 방법을 지우거나 LLM이 알아서 기억한다고 가정하지 않는다.

이 결과는 `live-run/archived-failure-review/report.json`과 `packet.json`에 있다.
복사본의 두 번째 요청은 오프라인 검사이며 실제 두 번째 API 요청이 아니다.
실패 시점의 키 상태와 release sequence를 그대로 두었고 새 입력 해제를 꾸며내지 않았다.
`archived_review` 계획은 live 스케줄에 설치할 수 없다.
