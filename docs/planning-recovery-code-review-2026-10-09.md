# 계획 인계 코드 검토 기록

ce-code-review 기준을 주 실행 흐름에서 적용했다. 사용자 지침에 따라 서브에이전트를 사용하지
않았으며, Git 저장소가 없는 작업 공간의 보존 원본과 현재 소스를 비교했다.
범위는 runtime/계획 controller/ReplanGuard/CLI/collector, Windows 브로커/WSL mailbox,
일회 실행기와 유료 준비 경계다.

확인한 불변식은 STOP·목표 완료 우선, 대기 중 행동/추론0, 중립의 문맥 전이 기록,
현재 상태/세대/요청 ID 재검토, 원래 RM/기억 보존, 한 번의 bounded intervention,
오류·만료 시 대체 행동 없음, 호출 예산과 응답 재사용 차단, 네트워크와 게임의 별도 종료다.

발견·수정한 사항:

- 실제 MineRL 모니터의 held_key_count0.0을 엄격 snapshot int 검사가 거부했다. 원본438전이를
  보존하고 유한한 비음수 정수값만 정규화했다. 실제 관측 재생 및 수정 후 실제 인계를 확인했다.
- 공급자 준비 중 요청이20초를 넘길 수 있었다. 공급자 구성 후와 실제 전송 직전에 만료를
  다시 확인하도록 고쳤고 준비 중 만료 회귀를 추가했다.
- 실제 유료 호출 수는 WSL 요청 횟수로 알 수 없다. worker는 미확인일 때 null로 남기고
  Windows 전송 영수증을 기준으로 합산한다. 게임 오류 때도 finally에서 영수증을 보존한다.
- 유료 준비 이후 소스/가중치가 바뀌는 경우 실행을 막도록 파일 해시 검사를 연결했다.
  준비 문서가 승인으로 취급되지 않으며, 명시적 유료 옵션 없이는 키/네트워크를 사용하지 않는다.

자동 검사: Windows 전체415개 중18환경 제외, WSL 전체420개 중9제외. 준비 검사2개는 각각 추가 통과.
실제5회/4509전이 감사와 Windows↔WSL 별도 프로세스·실제 게임 연결을 확인했다.
최종 소스/테스트/실제 증거는 `results/planning-recovery-implementation-20261009/final-verification.json`
및 `results/planning-recovery-live-prepared-20261009/manifest.json`에 연결한다.

남은 한계는 구현 완료로 표기하지 않는다. 실제 유료 LLM 게임은 미실행이며, 고정 응답의 두
실행은 인과 대조가 아니다. 벽 횡단 이후 원목 재획득과 재정체 대응은 미해결이다. 현재 제안
vocabulary는 임시 탐색/일시정지만 지원하며 방향성 우회 skill이나 다중 RM 스케줄러가 아니다.
취소 워커는 저장 완료 후 SIGTERM으로 정리된 사례가 있어 완전한 자발적 종료로 주장하지 않는다.
