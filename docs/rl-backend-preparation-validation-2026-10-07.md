# RL 첫 추론 준비 경계 검증 — 2026-10-07

실제 두 시행·준비 도중 취소·원시 로그 감사가 통과했다. 전체 회귀 검사의 최종 결과는 아래 검증 기록을 참조한다.

## 변경과 원인 범위

이전 실제 첫 추론 9.42~137.24초가 180초 제어 예산 안에 포함됐다. 첫 Conv2d에 지연이 집중되고 첫 호출 뒤 cuDNN 하위 라이브러리가 매핑되는 것을 확인했다. NVIDIA의 [cuDNN 8.5 FAQ](https://docs.nvidia.com/deeplearning/cudnn/archives/cudnn-850/developer-guide/index.html)도 첫 합성곱의 지연 로딩을 설명한다. 다만 독립 재현은 약 2초였으므로 **100초대 변동의 정확한 OS/CUDA/I/O 원인은 미확정**이다.

`RLPolicy` 생성 중 실제 첫 합성곱만 동일 크기·stride의 영 입력으로 미리 호출한다. 순환 상태·행동 샘플러·월드는 호출하지 않으며 완료 후 STOP을 다시 확인한다. 초기화 비용을 제거한 것이 아니라 게임 reset과 제어 예산 앞에서 별도로 측정한다. `backend-preparation*.json`이 근거다. 준비 실패는 정상 완료로 처리하지 않는다.

CPU 단위 검사에서 가중치·난수·학습 모드 보존과 비유한 출력 차단을 확인했다. 실제 CUDA 모델의 저장 화면 재생에서는 첫 특징 계산 2.106초→0.107초, 원본 10행동·특징·logp가 정확히 일치했다. 이는 오프라인 재생이며 실제 게임 성공 표본이 아니다.

## 실제 게임 실행

동일 부모 78회 checkpoint·embedding·기존 세계를 사용하고 학습에서 제외했다. 각 제어 제한은 180초, actor/value optimizer 갱신은 0이다.

| 시드 | 별도 사전 준비 | 첫 실제 추론 | 제어 시간 | 행동 | 서버 원목 획득 |
|---|---:|---:|---:|---:|---|
| 104869 | 1.789초 | 0.275초 | 43.796초 | 300 | 확인 |
| 104831 | 7.374초 | 0.195초 | 48.752초 | 244 | 확인 |

사전 기준인 첫 실제 추론 2초 미만은 두 시행 모두 충족했다. 이것은 실행 준비의 효과이며 정책 학습 개선 증거가 아니다. 이전 같은 시드의 첫 추론은 각각 137.24초·132.90초였지만 관측과 행동이 달라질 수 있어 전체 수행 시간의 차이를 순수 정책 개선으로 해석하지 않는다.

첫 시도는 `java -version` 20초 초과로 준비 단계에서 blocked/0행동이었다. 동일 전용 Java 8은 후속 검사에서 3.755초로 정상 응답했다. 원인 미확정이며 검사 제한과 설치를 변경하지 않았다. 원본 `results/rl-backend-preparation-20261007`을 보존하고, 0행동 준비 실패에 한해 한 번 복구한 결과는 `results/rl-backend-preparation-recovery-20261007`에 별도 저장했다. 이 준비 실패는 게임 성공/실패 표본에서 제외한다.

진단 실행의 LD_LIBRARY_PATH 누락 실패와 ndarray 비교 실패도 별도 원본으로 보존했다. Windows 실행기의 첫 호출은 PYTHONPATH 누락으로 import 단계에서 끝났고, 프로세스 환경에 `src`만 지정해 실행했다. 이들은 실제 정책 시행이 아니다.

최종 평가 5시드는 미실행이다. 가치함수 초반 오차 채택 기준 미충족과 실제 정책 개선 부재는 이전 단계의 미해결 상태로 유지한다. 전역 설정·기본 정책·보상·행동 경계·연구 명세는 변경하지 않았다.

## 원시 감사와 중단

`audit.json`에서 두 실제 궤적의 초기 actor/value 보존, 서버 인벤토리 기반 보상, 1행동/서버 tick, RM 수락 후 추가 추론·정책 전달 없음, 중단 확인 후 추가 전달 없음, 입력 해제와 소유 프로세스 정리를 검증했다. 초기 세계·인벤토리·위치·시선·시간·생명·순환 상태·seed·embedding은 이전 시행과 일치했다. 초기 화면은 104869만 정확히 일치하고 104831은 달랐다.

| 시드 | 추론 중앙값 / p95 | 전체 제어 주기 중앙값 / p95 | 장치 전체 사용 VRAM 표본 최대 |
|---|---:|---:|---:|
| 104869 | 42.92 / 51.37ms | 136.34 / 227.63ms | 2861MiB |
| 104831 | 44.23 / 53.56ms | 137.27 / 526.71ms | 2834MiB |

VRAM은 다른 프로세스를 포함한 장치 전체의 표본 최대이며 순간 최대를 놓칠 수 있다. CUDA 사전 준비는 제어 시간에서 분리했지만 전체 사용자 대기 시간이 사라진 것은 아니다.

취소 전용 시행은 준비 시작 파일 이후·완료 파일 이전·이벤트 파일 이전에 STOP을 기록했다. 실제 `InterruptedError('stop before RL environment reset')`로 월드 reset 전에 종료했고, 감독기는 cancelled/0행동/학습 부적격으로 기록했다. 잔존 소유 PID는 0이다. 시작 전 취소여서 해제할 게임 입력은 없었으며, 두 정상 시행의 입력 해제는 별도로 감사했다. STOP은 유지한다.

후속 WSL 감사 시작에서는 systemd 사용자 세션 경고와 Python의 `p9_client_rpc` I/O 대기가 관측됐다(당시 읽기 약 628MB). 감사 자체는 통과했다. 이는 해당 시작 지연의 I/O 관측이며 과거 100초대 GPU 첫 호출의 단일 근본 원인을 입증하지 않는다.

다음 연구 단계는 actor 갱신보다 가치함수 초반 오차의 원인 분리다. 기존 초반 기준은 남은 에피소드 길이에 조건을 건 평가라 선택 편향이 있고, 시간 초과 타깃에는 기존 value bootstrap이 들어간다. 채택 기준을 사후 완화하거나 이 실행 준비 진단을 새 학습 데이터로 편입하지 않는다.

## 회귀 검사

Windows는 178개 중 171개 통과·7개 환경 제외, WSL은 178개 모두 통과했다. 로그는 결과 폴더의 `tests-windows.txt`, `tests-wsl.txt`다. 준비 함수의 두 새 검사는 가중치·난수·모드 보존과 비유한 출력 차단을 검사하며, 실제 GPU/중단 검증은 별도 시행 기록으로 보완했다. 최종 보존·정리 결과는 `final-verification.json`을 기준으로 한다.

최종 확인은 `verified:true`다. 기존 24개 궤적, 부모 78회·기존 472회 체크포인트, 연구 명세 및 이번 수정 대상이 아닌 기존 실행/학습 소스의 해시가 보존됐다. 실제 preflight에서 공식 모델 가중치와 소스 revision도 검사했다. Windows/WSL 프로젝트 실행 프로세스는 모두 0이며 취소 STOP은 유지한다.
