# 일괄 제작 입력 제한 실제 검증 — 2026-10-05

정책 전달 직전에 Shift(sneak)를0으로 제한하는 선택적 조합 실험 조건을 추가했다.
같은 저장본과 시드5개에서 **막대기4개·판자2개 보존은0/5→2/5**, 막대기8개 과다 제작은
2/5→0/5였다. 목표 막대기의 제작·저장 자체는 두 조건 모두2/5다. 레시피 선택과
재료 배치 실패가 남아 있으며 일반 제작 지원 완료로 해석하지 않는다.

## 변경과 범위

- `--craft-no-quick-move`는 별도 craft-probe + cursor recovery 조건에서만 허용한다.
  실험 실행기에서는 `--no-quick-move`로 전달한다. 기본값은 꺼짐이다.
- 조합 실험 전체에서 실제 전달 행동의 sneak를0으로 바꾼다. GUI 밖 웅크리기도 제한한다.
  클릭 위치·종류, 카메라, 재료 배치는 정책에 맡긴다. 일반 수집·대화는 바꾸지 않았다.
- 모델 제안은 변경하지 않고 별도 복사본을 전달한다. 매 transition의
  `info.craft_action_guard`에 원본 제안과 실제 행동을 모두 기록한다.
- 모델 가중치·프롬프트는 그대로다. 조합 API나 아이템 지급은 없다.
  **정책+명시적 입력 제약+커서 회수 보조**의 결과이며 순수 정책 학습 개선이 아니다.
- [실행 전 조건](craft-shift-guard-protocol.md), [기존 비교 기준](craft-recipes-validation-2026-10-05.md).

모든 회차는 판자4/흙1로 시작하며 독립 복사본이다. 표는 공통으로 보존된 흙1을 생략한다.

성공한 두 회차는 커서에 만들어진 막대기4개를 명시적 회수 보조로 인벤토리에 넣었다.
서버 커서가 비고 막대기4개가 확정된 뒤 GUI를 닫았으며, 남은 판자2개도 서버 인벤토리에
돌아올 때까지 기다렸다. level.dat와 playerdata의 실제 저장 NBT가 모두 일치했다.
시드130363에서는 정책의 행동 경로가 달라져 제작을 끝내지 못했다. 이 부작용 때문에
모든 조건의 기본 입력 제약으로 켜지 않는다. 넓은 재료 배치/레시피 선택 개선은 남았다.

## 과다 제작 원인에 대한 실제 대조

시드155921는 기존/수정 실행 모두96번째 행동에서 결과를 꺼냈다. 원본 정책 제안96개 중
95개가 같았고, 유일한 차이인 step19도 sneak 값뿐이었다. 마지막 Shift+클릭 제안에서
Shift를 제거한 조건은 막대기4개를 커서에 생성하고 정확히 보존했다. 이전 조건은 서버에서
막대기8개로 확정됐다. `results/craft-shift-guard-paired-155921.json`에 대조를 보존했다.

첫 목표 관측 후 정책을 멈추는 검사와 서버 확정 대기는 유지한다. 이번 수정은 그보다
앞선 행동 전달 단계의 일괄 제작을 제한한다. [서버/클라이언트 수량 차이의 코드 경로](craft-batch-click-cause.md).
한 시드의 가까운 행동 대조와 소규모5회 결과이며, 모든 제작/월드에 대한 보장은 아니다.

## 검증과 분석 보완

- 총5054개 실제 정책 전달에서 sneak0을 확인했다. 원본 제안 중573개의 Shift 값을 바꿨고,
  다른 행동 필드는 모두 같았다. 모델 제안 자체는 변조하지 않았다.
- 성공2회는 첫 목표 관측 뒤 새 추론/정책 전달0. 모든5회는 STOP 확인 뒤 새 호출0.
- 입력 해제·GUI 종료·빈 커서·소유 자식 정리와 저장 NBT5/5 일치.
- 원본 월드 포인터/해시, 연구 명세 해시 유지. 기술 실행 오류·미실행·추가 API0.
- Windows127개 통과/4개 플랫폼 제외, WSL131개 통과. 최종 로그는
  `results/craft-shift-guard-windows-final-tests.log`, `results/craft-shift-guard-wsl-final-tests.log`.
- 저장본의 기존 판자 제작 통계가 늦게 도착해 새 제작처럼 보이는 분석 오류를 발견했다.
  관측 가능한 제작 항목은 첫 transition의 서버 통계를 비교 기준으로 사용하도록 보완했고,
  지연된 과거 통계의 회귀 검사를 추가했다. 시드130363은 새 제작0으로 정확히 분류된다.
  원자료나 정책 실행 조건을 바꾼 것은 아니다.

재현은 프로젝트 PowerShell에서 다음과 같이 실행한다. 기존 실행이 종료되고 STOP이
설정된 상태에서 실행기가 자체적으로 재무장하며, 종료 후 다시 STOP을 설정한다.

```powershell
$env:PYTHONPATH='src'
python scripts/run_crafting_probe.py --recipe sticks --recover-cursor --no-quick-move --seeds 130363 155921 104729 196613 262147
```
