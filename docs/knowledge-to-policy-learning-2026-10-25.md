# 고정 관측기에서 지식을 RL 학습으로 연결하기

2026-10-25. 사용자는 LLM/KB에 지식을 추가하는 것과 RL 정책이 그 행동을 습득하는 것은
별개임을 지적하고 실사용 관측기 고정을 요구했다. 관측기 고정은 요구사항이고 아래 학습 연결은
추천 설계다. 코드 구현·게임·학습·프로젝트 LLM/API 실행 결과가 아니다. STOP은 유지한다.

## 실사용에서 고정할 것

관측기의 허용 입력 채널, 전처리, 모델/가중치, 추출 프롬프트/규칙, 출력 스키마와 측정 정의를
배포 전에 정하고 실행 중 바꾸지 않는다. 새로운 실패마다 서버 센서·전용 판정기·프롬프트를
추가하거나 관측기 자체를 학습시키는 경로를 기본 시스템에 두지 않는다. 버전/hash를 로그에 남긴다.
관측 내용과 버퍼/추적 상태는 시간에 따라 갱신된다. 고정은 매번 같은 출력이라는 뜻이 아니다.

KB의 조건부 지식과 근거는 기존 합의대로 수정할 수 있다. 고정 관측으로부터 새 지식에 따라
상황을 해석하는 LLM의 판단은 달라질 수 있지만 관측 사실을 바꾸지는 않는다. 따라서 '관측기 고정'
과 '전체 시스템의 판단 함수 불변'을 같은 주장으로 쓰지 않는다. 같은 실험에서 KB가 고정인지
적응 가능한지도 명시하고 시점별 revision을 보존한다. 독립 성공 평가의 기준도 실험 중 유지한다.

외부 상황 관측기와 STEVE-1 내부 시각 인코더는 다른 구성 요소다. 초기 추천 조건에서는 외부
관측기뿐 아니라 STEVE-1 시각 인코더와 목표 임베딩 모델도 고정한다. 정책의 head/선택한 상위
또는 순환 층과 value head 중 학습할 부분은 사전에 선언한다. 이 초기 범위가 충분한지는 미검증이다.
관측기 변경이 필요한 경우 배포 중 우회하지 않고 별도 개발 버전/실험 조건으로 다룬다.

## 지식이 들어갈 세 경로

| 경로 | 지식이 바꾸는 것 | 실제 정책 가중치 갱신 여부 |
|---|---|---|
| 목표 조건 | 현재 목표/하위 목표를 기존 goal encoder로 표현해 정책에 전달 | 없음. 이미 가진 능력의 실행 요청이며 새 능력 보장 아님 |
| RL 학습 요청 | 연습 조건 분포, 측정 가능한 성공/보상 후보, 예산과 검증 조건 | 환경 경험과 RL 업데이트를 거친 경우에만 갱신 |
| 추가 지식 입력 표현 | 사전에 설계한 조건 입력/adapter로 관련 지식을 표현 | 그 표현과 행동의 관계를 학습해야 활용 가능. 초기 기본 경로에는 넣지 않음 |

추천 출발점은 기존 목표 조건 경로를 유지하면서 두 번째 경로를 구현하는 것이다. 자연어 지식
전체를 임의의 벡터로 바꿔 기존 512차원 goal 자리에 넣지 않는다. 같은 차원은 같은 의미 공간을
뜻하지 않는다. 새 입력 채널/adapter를 나중에 연구한다면 배포 전 인터페이스를 고정하고 비교한다.
검색한 문장은 세계 모델의 확정 전이도 아니고 정답 행동 라벨도 아니다. 지식은 근거와 조건을
갖춘 가설로 연습 선택에 영향을 주며, 실제 행동과 결과로 학습한다.

현재 `policies.py`의 Steve1Policy는 텍스트를 MineCLIP/prior 경로의 goal embedding으로 바꾸고
화면과 함께 정책에 전달한다. 단순 텍스트 변경은 가중치 학습이 아니다. `rl_policy.py`의 기존
head 경로와 6차원 RM context 확장은 범용 KB 임베딩이나 새로운 온라인 학습 서비스가 아니다.

## 학습 요청을 실행으로 바꾸는 계약

상호작용 LLM은 같은 응답의 learning_request에 다음 후보를 만든다. 프로그램은 배포 전에
검증한 관측/성공 판정/연습 초기화/학습 기능에 연결하고 지원 여부를 반환한다. 자동으로 새로운
센서나 임의의 실행 코드를 추가해 후보를 성공시킨 것으로 처리하지 않는다.

| 항목 | 필요한 내용 |
|---|---|
| 이유 | goal ID/revision, 지식 근거와 적용 조건, 실패/이상 사건, 원인 가설 |
| 배우려는 행동 | 특정 좌표의 키 순서가 아닌 조건부 공통 능력과 목표 조건 |
| 정책이 볼 정보 | 고정 관측 계약, 실제 정책 입력, 사용 가능한 기억/목표 조건 |
| 연습 분포 | 지원되는 초기화로 변화시킬 배치·거리·시선·물체/도구 등과 예산 |
| 학습 신호 | 실행 가능한 측정 항목으로 구성한 보상/종료 후보, unknown 처리 |
| 독립 성공 | 사용자 목표에 맞는 판정과 보존 평가. LLM이 성공 정의를 약화하지 않음 |
| 갱신/채택 | 정책 초기값, 학습 층, 알고리즘/예산, 개발 평가와 후보 채택 조건 |

프로그램은 (1) 관측/목표 조건으로 필요한 상황을 구별할 수 있는지, (2) 결과를 판정할 수
있는지, (3) 유용한 경험을 얻을 수 있는지, (4) 그 결과에 에이전트 행동이 영향을 줄 수 있는지를
점검한다. 관련 사실이 새롭다는 이유만으로 학습이 필요하지는 않다. 기존 동결 정책과 계획
변경만으로 수행 가능한지의 근거도 사용한다. 모든 원인의 완전한 증명을 요구하지 않되 unknown과
미지원 사유를 보존한다. 지원되지 않는 지식도 KB에 저장할 수 있다.

연습 보상은 검증된 측정 요소의 조합에서 시작한다. LLM이 그 값을 임의로 읽거나 성공 판정기를
실행 중 수정하지 않는다. 실제 목표 성공과 보상 총량은 별도 보고한다. 보상 후보/KB/RM은
학습 배치마다 고정하고, 상위 목표 RM과 과거 목표를 지우거나 쉬운 목표로 바꾸지 않는다.

## 정책에 남는 것은 경험으로 학습한 행동

추천 흐름은 `조건부 지식 → 학습 요청 → 검증된 연습 환경/보상 → rollout → RL 업데이트 →
독립 평가 → 후보 채택`이다. LLM이 가중치 값을 직접 작성하거나 사실 문장을 입력한 것만으로
정책이 학습했다고 하지 않는다. 초기 PPO 후보에는 해당 수집 정책의 행동 확률과 순환 상태가
필요하며 이전 정책의 임의 궤적을 그대로 섞지 않는다.

예를 들어 목표가 원목 수집인데 장애물 때문에 접근하지 못하고, 진단 근거가 수행 능력 부족을
지지한다면 기존 수집 목표를 유지한 채 연습의 장애물 배치·시선·거리와 우회 가능 조건을 다양화한다.
성공은 실제 원목 획득으로 판단하며 접근은 별도 진행 지표로 기록할 수 있다. 정확한 우회 키
순서나 특정 월드 좌표를 정책 대신 실행하지 않는다. 이 예시는 후보 설계이며 새로운 정책 성공이 아니다.

돼지의 번개 변환처럼 행동 목표가 정해지지 않은 사실은 KB 지식으로 남을 수 있다. 그것만으로
변환 성공 보상을 만들거나 번개 회피 능력을 획득했다고 주장하지 않는다. 목표가 생기더라도
해당 조건의 관측 가능성, 행동으로 바꿀 수 있는 결과, 연습 빈도를 검토해야 한다.

## 고정 관측의 한계와 평가

서로 다른 행동이 필요한 두 상황이 정책의 전체 가용 관측 이력·기억·목표 조건에서 구별되지
않는다면 보상만 바꿔 두 상황을 항상 올바르게 구별하게 할 수 없다. 한 프레임이 같더라도 과거
관측이나 허용된 추가 관찰 행동이 단서를 줄 수 있으므로 단일 화면만으로 불가능을 단정하지 않는다.
그래도 구별할 정보가 없으면 불확실성을 남기고 최악의 피해를 줄이는 행동 등을 검토한다.
새 관측기를 실사용 중 추가하는 것으로 문제를 숨기지 않는다.

훈련/평가 전용 서버 상태는 실제 성공 라벨이나 명시한 특권 보상에 사용할 수 있지만 정책 입력과
영상 전용 감시자 입력에 섞지 않는다. 해당 라벨을 실사용에서도 계속 얻을 수 있는지는 별도 조건이다.
실사용 중 얻을 수 없는 판정을 관측기가 제공하는 것처럼 가정하지 않는다. 고정 관측만으로 검증할
수 없고 별도 평가 환경에서도 판정할 수 없다면 그 학습 후보의 개선을 확정할 수 없다.

정책 전후 비교는 관측기·임베딩 조건·목표/프롬프트·도움 수준·성공 판정을 맞춘다. 새로운
지시/KB/재계획만으로 좋아진 효과와 가중치 업데이트 효과를 분리한다. 새 조건의 성공과 기존
능력 보존을 함께 평가한다. 지식이 철회되면 학습 요청/의존 정책을 재검토하며 KB 수정만으로
가중치에 남은 행동이 자동 교정됐다고 보지 않는다. 본 게임은 기존 정책으로 플레이를 유지하고
별도 연습기에서 후보를 학습하는 이전 요구와 STOP 우선순위를 그대로 따른다.

## 참고 근거와 적용 한계

- STEVE-1: https://arxiv.org/abs/2306.00937 — 목표 조건과 BC 기반 원래 학습. 임의 지식 주입이나 본 프로젝트의 지속 RL 성공을 보장하지 않음.
- Eureka: https://arxiv.org/abs/2310.12931 — LLM이 생성한 보상으로 실제 RL을 수행하는 연결 사례. 고정 영상 관측 Minecraft와 동일한 조건의 검증은 아님.
- UVFA: https://proceedings.mlr.press/v37/schaul15.html — 상태와 목표에 조건화한 가치 학습의 근거. 임의 자연어 목표가 즉시 일반화된다는 보장은 아님.
