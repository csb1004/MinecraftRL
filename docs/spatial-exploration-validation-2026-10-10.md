# 방문 기억·경로 우선순위와 실제 F3 좌표 — 2026-10-10

사용자가 승인한 미방문 경로 우선/집 등 반복 방문 허용과 F3 좌표 활용을 구현·검사했다.
실제 Windows 프로젝트에서 PowerShell/WSL을 사용했다. 새 유료 API·학습·정책 평가 게임은0이며,
별도의 실제 MineRL UI 진단1회에서 F3 화면을 열고 닫았다. 원래 연구 명세/RM/보상은 유지했다.

## 구현 범위

`spatial_memory.py`는 위치를 x/z 2블록, y 4블록 단위로 기록한다. 체류 프레임 수와 구역 진입
횟수를 구분하며, 실제 관측한 방향의 이동만 연결한다. 관측 공백/급격한 이동은 연결을 끊고,
관측하지 않은 역방향 길을 만들어내지 않는다. 4블록 높이 구분은 보통 점프의 중복을 줄이는
근사이며 층 구조·벽·통행 가능성 지도는 아니다. 격자 경계 흔들림도 추가 연구 대상이다.

탐험 경로 비용은 `거리 × (1 + min(통과 횟수, 8))`, 귀환/자원 왕복은 거리만 사용한다.
이는 관측된 연결에서 경로 후보를 고르는 비용이다. 기존 RM에 새 보상/벌점을 주지 않는다.
뒤로 돌아가는 행동을 금지하지 않으며, 집·작업대 등 이름을 붙인 위치를 별도로 저장·조회·삭제한다.
이름 등록은 실제 관측된 구역만 허용한다. 실제 사용자의 집 위치는 아직 지정하지 않았다.

월드 ID·차원·좌표 출처가 다른 지도는 섞지 않는다. 지도 파일 복원 API와 CLI가 있으며,
복원 직후 과거 마지막 위치와 새 위치를 이어 가짜 경로를 만들지 않는다. 현재 개발 controller는
실험 오염을 막기 위해 에피소드마다 새 지도를 만든다. 지속 월드 세션의 자동 복원 연결은 미완료다.

`NeuralSubgoalController`는 매 전이의 서버 좌표를 지도에 기록하고, 정체 후 계획 요청에 현재
방문 수·방향별 연결 수·명명 위치·덜 방문한 조사 후보를 전달한다. 실제 제공자 payload까지
내용이 보존됨을 모의 검사했다. 조사 후보의 미관측 방향은 `unknown`, 실행 가능 여부는 false다.
좌표 추종 skill이 없으므로 이동 명령을 LLM 실행 vocabulary에 추가하지 않았다.

## 실제 F3 화면 판독

실행: `results/spatial-exploration-20261010/f3-probe/`.
검증: `results/spatial-exploration-20261010/f3-verified/report.json`.
기존 development-corner 월드/seed104761, MineRL Minecraft1.16.5,1280×720,GUI scale2 조건이다.
가중치를 로드하지 않은 UI 진단이며 F3 press/release/닫기 등을 포함한7전이, 제어시간0.981초였다.
실행기는 준비 과정의 출력 상위 폴더 누락을 수정한 뒤 시작했다. 그 오류 시점에는 게임이 없었다.

Windows 기본 한국어 OCR과 명시적 영어 OCR 모두 Minecraft 픽셀 글꼴을 잘못 읽었다.
원본 화면/두 OCR 출력은 보존하고 잘못된 좌표는 모두 거부했다. 서버값으로 보정하지 않았다.
대신 해시가 고정된 공식 Minecraft JAR의 기본 글꼴 마스크를 사용해 XYZ 한 줄을 직접 판독했다.

| 화면 | 결과 |
|---|---|
| F3를 연 뒤 첫 화면,server tick25 |`229.500 / 201.00000 / -785.300`|
| 다음 F3 화면,server tick26 |같은 좌표, 별도 이미지 해시|
| F3를 닫은 화면 |XYZ 없음으로 거부|

두 판독 좌표는 동일 시점 서버값과 각 축 오차0이었다. 판독기는 서버 좌표를 입력으로 받지 않는다.
화면 해시·글꼴/JAR 해시·독립 판독 결과를 먼저 저장하고, 별도 검증기에서 서버값과 비교했다.
F3 좌표 두 표본으로 `f3_ocr` 출처의 별도 지도를 저장했다. 여기서 tick은 서버 시각 메타데이터,
차원은 개발 월드 설정을 사용했다. 차원 이름이나 tick까지 OCR로 읽은 것은 아니다.

실제 확인 범위는 **정지한 한 위치/기본 글꼴/위 해상도**다. 합성 글꼴 검사에서 scale1~4,
음수 좌표, 손상된 숫자 거부를 확인했지만 이동 중 판독·리소스팩·다른 렌더링은 미검증이다.
F3를 항상 띄우면 정책이 보는 영상이 달라지므로 live 신경망 게임에 자동으로 켜지 않았다.
이 관측은 F3 HUD를 허용한 조건이며, 디버그 HUD 없는 영상 관측 조건과 구분한다.
현재 live planner 지도는 여전히 `privileged_server` 출처다. F3 지도와 조용히 교체하지 않는다.

로컬 사용 예시는 프로젝트에서 `$env:PYTHONPATH='src'`를 설정한 후 실행한다.

```powershell
python scripts/read_f3_coordinates.py <saved-f3-image.png> results/<new-reading.json>
python scripts/spatial_memory_cli.py <map.json> --world-id <id> --source f3_ocr --mark home --cell <x> <y> <z> --output results/<new-map.json>
python scripts/spatial_memory_cli.py <map.json> --world-id <id> --source f3_ocr --route-to home --start-cell <x> <y> <z> --mode return
```

CLI의 cell은 원시 좌표가 아닌 지도 격자 ID다. 기존 결과를 덮어쓰지 않으며 게임 입력을 보내지 않는다.
