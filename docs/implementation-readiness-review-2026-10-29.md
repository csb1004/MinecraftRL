# LLM RM RL 구현 착수 전 결정 목록

작성일: 2026-10-29. 팀 회의용 설계 검토 결과이며, 아래 추천안은 아직 팀의 확정 결정이 아니다.

후속 사용자 지시에 따라 **D01~D13은 모두 OPEN인 미결정 과제**로 유지한다.
구현 순서는 [4단계 명세](plans/2026-10-29-001-feat-four-stage-llm-rm-rl-plan.md)를 따른다.
아래 각 항목의 '확정'은 확정해야 할 내용의 목록이며 이미 결정됐다는 뜻이 아니다.
VLM과 최근 3분 영상 입력도 D03의 검토 후보로 남기며 이번 단계 순서에 자동 채택하지 않는다.

목표는 빈 지식 DB에서 시작해 LLM으로 필요한 정보를 확보하고, 이를 RM의 단계·전이·보상과
정책의 목표 조건으로 연결하여 실제 RL 능력을 얻고 재사용하는 것이다. 실사용 관측·감지기는
사전에 검증한 버전으로 고정하고, 학습기는 대화/API 세션과 독립적으로 실행한다.

이 목록을 채우면 명시한 첫 실험 범위의 구현에 착수할 수 있다. 모든 새 지식을 인식하거나
정책이 반드시 학습한다는 보장은 아니다. 구현 전에 결정할 계약과 구현 후 확인할 가설을 분리한다.
실측이 필요한 항목은 시험 방법·담당자·예산·중단 기준을 정하면 착수 조건을 충족한 것으로 본다.
단, 핵심 의존성을 확보하기 전에는 그 다음 통합·성능 주장을 통과시키지 않는다.

## 유지하는 합의와 기존 문서

- 공식 STEVE-1 및 MineRL/Minecraft 1.16.5를 기본으로 유지한다. 원본 가중치는 변경하지 않는다.
- 실사용 관측기를 새로운 실패마다 수정하지 않는다. 사전학습 이상 감지기의 구체 모델·데이터는 미확정이다.
- 같은 페르소나·공유 목표 맥락의 LLM 응답에서 대화와 구조화된 개선 후보를 함께 생성한다.
- RL 가중치 개선이 중심이며, 지식 저장·RM 생성·프롬프트 변경만으로 학습 성공이라 하지 않는다.
- 상위 목표의 약속·취소·우선순위·완료 이력과 skill 내부 단계를 구분한다.
- 본 게임은 검증된 정책을 사용하고, 별도 연습·학습 프로세스가 후보를 만든다. STOP을 우선한다.
- 비단조 지식 수정, 넓은 세계 지식 검색, 장기 동료 에이전트 목표는 유지한다.

[원문 연구 명세](research-spec.md), [기존 구현·검증 계획](plans/2026-10-26-001-feat-llm-rl-bottleneck-validation-plan.md),
[상태 변화에 따른 과업 분해](task-decomposition.md)를 함께 적용한다.
이 문서는 이전 계획의 18개 요구와 15개 병목 시험을 폐기하지 않는다. 최근 논의에서 강조한
사전학습 감지기, 빈 KB, LLM→RM→RL, 증류에 관한 추가 결정과 충돌 지점을 보완한다.
과거 과업 분해 문서의 구현 상태는 당시 이력이며, 공식 정책 전환 이후의 현 구현 증거가 아니다.

## 1차 검토: 학습 경로의 누락 검사

학습 경로는 다음 계약을 모두 통과해야 한다.

`허용 관측 → 이상/지식 결손 → LLM+검색 → 지식 후보 → 검증 수준·실험 적격성 판정 → RM 명세 → 실행 가능한 사건 판정 → 현재 RM 단계의 정책/value 입력 + 보상 → 실제 경험 → PPO 갱신 → 독립 평가 → 적용/증류 → 재사용`

SQLite는 후보·근거·조건·의존성·이력을 저장한다. DB 저장 자체는 정책 학습이 아니다.
RM을 사용하는 것과 RM의 상태를 로그에만 기록하는 것도 다르다. 단계 정보는 행동 선택과
value 계산에 실제 전달되고, 보상은 실제 전달한 행동의 결과에 연결되어야 한다.

다음 13항목은 각각 **확정할 내용 / 추천 시작안 / 회의 산출물 / 검증·실패 대응**을 가진다.
추천안을 선택해도 정확한 수치·버전·담당자는 기록해야 한다.

### D01 연구 주장과 첫 검증 범위

- **확정:** 이번에 입증할 주가설, 첫 목표군, 초기 조건, 관측·행동 공간, 후속 확장 범위.
- **추천:** 주가설은 지식→RM을 통한 실제 정책 개선과 재사용으로 두고, 선택적 학습의 비용 효율을
  이어서 비교한다. wood/dirt는 학습 엔진 진단에 사용하고, 지식 결손·조건 수정이 필요한 짧은 과업군을
  별도 포함한다. 수집만으로 지식 습득 전체를 입증하지 않는다. 장기 제작 목표는 후속 조합 평가다.
- **산출물:** 과업별 성공 정의, 초기 제공 자원·도구·레시피 정보, 제한 시간, 사용자 목표의 허용 수정 범위.
- **검증/대응:** 공식 정책의 사전 능력을 측정한다. 아직 수행 경험을 얻지 못하는 과업은 준비된 연습부터
  단계적으로 시험하고 그 조건을 공개한다. 고수준 자동 제작을 도입한 결과는 UI 조작 정책 결과와 분리한다.

### D02 관측 권한과 사건 판정

- **확정:** 정책 P, 감시/LLM M, 보상·독립 평가 E가 받는 정보와 사건별 근거·신뢰도·유효 시간.
- **추천:** 실행 RM의 전이와 그에 따른 정책 목표도 P/M에 허용된 정보만 사용한다. 서버 정답으로 RM을
  진행시켜 목표 임베딩에 전달하면 숨은 정보가 정책에 유입된다. 이를 사용하려면 별도 privileged 조건으로
  선언한다. E의 학습 보상·종료 권한과 학습 중 privileged supervision도 명시한다.
- **산출물:** 사건 registry. 각 항목에 의미, 파라미터, 관측 출처, true/false/unknown, 누락·지연 처리,
  실제 판정 구현과 예제를 적는다. 현재 보유와 과거 획득, 접근 가능과 단순 가시성을 구분한다.
- **검증/대응:** 같은 화면/허용 이력이지만 서버 상태가 다른 사례에서 정책 조건이 몰래 달라지는지 검사한다.
  확인 불가능한 새 조건은 unsupported/unknown이다. 실사용 센서를 추가해서 통과시키지 않는다.

### D03 사전학습 감지기와 호출 경로

- **확정:** 감지기 모델·학습 데이터·배포 전 보정 방법, 고정할 가중치/전처리/프롬프트/판정 기준,
  출력 점수의 의미, 정상 참조 데이터와 평가 분리, 오탐·미탐·탐지 지연 허용치.
- **추천:** 감지기는 이상 후보를 찾고 원인과 개입은 LLM이 판단한다. 계획 중 KB 결손/충돌도 독립 호출
  계기로 둔다. 감지기가 놓친 의미적 이상을 살필 저빈도 정기 검토와 그 API 예산을 미리 정한다.
- **산출물:** 후보 모델/가중치와 실행 가능성 확인 작업, 데이터 수집 담당, 검증 시한, 미달 시 대체 실험.
  적합한 공개 가중치가 존재한다고 가정하지 않는다. 없으면 배포 전 자체 학습 비용을 명시한다.
- **검증/대응:** 정상 우회·채굴·로딩, 비정상 반복, 관측 장애, 새 정책의 정상 행동을 함께 검사한다.
  정책이 개선되면 정상 분포가 변할 수 있다. 배포 중 감지기를 몰래 재학습하지 않고 오탐 증가/지원 범위를 보고한다.

### D04 빈 KB와 근거 기반 지식 수정

- **확정:** 초기 사실 테이블, 제공 스키마·사전학습 지식·아이템/행동 목록, 검색 출처/게임 버전 범위,
  후보 채택·보류·철회 기준, 검증 실험의 조건과 예산.
- **추천:** 사실·경험 테이블은 비우되 관측/실행 계약은 제공한다. DB miss를 LLM의 무지와 동일시하지 않는다.
  후보를 즉시 기록하고 출처, 조건, 예외, 지지/반대 증거, 의존성을 덧붙인다. confidence만으로 확정하지 않는다.
- **산출물:** 무엇을 알고 시작하는지의 manifest와 지식 수명주기. 일반 세계 규칙, 현재 월드 사실, 사용자 선호,
  정책 능력 평가를 구분한다. 지식을 얻었다고 항상 학습 job을 만들지 않는다.
- **검증 순환 방지:** 행동 능력이 없어 규칙을 확인할 수 없으면 검증된 지식으로 승격하지 않는다.
  제한된 가설 검증용 연습은 허용하되 후보 가정·예산·독립 결과 판정을 명시한다. 준비된 환경/규칙 검사와
  학습된 조작 성공을 분리하고, 충분한 구별 근거를 얻지 못하면 미해결로 남긴다. 검증을 기다리며 무한 대기하거나
  후보를 정답으로 간주한 보상만으로 자기 가설이 맞다고 결론 내리지 않는다.
- **검증/대응:** 조작 실패만으로 올바른 규칙을 철회하지 않는다. 규칙이 철회되면 관련 RM/job/교사 자료/
  체크포인트를 재검토한다. DB 삭제로 학습된 잘못된 행동까지 제거되는 것은 아니며 회귀 평가·복구가 필요하다.

### D05 LLM 응답과 원인별 개입

- **확정:** API 모델·고정 프롬프트·출력 schema, 의도/권한 판정, 검색·관찰 확인·재계획·RM 수정·RL 요청의
  선택 근거, 복합 원인/unknown 처리, 제한된 확인 행동·재시도·중복 요청 예산.
- **추천:** 한 응답에 자연어 답변, 지식 후보/근거, 경쟁 가설, RM 변경 후보, learning request를 둔다.
  프로그램이 지원 기능·버전·예산·목표 약속을 검증한다. 검색 결과와 LLM 출력은 실행 권한을 부여하지 않는다.
- **산출물:** 정상/잘못된 응답 예제와 개입 선택표, API timeout·불완전 응답·취소·중복 요청의 처리 결과.
  추가 코드를 자동 설치하거나 최상위 성공 정의를 바꾸는 권한은 주지 않는다.
- **검증/대응:** 지식 부족, 계획 오류, 관측 오류, 수행 능력 부족이 공존하는 사례를 포함한다. 원인 F1 외에
  불필요한 학습 시간·잘못된 지식 수정·유효 개입률·보류율을 측정한다. 참고 라벨의 불확실성도 남긴다.

### D06 RM 생성과 수정의 실행 계약

- **확정:** LLM 출력에서 RM으로 변환할 형식, 허용 상태/전이/보상 문법과 크기 상한, 상위 RM과 skill RM의 경계,
  자원 수량·소모·대체 경로·선행조건·재진입·종료·동시 사건의 의미.
- **추천:** LLM은 고정 registry의 사건을 조합한 데이터 명세를 만들고 compiler가 검사한다. 신규 인식 코드를
  실행 중 생성하는 경로는 제외한다. 상태는 검증 가능한 변화 단위로 두고 개별 키 입력으로 쪼개지 않는다.
  완료 이력과 현재 재료 보유를 구분하고 기존 목표를 삭제하지 않은 채 조건·우선순위·revision을 관리한다.
- **산출물:** 정상 RM 하나, 중복/충돌 전이·도달 불가·unknown·잘못된 predicate를 가진 거부 예제들,
  RM patch 전후 상태 대응표와 사용자 목표 보존 조건.
- **검증/대응:** 이미 완료한 단계, 보유 재료 소모, 동시에 채굴·획득, 조건 소실, 새로운 우회 경로를 재생한다.
  unknown은 부정 조건을 만족하는 false로 변환하지 않는다. mapping이 불가능한 RM 변경은 현재 상태에
  억지로 끼우지 않고 재계획/다음 episode로 보류한다.

### D07 RM 상태에서 정책과 value 입력으로 가는 경로

- **확정:** 현재 RM 상태/활성 하위 목표/필요 수량/허용 이력을 정책과 critic에 표현하는 방법,
  encoder·guidance·행동 공간·순환 상태 계약과 버전 호환성.
- **추천:** 공식 STEVE-1 목표 임베딩 경로를 우선 사용하되, 동일 화면에 다른 RM 진행 상태를 주었을 때
  구분 가능한지 먼저 시험한다. 임의의 언어 임베딩을 차원만 맞춰 끼우지 않는다. 목표 embedding의 표본과 hash를
  기록하고 한 단계에서 불필요하게 재추출하지 않는다. 필요한 추가 context adapter는 별도 학습·비교 조건이다.
- **산출물:** 실제 policy/value 입력 예제, goal encoder 호출 규칙, reset/handover 규칙, 동일 입력 확률 대조 시험.
  입력 shape가 같아도 의미가 달라진 RM/encoder는 호환된다고 보지 않는다.
- **검증/대응:** 입력에 RM 단계가 누락되는지, 단계가 바뀌어도 같은 의미로 뭉개지는지, critic이 reward 맥락을
  구분하는지 검사한다. 단계 입력이 추가되었다고 공식 정책이 바로 이해하거나 새 스킬을 갖췄다고 하지 않는다.

### D08 보상과 최종 성공의 독립성

- **확정:** 최종 성공, 중간 보상, 시간·실패 비용, 할인/GAE 시간 단위, 실제 terminal과 time limit/STOP 처리.
- **추천:** 최상위 성공 조건은 사용자 목표에서 고정한다. LLM이 바꾸는 하위 RM/보상과 별도 환경 판정으로
  대조한다. 같은 GoalSpec에서 생성됐다는 이유만으로 평가가 독립적이라고 하지 않는다. 중간 보상은 제한된
  검증 규칙으로 계산하며 정책 불변성을 자동 주장하지 않는다.
- **산출물:** 보상 식과 모든 계수의 단위, episode/단계별 지급 규칙, rollout 종료·bootstrap 표,
  시작 아이템·버렸다 줍기·목표 수량 변경·조기 사망 사례의 예상 보상과 성공 판정.
- **검증/대응:** 단계 왕복·반복 탐험으로 점수만 올릴 수 있는지 확인한다. 실제 획득/제작이 늘지 않으면 후보를
  승격하지 않는다. 지연 보상이 advantage까지 도달하는지 검사하고 감마만 높여 해결됐다고 하지 않는다.

### D09 실제 학습 경험과 PPO 갱신

- **확정:** 학습 가능한 층, optimizer/value 구성, 수집·update 단위, 연습 환경 분포와 준비 개입,
  유용한 경험 확보 방법, 성공 경험이 없을 때의 curriculum/중단 기준.
- **추천:** 공식 초기값에서 사람이 확인한 RM으로 먼저 PPO가 개선되는지 검증한다. 학습 job은 RM·보상·
  관측·policy-parent snapshot을 고정한다. 별도 연습에서 현재 수집 정책으로 경험을 얻고, 본 게임의 오래된
  기록은 진단/조건 선택에 사용한다. 이를 그대로 on-policy PPO batch에 섞지 않는다.
- **산출물:** API 없이 실행 가능한 resolved job 설정, 실제 전달 행동과 old logp·value·종료·목표가 포함된
  rollout 계약, scope hash, 교차 seed·시작 조건 목록, 무신호/표현 부족/자원 부족의 분리 기준.
- **검증/대응:** 무업데이트 확률 일치, 실제 gradient/가중치 변경, 보상·advantage 유효성, held-out 개선을
  순서대로 확인한다. 준비된 환경의 규칙 검증 성공은 화면 조작 정책 성공으로 세지 않는다.

### D10 증류와 지속학습의 교사 및 학생

- **확정:** 무엇을 증류할지, 교사·학생 정책, 입력과 행동 공간의 대응, 호출 시점, 학습 자료·예산,
  기존 능력 보존과 KB 철회 시 교사 자료 무효화 방법.
- **추천:** 실제 RL로 개선되고 독립 평가를 통과한 후보가 교사, 공통 목표 조건부 정책이 학생이다.
  LLM 문장 저장은 증류가 아니다. 처음부터 모든 job에 증류를 강제하지 않고 능력 통합 필요 시 별도 job으로
  실행한다. RL과 증류 효과/비용을 분리한다. 후보 적용과 증류 학생 적용도 별개 평가를 거친다.
- **산출물:** teacher/student manifest, 조건별 행동 분포/행동 label 자료, 유지할 과거 능력 목록,
  증류 전후 비교표와 허용 퇴행 기준. 체크포인트 가중치를 단순 평균하지 않는다.
- **검증/대응:** 교사만 숨은 상태를 아는 경우 학생이 같은 행동을 결정할 수 있는지 확인한다. 같은 허용 이력에
  서로 다른 교사 정답이 필요한 경우 추가 증류만으로 해결되지 않는다. 학생이 방문하는 실패·회복 상태도 평가하고
  성공 궤적만의 모방으로 일반화를 단정하지 않는다. 원래 정책을 보존하고 퇴행 시 승격을 보류한다.

### D11 비동기 실행과 버전 교체

- **확정:** 제어·감시·API·DB·학습의 실행 소유자, 큐 상한과 우선순위, RM/정책/KB 변경 적용 경계,
  후보 stale 판정, RNN 상태 복원, STOP·취소·pause/resume의 의미.
- **추천:** 게임 제어는 단일 소유자, 감시/API는 비동기, learner와 연습 게임은 별도 프로세스다.
  SQLite는 기록 소유자 하나가 쓰고 제어 루프가 DB/API 완료를 기다리지 않는다. 학습 job은 불변 명세로
  독립 실행한다. 실행 중인 모델을 직접 갱신하지 않으며 호환된 RM/목표/policy 상태 묶음을 행동 경계에서 적용한다.
- **산출물:** 상태도, 버전 의존성/적용 검증표, 중복 방지 key, 이벤트 시각과 실제 발생 순서 규칙,
  API 끊김·DB 잠금·순서 역전·콘솔 종료·정책 교체 중 STOP의 예상 결과.
- **검증/대응:** 늦게 도착한 보상/사건을 잘못된 행동·RM에 붙이지 않는다. KB의 무관한 수정으로 모든 job을
  취소하지 않고 의존 항목별 판단을 한다. 이미 전송한 step의 완료와 STOP 이후 새 dispatch를 구분한다.
  완료·취소를 수락한 목표에는 새 행동을 보내지 않고, 다른 과업은 별도 활성화 계약을 따른다.
  입력 해제·소유 PID 정리·체크포인트 재개를 실제 확인한다. RM 상태 mapping이나 RNN 준비 실패 시 교체를 보류한다.

### D12 비교 실험과 증거의 분리

- **확정:** 주 비교, 보조 비교, 기준선, 총 환경 경험·API·학습 시간 예산, 데이터 분할과 통계 판정 계획.
- **추천:** (a) 같은 RM/목표 조건의 가중치 고정 대 RL, (b) 고정 RM 대 LLM 수정 RM의 동일 learner,
  (c) 동일 RM 생성 권한을 가진 고정 학습 일정 대 선택적 학습, (d) 증류 전후를 순차 비교한다.
  모든 조합의 전수 실험을 첫 배치로 돌리지 않는다. 수동 정답 RM은 그 정보 이점을 밝힌 상한 대조로 사용할 수 있다.
- **산출물:** 비교군 표, 공통 초기값/KB·대화 상태, 정책 단독 평가의 정확한 목표 embedding, 학습/개발/
  최종 world·episode 분리, pilot 이후 표본 설계, 합격/실패/inconclusive/unrun 정의.
- **검증/대응:** DB 레시피 삭제는 로컬 기억 결손 시험이고 LLM 사전지식 제거가 아니다. 공유 모델에서 특정 스킬만
  삭제했다고 가정하지 않는다. 규칙 변경 조건과 기본 게임 조건은 구분한다. 최종 평가 자료는 LLM/KB/학습기에
  되돌리지 않는다. 기술 실패·취소·미실행을 숨기지 않고 완료율, 실제 능력, 지연, 비용, 망각을 함께 보고한다.

### D13 자원 상한과 재현 가능한 운영

- **확정:** 실제 사용 머신/GPU, 동시 게임·학습 수, CPU/VRAM/RAM/disk 상한, API 모델·호출/토큰/금액 상한,
  제어 지연·최대 공백·학습/중단 응답 허용치, 자원 부족 시 대응과 담당자.
- **추천:** 사전 admission probe로 단독·병행 부하를 비교하고, learner가 본 게임을 방해하면 pause/보류한다.
  3GB GPU에서 병행 가능하다고 전제하지 않는다. 다른 자원을 쓴다면 동일 job을 재현하고 승인·로컬/클라우드 결과를
  구분한다. 이전 API 시험 승인을 새로운 무제한 예산으로 해석하지 않는다.
- **산출물:** job별 실행·상태·중단·재개 명령 계약, code/model/RM/KB/observer hash와 초기 월드·seed,
  핵심 궤적 보존·저장량 관리 계획, 재현 묶음, 담당자·검증 기한. 사용자 게임 영역만 API에 제공한다.
- **검증/대응:** API/터미널 없이 학습 지속, 사용자 다른 앱 사용, OOM·디스크 부족·중복 worker·자식 실패를
  시험한다. 학습과 증류가 실제 플레이와 동시에 가능하지 않으면 그 요구의 미달을 명시한다.

## 회의 종료와 구현 착수 기준

각 D 항목에 다음을 기록한다.

`결정 ID / 선택안 / 제공 정보와 입출력 예제 / 성공·보류·거부 조건 / 검증 방법·예산 / 담당자·기한`

구현 전에 최적 학습률·감지 성능·최종 성공률을 알아야 하는 것은 아니다. 탐색할 범위와 평가 방법을
정하면 된다. 반대로 다음 공란은 단순한 구현 재량으로 남기지 않는다.

- RM 전이를 무엇으로 판단하며 그 정보가 정책에 허용되는가.
- LLM 응답이 어느 명세로 변환되고, 어떤 요청을 거부하는가.
- RM 단계가 policy/value 입력과 보상에 실제로 어떻게 연결되는가.
- 필요한 사건·행동·연습 환경·교사 데이터가 없을 때 어떻게 보류하는가.
- 본 게임을 계속하면서 학습/STOP/교체를 처리할 실행 경계가 무엇인가.
- 어떤 비교와 독립 성공 판정으로 실제 RL 개선을 인정하는가.

우선 검증 순서는 다음과 같다.

1. **실행 가능성:** 공식 정책·허용 관측·행동·기록과 자원 admission을 확인한다. 감지기 후보 확보도 병행한다.
2. **학습 연결:** 사람이 확인한 RM으로 입력·보상·PPO 수치와 실제 개선을 확인한다. LLM 생성기는 같은 계약의
   기록 재생 시험으로 따로 개발할 수 있다. 학습 실패를 대형 KB 구축으로 덮지 않는다.
3. **지식과 RM 자동 연결:** 빈 KB/충돌/미지원 사례에서 LLM 출력→검증→RM→동일 learner를 연결한다.
4. **실시간 통합:** 감지·검색·학습·후보 적용·STOP을 병행하고 지연·자원·버전 충돌을 확인한다.
5. **지속 능력:** 재사용·망각·증류를 시험하고, 잠근 비교군으로 최종 평가한다.

회의에서 13항목의 결정/검증 책임이 채워지면 **첫 범위의 구현 착수 가능**으로 판정한다.
실험의 성공, 무제한 지식 확장, 모든 병목 해소는 별도의 결과다. 범위를 넘는 사건은 미지원으로 드러내고
새 개발·평가 조건으로 다룬다. 원문 연구 목표를 축소하거나 승인받지 않은 구현을 완료로 표시하지 않는다.

## 근거와 해석 경계

- [ARM-FM](https://proceedings.iclr.cc/paper_files/paper/2026/file/68f24fad8f460d4b7bbac402c252ebbb-Paper-Conference.pdf):
  RM 구조·labeling function·상태 설명 임베딩을 연결한다. 고정된 우리 관측 계약에서 같은 범위가 지원된다는 증거는 아니다.
- [XENON](https://proceedings.iclr.cc/paper_files/paper/2026/file/df20e06b04dfc499a1a698796abb0856-Paper-Conference.pdf):
  MineRL 실험의 craft/smelt는 고수준 행동이다. 그 결과를 화면 기반 제작 조작 학습의 증거로 쓰지 않는다.
- [Auto MC-Reward](https://arxiv.org/abs/2312.09238): 보상 설계·실패 분석과 RL의 연결을 참고한다.
  사전 행동 능력·관측·연습 조건 차이를 함께 확인해야 한다.
- [Policy Distillation](https://arxiv.org/abs/1511.06295): 행동 정책의 이전/통합을 참고한다.
  KB에 문장을 넣거나 임의의 교사 행동을 기록하는 것만으로 증류 효과가 입증되지 않는다.
- [실시간 LLM 실패 감시 연구](https://arxiv.org/abs/2608.02464): 배포 환경에 따른 정상 기준 문제를 참고한다.
  Minecraft 정책에 바로 사용할 수 있는 검증된 감지기로 간주하지 않는다.

논문은 앞선 대화에서 원문/공식 페이지의 관련 부분을 확인했다. 이번 산출물은 그 근거와 기존 계획,
최근 사용자 요구를 대조한 설계 결정 목록이다. 코드 구현·게임·학습·프로젝트 API 실행은 수행하지 않았다.
