# 결과 슬롯 Shift 제한 비교 — 2026-10-05

전체 Shift 제한의 부작용을 줄이는 별도 조건이다. 기존 두 배치(제약 없음/전체 Shift 제한)를
보존한다. 판자4·흙1 동일 저장본, STEVE-1 가중치와 `craft sticks`, 시드5개, 제어180초 상한,
서버·회수·NBT 판정은 같다. 실행 순서130363/155921/104729/196613/262147을 유지한다.

변경은 현재2×2 인벤토리의 결과 슬롯에서만 sneak/Shift를0으로 만드는 것이다.
첫 관측 전과 inventory 키로 GUI가 바뀌는 행동은 위치를 확정할 수 없어 Shift0으로 둔다.
재료 칸/인벤토리 이동과 월드 웅크리기는 원래 정책 제안을 유지한다. 새 CLI 옵션은
`--craft-result-slot-guard`, 배치 실행기는 `--result-slot-guard`이며 기본은 꺼져 있다.

읽기 전용 Java 관측에 결과 슬롯 중심과 GUI 크기만 추가한다. 결과 슬롯 미리보기 아이템을
획득으로 세지 않는다. ReplaySender는 키→커서 이동→클릭 순서로 실행하므로 카메라 이동을
각도/0.15로 환산하고 화면 경계로 제한한 예상 커서 위치를 사용한다. 슬롯 판정 범위는
ContainerScreen과 같은 중심±9(하한 포함/상한 제외)다. 실제 다음 관측 커서가 예상과
1픽셀보다 다르면 기술 오류로 멈춘다. 정책 원본/실제 행동/판정 좌표·사유를 기록한다.

가설: 결과를 꺼낼 때의 일괄 제작은 차단하면서 재료 이동의 Shift 동작을 보존하면,
전체 Shift 제한에서 미제작으로 바뀐 시드130363을 포함해 정확 예산 성공이 개선될 수 있다.
잘못된 레시피를 막거나 대신 배치하지 않으므로 레시피 선택 실패는 여전히 가능하다.
이 조건도 정책+명시적 제약+회수 보조이며 순수 정책이나 일반3×3 제작 지원으로 보고하지 않는다.

단위 회귀/전체 테스트 및 Java 빌드 후 실제5회를 실행한다. 기술 오류는 중단·원인 조사하고
미실행은 표본에서 제외한다. 성공률뿐 아니라 제한 횟수, 비결과 슬롯에서의 Shift 유지,
좌표 예측 오차, 목표 관측 후 새 행동0, 저장 수량·메모리·지연·종료·원본 보존을 확인한다.
