# 작업대와 공통 레시피 GUI 실험

2026-10-05 사용자 요청: 작업대 제작·사용을 실행하고 제작 처리를 일반화한다.
이 경로는 사전학습 정책 추론이나 RL이 아닌 **명시적 GUI 보조**다.
기존 정책 실험을 대체하거나 기존 성공률에 합산하지 않는다.

## 입력과 동작

- STEVE-1으로 자연 채집한 원목 3개 저장 월드를 불변 원본으로 삼는다.
  아이템 지급, `/recipe give`, 서버 직접 제작·배치 API를 사용하지 않는다.
- 원본을 복제하고 기존 고정 5개 seed로 실행한다. 동일 저장 월드이므로
  5종 지형 시험이 아니라 같은 조건에서의 재현성 시험이다.
- 게임 JAR의 공식 JSON에서 재료 tag, shaped/shapeless, 결과 수량을 읽는다.
  재료를 공유하는 여러 제작 목표를 계획하고 재료가 부족하면 행동 전에 거부한다.
- 일반 책 클릭으로 재료를 1회분 배치하고 실제 그리드·미리보기·수량을 검사한다.
  일반 결과 클릭으로 생성한 뒤 커서에서 실제 인벤토리로 회수하고 서버 확인을 기다린다.
  Shift 반복/전체 제작으로 예산을 초과하지 않는다.
- 3×3이 필요한 경우 미리 제작한 작업대를 핫바에 장착한다. 3.7블록 이내의
  비어 있고 몸과 겹치지 않는 위치, 단단한 비상호작용 바닥, 실제 ray hit를 확인한다.
  일반 `use`로 배치하고 서버 블록과 재료 감소를 확인한다. 다시 작업대를 바라보고
  `use`로 연 다음 screen/width를 확인한다.
- 기본 목표는 나무 곡괭이 1개와 나무 도끼 1개다. 최종 인벤토리에는 두 도구,
  월드에는 작업대 1개가 남아야 한다. 생성 후 새 제작은 허용하지 않는다.

## 종료와 판정

각 실행 제어 시간은 최대 180초다. 완료·STOP·시간 제한은 실행 게이트로 처리한다.
종료 시 커서 물품 반환·입력 해제·GUI 닫기는 명시적 cleanup으로 기록하며 새 제작은 하지 않는다.
저장 완료 확인 뒤 서버 인벤토리와 `level.dat`/`playerdata`를 대조하고,
Anvil 청크의 실제 블록도 읽어 작업대가 보존됐는지 확인한다.
소유한 자식 프로세스 잔존과 stop acknowledgment 이후 새 dispatch도 검사한다.

게임 스레드에서 관측 스냅샷을 만든 뒤 통신 스레드가 이를 읽는다.
통신 스레드에서 서버 청크 접근을 예약하고 기다리는 방식은 동기식 MineRL 실행과
교착하므로 사용하지 않는다. 관측 코드는 블록·재료·레시피 해금을 수정하지 않는다.

## 일반화의 범위

공통 계획·실행기는 2×2/3×3과 mirrored/translated shaped 패턴, shapeless,
재료 tag 대체를 처리한다. 목록은 판자 6종·막대기·작업대·나무 곡괭이·나무 도끼·참나무 반블록이다.
책의 검색 탭과 페이지 탐색을 지원하지만 모호한 그룹 버튼은 거부한다.
구현 지원과 실제 시험한 레시피는 구분해서 결과에 기록한다.
원거리 작업대 탐색·장애물 우회·책의 모든 그룹/검색어·화로/대장장이 작업대 등은 범위 밖이다.
이번 결과만으로 임의의 제작·월드에 대한 학습 일반화가 입증되지는 않는다.

실행:

```powershell
$env:PYTHONPATH='src'
python scripts/collect_workshop_materials.py
python scripts/run_workshop_probe.py --source results/workshop-materials-<실제 실행 ID>
```

재료 수집은 기존 원본이 이미 검증됐다면 반복할 필요가 없다.
결과에는 GUI 판단 지연, 전체 제어 주기, VRAM, 단계별 서버 커밋, 저장 검증을 남긴다.
초기화 중 오류로 행동이 없었던 조건과 미실행 조건은 과업 성공/실패 분모에 넣지 않는다.
