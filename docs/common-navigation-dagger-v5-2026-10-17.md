## 별도 mode 진단의 사후 프로토콜 수정

기존 제안 확률 gate는 stochastic sampling용이고, 현재 실제 mode 행동의 확률은 point mass다.
따라서 그 실패를 지우거나 통과로 바꾸지 않고 **새 탐색적 train calibration 준비 조건**을 만들었다.
`results/common-navigation-dagger-preparation-20261017-v5/mode-readiness-protocol.json`을
새 mode 진단 전에 저장했다. 기존 NBT 확인4상태에서 .05블록은 정확한 중립 명령4/4,
3블록은 다른 버튼 없이 전진4/4를 요구한다. 검사 자체는 게임/optimizer0이다.
이를 통과해야만 별도 train-b 실제 calibration5/6을 시도하며, 개발 비교는 그다음이다.
이것은 v5 결과를 본 뒤 수행한 **프로토콜 수정**이며 원래 사전 gate 통과로 주장하지 않는다.
배포/기본 승격을 승인하는 gate도 아니다. 실제 개발은 동일한 mode에서 이전/새 가중치를 비교해야 한다.

완료 결과는 근거리4/4, 원거리3/4로 이 별도 기준도 미달했다. 결과는
`results/common-navigation-dagger-preparation-20261017-v5/mode-readiness.json`에 보존한다.
따라서 v5 실제 calibration은 실행하지 않았으며 같은 자료로 [v6 추가 학습](common-navigation-dagger-v6-2026-10-17.md)을 시작했다.
