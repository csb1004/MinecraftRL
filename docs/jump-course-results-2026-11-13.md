## 4. 왜 떨어졌나 (사후 분석, 판정 아님)

같은 결정 상태에서 교사가 냈을 라벨과 정책의 실제 행동을 비교했다(`results/jump-20261113/analysis/jump_diag.py`, `jump_yaw.py`).

**도는 방향 (yaw 부호가 교사와 같은 비율, 대상 각도별)**

| 갈래 | 15도 미만 | 15–35도 | 35–90도 | 90도 이상 | 최대 회전(±10도)을 낸 결정 |
|---|---|---|---|---|---|
| R1 j-r1 | 0.46 | 0.53 | 0.49 | 0.47 | 83% |
| R2 j-r2 | 0.57 | 0.65 | 0.40 | 0.44 | 75% |
| 개발 j-final | 0.57 | 0.57 | **0.35** | 0.47 | 50% |
| 개발 공식 | 0.19 | 0.26 | 0.16 | 0.11 | 12% (대부분 0) |

- 다음 발판이 화면 안이면 학생은 조금 맞게 돈다(0.57–0.65). 화면 밖(35도 이상)이면 우연 수준이거나 그보다 나쁘다.
- 헤드 입력은 화면 latent와 단계 one-hot뿐이다. 그래서 "turn" 단계에서 다음 발판이 왼쪽인지 오른쪽인지 알 수 없다. 교사 라벨은 특권 좌표로 방향을 알고 있다.
- 교사 turn 라벨은 대부분 상한(±10도)이었다. 학생은 "세게 돌기"만 배우고 방향은 거의 무작위로 골랐다.
  개발 실행 c202(n1)에서 j-final은 가장자리 1.1블록 앞에서 교사와 반대 방향으로 돌기 시작했다. 24스텝 만에 다음 발판에서 140도 벗어났고, 옆을 본 채 뛰어 떨어졌다.

**키**

| 개발 j-final, 교사가 누른 결정 중 학생도 누른 비율 | 값 |
|---|---|
| run 단계 앞으로 | 75/78 |
| run 단계 달리기(틈 2 또는 오르막) | **6/36** |
| air 단계 달리기 | 35/91 |
| edge 단계 점프 | 3/9 |

- 달리기를 거의 누르지 않아 틈 2칸 점프가 1/7만 착지했다. 어느 점프에서 달려야 하는지(틈·높이)는 교사만 아는 코스 정보다.
- 그래도 점프 지점은 가장자리 근처로 옮겨 갔다. 뛰어오를 때 가장자리까지 거리 중앙값은 j-final 0.38블록(교사 기준 0.35), 공식 1.93블록이었다.
- 떨어진 방식(개발): j-final은 점프 후 못 미침 4, 점프 없이 시작 발판에서 걸어 나감 3이다(돌다가 가장자리를 넘음). 공식은 점프 후 못 미침 5, 걸어 나감 3이다.
