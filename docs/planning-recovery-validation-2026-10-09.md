## 연결한 실행 경계

정체 뒤 중립 행동1tick을 보내고 서버 held_key_count=0을 확인한다. 해당 화면은 행동을
샘플링하지 않고 신경망 문맥으로 인코딩해, 실제 전이가 끝난 때에만 순환 기억에 반영한다.
중립도 원래 RM을 진행시키고 보상/상태/화면/기억 hash를 보존한다. 학습 정답으로 쓰지 않는다.

계획 대기는 별도 제어 단계다. 매20ms STOP과 전체180초 제한을 확인하고 게임 입력·정책 추론은
하지 않는다. 응답 뒤 중립1tick으로 관측을 갱신한 후 요청 ID·실행 세대·월드/목표·현재 전제·
입력 해제·남은 시간을 기존 ReplanGuard로 검사한다. STOP/실제 목표 만족은 제안보다 우선한다.

`explore_then_resume`은 명시적으로 켠 진단 실행에서만 등록한다. 방향 지정/보장된 우회 skill이
아니며 최대200tick 또는30초 중 먼저 도달하는 한도를 적용한다. 원래 원목 RM/진행도/기억을
삭제하지 않고 조건을 복귀시킨다. 새 요청1회·개입1회로 제한하고 오류/만료/일시정지 제안에는
추가 정책 행동 없이 종료한다. 중립/계획 대기 시간도180초 제어 시간에 포함한다.

## 실제 환경에서 발견한 타입 경계

MineRL 수치 모니터는 held_key_count를0.0으로 반환한다. 기존 snapshot 검증기는 정수0만
허용해 실제 키 해제 뒤 `ValueError: invalid release evidence`가 발생했다.
`make_snapshot`에서 유한한 비음수 정수값만 int로 바꾸도록 수정했다. 소수·음수·bool·NaN·무한대는
거부한다. 실제438번째 관측을 다시 투영해 요청 계약까지 확인했고 원본 실패 로그는 보존했다.
합성 검사의 키 개수가 int0뿐이어서 놓친 차이였으며 수정 전 실패/후 통과 회귀를 추가했다.

## Windows/WSL LLM 연결 준비

키는 Windows 프로세스에만 두고 WSL은 요청/응답 파일만 주고받는 일회 mailbox를 구현했다.
Windows↔WSL 실제 별도 프로세스 통신은 합성 fixture로 검증했다. 실제 API 호출/게임 행동은0이다.
종료 뒤 응답 무시, 중복 요청 금지, 응답 ID 일치, 요청 크기 제한, 원자적 파일 교체를 검사했다.

유료 브로커는 명시적 `--allow-paid`일 때만 기존 설정을 읽고, 요청당 최대1회/출력1024tokens/
20초 socket timeout/재시도0을 사용하도록 준비했다. 게임 실행기의 독립20초 대기 제한과 STOP이
계속 적용된다. 실제 유료 연결은 아직 실행하지 않았으며 이전 승인2회는 이미 소진됐다.
브로커 CLI/실제 게임 경로 결합 및 합성 통합은 완료했다. Windows 전체415검사(18skip),
WSL 전체420검사(9skip), 이후 추가한 준비 manifest 검사2개는 양쪽에서 통과했다.
종료/오래된 응답/현재 관측·목표 변화/호출 한도/만료 중 공급자 준비를 검사했다.
[별도 무료 실제 연결1회](planning-recovery-mailbox-protocol-2026-10-09.md)에서 요청/응답/검토/조건 복귀와
행동 확률·RM·중단까지 감사했다. 요청 패킷과 브로커 기록의 해시 및 응답 일치도 확인했다.
[실시간 유료1회 조건](planning-recovery-live-protocol-2026-10-09.md)은 추가 승인용이며 아직 실행하지 않았다.
최종 manifest 검사는 현재 소스·실제 가중치·월드·프롬프트를 읽기만 하며 키/네트워크를 사용하지 않았다.
코드 검토는 주 실행 흐름에서 수행했다. 서브에이전트와 GitHub 작업은 사용하지 않았다.
