# 단일 목표 계약 U1

사용자가 목표 표현 통일에 동의했다. 기존 목표 큐·공식 정책·고정 관측기를 재사용한다.
추가 예측 모델, 새 가중치 학습, API 호출, 게임 실행은 이 변경에 포함하지 않는다.

## 입력과 보장

`goal_spec_v1`의 각 목표는 id, target, quantity, priority, depends_on, requires를 가진다.
현재 실행 등록 대상은 wood(기존 원목 집합)와 dirt다. requires도 target/quantity로 쓴다.
등록되지 않은 대상·자유 prompt/skill/성공식·알 수 없는 필드는 거부한다.
목표 목록은 의존 대상이 먼저 나오는 순서로 작성한다. 형식 검사는 자연어 의도 해석의 정확성이나
정책 실행 능력을 증명하지 않는다. 사람과 LLM은 같은 입력·검증 경로를 쓴다.

단일 입력에서 다음을 결정론적으로 만든다.

- 기존 GoalQueue가 사용하는 아이템 집합·스킬 바인딩·수량·선행 조건.
- 목표 활성화 시 인벤토리를 기준으로 한 순증가량 >= quantity라는 완료 조건과 기존 일회성 보상.
- 정책에 전달되는 대상·수량·진행/잔량 계약 및 이미 검증된 임베딩 키/문구의 선택.
- 원본 입력 해시와 목표별 계약 해시. 실행 로그와 학습 궤적에도 연결한다.

상위 목표는 수량/순서를 유지하고 내부 RM은 기존 관측과 세 번 연속 단계 확인 규칙을 사용한다.
임베딩은 기존 고정 bank를 재사용한다. 수량과 선행 조건을 임베딩에 들어 있다고 주장하지 않는다.
목표 수량/잔량은 기존 S2/R1 추가 입력으로 전달하며 새 입력 규격이나 학습된 준수 능력을 주장하지 않는다.
정책 내부의 알려지지 않은 관측은 기존 unknown mask를 유지한다.

`--rm-program`은 기존 goal_queue_v1과 새 goal_spec_v1을 구분해 읽는다. 새 계약은 추가 RM 입력이
켜진 S2/R1 경로에서만 허용한다. 기존 실행과 완료한 배치는 보존한다. 우선순위 변경은 기존 revision
API와 이벤트를 유지하고, 대상/수량/선행 조건의 묵시적 변경은 보상 계산과 정책 실행 전에 거부한다.
pickup은 기존 R1의 단일 목표/저장 월드 규칙을 그대로 따른다. 제작 등 미지원 과업으로 확대하지 않는다.

## 구현·검증 단위

1. 단일 입력 컴파일러, 사람/LLM 공통 요청 schema와 검토용 CLI, 예제 파일.
2. 실제 GoalQueue/정책 바인딩/학습 입력·로그 연결. 기존 경로의 기본 동작 보존.
3. 잘못된 대상/수량/순서/변조/문구 차단, 수량 변경과 임베딩 고정의 분리,
   기존 인벤토리·중복 보상·완료 후 행동·우선순위 변경·대상 전환 회귀 검사.
4. 기존 실제 원본 기록을 새 계약으로 재생해 완료와 수량 입력 일치 확인. 이는 오프라인 검사이며
   새 정책의 실전 성공 표본으로 계산하지 않는다. STOP 유지와 원본 자료 보존 확인.

확인 결과와 사용법은 별도 작업 문서에 기록한다. 원문 연구 명세와 4단계 연구 방향은 유지한다.
