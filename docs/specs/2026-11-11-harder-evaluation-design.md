# 학생을 구분할 수 있는 어려운 평가 — 설계 (2026-11-11)

- 상태: 사용자 방향 결정(11/11). 가림 정답 결과 뒤 "어려운 평가 설계"를 골랐다. main 병합은 계속 보류다.
  **(내 결정)** 표시 값은 사용자가 정하지 않은 것이며 바꿀 수 있다.
- 근거 기록: [가림 정답 결과 §5, §7](../line-of-sight-results-2026-11-10.md).

## 1. 왜

지금 평가(벽 속 눈높이 철광석)에서는 학생들이 이미 만점이다. 최종 seed 두 개에서 approach 학생 16/16, sight 학생 8/8이었다.
교사를 고쳐도 이 평가로는 차이를 잴 수 없다. 학습 블록에서는 press·sight 교사가 뚜렷이 나았지만(누르기, 판자), 그것은 학습한 블록이다.

이번에는 아무것도 학습하지 않는다. 이미 있는 학생들을 처음 보는 조건에서 비교하는 평가만 새로 만든다.

## 2. 평가 조건

두 조건 모두 같은 경기장(fixture v2 + 돌 곡괭이)을 쓰고, 학습에 한 번도 나오지 않은 것을 하나씩 바꾼다.

| 조건 | 대상 | 위치 | 문구 | 성공 아이템 | 돌 곡괭이 파괴 시간 | 무엇을 보나 |
|---|---|---|---|---|---|---|
| **낮은 철광석** | 철광석 (학습 안 함) | 벽 맨 아래 칸(발 높이, 기존보다 1칸 아래) | mine iron ore | iron_ore | 약 23틱 | 학습한 적 없는 높이. 내려다보며 캐야 하고, 걸으면서 캐면 조준선이 위로 밀린다 |
| **책장** | 책장 (학습 안 함) | 기존 눈높이 자리 | mine bookshelf | book | 약 45틱 | 처음 보는 블록, 철광석의 두 배 누르기. 나무 무늬라 경기장의 원목과 헷갈릴 수 있다 |

- **책장 (내 결정).** 1.16에서 GUI가 없고, 돌 곡괭이로 약 45틱에 깨지며, 책 3권이 떨어진다. 책은 경기장의 다른 블록에서 나오지 않는다.
  더 긴 누르기(제작대·상자 75틱)는 우클릭하면 창이 열려 누르기와 무관한 실패가 섞여서 뺐다.
- **낮은 위치 (내 결정).** 높은 위치(머리 위)보다 낮은 위치를 골랐다. 앞선 결과에서 sight 학생은 걸으면서 캐다 조준선이 밀리는 약점이 보였고, 발 높이 대상에서 그 약점이 가장 크게 드러난다.
- 철광석·책장은 어떤 학습 자료에도 없다. 평가 seed는 학습 seed가 아니므로 자료 구축이 거부한다.

## 3. 갈래와 seed

- **갈래 (내 결정):** 공식 STEVE-1, approach 학생(a-final), sight 학생(s-final). press 학생은 sight 교사가 press 정답을 포함하므로 뺐다.
- **seed (지금 정함): 141421, 173205** (둘 다 처음 쓰는 world seed). seed마다 샘플링 41–44, 갈래·조건마다 8회.
  한 seed에만 기대면 경기장 시작 상태가 결과를 좌우한다(공식이 seed 662607에서 7/8, 299792에서 2/8). 그래서 두 seed로 나눈다.
- 게임 수: 조건 2 × 갈래 3 × 8회 = 48회(약 4시간).
- 조정 단계는 없다. 학습하거나 고르는 것이 없으므로 이 평가 전체가 최종 평가다. 한 번 돌리면 두 seed는 쓴 것으로 본다.

## 4. 미리 정하는 판정

조건마다 따로 본다. 성공은 서버 인벤토리, 시간은 성공한 실행의 대상 단계 게임 시간(서버 틱 / 20)이다.

- **천장·바닥 규칙.** 세 갈래가 모두 7/8 이상이면 "이 조건도 천장", 모두 1/8 이하면 "바닥"으로 적고 갈래 비교 주장은 하지 않는다.
- **판정 A — 학생이 공식보다 낫다** (approach, sight 각각). 셋 다 만족해야 한다.
  1. 성공 수가 공식보다 적지 않다.
  2. 채굴 시도 중 파괴로 끝난 비율이 공식의 2배 이상이고 공식보다 높다.
  3. 성공 시간 중앙값이 공식보다 길지 않다(공식 성공이 0이면 통과).
- **판정 B — sight가 approach보다 낫다.** 셋 다 만족해야 한다.
  1. 성공 수가 approach보다 적지 않다.
  2. 파괴 비율이 approach보다 높다.
  3. 성공 시간 중앙값이 공식보다 길지 않다.
- 판정 A·B는 앞선 실험과 같은 함수(`dev_verdict`, `hold_verdict`)로 계산한다.
- 갈래마다 8회라 관찰로 보고한다. 조건 2개 × 판정 3개를 보므로, 하나가 우연히 통과할 수 있다.
- 함께 보고(판정 아님): 근처 멈춤 실행 수, 시도 종료 방식(파괴·뗌·벗어남), 첫 대상 파괴 시점, 캔 거리, 단계별 시간 비율.

## 5. 점검

- 게임 전: 두 조건의 fixture가 바뀐 칸만 바뀌었는지 단위 검사로 확인한다. 책장 문구 임베딩은 기존 방법(공식 prior, seed 31031)으로 만든다.
- 게임 중: 책장 조건의 첫 갈래(sight) 8회가 끝나면 책이 실제로 인벤토리에 들어오는지 본다. 책장이 깨진 실행이 있는데 책을 얻은 실행이 하나도 없으면
  평가를 멈추고 원인을 본다. 개별 실행에서 책을 못 줍는 것은 회수 실패일 수 있어서 실행 하나로 판단하지 않는다.
- 평가 중 교사·규칙은 행동을 보내지 않는다. STOP 이후 새 행동 0, 입력 해제, 소유 PID 정리를 확인한다. 유료 API 0, GitHub 공개 0.
- 배치가 도는 동안 `results/` 전체를 훑는 명령과 실행 폴더로의 `cd`를 하지 않는다.

## 6. 구현

- `scripts/prepare_demo_prompts.py`: 문구 묶음 `eval`("mine bookshelf").
- `configs/multi-block-eval-v1.json`: 평가 전용 블록 목록(책장). 학습 블록 목록과 따로 둔다.
- `scripts/run_reacquire_batch.py`: 모드 `eval4` = (141421, 173205). 평가 모드는 평가 블록 목록만, 다른 모드는 학습 블록 목록만 쓴다.
  `--layout low`는 대상 두 칸을 한 칸 아래로 옮긴다(기본값 `wall`은 지금과 같은 파일).
- `scripts/multi_block_report.py iron --block`: 철광석이 아닌 대상도 같은 표와 판정으로 본다.
- 결과: `results/multi-block-20261108/eval4-low/`, `eval4-bookshelf/`. 실행 스크립트 `launch/eval4.sh`.
