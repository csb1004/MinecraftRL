# 건축(설계도 칸 채우기) 기술 — 설계 (2026-11-14)

- 상태: 사용자 요청(11/13 "블럭으로 다리 잇기, 건축하기, 점프맵하기 등등", 11/14 "계속해줘. 중간에 멈추지 말고 네 판단에 필요하다고 판단되면 해").
  세부는 내가 정했다. **(내 결정)** 표시 값은 사용자가 정하지 않았고 바꿀 수 있다.
- [블록 놓기 설계](2026-11-14-place-block-design.md)의 놓기를 여러 칸에 순서대로 되풀이한다. 브랜치 `build`(`bridge` 위, 워크트리 `../MinecraftRL-build`).
- 블록 놓기·다리 잇기 배치가 끝난 뒤 게임에서 확인한다. 이 기술은 검증 전까지 LLM 계획 vocabulary에 넣지 않는다.

## 1. 과업과 성공

- 블록 놓기와 같은 경기장(풀 바닥, 보이지 않는 벽, 조약돌 32개). 시작 위치 앞 3–4칸, 옆 −1..1칸에 작은 설계도 하나를 둔다. **(내 결정)**
- 설계도 6종(칸은 기준점 기준, 짓는 순서대로):

| 이름 | 칸 | 짓는 순서 |
|---|---|---|
| row3 | 옆으로 3칸(바닥) | 왼쪽부터 |
| line3 | 앞으로 3칸(바닥) | 먼 칸부터(가까운 블록이 먼 바닥을 가리지 않게) |
| pillar2 | 2칸 기둥 | 아래부터 |
| corner3 | L자 3칸(바닥) | 먼 칸부터 |
| stair3 | 뒤 2칸 기둥 + 앞 1칸 | 뒤 아래, 뒤 위, 앞 |
| square4 | 2×2 바닥 | 먼 줄부터 |

- 3칸 기둥은 뺐다. 세 번째 칸을 놓을 면(둘째 블록 윗면, 높이 2)이 눈(1.62)보다 높아서 서서는 보이지 않는다.
- **성공(서버 기준):** 서버 놓기 기록으로 설계도의 모든 칸이 채워짐. 설계도 밖에 놓은 블록은 `wrong`으로 센다. 시간 제한 60초.
- 과업 생성기 seed: 학습 101–112, 개발 201–204, 최종 301–308. world seed는 학습 3개를 번갈아, 개발 130363, 최종 **662607(처음 씀)**. **(내 결정)**

## 2. 단계 (기술 내부 RM)

- 지금 칸 = 짓는 순서에서 아직 채우지 않은 첫 칸(서버 놓기 기록). 지금 칸에 대해 블록 놓기와 같은 단계를 쓴다.

| 단계 | 진입 조건 |
|---|---|
| reach | 눈에서 지금 칸 중심까지 4.0블록 넘음 |
| aim | 닿는 거리 안, 조준한 블록·면으로 놓으면 지금 칸이 아님 |
| place | 조준한 블록·면으로 놓으면 지금 칸에 들어감 |
| done | 모든 칸이 채워짐(서버, 성공) |

- 한 칸이 채워지면 다음 칸으로 넘어가며 단계가 다시 정해진다. 키 입력은 단계가 아니다.

## 3. 교사와 학생 입력

- 교사: 지금 칸에 대해 블록 놓기 교사와 같다(보이는 받침 면 중 가장 가까운 면 중심을 겨누고 use, 너무 가까우면 뒤로).
  놓은 블록은 다음 칸의 받침이 된다.
- 학생 특권 입력(배율 10): 블록 놓기 특징 7개(지금 칸·고른 면 방향) + `left`(남은 칸 / 4).
- 게임 전 대략 점검: 블록 놓기 시뮬레이터를 여러 칸으로 늘려 교사를 흉내 낸다(`scripts/simulate_build_teacher.py`).
  걷기는 놓은 블록에 막히고, 플레이어가 선 칸에는 놓지 못하며, 놓기 간격은 4틱이다.
  과업 324개(무작위 300 + 학습·개발·최종) × 시작 방향 4개 중 **1296/1296** 성공했고 잘못 놓은 블록은 0개였다(중앙값 13결정, 최대 21결정).
  지연·관성은 단순화했으므로 게임 점검을 대신하지 않는다.
- 설계도는 대부분 시작 위치에서 닿는 거리 안에 있다. 그래서 이 과업은 걷기보다 "순서대로 여러 번 조준해 놓기"를 본다.

## 4. 학습과 평가 (게임 전에 정함)

- 문구 후보 "build a small structure". 교사 점검 학습 과업 12개, **10/12 미만이면 학습하지 않는다.**
- DAgger: R0 공식 → c-r1 → R1 → c-final. KL 10, 단계 균형, patience 2, 특징 배율 10.
- **개발 판정:** 개발 과업 4개 × 샘플링 2 = 8판. c-final 성공이 공식보다 많고 4/8 이상. 통과할 때만 최종 과업 8개 × 1판.
- 함께 보고: 채운 칸 수, wrong, 성공 시간 중앙값, 설계도별 성공.
