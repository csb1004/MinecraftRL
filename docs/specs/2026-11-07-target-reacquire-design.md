# 대상 쪽으로 돌아서기 학습 — 설계 (2026-11-07)

- 상태: 사용자 승인(11/7, "우선 돌아서기부터 가르치고, 이거를 탐험으로 확장"). 구현 계획은 `docs/superpowers/plans/`에 따로 쓴다.
  탐험 확장(§10)은 방향만 합의했고 설계는 아직이다.
- 근거: [하위 단계 분해 결과](../skill-stages-replay-2026-11-07.md), [STEVE-1 단독 철광석](../steve1-alone-iron-2026-11-06.md),
  [과업 분해 원칙](../task-decomposition.md), 앞선 증류 [프로토콜](../common-skill-distillation-protocol-2026-10-17.md)·[결과](../common-skill-distillation-validation-2026-10-17.md).
- 사용자 결정(11/7): "그렇게 가르치자" — 손 닿는 거리에서 대상 쪽으로 돌아서는 행동을 학습시키고, 효과를 낭비 시간으로 잰다.

## 1. 왜

사용자가 정한 개선 지표는 실행 시간, 즉 쓸데없는 행동을 얼마나 하느냐다. 기록으로 보면 그 시간이 어디서 새는지 분명하다.

- 돌 곡괭이로 끝낸 철광석 단계(평가 9개, 게임 1,250초): 채굴 2%, 조준 1%, **손 닿는 거리인데 철광석을 보지 않은 시간 37%**.
- 그 37% 동안 시선과 철광석 사이 각도는 90도 이상이 55%, 15도 미만이 2%였다. 철광석을 등지고 있었다.
- STEVE-1 단독 4회도 같은 분포다. 지금 파이프라인이 성공하는 것은 정책이 잘 조준해서가 아니라 곡괭이를 들면 짧은 접촉으로도 블록이 부서지기 때문이다.
- 원목 시간 초과 3개도 같은 모양이다. 손 닿는 거리 62%, 조준 0%였고 그동안 조준선은 방벽(경기장 바깥)에 있었다.
- 고정된 STEVE-1 영상 인코더는 조준선 아래 철광석을 88% 알아본다(CNN probe). 정보는 있는데 정책이 그쪽으로 돌지 않는다고 본다.
  probe는 조준선 아래 블록만 시험했으므로 화면 가장자리나 등 뒤의 대상은 이 근거에 들어 있지 않다.

사용자가 말한 RM 세분화(찾기 → 이동 → 캐기)에서, 이 설계는 "이동이 끝났는데 캐지 못하는" 구간을 별도 단계로 떼어 학습시킨다.

## 2. 목표, 비목표, 실패로 볼 것

**목표**

1. STEVE-1이 대상 블록에 손이 닿는 거리에서 대상 쪽으로 돌아서 조준하도록 **학습**시킨다. 규칙으로 돌리지 않는다.
2. 효과를 철광석 단계의 게임 시간과 "손 닿는데 안 보는 시간" 비율로 잰다. 성공은 서버 인벤토리로만 판정한다.
3. skill 내부 단계를 기록만 하지 않고 학습 입력과 실행 입력에 실제로 연결한다([과업 분해](../task-decomposition.md) 단계 계약 4항).

**비목표 (이번 범위 밖)**

- 원목·돌 단계. 같은 방법을 철광석에서 확인한 뒤 원목에 적용한다(§10). **(내 결정)**
- 영상 인코더(CNN) 학습. 1차는 고정한다.
- 돌을 발밑으로 파는 습관. 이는 RL 시간 벌점으로 다룰 문제다.
- SQL/온톨로지 지식, LLM 감시 명세, M3 실시간 감시 비교.
- 파이프라인 기본 정책 교체. 후보 저장은 채택이 아니다.

**실패로 볼 것 (기술적으로 돌아가도)**

- 평가 실행 중 교사나 규칙이 행동을 보내는 것. 교사는 학습 자료의 정답만 만든다.
- 평균 시간이 줄었는데 성공률이 떨어진 것을 개선이라고 부르는 것.
- 개발(130363)·평가(104729) 기록이나 최종 평가 seed를 학습에 쓰는 것.
- 특권 단계 입력을 쓴 결과를 영상만으로 한 결과라고 부르는 것.

## 3. 새 하위 단계: 돌아서기

[stage_replay](../../src/minecraftrl/pipeline/stage_replay.py)의 단계 정의(먼 곳·다가감·손 닿는 곳·조준·채굴·회수·gui)를 그대로 쓴다.
그중 **손 닿는 곳이면서 조준·채굴이 아닌 행**을 "돌아서기" 단계로 부른다. 이름만 붙이는 것이고 판정은 바꾸지 않는다.

| 계약 항목 | 내용 |
|---|---|
| 진입 증거 | 서버 좌표·yaw·pitch, fixture에서 계산한 대상 블록 위치, 서버 파괴 기록. **모두 특권 관측**이다 |
| 완료 | 서버 조준 블록이 대상 계열이 됨(→ 조준 단계). 블록 획득은 서버 인벤토리로만 인정 |
| 소실·복귀 | 남은 대상이 4.5블록 밖이면 다가감/먼 곳으로 돌아간다. 대상이 모두 부서지면 단계 없음 |
| 시간 초과 | probe 단계 제한(제어 180초)을 따른다. 단계별 시간 제한은 두지 않는다 |
| 정책 입력 | 단계 one-hot을 학생의 residual 입력으로 학습·실행 모두에 넣는다(§5) |
| 보상 | 이번에는 BC라 보상이 없다. 성공, 단계별 게임 시간을 따로 기록한다 |
| 중단 | 기존 STOP 계약을 그대로 따른다 |
| 검증 | 실시간 단계 판정과 기록 재생 판정이 같은 기록에서 같은 답을 내는지 시험한다 |

실시간 판정은 재생 판정과 **같은 함수**를 써야 한다. 판정이 두 벌로 갈라지면 학습 입력과 측정이 서로 다른 것을 보게 된다.

## 4. 교사 (학습 자료 전용, 특권)

교사는 실행 중에 행동하지 않는다. **기록된 행에서 나중에(offline) 정답을 계산한다.** 그래서 DAgger 수집도 실행은 학생이 하고 정답은 나중에 붙인다.

- 정답을 붙이는 행: 돌아서기·조준·채굴 단계의 정책 행. 나머지 행은 정답 없이 원래 정책 유지(§6의 KL)에만 쓴다.
- 대상: 조준선이 이미 대상 블록 위에 있으면 그 블록, 아니면 눈(서버 y + 1.62)에서 가장 가까운, 아직 부서지지 않은 대상 블록.
  겨냥점은 블록 중심이다. 좌표 규약은 `stage_replay.view_angle`과 같다.
- 시선 정답: 그 중심을 향하는 (pitch, yaw) 차이를 한 스텝 최대 ±10도로 자르고, 공식 VPT 행동 변환기로 같은 camera 칸에 넣는다.
  공식 mapper의 camera meta 처리도 앞선 BC 코드(`bc_core`, `navigation_marginal_bc`)와 같게 한다.
- 버튼 정답: 조준선이 대상 계열이면 attack=1, 아니면 0. 이동 키·점프·기타는 0. 손 닿는 거리 안이므로 걷지 않는다.
- 대상이 화면 밖(등 뒤)일 때: 짧은 쪽으로 돈다. **(내 결정)** 학생은 화면만 보므로 방향을 알 수 없는 경우가 있다.
  기억(transformer)이 방향을 담는지 보려고, 진단에서 화면 안/밖 행의 정답 일치율을 나눠 기록한다.
- 정답은 정책이 그 행동을 고를 때 본 상태(직전 관측)에 맞춰 붙인다.

## 5. 학생

- 공식 STEVE-1(영상 인코더, transformer, 행동 head 모두 고정) 위에 **0으로 초기화한 작은 residual**을 하나 얹는다.
  입력은 행동 head 직전의 정책 잠재 벡터와 단계 one-hot이고, 출력은 그 잠재 벡터에 더한다.
  기존 `ConditionedHead`의 nonlinear 구조(폭 64, 마지막 층 0 초기화)와 같은 모양이다. **(내 결정)**
- 학습 직후가 아니라 **학습 전**에는 공식 STEVE-1과 출력이 같아야 한다(출력 차이 0 검사).
- STEVE-1은 실행 때 조건 있는 계산과 조건 없는 계산을 한 번씩 하고 `(1 + s)·조건 - s·무조건`으로 행동 분포를 섞는다
  (`embed_conditioned_policy.py`, cond_scale). residual은 **두 계산 모두에** 같은 단계 입력으로 더한다.
  BC와 KL은 실제로 샘플한 섞인 분포에 건다. 그래서 기록에는 두 계산의 잠재 벡터를 모두 남긴다. **(내 결정)**
- 두 갈래를 만든다:
  - **단계 입력 있음**: 실행 중에도 fixture 좌표로 단계를 계산해 넣는다(특권, 보고에 밝힘).
  - **단계 입력 없음**: 단계 칸을 0으로 둔다. 영상과 기억만으로 돌아서는지 본다. 일반 지형으로 가져갈 수 있는 쪽은 이것이다.
- 학습하는 것은 residual뿐이다. 기존 skill(`mine_iron_text`)의 프롬프트·cond_scale은 바꾸지 않는다.
- 파이프라인 설정에서 고를 수 있는 새 skill 변형으로 넣고, 기본값은 바꾸지 않는다.

## 6. 자료와 학습

**수집 장면.** 이미 있는 철광석 probe를 쓴다: fixture v2의 개발 probe 변형(돌 곡괭이 지급), 계획은 철광석 한 단계, 제어 180초,
감시(oversight) 없음. 이 장면에서는 규칙 행동(시선 수평 맞추기, 돌아서기 재시도)이 일어나지 않는다. 곡괭이 지급은 준비 단계이며 정책 성공으로 세지 않는다.

**seed.** 새 world seed 3개를 학습 전용으로 계획서에서 고정한다. 개발 130363은 후보 비교에만, 최종 평가는 아직 쓰지 않은 새 seed에서 한다.
104729는 이미 분석에 썼으므로 최종 평가에 쓰지 않는다. **(내 결정)**

**DAgger 3라운드. (내 결정)**

| 라운드 | 실행 정책 | 실행 수 |
|---|---|---|
| 0 | 공식 STEVE-1 | 6 |
| 1 | 라운드 0 자료로 학습한 학생(단계 입력 있음) | 6 |
| 2 | 라운드 0–1 자료로 학습한 학생 | 6 |

- 단계 입력 없는 학생은 같은 누적 자료로 따로 학습한다. 방문 상태가 조금 다를 수 있다는 점을 보고에 밝힌다.
- 실행 하나에 정답 행이 수백 개 나올 것으로 본다(앞선 probe가 1,200–2,000스텝, 손 닿는 곳 비율이 약 40%).
- 기록: 정책 스텝마다 고정 정책 잠재 벡터(fp16), 단계, 실제 보낸 행동, 샘플링 정보를 남긴다. 그래야 화면을 다시 돌리지 않고 정답을 붙여 학습할 수 있다.
  영상용 프레임은 지금처럼 따로 저장한다.

**학습.** 정답 행에는 BC(공식 행동 head의 NLL), 정답 없는 행에는 공식 정책과의 KL을 건다.
시작값은 앞선 증류에서 효과가 있던 값: lr 1e-4, 평균 KL 한도 3, 최대 16 epoch, KL 계수 0.01, gradient clip 1, 한도를 넘은 epoch는 되돌림. **(내 결정)**
학습 실행 1개를 떼어 내부 검증 NLL을 본다. 게임 전 검사: 학습 전 출력 차이 0, 저장/재로드 차이 0, 떼어 둔 실행의 정답 NLL 감소.

## 7. 평가

**개발 비교(후보 고르기).** seed 130363의 철광석 probe에서 공식 / 학생(단계 있음) / 학생(단계 없음)을 같은 샘플링 seed로 4회씩 짝지어 돌린다.

**최종 평가.** 새 seed에서 세 갈래 각 8회. **(내 결정)** 단계 없는 학생이 개발 비교에서 공식보다 나쁘면 최종 평가는 두 갈래로 줄인다.

**잴 것**

- 주 지표: 성공 수(서버 철광석 +1, 제어 180초 안)와 철광석 단계 게임 초(성공한 실행). 실패 실행은 따로 센다.
- 단계 지표(`stage_replay`): 돌아서기 비율, 시선 각도 분포, 조준·채굴 비율, 먼 곳·다가감 시간.
- 부작용: 먼 곳·다가감 시간이 늘지 않았는지. residual이 이동까지 망치지 않았는지 본다.

**미리 정하는 판정. (내 결정)** 학생이 "나아졌다"고 쓰려면 셋 다 만족해야 한다.

1. 성공 수가 공식보다 적지 않다.
2. 돌아서기 비율이 공식의 절반 이하다. 비율은 그 갈래의 모든 실행(성공·실패)의 철광석 단계 게임 시간을 합쳐서 계산한다.
3. 성공한 실행의 단계 시간 중앙값이 공식보다 짧다.

하나라도 안 되면 개선이라고 쓰지 않고 상태별 정답 확률·행동·위치로 분석한다. 표본이 작으므로 성공률이 아니라 관찰로 보고한다.

## 9. 위험

- **등 뒤 대상.** 화면만 보는 학생은 돌 방향을 모를 수 있다. 그러면 한쪽으로 돌기만 배울 수 있다. 진단에서 화면 안/밖을 나눠 본다.
- **경기장 하나.** 모든 자료가 같은 fixture 배치다. 결과는 이 경기장에 대한 것이다.
- **얻을 수 있는 몫에 상한이 있다.** 돌아서기를 0으로 줄여도 줄어드는 것은 37%다. 먼 곳(44%)은 그대로다.
- **특권 단계 입력은 fixture 밖에서는 없다.** 그래서 단계 없는 갈래를 함께 본다. 영상으로 단계를 판정하는 방법은 다음 일이다(§10).

## 10. 이후 (이번 범위 밖)

- **탐험으로 확장(사용자 방향, 11/7).** 사용자 말: "목표를 찾는다는 게 사실 돌아서는 것만으로 되는 게 아니니까, 주변을 돌아보기도,
  돌아다녀 보기도 해야 된다. 근데 또 같은 곳만 돌아다녀도 안 된다." 철광석 단계 시간의 44%(먼 곳)와 평가 실패 대부분(탐색 시간 초과)이 여기다.
  설계 전에 정할 것(아직 미정):
  - 탐험 교사는 대상 좌표를 쓰면 안 된다. 쓰면 그냥 대상으로 가 버려서 학생이 따라 할 수 없다. 지금까지 간 곳과 본 방향만 쓰는 교사여야 한다.
    이미 있는 부품: `exploration_route.ExplorationRoute`(간 칸 기록으로 새 목적지 제안, 자원 좌표 없음),
    `StallDetector`의 '새 칸'·'새 시야' 진행 신호와 반복 순환 감지.
  - 지금 경기장(11×12, 투명 벽)은 돌아다닐 공간이 거의 없다. 탐험을 배우고 잴 더 넓은 장소가 필요하다.
  - 이번 학생 구조(단계 입력 residual)에 '먼 곳' 단계 정답을 더하는 식으로 이어 붙일 수 있게 1단계를 만든다.
- 원목: 같은 교사·학생 구조로 적용한다. 원목 시간 초과(손 닿는 곳 62%, 조준 0%)를 직접 겨냥한다.
- 영상으로 단계 판정: CNN probe를 넓혀 "대상이 보인다/가운데 있다"를 영상에서 예측하고, 특권 단계 입력을 대체한다. CNN 공동 학습 논의와 이어진다.
- 시간 벌점 RL: 돌을 발밑으로 파는 습관처럼 위치에 묶인 낭비는 SQL이 아니라 보상으로 다룬다.
- 감시기 연결: 감시 신호가 낭비 구간을 표시하면, 그 구간을 다음 교정 자료로 자동 선별한다.

## 11. 구현자에게 맡기는 것

- residual을 붙이는 정확한 지점과 코드 위치(정책 잠재 벡터를 꺼내는 방법).
- 실시간 단계 판정을 `stage_replay`와 공유하는 방식.
- 잠재 벡터 기록 형식과 파일 배치.
- 학습 전용 seed 3개와 샘플링 seed 값(계획서에서 고정).
