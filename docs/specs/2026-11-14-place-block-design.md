# 블록 놓기 기초 기술 — 설계 (2026-11-14)

- 상태: 사용자 요청(11/13 "블럭으로 다리 잇기, 건축하기…", 11/14 "계속해줘. 중간에 멈추지 말고 네 판단에 필요하다고 판단되면 해").
  세부는 내가 정했다(**(내 결정)**). [블록 놓기 → 다리 잇기 → 건축 계획](2026-11-13-block-placing-plan.md) §1을 구체화한다.
- 이 기술은 구현과 검증이 끝나기 전까지 LLM 계획 vocabulary에 넣지 않는다.
- 브랜치 `block-place`(워크트리 `../MinecraftRL-place`). 점프·채굴 배치가 주 작업 폴더에서 게임을 쓰는 동안 여기서 만들고, 배치가 끝난 뒤 게임에서 확인한다.

## 1. 관측 (만듦, 3dcd24e)

- 실행 설정에 `place_monitor: true`가 있으면 데모 jar가 서버에서 놓인 블록을 모두 센다(`BlockItem.tryPlace`).
  기록 행의 `place`에 `place_count`, `place_last_tick`, `place_last_block`, `place_last_x/y/z`가 들어간다.
- 플래그가 없으면 jar 해시가 이전 데모 jar와 같다. 채굴·점프 실험은 바뀌지 않는다.
- 조준 블록과 면은 이미 workshop 기록(`hit_x/y/z`, `hit_face`: 아래 0, 위 1, 북 2, 남 3, 서 4, 동 5)에 있다.

## 2. 과업과 성공

- **과업:** 손에 든 블록(조약돌 32개, fixture가 줌)을 정해진 칸 하나에 놓는다. 그 칸은 받침 블록 하나 이상과 면이 닿아 있다.
- **성공(서버 기준):** 서버 놓기 기록에서 놓인 칸이 목표 칸과 같다. 다른 칸에 놓으면 `wrong` 하나로 세고 계속한다.
  시간 제한 45초. 화면 판정은 쓰지 않는다.
- 목표 칸은 시작 자세 기준으로 무작위로 뽑는다(학습·개발·최종 생성기 seed 분리). **(내 결정)**
  - 거리: 앞으로 2–5칸, 옆 −2..2칸.
  - 높이: 발 높이(dy 0, 바닥 위) 또는 한 칸 위(dy 1, 받침 기둥 옆면이나 윗면).
  - 받침: dy 0이면 아래 바닥, dy 1이면 목표 칸 아래·뒤·바깥쪽 옆의 석재 벽돌 한 개.
    처음에는 안쪽 옆(시작 열과 목표 사이)도 허용했다. 하지만 그 받침의 유일한 면은 시작 위치에서 보이지 않았다(게임 전 점검, 42개 목표). 그래서 뺐다.
- **게임 전 대략 점검(게임 아님):** 직선 걷기, 결정마다 축별 10도 회전, 4.5블록 복셀 조준선으로 교사를 흉내 냈다.
  목표 324개(무작위 300 + 학습·개발·최종) × 시작 방향 4개 중 1296/1296 성공했고, 잘못 놓은 블록은 0개였다(중앙값 5결정, 최대 10결정).
  지연, 관성, 충돌은 단순화했으므로 게임 점검을 대신하지 않는다.
- 둘레는 보이지 않는 벽이다. 목표 칸 표시는 하지 않는다. 학생은 특권 입력(목표 방향)으로 목표를 안다. 이 점은 기록에 밝힌다.

## 3. 단계(기술 내부 RM)

| 단계 | 진입 조건(증거: 클라이언트 자세, 조준, 특권 목표) |
|---|---|
| reach | 눈에서 목표 칸 중심까지 4.0블록 넘음 |
| aim | 닿는 거리 안, 조준한 블록·면으로 놓으면 목표 칸이 아님 |
| place | 조준한 블록·면으로 놓으면 목표 칸에 들어감 |
| done | 서버 놓기 기록이 목표 칸(성공, 끝) |

- 키 입력(use)은 단계가 아니다. 목표 칸이 채워져야 done이다.
- 단계는 헤드 one-hot(4칸)과 기록에 실제로 들어간다. 채굴·점프 체크포인트와 섞이지 않는다.

## 4. 교사(특권, 정답 라벨 전용)

- reach: 목표 칸 쪽으로 시선(축마다 최대 10도) + 앞으로.
- aim: 놓을 면을 고른다. 목표 칸에 닿은 받침 면 중에서, 눈에서 보이고 가장 가까운 면이다. 그 면의 중심을 겨눈다. 너무 가까우면(2블록 이내) 뒤로 물러선다.
- place: 시선 유지 + use.
- 특징 입력(점프 v2와 같은 방식, 배율 10): 목표 칸 중심 방향 sin·cos(yaw), pitch/60, 거리/6, 고른 면 중심 방향 sin·cos(yaw), pitch/60.

## 5. 학습과 평가

- 정책: 고정 STEVE-1 + 단계·특징 입력 잔차 헤드. 문구 후보 "place a block". 문구 임베딩은 배치 첫 단계에서 만든다.
- 교사 점검(준비용, 정책 성공 아님): 학습 목표 12개. 10/12 미만이면 학습하지 않고 교사부터 고친다.
- DAgger: R0 공식 → p-r1 → R1 → p-final(R0–R1). 라운드마다 학습 목표 12판. **(내 결정)**
- **개발 판정(미리 정함):** 개발 목표 4개 × 샘플링 2 = 8판. p-final 성공이 공식보다 많고 4/8 이상.
  통과할 때만 최종 목표 8개 × 1판(공식, p-final)으로 같은 기준을 본다.
- world seed: 학습 3개를 번갈아, 개발 130363, 최종 **357913(처음 씀)**.

## 6. 그다음

다리 잇기(뛰어 건널 수 없는 틈에 블록을 이어 놓기)는 이 기술과 점프 코스의 이동을 합친다. 건축(설계도 칸 채우기)은 여러 칸을 순서대로 놓는다. 둘 다 이 설계의 검증 뒤에 따로 설계한다.
