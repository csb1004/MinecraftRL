## 0. 요약

- **틀(사용자 결정):**
  - RL 헤드는 카테고리마다 둔다.
  - RM 단계마다 그 단계의 카테고리 헤드를 쓴다. 연속한 단계의 카테고리가 같으면 헤드를 그대로 둔다(3판).
  - 실행 중에도 헤드를 갱신한다.
  - 감시로 RM 보상 악용을 잡는다.
- **탐색은 자리만 둔다(3판, 팀원 담당).**
  - 채굴 같은 RM 단계는 "탐색 → 채굴" 두 단계로 나누고, 그 경계에서 헤드를 바꾼다.
  - 탐색 헤드를 어떻게 학습할지는 팀원이 정한다. 그 전까지 탐색 자리에서는 0 초기화 헤드, 즉 공식 STEVE-1이 돈다.
- **인식 모듈 없이 간다.** 실행할 때 정책(actor)은 화면과 정당한 정보만 본다.
  - 정당한 정보의 범위는 §6.1 센서 등급 제안(D7)을 따른다. 몸에 단 센서로 잴 수 있는 값은 actor가 보고, 센서로 잴 수 없는 값(오라클)은 보지 않는다.
  - 오라클 정보는 학습할 때 가치 함수(critic) 입력으로만 쓴다(11-19 사용자 결정). 이 방식을 비대칭 actor-critic이라 한다. 보상과 교사에는 쓰지 않는다.
  - 지금 잘하는 특권 헤드(채굴 v3, 놓기, 건축, 다리, 점프)의 결과는 "특권 조건"으로 남긴다. 교사로 쓰지 않고, 센서 값만 읽는 규칙 교사로 다시 학습한다([센서 등급 설계](2026-11-19-sensor-tier-observation-design.md) §5).
- **최적화 방법:**
  - 기본은 최고 기록 모방(자기 모방 학습)과 STEVE-1 방식의 사후 재라벨링이다.
  - 그 위에 LLM 지식을 세 군데 쓴다. 하위 목표를 세분화하고, 그 판정식으로 조밀한 보상을 만들고, 실패 궤적을 분석한다.
  - 판정식은 LLM이 쓰고 자동 검사가 거른다(Auto MC-Reward 방식). 사람이 손으로 짜지 않는다.
  - 마지막에 PPO로 다듬는다.
- **지식과 CLIP의 상승 효과:**
  - 세분화한 하위 목표 하나를 세 곳에 함께 쓴다.
    - 정책 조건: MineCLIP 문장 임베딩과 헤드 단계 입력.
    - 보상·판정: 서버로 확인되는 판정식, 또는 MineCLIP 진척.
    - 학습 표적: 자기 모방과 재라벨링.
  - 문장만 바꾸는 것으로는 지난 실험에서 개선이 없었다(§1). 그래서 세 곳을 함께 묶어야 한다.
- **장비:**
  - 지금 GPU로도 고정 STEVE-1 위 헤드의 실행 중 갱신은 할 수 있다.
  - 5070 Ti(16GB)가 있으면 STEVE-1 일부(LoRA)를 학습할 수 있다. 정밀 기술을 화면만으로 배우려면 이 단계가 필요할 가능성이 크다.
  - 다만 Minecraft 시뮬레이션 속도는 GPU가 아니라 CPU와 RAM이 정한다. 그리고 PyTorch를 2.0.1에서 2.7 이상으로 올려야 한다.
- **핵심 원칙:**
  - 보상은 서버가 확인한 상태 변화나, 자동 검사를 통과한 판정식에서만 나온다.
  - 최종 성공 기준은 호출자(RM)가 가진다. 판정식은 그것을 바꿀 수 없다.
  - 감시 결과는 보상에 넣지 않고 관문으로만 쓴다.
  - 실행 중 학습한 판은 평가가 아니다.
- **설계로 답할 수 없는 위험:**
  - R1 실전 경험으로 최적화가 실제로 일어나는가.
  - R2 고정 STEVE-1 latent 위 헤드만으로 대상을 찾고 맞출 수 있는가.
    - D7을 승인하면 R2가 줄어든다. 시야 안·범위 안 대상의 방향과 거리는 센서로 받는다.
    - 남는 것은 어느 센서에도 잡히지 않는 대상을 찾는 일이고, 이것은 탐색(팀원)이다.
  - 둘 다 §7 단계별 통과 조건으로 확인하고, 실패하면 정해 둔 다음 사다리로 간다.

## 2. 조사: 쓸 만한 방법

| 방법 | 핵심 | 여기서 쓰는 곳 | 주의할 점 |
|---|---|---|---|
| 자기 모방 학습(SIL, [Oh 외 2018](https://arxiv.org/abs/1806.05635)) | 드물게 얻은 좋은 경험을 저장해 다시 따라 배운다. 보상이 드물 때 효과가 크다 | 최고 기록 모방(사용자 제안)의 정식 형태. 버전이 섞인 자료도 쓸 수 있다 | 운 좋은 성공을 따라 배울 수 있다. 판정은 서버로 한다 |
| 사후 재라벨링(STEVE-1, [Lifshitz 외 2023](https://arxiv.org/abs/2306.00937)) | 궤적 뒤쪽 프레임의 MineCLIP 임베딩을 목표로 붙여 BC한다 | 실패한 판도 "실제로 한 일"을 목표로 한 예시가 된다. STEVE-1이 원래 배운 방식이라 조건 입력이 그대로 맞는다 | 프레임을 저장해야 한다 |
| LLM 조밀 보상 설계(Auto MC-Reward, [Li 외 CVPR 2024](https://arxiv.org/abs/2312.09238)) | LLM이 정해진 관측 위의 보상 함수를 쓰고, 비평 LLM이 검사하고, 궤적 분석 LLM이 실패 원인으로 고친다. 다이아몬드 성공 36.5%를 보고했다 | 지식 → 하위 단계 판정식 → 조밀 보상. 우리는 LOGO 판별식 틀 안에서만 쓴다. 보상 함수는 RL 학습 전에 만들고 학습 회차 사이에 고친다 | 보상 악용 위험이 그대로 남는다. 자동 검사와 감시가 필요하다 |
| 기술 RL + LLM 기술 그래프(Plan4MC, [Yuan 외 2023](https://arxiv.org/abs/2303.16563)) | 탐색·조작·제작 기술을 RL로 따로 배운다. 탐색 기술은 돌아다닌 넓이를 보상으로 받는다. LLM은 실행 전에 기술 의존 그래프만 만든다 | 탐색 보상의 참고 자료(팀원에게 넘김). "LLM은 계획 쪽, 실행은 RL 기술" 구조가 우리와 같다 | 탐색 보상이 넓이뿐이면 대상과 무관하게 돌아다니기만 한다 |
| MineCLIP 보상(MineDojo, [Fan 외 2022](https://arxiv.org/abs/2206.08853)) | 최근 16프레임과 문장의 유사도를 보상으로 쓴다. MineDojo도 자기 모방과 함께 썼다 | 판정식이 없는 시각 목표(예: "나무가 보인다")의 진척 신호 | 1.5억 파라미터라 무겁다. 손으로 만든 보상보다 낮은 과업이 있다(소 젖 짜기 64.5% 대 83.5%). 대상까지 거리에 둔감하다는 보고가 있다([CLIP4MC](https://arxiv.org/abs/2303.10571) 등) |
| LLM 목표 제안(ELLM, [Du 외 ICML 2023](https://proceedings.mlr.press/v202/du23f.html)) | LLM이 현재 상태 설명을 보고 할 만한 목표를 제안하고, 달성하면 보상을 준다 | 연습 월드의 과제 순서(커리큘럼) | 실행 중 LLM 호출 비용과 지연이 든다. 연습 쪽에만 쓴다 |
| 비대칭 actor-critic([Pinto 외 2017](https://arxiv.org/abs/1710.06542)) | critic은 학습 때 전체 상태를 보고, actor는 화면만 본다. 배포 때는 화면만 쓴다 | 인식 모듈 없이 특권 정보를 학습에만 쓰는 방법 | critic만 똑똑해도 actor 표현이 부족하면 못 배운다(R2) |
| 처음부터 RL(DreamerV3, [Hafner 외](https://danijar.com/project/dreamerv3/)) | 사람 자료 없이 다이아몬드까지 갔다. 첫 다이아몬드에 약 3,000만 환경 스텝, V100 한 장으로 약 17일 | 규모 감 잡기용 | 우리는 처음부터가 아니라 STEVE-1에서 출발하고, 기술 단위로 배운다 |

- 정리:
  - 표본이 적은 실전에는 자기 모방과 재라벨링이 맞다.
  - LLM 지식이 가장 크게 기여할 곳은 보상과 판정의 밀도다(Auto MC-Reward, Plan4MC). 정책에 문장을 더 주는 것만으로는 부족하다.
  - 인식 모듈 없이 특권을 쓰는 표준 방법은 비대칭 actor-critic과 교사-학생 증류다.

## 3. 검토: 부족한 점(1판 G1–G26 + 2판 추가)

빈틈마다 대응하는 절을 적었다.

### 3.1 계획대로 행동할까

- **G1 단계 신호가 특권이다.** 대응: §4.4 정당한 근거로 단계 판정, 'unknown' 단계.
- **G2 한 판에 헤드가 하나다.** 대응: §4.1 헤드 레지스트리와 RM 단계마다 교체(필수, L0).
- **G3 단계 완료 보상만 보면 계획 밖 수단을 배운다.** 예: 제작용 재료(`Plan.keep`)를 발판으로 쓰기, 보호 블록 캐기. 대응: §4.4, §4.6.
- **G4 계획 준수 지표가 없다.** 대응: §4.4.
- **G5 실전 시작 상태가 학습 때와 다르다.** 대응: §4.1 실전 자격 관문과 대체 실행.
- **G27 (2판) 탐색→채굴 경계를 특권 없이 판정해야 한다.** 대응: §4.4 경계 판정, §9 D5.
- **G33 (3판) 같은 카테고리 단계가 이어질 때 헤드를 다시 올리면 낭비이고, 기록에서 교체와 유지가 구분되지 않는다.** 대응: §4.1 유지 규칙과 `head_kept`/`head_swapped` 기록.

### 3.2 RL 최적화가 일어날까

- **G6 헤드에 보상으로 배우는 경로가 없다.** 대응: §4.3.
- **G7 실전 경험이 적다.** 대응: §4.3 자기 모방·재라벨링 우선, 연습 월드, §7 L2.
- **G8 행동 확률을 기록하지 않고, 도구 고정이 행동을 바꾼다.** 대응: §4.2 기록 보강.
- **G9 버전이 섞인 자료를 쓰게 된다.** 대응: §4.2, §4.3 자료 사용 규칙.
- **G10 보상이 드물고 늦다.** 대응: §4.3 지식 판정식으로 조밀 보상.
- **G11 이전 능력을 잊을 수 있다.** 대응: §4.3 보존.
- **G12 계산이 게임을 방해할 수 있다.** 대응: §4.2 자원 예산, §6.
- **G28 (2판) MineCLIP 보상은 잡음이 있고 거리에 둔감하며 악용될 수 있다.** 예: 멀리서 대상만 바라보기. 대응: 판정식이 있으면 판정식을 먼저 쓰고, MineCLIP은 탐색 진척에만 쓴다. 악용 검사도 붙인다(§4.6).

### 3.3 카테고리별로 잘 묶일까

- **G13 묶는 기준이 없다.** 대응: §4.1 카테고리 규칙.
- **G14 카테고리가 겹친다.** 건축 p5 안의 치우기, 다리 안의 놓기가 그렇다. 대응: §4.1 겹침 규칙(D1).
- **G15 탐색 카테고리가 없다.** 대응: §4.1 탐색 자리와 인터페이스. 학습 방법은 팀원이 맡는다(사용자 결정, 3판).
- **G16 공식 프롬프트 기술에는 갱신할 헤드가 없다.** 대응: §4.1 0 초기화 헤드.
- **G17 대상이 여럿이다.** 대응: §4.1 대상 조건 입력.
- **G18 특징 꼴이 카테고리마다 고정이다.** 2판 대응: actor 입력에서 특권 특징을 없앤다. 특징은 학습 신호(critic, 보상, 교사)에만 쓴다(§6). 3판: D7을 승인하면 센서 등급 특징은 actor에 남기고 오라클 특징만 뺀다(§6.1). 11-19: 오라클 특징은 critic에만 쓴다.

### 3.4 LLM 지식이 잘 반영될까

- **G19 지식이 계획·가드에만 닿는다.** 대응: §4.5 하위 목표를 세 곳에 함께 쓰기.
- **G20 틀린 지식이 학습 자료를 오염시킬 수 있다.** 대응: §4.5 KB revision 표기와 제외 규칙.
- **G21 개선이 지식 덕인지 RL 덕인지 구분되지 않는다.** 대응: §5 비교 조건.
- **G22 LLM이 보상·성공 기준을 바꾸면 감시가 무력해진다.** 3판 대응:
  - 최종 성공 기준은 호출자(RM)가 가지고, 판정식은 그것을 바꿀 수 없다(LOGO 규칙).
  - LLM 판정식은 자동 검사를 통과해야 보상에 쓴다(§4.3).
  - 같은 판정식이 악용 판정을 두 번 받으면 끄고 사람에게 보고한다(§4.6).
- **G29 (2판) 문장 세분화만으로는 개선이 없었다(P2 3/5 대 공식 4/5).** STEVE-1은 시각적인 "무엇"은 알아듣지만, "얼마나 오래 누르기" 같은 "어떻게"는 문장으로 잘 전해지지 않는다. 대응: §4.5 "무엇"은 CLIP 조건으로, "어떻게·끝났는지"는 판정식 보상으로 나눈다.

### 3.5 보상 악용 감시 자체

- **G23 알려진 패턴만 잡는다.** 대응: §4.6 보상 대 실제 지표 비교, 고정 버전 정기 평가, 사람이 보는 사례 표본.
- **G24 감시를 벌점으로 쓰면 감시 회피를 배운다.** 대응: 관문으로만 쓴다.
- **G25 감시 기준이 헤드 버전에 따라 흔들린다.** 대응: 기준은 고정 평가에서만 갱신한다.
- **G26 감시가 서버 기록(특권)을 쓴다.** 정책 입력이 아니라 심판이므로 허용하고, 보고에 밝힌다.

### 3.6 장비와 순수 RL (2판)

- **G30 고정 latent 위 헤드만으로는 화면 밖 대상의 방향을 못 담을 수 있다(§1 근거).** 대응: §6 사다리. 고정 헤드로 먼저 시험하고, 안 되면 LoRA, 그래도 안 되면 그때 작은 인식 부품을 다시 검토한다.
- **G31 Minecraft 시뮬레이션 속도는 GPU가 아니라 CPU·RAM이 정한다.** 대응: §6 처리량 계산과 측정.
- **G32 5070 Ti에는 PyTorch 2.7 이상 + CUDA 12.8이 필요하다.** 지금 환경은 2.0.1이다. 또 PyTorch 2.8 이상의 CUDA 12.8 빌드는 1060(Pascal) 지원을 뺐다는 보고가 있다. 대응: §6 새 환경과 동등성 검사.
- **G34 (3판) 센서와 오라클의 경계가 모호하면 오라클 정보가 actor로 샌다.** 예: fixture 좌표로 바로 계산한 대상 방향. 대응: §6.1 등급표와 L0 특징 감사.
- **G35 (3판) 잡음 없는 센서는 심사에서 비현실적이라는 지적을 받는다.** Habitat 2020이 같은 이유로 GPS+나침반을 뺐다. 대응: §6.1 센서 한계(범위·가림·지연)와 잡음 강건성 조건.

### 3.7 결론

- 사용자 틀에 2판 대응을 더하면 설계로는 충분하다고 본다.
- 남는 위험 R1(최적화가 일어나는가)과 R2(화면만으로 되는가)는 실험으로만 답할 수 있다. §7에서 순서대로 확인하고, 실패하면 정해 둔 사다리로 간다.

## 4. 구조

### 4.1 RL 헤드 카테고리와 교체

- **카테고리 규칙 (내 결정):** 한 RL 헤드 카테고리는 성공 증거의 종류와 행동 꼴이 같은 기술의 묶음이다.

| 카테고리 | 성공 증거(심판) | 기술 내부 단계 | 지금 있는 것 | 조건 입력 |
|---|---|---|---|---|
| 탐색 | 대상 블록이 조준선에 있고 손 닿는 거리 안(F3에 보이는 조준 블록) | 팀원이 정함 | 자리만 있음. 그 전까지 0 초기화 헤드(공식 STEVE-1) | 대상 종류(MineCLIP 문장 + 대상 id) |
| 채굴 | 대상 블록의 서버 파괴 기록 + 해당 아이템 증가 | 조준→채굴→회수 | 채굴 v3(특권, 11-19부터 참고 조건 R). 원목·조약돌·철광석은 공식 프롬프트 | 대상 종류 |
| 놓기·건축 | 서버 설치 기록이 설계도 칸과 일치, 설계도 밖 블록 0 | 이동→조준→놓기(→치우기) | 놓기, c4-final, p5-final(특권, 11-19부터 참고 조건 R) | 설계도 |
| 이동 | 목표 지점 도달(서버 위치), 떨어짐 0 | 진행→가장자리→점프 또는 놓기 | 점프 v2, 다리(특권, 11-19부터 참고 조건 R) | 목표 지점 |
| 규칙 기술 | 인벤토리 | 규칙 스크립트 | 제작, 장착, 천장 치우기 | 학습 대상 아님(범위 밖) |

- **RM 단계마다 헤드 확인 (사용자 결정, 필수. 3판에서 유지 규칙 추가):**
  - 플래너의 채굴 단계는 "탐색(대상) → 채굴(대상)" 두 RM 단계로 나눈다.
  - 대상을 놓치면 채굴에서 탐색으로 되돌아간다.
  - RM 단계 경계마다 새 단계의 카테고리를 본다.
    - 카테고리가 다르면 헤드를 바꾼다(`head_swapped`).
    - 카테고리가 같으면 헤드를 그대로 둔다(`head_kept`). 예: 원목 채굴 → 조약돌 채굴. 이때도 대상 조건 입력, 하위 목표 문장, 기술 내부 단계는 새 단계 것으로 바꾼다.
    - 같은 카테고리라도 학습 프로세스가 새 버전을 관문에 통과시켰다면 그 경계에서 버전만 바꾼다(`head_version_swapped`).
  - 헤드는 STEVE-1의 행동 출력 부분만 바꾸므로 순환 상태는 그대로 이어간다.
- **탐색 자리 (사용자 결정 11-18: 보류, 팀원 담당):**
  - 이 설계는 자리와 인터페이스만 정한다. 탐색 헤드의 구조, 보상, 학습 방법은 팀원이 정한다.
  - 기본 구현: 탐색 카테고리에는 0 초기화 헤드를 등록한다. 행동은 공식 STEVE-1과 같다. 대상 문장은 지금 그 대상에 쓰는 공식 프롬프트를 그대로 쓴다. 그래서 단계를 나눠도 지금보다 나빠지지 않는다.
  - 팀원과 맞출 인터페이스:
    - 입력: STEVE-1 latent, 대상 id와 대상 문장, 센서 등급 관측(D7).
    - 출력: 다른 헤드와 같은 행동 꼴. 헤드 레지스트리에 같은 방식으로 등록한다.
    - 끝 조건: §4.4 탐색→채굴 경계. 성공은 조준 블록이 대상이고 손 닿는 거리 안인 것이다. 제한 시간을 넘으면 실패로 보고 RM이 다시 계획한다.
    - 기록: §4.2의 행 기록을 그대로 쓴다. 팀원은 이 기록으로 학습할 수 있다.
    - 평가: 대상이 화면 밖에서 시작해 경계에 닿을 때까지 걸린 시간과 성공률. 개발·최종 seed는 이 설계와 같은 것을 쓴다.
  - 팀원 헤드가 실전 자격 관문을 넘으면 0 초기화 헤드를 대신한다.
- **헤드 레지스트리:** 카테고리마다 헤드 체크포인트, 버전, 해시, 단계 목록, 조건 입력, 실전 자격을 기록한다.
- **0 초기화 시작 (내 결정):** 공식 프롬프트 기술과 탐색 자리는 0 초기화 헤드로 시작한다. 처음에는 공식 정책과 행동이 같다(학습 전 KL 0 확인).
- **실전 자격 관문:**
  - 고정 평가(개발 seed)에서 공식 프롬프트 또는 이전 버전 이상이어야 실전에서 쓴다. 못 넘으면 공식 프롬프트나 이전 버전으로 대신 실행한다.
  - 자격을 통과한 카테고리만 LLM 실행 vocabulary에 등록한다.
- **겹침 규칙 (D1 기본안):** 검증된 헤드는 그대로 둔다. 새 기술이 다른 카테고리의 능력을 필요로 하면 그 부분을 별도 RM 단계로 떼어 해당 카테고리 헤드를 부른다.

### 4.2 실행 중 학습 고리

```
본 게임(제어 루프) ──행 기록──► 카테고리별 경험 버퍼 ──► 학습 프로세스(카테고리별 후보)
      ▲                              │                              │
      │                       악용 감시(자료 제외)                    ▼
      └──── RM 단계 경계에서 버전 교체 ◄──── 후보 관문(회귀 시나리오 + 최근 실전 지표 + 악용 감시)
```

- **실행 버전 고정:** 한 RM 단계 동안 헤드 버전을 바꾸지 않는다. 교체는 그 카테고리의 다음 단계가 시작할 때만 한다.
- **학습 프로세스:**
  - 게임과 분리하고, 세션이 소유한 자식 PID로 둔다.
  - 게임 입력을 보내지 않고, 실행 중인 모델 객체를 고치지 않는다.
  - 새 버전은 새 파일로 쓰고 레지스트리 포인터만 바꾼다.
  - STOP 때 함께 정리한다. STOP 뒤에는 버전도 바꾸지 않는다.
- **행마다 추가로 기록할 것 (L0):**
  - 카테고리, 헤드 버전·해시, 단계 경계의 헤드 사건(`head_swapped`/`head_kept`/`head_version_swapped`)
  - 센서 등급 관측 값(D7). 나중에 만든 판정식도 이 값으로 다시 계산할 수 있게 한다.
  - 정책이 뽑은 행동과 그 log 확률, 가린 키, 실제 보낸 행동
  - 기술 내부 단계와 그 근거(정당 / 특권 / unknown)
  - KB·RM·계획 revision, 하위 목표 문장과 판정식 id
  - 본 게임 / 연습 / 평가 구분
  - 재라벨링과 MineCLIP 보상용 프레임: 16프레임 창을 다시 만들 수 있는 해상도로 저장한다(용량은 L0에서 잰다)
  - latent는 지금처럼 저장한다.
- **자원 예산 (내 결정):**
  - 지금 GPU에서는 학습을 CPU로 먼저 돌린다.
  - MineCLIP 보상과 재라벨링은 실행 중이 아니라 학습 프로세스에서 저장된 프레임으로 계산한다. 1060에는 STEVE-1과 MineCLIP을 함께 올릴 여유가 없다.
  - 제어 주기 p95나 서버 틱률이 학습 없을 때보다 정해 둔 한도를 넘게 나빠지면 학습을 늦추거나 멈춘다.

### 4.3 최적화: 지식 유도 자기 개선

한 번의 갱신은 아래 순서로 만든다 **(내 결정)**.

1. **하위 목표와 판정식 (LLM 지식).**
   - KB의 지식으로 카테고리 단계를 더 잘게 나눈다. 예: "철광석 채굴" → 돌 곡괭이 들기 / 철광석 조준 / 부서질 때까지 계속 공격 / 떨어진 것 줍기.
   - 각 하위 목표에 판정식을 붙인다. 판정식은 LOGO 판별식 틀 안에서만 쓴다(고정 관측, 등록된 사실, 반례 검사).
   - Auto MC-Reward처럼 역할을 나눈다(3판).
     - 설계: LLM이 정해진 관측 위의 판정식을 쓴다. 사람이 손으로 짜지 않는다.
     - 검사: 프로그램이 거른다. LOGO 컴파일(미등록 사실 거부), 반례 검사, 지난 기록 재생(성공 판에서는 끝까지 전이하고, 엉뚱한 판에서는 전이하지 않는지).
     - 분석: 학습 회차가 끝나면 궤적 분석 결과로 판정식을 고치고, 고친 판정식은 같은 검사를 다시 거친다.
   - **사람 승인 (내 결정, 3판):** 검사를 통과하면 사람 승인 없이 보상에 쓴다. 사람은 아래 경우에만 본다.
     - 같은 판정식이 악용 판정을 두 번 받았을 때(§4.6).
     - 판정식이 새 관측 항목을 요구할 때. 관측 목록을 늘리는 것은 코드 변경이다.
   - **판정식을 언제까지 만들어야 하나:**
     - 실행 중 하위 목표 문장을 바꾸는 데 쓰는 판정식은 그 판을 시작하기 전에 있어야 한다.
     - 보상에만 쓰는 판정식은 판이 끝난 뒤에 만들어도 된다. 보상은 학습 프로세스가 저장된 행으로 계산하기 때문이다. 단, 판정식이 읽는 관측이 행에 기록되어 있어야 한다.
     - 최종 성공 기준은 RM이 가진다. 판정식은 그것을 바꿀 수 없다.
2. **보상 계산 (학습 프로세스).**
   - 서버 완료와 판정식 단계 전이에 potential 차이 꼴로 보상을 준다. 순환하면 이득이 0이다.
   - 비용은 시간과 헛손질이다. 헛손질의 정의는 L0에서 고정한다.
   - 판정식이 없는 시각 목표만 MineCLIP 유사도의 상승분을 보조 보상으로 쓴다(G28). 탐색 보상은 팀원이 정한다.
   - 오라클로 만든 조밀 보상(예: 숨은 대상까지 거리)은 쓰지 않는다(11-19). 연습 월드에서도 같다.
3. **최고 기록 모방 (사용자 제안, SIL).**
   - 카테고리×대상마다 기록을 둔다. 서버 판정으로 성공했고, 지금 기록보다 빠르거나 헛손질이 적은 구간만 버퍼에 넣는다.
   - 이 구간의 자기 행동을 라벨로 BC한다(지금 학습기 그대로). 행동 확률이 필요 없어서 버전이 섞인 자료도 쓸 수 있다.
4. **사후 재라벨링 (STEVE-1 방식).**
   - 실패한 판도 실제로 일어난 일(예: 흙을 캤다)의 MineCLIP 임베딩을 목표로 붙여 같은 카테고리 학습에 쓴다.
5. **PPO 미세 조정.**
   - 최신 버전이 모은 자료 중 행동 확률이 있는 행만 쓴다. 도구 고정이 바꾼 행은 뺀다.
   - critic은 특권 정보를 볼 수 있다(비대칭, 학습 프로세스 안에서만). 11-19부터 오라클을 쓰는 곳은 critic 하나뿐이다. critic을 L2의 AWR 꼴 가중치에 먼저 쓸지는 센서 등급 설계 D-S2다.
6. **연습 월드.**
   - 본 게임에서 막힌 조건을 별도 Minecraft 프로세스에서 반복한다.
   - 센서 값만 읽는 규칙 교사로 DAgger 라벨을 만든다(11-19). 특권 헤드를 교사로 쓰는 것은 사용자가 건별로 승인할 때만이다(센서 등급 설계 D-S3).
   - 연습 결과는 따로 표기한다.
- **LLM 궤적 분석:**
  - 실패하거나 느린 판을 요약해서 어느 하위 목표에서 막혔는지 짚는다.
  - 결과는 판정식 수정안, 또는 연습 과제 제안으로만 낸다. 가중치나 성공 기준을 직접 바꾸지 않는다.
- **보존:** 다음 셋을 모두 지켜야 새 버전으로 교체한다.
  - 이전 학습 자료를 섞어 재생한다.
  - 직전 정상 버전과의 KL을 제한한다.
  - 카테고리별 고정 회귀 시나리오를 통과한다.

### 4.4 계획 준수와 단계 판정

- **정당한 단계 근거 (인식 모듈 없이):**
  - 인벤토리, 손에 든 아이템
  - F3에 보이는 자기 좌표·시선·조준 블록(D5)
  - D7을 승인하면 §6.1 센서 등급 값 전부
  - 판정식, MineCLIP 유사도
  - 근거가 없으면 'unknown' 단계를 넣는다. 헤드는 unknown 단계 행도 학습한다.
- **탐색→채굴 경계 (내 결정):**
  - 조준 블록이 대상이고 손 닿는 거리 안이면 채굴로 넘어간다.
  - 채굴 중 조준 블록이 대상이 아닌 상태가 정해진 시간 넘게 이어지면 탐색으로 되돌아간다.
- **준수 지표 (단계별, 감시가 계산):**
  - 단계 의도에 맞는 행동 비율
  - 계획 밖 상호작용(대상이 아닌 블록 파괴, `Plan.keep` 재료 소비, 보존 조건 위반)
  - 단계 시간 / 제한 시간
- 계획 밖 수단으로 얻은 진척에는 보상을 주지 않는다(§4.6 출처 대조).

### 4.5 지식과 CLIP의 상승 효과

- **하위 목표 하나를 세 곳에 함께 쓴다:**

| 쓰는 곳 | 하는 일 | 다루는 지식 |
|---|---|---|
| 정책 조건 | 하위 목표 문장을 MineCLIP 임베딩으로 STEVE-1에 주고, 헤드에는 하위 단계로 준다 | "무엇을 향해"(시각적인 것: 나무, 철광석, 구멍) |
| 보상·판정 | 판정식으로 단계 전이를 판정하고 조밀 보상을 준다 | "어떻게·끝났는지"(도구, 계속 누르기, 줍기, 순서) |
| 학습 표적 | 그 하위 목표를 기록보다 잘 해낸 구간을 자기 모방하고, 재라벨링한다 | 둘 다 |

- 문장만 바꾸면 효과가 없었다(G29). 같은 하위 목표로 조건·보상·표적을 맞춰야, 정책이 그 문장을 따를 때 보상을 받고 그 행동을 배운다. 상승 효과는 여기서 생긴다고 본다(가설, §5 비교로 잰다).
- **실행 중 행동 교정:**
  - 느린 판단(hold)에서 LLM의 교정은 두 갈래로 간다. 예: "곡괭이로 바꾸고 부서질 때까지 계속 눌러라".
    - 즉시: 남은 판의 RM 단계와 하위 목표 문장을 바꾼다. 가중치는 바뀌지 않는다.
    - 나중: 그 하위 목표의 판정식과 연습 과제를 학습 요청으로 만든다. 판정식은 §4.3의 자동 검사를 거친다.
  - 같은 교정이 반복되면 판정식이 학습에 들어가고, 이후에는 교정 없이도 해야 한다. 이것을 "지식이 정책에 남았다"의 판정 기준으로 쓴다.
- **오염 방지:**
  - 모든 행에 KB revision을 남긴다.
  - 지식이 철회되면 그 지식으로 만든 하위 목표·판정식 구간을 학습에서 빼거나 다시 판정한다.
  - '지식 오류'나 '관측 장애'로 분류된 실패는 정책 학습 표본에서 뺀다.
- 위치 특정 지식은 KB에 넣지 않는다(사용자 방침).

### 4.6 보상 악용 감시

- **위치:**
  - 행 단위 검사는 감시 스레드에 '보상 감사'로 더한다. 행동을 막지 않고 기록만 한다.
  - 버전 단위 검사는 학습 프로세스의 후보 관문에서 한다.
- **행 단위 검사:**

| 악용 꼴 | 검사 | 사건 |
|---|---|---|
| 의도하지 않은 출처로 진척 | 보상을 낳은 인벤토리 증가마다, 가까운 시점에 맞는 서버 파괴 기록(대상 블록, 맞는 도구)이 있는지 | `reward_unexplained` |
| 금지된 수단으로 진척 | 보호 블록 파괴, 설계도 블록 부숨, `Plan.keep` 재료 소비, 보존 조건 위반 | `reward_by_violation` |
| 순환 | 같은 아이템 얻고 잃기, 같은 칸 놓고 부수기 반복 | `reward_cycle` |
| MineCLIP 보상만 오름 | 유사도 보상은 오르는데 거리·조준 블록·판정식 진척이 없음(멀리서 바라보기) | `clip_without_progress` |
| 감시 경계 맴돌기 | 정체 판정 기준 바로 위의 움직임 반복 | `near_threshold`(참고 지표) |

- **버전 단위 검사:** 버전별로 보상 합의 증가와 실제 지표(서버 성공률, 시간, 헛손질)를 비교한다. 보상만 오르면 `proxy_gap`이다.
- **대응 (D2 기본안):**
  1. 해당 구간을 학습 자료에서 뺀다.
  2. 그 카테고리의 갱신을 멈춘다.
  3. 마지막 정상 버전으로 자동으로 되돌린다.
  4. 사건을 기록한다.
  - 판정식이 원인이면 LLM이 수정안을 내고, 수정안은 §4.3의 자동 검사를 다시 거친다.
  - 같은 판정식이 두 번 악용 판정을 받으면 그 판정식을 끄고 사람에게 보고한다 **(내 결정)**.
- **원칙:**
  - 감시 결과는 보상에 넣지 않는다.
  - 근거는 정책이 바꿀 수 없는 서버 기록이고, 심판용 특권 관측으로 보고에 밝힌다.
- **감시 자체의 검증:** 합성 기록과 연습 월드의 scripted probe로 탐지율을 확인한다. probe는 정책 성공으로 세지 않는다.

## 5. 평가와 판정

- 실행 중 학습한 판은 학습 자료다. 성공률은 따로 보고하되 평가로 세지 않는다.
- 평가는 버전을 고정해 개발 seed와 최종 seed에서 한다. 판정 기준은 실행 전에 기록한다. 공식 프롬프트 이상이어야 한다.
- 지표:
  - 카테고리별 단계 성공률, 단계 시간, 헛손질 수
  - 준수 지표, 악용 사건 수
  - 이전 능력 회귀
  - 교정 없이 해낸 비율(§4.5)
- 상승 효과를 재는 비교(G21):

| 조건 | 정책 | 지식(하위 목표·판정식) |
|---|---|---|
| a | 고정 | 쓰지 않음 |
| b | 고정 | 조건으로만 씀(문장) |
| c | 갱신(최고 기록 모방 + 재라벨링만) | 쓰지 않음 |
| d | 갱신 | 조건·보상·표적 모두에 씀 |

- d가 b와 c보다 모두 좋아야 "상승 효과"라고 쓴다.

## 6. 인식 모듈 없는 순수 RL과 장비

- **"순수 RL"의 뜻 (내 결정):**
  - 실행 때 actor는 화면(STEVE-1 latent)과 정당한 정보만 본다. 정당한 정보는 하위 목표 문장, 설계도, 그리고 §6.1의 센서 등급 값이다(D7).
  - 학습 때만 오라클 정보를 critic에 쓴다(11-19, 보상·교사에서는 뺐다). 따로 붙는 인식 모델은 없다.
- **사다리 (G30):**
  1. 고정 STEVE-1 + 카테고리 헤드(지금 GPU).
     - 채굴부터 한다. 탐색 자리는 팀원 헤드가 올 때까지 공식 STEVE-1이 돈다.
  2. 1이 L2 통과 조건을 못 넘으면 STEVE-1 일부에 LoRA를 붙여 학습한다(5070 Ti 필요).
     - 화면 밖 대상 방향 같은 표현을 STEVE-1 쪽에서 배우게 한다.
     - 추가 파라미터는 작다(헤드와 같은 규모).
  3. 2도 못 넘을 때만 작은 인식 부품을 다시 검토한다. 이것은 사용자가 다시 정한다.
- **5070 Ti가 주는 것과 못 주는 것:**

| 준다 | 못 준다 |
|---|---|
| LoRA·부분 미세조정(3GB로는 불가, 16GB로는 가능할 것으로 봄) | Minecraft 시뮬레이션 속도(CPU가 정함) |
| 여러 게임의 정책 추론을 한 장에서 함께 처리 | 동시에 돌릴 게임 수(RAM 24GB가 정함, 측정 필요) |
| 게임 추론과 학습을 한 장에서 함께 돌리기, MineCLIP 보상 계산 | 보상이 드문 문제(§4.3 방법으로 풀어야 함) |

- **처리량 감:**
  - 게임 하나는 초당 약 10행동, 하루 최대 약 86만 행동이다.
  - 지금까지 헤드는 수만 행으로 학습됐다(p5-final 약 2.9만 행).
  - 기술 단위의 자기 모방·DAgger는 게임 1–3개로도 하루 몇 번 갱신할 양이 된다.
  - 처음부터 RL(DreamerV3 3,000만 스텝)과는 규모가 다르다. STEVE-1에서 출발하고 보상이 조밀하기 때문이다.
- **소프트웨어 (G32):**
  - 5070 Ti는 PyTorch 2.7 이상 + CUDA 12.8 빌드가 필요하다. 지금 STEVE-1 환경은 2.0.1 + CUDA 11.7이다.
  - 새 환경을 따로 만든다. 같은 입력에서 공식 STEVE-1의 행동 확률이 지금 환경과 허용 오차 안에서 같은지 먼저 확인한다(동등성 검사).
  - 1060과 함께 쓰는 구성은 빌드 지원이 엇갈려서 권하지 않는다.
- 유료 자원과 장비 구매는 이 설계의 범위가 아니다. 사용자가 정한다.

### 6.1 센서 등급 (3판 제안, 11-19 채택)

- 11-19: 세부(다섯 등급, 센서 목록과 한계, 헤드 감사, 누출 검사, 평가 조건)는 [센서 등급 관측 설계](2026-11-19-sensor-tier-observation-design.md)로 옮겼다. 아래 표와 문안은 그 문서를 따라 고쳤다.

- **사용자 제안(11-18):** 현실의 센서가 주는 값은 특권 정보로 주었다고 밝힌다. 이유는 Minecraft를 에이전트 실행 환경으로 썼기 때문이라고 논문에 쓴다(머리말 인용).
  - 같은 날 다듬은 표현: "정확히는 다른 task에 적용하기 전, 실험적인 환경으로 사용하였고, 실제 자율주행, 로봇 등의 환경에서는 센서가 특권 정보를 대체할 것이기에 사용했다~ 이런 식으로?"
- **판단: 쓸 수 있다.** 근거는 셋이다.
  - MineDojo([관측 공간](https://docs.minedojo.org/sections/core_api/obs_space.html))는 자기 위치, 시선(yaw·pitch), 인벤토리, 장비, 체력, 주변 3×3×3 블록을 기본 관측으로 준다.
    - 더 넓은 블록 범위와 lidar 광선은 공정성을 위해 '특권 관측'으로 따로 둔다([특권 관측](https://docs.minedojo.org/sections/customization/privileged_obs.html)).
    - 즉 이 분야에도 "기본 센서"와 "특권"의 선이 이미 있다.
  - 연구 명세도 플래너 입력에 World State와 World Memory를 두고, 결정적 행동에는 API·규칙 기술을 허용한다(`research-spec.md` §4.6, §10). 연구 질문(RQ1–RQ2)은 대화 → 목표 식별 → RM 구조화에 있고, 화면 인식 자체가 아니다.
  - 특권 교사 → 화면 학생 구조에도 선례가 있다([Learning by Cheating, Chen 외 CoRL 2019](https://arxiv.org/abs/1912.12294)).
- **조건 (심사에서 버티려면):**
  1. **경계 기준:** 에이전트 몸에 단 센서로 지금 그 자리에서 잴 수 있는 값만 센서 등급이다. 서버는 알지만 몸에서 잴 수 없는 값은 오라클이다.
  2. **센서 한계를 둔다:** 범위, 가림(가려진 블록은 못 봄), 지연. 서버 위치가 클라이언트보다 약 4틱 늦는 것도 지연으로 밝힌다.
  3. **화면만 쓴 조건을 함께 보고한다.** 이미 일부 근거가 있다(§1: 점프 v1 1/8, 화면 밖 방향 0.52–0.55).
  4. **잡음 강건성 조건을 하나 둔다.**
     - Habitat 2020은 실내 GPS가 부정확하다는 이유로 PointNav에서 GPS+나침반을 빼고 행동 잡음을 넣었다([Habitat Challenge 2020](https://aihabitat.org/challenge/2020/)).
     - 잡음 없는 조건에서 99.6%였던 에이전트가 잡음·위치 정보 없음 조건에서 0.3%로 떨어졌다는 보고가 있다([Zhao 외 ICCV 2021](https://arxiv.org/abs/2108.11550)).
     - 그래서 심사자는 "잡음 없는 센서"를 물을 것이다. 평가에 센서 잡음·지연을 넣은 조건을 하나 둔다.
  5. **표현을 맞춘다.**
     - 사용자가 다듬은 "다른 과업에 적용하기 전의 실험 환경, 실제 환경에서는 센서가 대신한다"는 표현이 "마인크래프트 에이전트를 만드는 목적이 아니다"보다 낫다.
     - 다만 두 가지를 지킨다.
       - "센서가 대신한다"는 센서 등급 값에만 맞다. 가려진 대상의 좌표처럼 현실에도 대응 센서가 없는 값(오라클)은 정책 입력에서 뺐다고 함께 쓴다.
       - 다른 환경으로 옮겨 보는 실험은 하지 않았으므로, 이전 가능성은 결과가 아니라 동기와 향후 과제로 쓴다.
     - 연구 명세의 목표는 "Minecraft Embodied Agent"이고, RQ3·RQ4는 Minecraft 고유의 플레이 습관과 페르소나를 다룬다. 논문에서 "실험 환경" 틀을 쓰면 이 부분은 "환경 고유 사전 지식"으로 위치를 정해야 한다. 명세 원문은 고치지 않는다.
- **등급표 (제안):**

| 등급 | 예 | 현실 대응 | actor 입력 | 학습 신호(보상·critic·교사) |
|---|---|---|---|---|
| 화면 | STEVE-1 latent | 카메라 | 씀 | 씀 |
| 센서 | 자기 위치·시선(F3), 인벤토리·손 아이템, 체력·배고픔, 조준 블록과 거리(손 닿는 거리), 주변 블록(작은 반경), 시야 안 제한 거리 광선(블록 종류·거리) | GPS·IMU, 고유 감각, 근접·거리 센서, 짧은 거리 LiDAR + 물체 인식 | 씀 | 씀 |
| 오라클 | 가려진 대상의 좌표(fixture 좌표), fixture 정의로 바로 계산한 기술 단계, 월드 seed·생성 정보 | 없음 | 쓰지 않음 | critic에만 씀(11-19, 보고에 밝힘) |

  - 11-19: 지시(설계도·목표 지점·문장)와 심판(서버 기록)은 센서 등급 설계 §2.1에서 따로 등급을 두었다.

  - 광선의 블록 종류는 완벽한 물체 인식을 가정한다. MineDojo도 lidar를 특권으로 분류한다. 그래서 범위를 좁게 잡고, 이 값을 쓰는 기술을 보고에 밝힌다. 반경과 광선 수는 L0에서 정해 기록한다.
- **논문 문안 초안:**
  > 본 연구는 Minecraft를 자율주행·로봇 같은 실제 환경에 적용하기에 앞선 실험 환경으로 사용했다. 연구의 질문은 대화에서 실행할 목표를 식별하고, 이를 Reward Machine으로 구조화해 기술 실행으로 잇는 구조에 있다. 실제 환경에서는 GPS·관성 센서·LiDAR 같은 센서가 자기 위치와 방향, 주변 거리 정보를 제공하므로, 그에 해당하는 값(자기 위치와 방향, 인벤토리, 조준 블록, 제한된 범위의 시야 안 블록)을 관측으로 주었다. 실제 센서로도 얻을 수 없는 값(보지 못한 대상의 좌표, 월드 생성 정보)은 정책 입력과 보상·교사 라벨에서 빼고, 학습 때 가치 함수(critic)의 입력으로만 썼다. 화면만 쓰는 조건과 센서 잡음 조건의 결과를 함께 보고한다. 다른 환경으로의 이전은 본 연구에서 검증하지 않았다.
- **D7을 승인하면 바뀌는 것:**
  - R2가 줄어든다. 시야 안·범위 안 대상의 방향과 거리는 센서로 받는다. 남는 어려움은 어느 센서에도 잡히지 않는 대상을 찾는 일이고, 그것은 탐색(팀원)이다.
  - L0에서 기존 특권 헤드의 특징을 감사한다. 11-19 서류 감사로는 그대로 센서 등급인 헤드가 없고, 모두 지시+센서(본 지도 포함)로 다시 계산할 수 있다. 그래서 센서 교사로 다시 학습한다. 특권 헤드는 교사로 쓰지 않는다(센서 등급 설계 §4–5).
  - 11-17 기준("최소한 이 정책은 스스로 시키는 것 정도는")은 "오라클과 스크립트 대행 없이, 센서는 써서"로 읽는다.
  - AGENTS.md의 "privileged server 관측은 영상 전용 조건과 구분한다"는 센서 등급 조건과 화면 전용 조건을 따로 보고하는 것으로 지킨다.

## 7. 단계와 통과 조건

| 단계 | 하는 일 | 통과 조건 | 실패하면 |
|---|---|---|---|
| L0 기록·교체 | 행 기록 보강(§4.2), 헤드 레지스트리, RM 단계마다 헤드 교체·유지, 탐색 자리(0 초기화 헤드), 탐색→채굴 경계, 보상 감사 행 단위 검사. D7 승인 시 센서 등급 관측 기록과 기존 헤드 특징 감사 | 단위 검사. 게임 1판에서 카테고리가 바뀔 때만 헤드가 바뀌고(같으면 `head_kept`), 기록한 확률을 다시 계산했을 때 오차 0 | 고친다 |
| L1 정책 단독 기준선 | 채굴 3종(원목·조약돌·철광석). 탐색 자리는 공식 STEVE-1. 오라클 입력·LLM·규칙 행동·도구 고정 없이, 대상이 화면 밖에서 시작. 화면 전용과 센서 등급(D7)을 따로 잰다 | 측정만 한다 | — |
| L2 오프라인 최적화 확인 | L1과 지난 실전 기록으로 §4.3의 1–4를 해 보고 고정 평가 | 개발 seed에서 기준선보다 좋음(D4). 지식 쓴 쪽(d)과 안 쓴 쪽(c)을 함께 잰다 | 사다리 2(LoRA) 또는 멈추고 보고 |
| L3 판 사이 갱신 | 실전 판 → 판 사이 학습 → 관문 → 다음 판 교체. 버전 단위 악용 검사와 자동 되돌리기 | 정한 판 수 동안 고정 평가가 나아지거나 유지 | 되돌리고 보고 |
| L4 게임 중 병행 학습 | 학습 프로세스 병행, RM 단계 경계 교체 | 제어 주기·틱률 저하가 한도 안 | 판 사이 방식 유지 |
| L5 지식 → 학습 요청 | hold 교정 → 판정식(자동 검사) → 연습 → 관문 | 교정 없이 해낸 비율 상승 | KB에만 남김 |
| (조건부) LoRA | 5070 Ti와 새 환경, 동등성 검사 뒤 L2를 다시 한다 | L2와 같음 | 사용자에게 보고(사다리 3) |

- 놓기·건축·다리·점프의 센서 헤드는 채굴이 L2를 넘은 뒤에 같은 방법으로 만든다. 교사는 센서 값만 읽는 규칙 교사다(11-19, 센서 등급 설계 §5·§8). 특권 헤드는 평가의 참고 조건(R)으로만 남는다.
- 탐색 헤드는 팀원 일정에 따른다. 팀원 헤드가 들어오면 같은 실전 자격 관문(§4.1)을 거친다.

## 8. 지키는 규칙과 범위 밖

- **지키는 규칙:**
  - 성공은 서버 상태·인벤토리·NBT로만 판정한다.
  - 학습·개발·최종을 나눈다. 실전 학습 판은 평가가 아니다.
  - STOP: 학습 프로세스도 소유 자식 PID다. 입력 해제와 PID 정리를 확인한다. STOP 뒤에는 행동도 버전 교체도 없다.
  - 오라클 관측은 critic에만 쓰고 보고에 밝힌다(11-19). actor 입력, 보상, 교사 라벨, 하위 목표 전환에는 넣지 않는다. 성공 판정과 감시는 심판(서버 기록)으로 한다.
  - 센서 등급 관측(D7)은 actor 입력으로 쓰되, 목록과 한계(범위·가림·지연)를 보고에 밝히고 화면 전용 조건과 따로 보고한다.
  - 원본 궤적·체크포인트·월드를 보존한다. 버전 파일은 쓴 뒤 바꾸지 않는다.
  - 실전 자격을 통과하지 않은 카테고리는 LLM 실행 vocabulary에 넣지 않는다.
  - 유료 API는 `--allow-paid`일 때만 쓴다. 실행 중 LLM 호출 예산을 기록한다.
  - 배치 중 작업 트리의 src를 고치지 않는다.
- **범위 밖:**
  - 별도 인식 모듈(사용자 11-18: "빼고 싶은데"). 사다리 3에서만 다시 묻는다.
  - STEVE-1 전체 미세조정. LoRA는 조건부로 범위 안이다.
  - 제작의 학습 정책화. 규칙 기술로 둔다.
  - 살아 있는 월드의 즉시 복제.

## 9. 사용자가 정할 일

- **D1 카테고리 겹침:** 검증된 헤드는 그대로 두고 새 기술부터 규칙을 적용(기본안) / 기존 헤드도 다시 나누기.
- **D2 악용 의심 때 대응:** 자동으로 되돌리기(기본안) / 사람 확인까지 그 카테고리 갱신만 멈추기.
- **D3 첫 대상:** 채굴 3종(기본안, 3판). 탐색은 팀원이 맡고, 그 전까지 공식 STEVE-1이 탐색 자리를 채운다.
- **D4 L2·L3 통과 수치:** 실행 전에 기록한다. 제안은 개발 seed 8판에서 성공 수가 기준선 이상이고, 단계 시간 중앙값이 20% 이상 줄어드는 것이다.
- **D5 F3에 보이는 조준 블록을 정당한 입력으로 볼지:** 사람도 F3 화면에서 보는 값이라 정당하다고 본다(기본안). 인식 설계(11-17)는 이 값을 인식 입력에서 뺐다. 이 설계는 탐색→채굴 경계 판정에 쓴다. D7을 승인하면 D5는 D7에 포함된다.
- **D6 5070 Ti:** 구매와 새 환경 구축은 사용자 결정이다. LoRA 단계는 L2 결과를 본 뒤에 필요한지 정하는 것을 제안한다.
- **D7 센서 등급 (3판):** §6.1 등급표대로 센서 등급 값을 actor 입력으로 허용하고, 오라클만 학습 신호로 돌린다(기본안) / 2판대로 화면과 F3 값만 허용.
  - 11-19: 사용자가 종합설계 요약계획서에 센서 등급을 넣기로 했다(기본안 채택).
  - 11-19: 사용자가 오라클은 critic에만 쓰기로 했다. 세부와 남은 결정(D-S1–D-S3)은 [센서 등급 관측 설계](2026-11-19-sensor-tier-observation-design.md) §10에 있다.
- **11-19 요약계획서에 적은 범위 (사용자 결정):**
  - 본 내용: 판 사이 갱신(L3까지), 최고 기록 모방, LLM 판정식 보상, 보상 악용 감시, 센서 등급, 하위 목표별 판정식·감시 조건의 LLM 생성과 자동 검사. 금지 조건은 사람이 정한다.
  - (확장): 게임 중 병행 학습(L4).
  - 적지 않음: PPO 미세조정, LoRA(5070 Ti). 이 설계에서는 조건부 단계로 남는다.
