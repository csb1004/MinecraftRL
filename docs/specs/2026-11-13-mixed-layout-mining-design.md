# 대상 위치를 섞은 채굴 학습 — 설계 (2026-11-13)

- 상태: 사용자 지시(11/13 02:00): "블럭을 제대로 캐는 것도 잘 안됐잖아? 밤동안 계속해서 이것들 학습해줘."
  사용자는 자는 중이라 세부는 내가 정했다. **(내 결정)** 표시 값은 사용자가 정하지 않은 것이며 바꿀 수 있다. main 병합은 계속 보류다.
- 근거 기록: [어려운 평가 결과](../harder-evaluation-results-2026-11-11.md). 학생은 블록 종류는 일반화했지만, 대상이 한 칸 낮아지자
  sight 2/8, approach 0/8로 무너졌다(공식 8/8). 근처에서 시선을 거의 수평에 두고 학습 때 대상이 있던 줄만 보았다.
- 점프맵·다리 잇기·건축은 이 설계에 넣지 않는다. 이 배치가 게임을 쓰는 동안 점프맵은 게임 없이 준비만 한다(별도 설계).

## 1. 무엇을 바꾸나

지금까지의 학습 자료(R0–R6, 126회)는 모두 같은 자리(벽 가운데 줄, 눈높이)의 대상이다. 그래서 학생이 "대상은 눈높이에 있다"를 배웠다.
이번에는 대상 위치를 여러 가지로 바꾼 경기장에서 DAgger 라운드를 두 번 더 돌린다. 교사(`sight`), 학습 방법, 단계 입력은 그대로다.

**실패했던 자리(벽 맨 아래 줄, dy 0)는 학습에서 뺀다 (내 결정).** 그 자리를 학습하지 않고도 캐면 "위치를 따라 시선을 옮기는 법"을 배운 것이고,
그 자리를 학습해서 캐면 자리 하나를 더 외운 것인지 구별할 수 없다. 학습 모드에서 `low` 배치는 코드가 거부한다.

## 2. 배치

모두 fixture v2(11×12 경기장, 벽은 dz 8의 dx −2..2, dy 0..2)에서 대상 두 칸의 자리만 바꾼다. 좌표는 시작 블록 기준(dx 오른쪽, dy 위, dz 앞).

| 배치 | 대상 두 칸 | 높이 | 쓰임 |
|---|---|---|---|
| wall | (−1, 1, 8), (1, 1, 8) | 눈높이 | 기존 학습 자료(R0–R6) |
| **low** | (−1, 0, 8), (1, 0, 8) | 발 높이 | **평가 전용**(개발·최종). 학습 금지 |
| high | (−2, 2, 8), (1, 2, 8) | 머리 위(벽 맨 윗줄) | 새 학습 |
| floor | (−2, −1, 5), (2, −1, 6) | 바닥 속(잔디 자리) | 새 학습 |
| pillar | (−1, 1, 5), (2, 1, 6), 아래에 돌 한 칸씩 | 눈높이, 벽이 아닌 열린 자리 | 새 학습 |

- **(내 결정)** 학습 높이는 −1, 1, 2이고 평가 높이 0은 그 사이다. 위치는 벽·바닥·열린 기둥으로 섞었다.
- 벽 위(dy 3)는 뺐다. 캔 블록이 벽 꼭대기에 떨어져 땅에서 주울 수 없다(줍기 범위는 몸 위로 0.5블록).
- 바닥 대상은 캔 뒤 구멍(깊이 1)에 떨어진다. 교사의 회수 정답(떨어진 곳으로 걷기)대로 구멍에 들어가면 주울 수 있다.
- 모래는 세 배치 모두 아래가 막혀 있어 떨어지지 않는다(high는 벽 돌, floor는 흙, pillar는 돌 받침 위).

## 3. 라운드

블록 6개(석탄·청금석 광석, 모래, 점토, 흰 양털, 참나무 판자), 학습 seed 3개. **seed마다 배치를 하나씩 준다 (내 결정):**
271828 → high, 314159 → floor, 161803 → pillar. 라운드마다 블록 × 배치가 한 번씩, 18회다. 배치마다 배치 폴더를 따로 둔다(입력 기록이 블록마다 하나라서).

1. **L7:** sight 학생(s-final)으로 세 배치를 모은다(샘플링 9).
2. 자료 `l-r0-7` = R0–R6 + L7, sight 교사로 다시 라벨. 검증용으로 L7에서 블록마다 한 실행(배치를 고르게 섞음)을 뺀다. 학습 `l-r8`.
3. **L8:** `l-r8`로 세 배치를 모은다(샘플링 10). 자료 `l-r0-8` = R0–R6 + L7 + L8, 검증은 L8에서 같은 방식. 학습 `l-final`.
- 학습 설정은 앞선 라운드와 같다(KL 10, (블록, 단계) 균형, patience 2). **배치별 가중치는 주지 않는다 (내 결정).**
  학생이 낯선 배치에서 오래 헤매면 그 행이 많아져 자연히 비중이 커진다. 배치별 라벨 행 수는 보고한다.
- 오프라인 관문은 앞선 라운드와 같다(철광석 공식 실행의 mining 행에서 학생의 p_hold ≥ 공식). 통과하지 못하면 게임 평가를 하지 않는다.

## 4. 개발 평가와 판정

- **철광석, low 배치, 개발 seed 130363, 샘플링 1–4.** 갈래: 공식, sight(s-final, 기준 학생), layout(l-final). 12회.
  low 배치에서 이 seed는 처음 쓴다.
- **개발 판정** = `hold_verdict(공식, 기준 sight, 새 layout)`: 셋 다 만족해야 한다.
  1. 성공 수가 sight보다 적지 않다. 2. 파괴 비율이 sight보다 높다. 3. 성공 시간 중앙값이 공식보다 길지 않다.
- 함께 보고: 공식 대비 판정(`dev_verdict`), 근처 시선 각도, 조준선이 닿은 줄.
- **개발 판정 불통과 시 (내 결정):** 한 라운드 더(L9, `l-final`로 수집, 샘플링 11 → 자료 `l-r0-9` → 학습 `l-final2`) 하고
  갈래 `layout2`로 같은 개발 평가를 한다. 그래도 불통과면 최종 평가를 하지 않고 멈춘다.
- **수정 (11-13 04:35, 개발 평가 시작 전, 내 결정): L9의 학습만 배치 균형으로 바꾼다.**
  근거: L7 자료에서 근처 단계 라벨 행의 84%가 기존 벽 자료다(벽 74,170 · 바닥 7,297 · 머리 위 7,377 · 기둥 35).
  교사는 바닥에서 아래(+9.9도), 머리 위에서 위(−10.0도)를 가리키지만, 한 라운드 학습한 l-r8도 근처 시선 중앙값이
  머리 위 10.6도 아래·바닥 8.0도 아래로 L7(6.7·7.1도)과 거의 같았다(L8 첫 판 각 1회). 같은 방법의 한 라운드로는 바뀌지 않을 공산이 크다.
  바꾼 점: 균형 묶음을 (블록, 단계)에서 (블록, 벽/새 배치, 단계)로 나눠, 새 배치 행이 블록·단계마다 기존 벽 행과 같은 무게를 받는다.
  수집·교사·KL·patience·판정은 그대로다. 실행은 `launch/layout2.sh`(L9 배치 폴더의 STOP으로 원래 스크립트의 L9를 막았다).

## 6. 점검

- 게임 전: wall·low 배치 파일이 전과 바이트 단위로 같은지, 새 배치는 대상 칸(과 받침 돌)만 바뀌는지, 학습 모드가 low를 거부하는지 단위 검사.
- L7이 끝나면 배치별 실행 수·성공·라벨 행을 확인한다. 바닥 배치에서 교사 정답이 아래를 보는지(라벨 pitch 부호) 본다.
- 평가 중 교사·규칙은 행동을 보내지 않는다. STOP 이후 새 행동 0, 입력 해제, 소유 PID 정리. 유료 API 0, GitHub 공개 0.
- 배치가 도는 동안 `results/` 전체를 훑는 명령, 실행 폴더로의 `cd`, 게임 입력 파일(`WATCHED`, `src/minecraftrl/pipeline/*.py`) 수정을 하지 않는다.
  점프맵 준비는 새 파일에서만 한다.
- 시간 어림: L7 80분, 학습 10분, L8 70분, 학습 10분, 개발 50분, 최종 110분. 약 6시간.
