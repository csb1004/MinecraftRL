# 블록 놓기 → 다리 잇기 → 설계도 건축 — 계획 (2026-11-13, 구현 전)

- 상태: 계획만. 사용자 요청(11/13 "블럭으로 다리 잇기, 건축하기…")에 따른 다음 단계 초안이며 아직 아무것도 만들지 않았다.
  점프 코스(`2026-11-13-jump-course-design.md`)와 채굴 배치 실험이 먼저다. 구현 전까지 LLM 계획 vocabulary에 넣지 않는다.

## 1. 공통 기초 기술: 정한 면에 블록 놓기

다리 잇기와 건축은 모두 "손에 든 블록을 정한 칸에 놓는다"를 되풀이한다. 그래서 이것을 먼저 따로 배우고 검증한다.

| 단계(상태) | 진입 조건 | 완료 근거(서버) |
|---|---|---|
| hold | 손에 놓을 블록이 없음 | 서버 선택 슬롯의 아이템이 그 블록 |
| reach | 목표 칸이 손 닿는 거리(눈에서 4.5블록) 밖 | 거리 안으로 들어옴 |
| aim | 목표 칸에 붙은 면을 조준하지 않음 | 서버 조준 블록·면이 목표 칸의 이웃 면 |
| place | 조준 중 | **목표 칸의 서버 블록 상태가 그 블록으로 바뀜** |

- 우클릭(use) 키 입력 자체는 단계가 아니다. 완료는 서버 블록 상태로만 센다.
- **필요한 서버 관측(지금 없음):** 게임 모드가 "놓인 블록 수와 마지막으로 놓인 칸·블록"(파괴 카운터와 같은 방식)과
  fixture가 지정한 칸들의 현재 블록 상태를 보고해야 한다. 지금은 파괴만 보고한다. Java 변경이므로 채굴 배치가 쓰지 않을 때 만든다.
- 도구 고정(`policy_tool_lock`)은 슬롯 키를 막는다. 블록 놓기 실험은 블록을 처음부터 손에 쥐어 주고(fixture give + 선택 슬롯) 슬롯 변경 없이 시작한다.

## 2. 다리 잇기

- 코스: 점프 코스와 같은 생성기에 "뛰어 건널 수 없는 틈(3–5칸, 같은 높이)"을 둔다. 성공 = 건너편 발판 위(점프 코스와 같은 판정).
- 단계: 가장자리로 가기 → 웅크려 가장자리에서 아래 옆면 조준 → 놓기(서버 블록 확인) → 놓은 블록 위로 한 칸 → 반복.
- 교사: 점프 교사처럼 서버 자세와 코스로 다음 놓을 칸을 정하고, 1절의 놓기 기술을 쓴다.

## 3. 설계도 건축

- 과제: fixture에 설계도(칸 목록과 블록)를 적고, 빈 땅에 그대로 짓는다(예: 3×3 바닥, 2층 벽).
- 성공 = 설계도의 모든 칸의 서버 블록 상태가 일치. 진행 = 맞게 놓인 칸 수. 틀리게 놓인 칸은 따로 센다.
- 단계: 다음 칸 고르기(아래층부터, 받침이 있는 칸) → 1절의 reach·aim·place → 확인.

## 4. 순서와 검증

1. 게임 모드에 놓기 관측 추가 + 단위 검사 + 실제 게임에서 손으로 놓은 블록이 기록되는지 확인.
2. 놓기 교사 점검(준비용) → 기초 기술 DAgger(목표 칸 위치를 처음부터 섞는다).
3. 다리 잇기 → 설계도 건축. 각 단계는 학습·개발·최종 코스를 나누고 판정을 게임 전에 정한다.
