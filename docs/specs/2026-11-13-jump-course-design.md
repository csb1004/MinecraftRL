# 점프맵(발판 건너기) 기술 — 설계 (2026-11-13)

- 상태: 사용자 요청(11/13 01:00경 "점프맵…블럭으로 다리 잇기, 건축하기…", 02:00 "밤동안 계속해서 이것들 학습해줘").
  사용자는 자는 중이라 세부는 내가 정했다. **(내 결정)** 표시 값은 사용자가 정하지 않은 것이며 바꿀 수 있다.
- 다리 잇기·건축은 블록 놓기(우클릭, 손에 든 블록, 놓인 블록 확인)가 먼저 필요해서 이 설계에 넣지 않는다.
- 이 기술은 구현과 검증이 끝나기 전까지 LLM 계획 vocabulary에 넣지 않는다(작업 분해 원칙).
- 같은 밤에 채굴 배치(`2026-11-13-mixed-layout-mining-design.md`)가 게임을 쓴다. 점프맵은 그동안 게임 없이 만들고 검사만 한다.
  게임 입력 파일이 배치 도중 바뀌지 않도록 별도 작업 폴더(브랜치 `jump-map`)에서 만든다.

## 1. 과업과 성공

- **과업:** 시작 발판에서 출발해 공중에 뜬 발판들을 차례로 뛰어 건너 금 블록 발판(목표)에 선다.
- **성공(서버 기준):** 서버가 "땅에 서 있음"을 보고하고, 발 높이가 목표 발판 윗면과 같고, 몸 상자가 목표 발판 위에 걸친 상태. 화면 판정은 쓰지 않는다.
- **실패:** 아래 바닥으로 떨어짐(발 높이가 가장 낮은 발판 윗면보다 1.2블록 넘게 아래) 또는 시간 초과. 떨어지면 그 실행은 끝난다.
- 서버 좌표·땅 접촉은 이미 게임 모드가 보고한다(`server_x/y/z`, `server_on_ground`). 기록 행에 `server_on_ground`·`server_fall_distance`를 더한다.

## 2. 코스(배치를 처음부터 섞는다)

채굴 평가의 교훈(경기장 하나에서만 배우면 배치를 외운다)대로 코스를 처음부터 무작위로 만든다.
좌표는 시작 블록 기준(dx 오른쪽, dy 위, dz 앞)이고 시작 방향으로 돈다(fixture v2와 같은 규약).

- 시작 발판 폭 3 × 길이 2(플레이어는 앞줄, 윗면 높이 0). 중간 발판 2개는 폭 2 × 길이 3, 목표는 3×3 금 블록. 점프 3번. **(내 결정)**
- **수정(11-13 09:10, 게임 점검):** 처음 코스는 점프 4번·시작 3×3이었다. 교사 점검 첫 판이 3번 모두 게임 시작 전에 무효가 됐다
  (`fixture_failed`, 게임 모드가 시작점에서 16블록 넘는 좌표를 거부한다. 코스가 최대 25블록까지 뻗었다).
  게임 모드를 다시 빌드하지 않으려고 코스를 줄였다. 점프 3번, 시작 발판 한 줄 축소, 목표 바로 뒤에 벽(최대 16블록).
  중간 발판을 길이 2로 줄이는 안은 시뮬레이션에서 교사가 지나쳐 떨어져(415/800) 버렸다. 무효 3판은 `teacher-v0-offset-limit/`에 남겼다.
- 점프마다 틈 1 또는 2블록, 높이 변화 −1·0·+1(+1은 틈 1일 때만), 옆으로 −1·0·+1칸. 발판 윗면은 −1..2.
- 발판 재료는 석재 벽돌, 목표는 금 블록. 아래 바닥은 발판 윗면 0보다 3칸 아래 잔디(떨어져도 다치지 않거나 조금만 다친다). 둘레는 보이지 않는 벽.
- 코스는 생성기 seed로 정해지는 파일로 남긴다. 학습·개발·최종 코스를 서로 다른 생성기 seed에서 뽑아, 최종 코스는 학습에 한 번도 나오지 않는다.
- fixture에 코스 자체(`course`)를 함께 적는다. 게임 모드는 모르는 키를 무시하고, 단계 판정·교사·성공 판정은 이 값을 읽는다(특권 정보).

## 3. 단계(기술 내부 RM)

상위 목표 RM은 "목표 발판 도달" 하나다. 기술 내부 단계는 상태로 정의하고 키 입력을 단계로 만들지 않는다.

| 단계 | 진입 조건(증거: 서버 좌표·땅 접촉·코스, 특권) |
|---|---|
| turn | 발판 k 위에 서 있고, 다음 발판 쪽이 시선에서 20도 넘게 벗어남 |
| run | 발판 k 위, 다음 발판을 보고 있고, 다음 발판 방향의 가장자리까지 0.35블록보다 멂 |
| edge | 발판 k 위, 다음 발판을 보고 있고, 가장자리까지 0.35블록 이내 |
| air | 땅에 닿지 않음(떨어짐 아님) |
| fallen | 떨어짐(실패, 끝) |
| goal | 목표 발판 위(성공, 끝) |

- k는 마지막으로 서 있던 발판이다. 다음 발판에 내려앉는 것이 상태 변화(진행)이고, 이전 발판으로 돌아가면 k도 돌아간다(건너뛰기·되돌아가기 허용).
- 단계는 정책 입력(잔차 헤드의 one-hot, 6칸)과 기록에 실제로 들어간다. 채굴 헤드와 단계 목록이 달라 체크포인트가 섞이지 않는다.

## 4. 교사(특권, 정답 라벨 전용)

- turn: 다음 발판 윗면 중심 쪽으로 시선(한 번에 축마다 최대 10도), 이동 없음.
- run: 같은 시선 + 앞으로. 틈 2 또는 올라가는 점프면 달리기도 누른다.
- edge: run과 같고 점프를 누른다.
- air: 다음 발판 쪽 시선. 몸 중심이 다음 발판의 가까운 가장자리를 지나면 앞으로를 뗀다(지나쳐 떨어지지 않게, 달리기도 여기서 끝난다). 달리기는 run과 같다.
- goal·fallen: 라벨 없음.
- 가장자리 거리는 진행 방향으로 잰다. 높은 발판의 가까운 쪽에 몸 일부만 걸쳐 내려앉으면 몸 중심은 발판 밖이지만, 다음 점프까지는 발판 하나를 건너야 한다.
- **게임 전 대략 점검(2026-11-13, 게임 아님).** 마인크래프트 1.16 이동 규칙(지면 가속·마찰, 공중 가속·감속, 점프 0.42, 달리기 점프 가속)을
  흉내 낸 간단한 시뮬레이션으로 교사를 돌렸다. 처음 규칙은 생성 코스 800개(코스 200 × 시작 방향 4) 중 721개를 건넜다. 실패는 두 가지였다.
  (1) 위 가장자리 오판, (2) 올라가는 점프의 달리기가 다음 짧은 점프까지 이어져 지나침. 둘을 고친 뒤 788/800, 학습 코스 48/48이었다.
  점프 3번 코스(09:10 수정)에서는 800/800, 학습·개발·최종 코스 모두 통과.
  시뮬레이션은 충돌·미끄러짐을 단순화했으므로 게임 점검을 대신하지 않는다.
- 교사가 실제로 코스를 건널 수 있는지는 게임에서 먼저 확인한다(교사가 직접 조작하는 준비용 실행, 정책 성공으로 세지 않음).
  교사 단독 성공률이 학습 코스에서 80% 미만이면 학습을 시작하지 않고 교사부터 고친다. **(내 결정)**

## 5. 학습과 평가 (채굴 배치가 끝난 뒤)

- 정책: 고정 STEVE-1 + 단계 입력 잔차 헤드(채굴과 같은 구조, 단계 목록만 다름). 문구 후보 "jump across the platforms to the gold block".
- 코스(생성기 seed): 학습 101–112, 개발 201–204, 최종 301–308. world seed: 학습 코스는 학습 seed 3개를 번갈아(코스 번호 mod 3),
  개발 130363, 최종 **244948(지금 정함, 처음 쓰는 seed)**. 한 판 90초.
- 교사 점검(준비용): 학습 코스 12개를 한 번씩. 10/12 미만이면 학습하지 않는다.
- DAgger: R0 공식 → 자료 → j-r1 → R1 → 자료(R0–R1) → j-r2 → R2 → 자료(R0–R2) → j-final. 라운드마다 학습 코스 12판.
  학습 설정은 채굴과 같다(KL 10, 단계 균형, patience 2). 검증용으로 마지막 라운드의 코스 111·112 실행을 뺀다.
- **개발 판정 (미리 정함):** 개발 코스 4개 × 샘플링 2 = 갈래마다 8판. j-final의 목표 도달 수가 공식보다 많고 3/8 이상.
  통과할 때만 최종 코스 8개 × 1판(갈래마다 8판)을 같은 기준으로 본다.
- 함께 보고: 떨어짐 수, 성공 시간 중앙값, 가장 멀리 선 발판, 점프 종류(틈·높이)별 착지.
- 실행 스크립트: `results/jump-20261113/launch/jump.sh`(주 작업 폴더에서 `jump-map` 브랜치로).

## 6. 구현

- `src/minecraftrl/jump_course.py`: 코스 생성기, 코스 → fixture, 월드 좌표 변환, 단계 판정(`JumpTracker`), 교사.
- `src/minecraftrl/reacquire_head.py`: 헤드가 단계 목록을 인자로 받는다(기본값은 채굴 단계, 기존 체크포인트 그대로).
- 기록 행: `server_on_ground`, `server_fall_distance` 추가.
- 세션: `until='course'` 단계(목표 도달 = 성공, 떨어짐 = 실패로 끝). 점프 헤드용 hook과 latent 기록.
- 채굴 배치가 끝나기 전에는 이 브랜치를 주 작업 폴더에 가져오지 않는다.
