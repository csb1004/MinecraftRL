# P4.1: goal-queue STOP 도구의 bank 경로 사전검사 수정

P4 성능 배치 실행 중 코드 검토에서 발견했다. `probe_rm_conditioning_stop.py`에
`goal-queue` CLI 옵션은 추가했지만 bank 존재 검사에는 이전 단일 bank의
`goal-bank/manifest.json` 경로가 남아 있다. 실제 queue bank는 `goal-bank/wood/manifest.json`
및 공식 `goal-bank/dirt.npy`다. 따라서 원래 P4의 마지막 STOP 도구는 게임을 시작하기 전에
실패할 것으로 예상된다. 이는 STOP 전달/해제의 실제 실패 표본과 다르다.

고정된 성능 배치 도중 helper나 bank 구조를 변경하지 않는다. 원래 드라이버의 결과와
사전검사 오류를 보존하고 종료한 뒤에만 queue 모드의 manifest 경로를 수정한다.
기존 단일 bank 모드의 경로는 유지한다. 경로 검사의 회귀 테스트를 수정 전/후로 실행한다.
원래 성능/학습 19회를 다시 실행하지 않는다.

별도 `results/rm-goal-queue-stop-r1-20261031`에 P4 bank와 wood program을 복사해 해시를 확인하고,
수정 소스·명령·원래 실패 원인·재개 근거를 보존한다. 동일 seed 81031999,
`goal-queue --s1-record`, 초기 phase head, 정상 transition 10회 후 STOP 1회라는
원래 P4 진단 조건을 유지한다. 기준을 완화하지 않는다.

원래 배치가 남긴 STOP은 이 사용자 승인 작업의 기술 수정 검사를 위해 원문·해시를
보존해 한 번만 이동한다. 사용자가 새 STOP을 보냈거나 원문이 예상과 다르면 재개하지 않는다.
검사 뒤 STOP 유지. 새 정책 행동 0, 실제 입력 해제, held keys 0, 소유 PID 0,
정상 취소 worker exit 2를 모두 실제 실행에서 확인한다. 성능/학습 표본에 포함하지 않는다.
