# 다리 잇기 — 계획 (2026-11-14, 구현 전)

- 상태: 계획만. [블록 놓기 기초 기술](2026-11-14-place-block-design.md)이 게임에서 검증된 뒤 구현한다. LLM vocabulary에 넣지 않는다.
- **11-14 05:00 갱신:** [다리 잇기 설계](2026-11-14-bridge-design.md)로 구체화했다. §2–3의 "앞을 보고 걷다가 앞 옆면을 겨눔"은 조준이 닿지 않아, 설계에서 "뒤로 돌아 웅크린 채 뒷걸음"으로 바꿨다.
- 재료: 점프 코스(발판·낙하 판정·클라이언트 자세)와 블록 놓기(놓기 관측·조준 면·서버 놓기 기록)를 합친다.

## 1. 과업과 성공

- 시작 발판(폭 3)과 목표 발판(금 블록, 폭 3) 사이에 같은 높이의 틈 3–5칸이 있다. 뛰어서는 건널 수 없다. 아래는 3칸 낮은 바닥이다.
- 손에 조약돌 32개. 성공 = 서버가 목표 발판 위에 서 있음을 보고(점프 코스와 같은 판정). 실패 = 떨어짐 또는 시간 초과(90초).
- 진행 = 틈에 놓인 블록 수(서버 놓기 기록 중 다리 줄 위의 칸). 다리 줄 밖에 놓은 블록은 따로 센다.

## 2. 단계(기술 내부 RM, 상태로 정의)

| 단계 | 진입 조건 |
|---|---|
| walk | 발판이나 놓은 블록 위, 다리 줄의 다음 빈 칸 앞 가장자리까지 0.3블록보다 멂 |
| edge | 가장자리 0.3블록 안, 조준선이 다음 빈 칸을 채우는 면이 아님 |
| place | 조준선이 다음 빈 칸을 채우는 면(발밑 블록의 앞 옆면) |
| air / fallen | 점프 코스와 같다 |
| goal | 목표 발판 위(서버) |

- 다음 빈 칸 = 다리 줄(시작 발판 앞 가장자리에서 목표 발판까지, 발밑 높이)에서 아직 블록이 없는 첫 칸. 서버 놓기 기록으로 채운다.

## 3. 교사(특권)

- walk: 다리 줄 방향을 보고 웅크린 채 앞으로(웅크리면 가장자리에서 떨어지지 않는다).
- edge: 웅크린 채 서서, 발밑 블록의 앞 옆면 중심을 겨눈다(크게 내려다봄).
- place: 시선 유지 + use. 놓이면 다음 칸이 바뀌어 walk로 돌아간다.
- 마지막 칸을 채우면 목표 발판까지 걸어간다.

## 4. 검증 순서

1. 블록 놓기 기술의 교사 점검과 개발 판정을 먼저 본다.
2. 다리 교사를 시뮬레이션(점프 코스 이동 + 놓기 조준)으로 점검한 뒤 게임 교사 점검(10/12 관문).
3. DAgger와 개발·최종 판정은 점프·놓기와 같은 틀(학습·개발·최종 코스와 seed 분리, 판정은 게임 전에 정함).

## 5. 건축(그다음)

설계도(칸 목록) 채우기는 블록 놓기를 순서대로 되풀이한다. 아래층부터, 받침이 있는 칸부터 고르는 것이 교사의 몫이다. 성공은 설계도의 모든 칸이 서버 놓기 기록으로 채워진 것이다.
