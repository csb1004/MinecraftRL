# 지속 RM 진행 상태와 우선순위 목표 대기열

사용자 승인: 앞선 병목 개선안을 실행하고, 큰 목표를 우선순위 대기열로 유지한다.
예: 나무 확보 완료 → 돌 확보. 기존 연구 명세/P1~P3 조건·결과는 보존한다.

## 실행 계약

- 상위 목표 대기열은 기존 `PriorityLedger`를 재사용한다. 우선순위 큰 값 우선, 동률은 등록 순서.
  선행 목표는 **완료**만 의존성을 해제한다. 일시정지/실패/취소는 완료가 아니다.
- 시작한 목표는 대기 시간이 길어지거나 우선순위가 바뀌어도 자동 선점하지 않는다.
  완료 또는 명시적 차단/취소 뒤 실행 가능한 다음 목표를 선택한다. 목표·이력은 삭제하지 않는다.
- 현재 목표가 복구를 시도하는 동안 상위 목표 identity를 유지한다. 정체가 확정돼 실행을
  차단하면 미완료 원인과 증거를 남긴다. 실행 스킬 없는 목표를 기본 탐험으로 대체하지 않는다.
- 상위 완료는 활성화 시점 대비 실제 서버 inventory 순증가로 판정한다. 미리 가지고 있던
  아이템, 같은 관측의 중복 전달, 앞 목표의 획득을 후속 동일 목표에 중복 가산하지 않는다.
- 단계 RM은 현재 센서 힌트와 확인된 사건 이력을 분리한다. 상호작용 결과가 확인되면
  회수를 시도하되 획득/제한된 정체로만 해제한다. 대상 힌트 만료만으로 탐색으로 돌아가지 않는다.
- 신규 획득/확인된 상호작용/더 높은 도달 단계는 진전이다. 반복 버튼·이동량 자체는 진전이 아니다.
  현재 관측기로 확인할 수 없는 사실은 만들지 않는다. 관측기/JAR를 변경하지 않는다.
- recovery의 새 운동 스킬은 성공이 확인되기 전 capability로 등록하지 않는다. 제어 차단 시
  원인과 목표·과거 시도 기록을 저장하고, 외부 LLM 호출은 하지 않는다.
- STOP/실제 사망/최종 성공이 모든 선택보다 우선한다. 완료 행동의 RNN commit 후 다음 목표를
  선택하며 종료 후 새 행동은 없다. 목표 변경과 world reset을 구분한다.

## 구현 단위

1. `PriorityLedger`에 opt-in 완료 경계 선택/FIFO 동률을 추가한다. 기존 aging 세션 기본값은 유지한다.
   현재 LOGO 실행에 일반적인 상호작용/결과 회수 상태를 opt-in으로 연결한다.
2. caller-owned 목표 manifest와 inventory 완료 계약을 감싼 상위 큐를 연결한다. 정책에는 목표/단계/
   실제 임베딩과 goal revision을 함께 기록한다. 돌 목표는 저장하되 도구/실행 지원 미충족 시 차단한다.
3. 일반화된 단계 조건의 전달·행동 확률·실제 실행을 나눠 검사한다. 하위 조건이 같은 임베딩을
   쓰는 것은 숨기지 않는다. 상태를 늘리는 것만으로 스킬이 학습됐다고 보지 않는다.
4. 공식 모델에서 시작하는 별도 S1 학습 경로를 준비한다. 제거한 과거 전용 실험 경로/가중치를
   복구하지 않는다. 수집 확률 재현·STOP·종료/시간 제한 처리 검증 뒤에만 새 RL 업데이트를 실행한다.
   학습 범위/예산/시드와 평가는 실행 전에 별도 프로토콜에 고정한다.

## 검증

의존성/동률/우선순위 수정/활성 목표 유지/중복 획득/같은 자원 연속 목표/미지원 목표/차단/STOP를
회귀 검사한다. P3 원본 실패 궤적 replay는 전환 수정 검증이며 새로운 성공 표본으로 세지 않는다.
실제 게임은 새 결과 폴더/소스 해시/실행 전 프로토콜로 수행한다. 초기 상태·화면·tick/wall time을
따로 기록하고, 개발/학습/평가 시드를 분리한다. 미실행은 성공/실패 표본에 포함하지 않는다.

대기열 기능 완성과 나무→도구 제작→돌을 모두 자율 수행하는 능력은 별개의 검증 항목이다.
