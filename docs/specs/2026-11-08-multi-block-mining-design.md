# 여러 블록으로 캐기 하위 단계 학습 — 설계 (2026-11-08)

- 상태: 사용자 방향 결정(11/8). "여러 블록 학습 설계로 가자", "철 빼고 학습해줘".
  사용자가 질문 없이 바로 진행하라고 해서, 아래 **(내 결정)** 값은 사용자가 정하지 않은 것이다. 바꿀 수 있다.
- 앞선 설계: [대상 쪽으로 돌아서기](2026-11-07-target-reacquire-design.md). 교사·학생·단계 판정·잠재 벡터 기록은 그대로 다시 쓴다.
- 근거 기록: [돌아서기 결과와 최종 평가 뒤 점검](../reacquire-results-2026-11-07.md), 경기장 v2 문구 확인(`results/iron-demo-probe-20261104-arena-v2`).

## 1. 왜

사용자 질문(11/8): "탐색해서 뭔가를 캐는 걸 학습한다고 해도 특정 블록만 잘 하는 게 아니라, 다른 블록에 적용해도 잘 되게끔."

기존 기록을 다시 읽은 결과(게임 없음):

- 같은 경기장, 같은 고정 STEVE-1, 같은 파괴 시간(약 23틱: 나무 곡괭이로 돌, 돌 곡괭이로 철광석)에서 시도 결과가 문구에 따라 크게 갈렸다.

  | 목표 조건 | 대상 | 조준 중 공격 | 채굴 시도 중 파괴로 끝남 | 대상 위에서 공격을 뗌 |
  |---|---|---|---|---|
  | "mine stone" 문구 | 돌 | 99% | 9/12 | 3 |
  | "mine iron ore" 문구 | 철광석 | 70% | 2/49 | 25 |
  | dig 영상 조건 | 돌 | 59% | 4/203 | 115 |

- 나무 수집(10/31)에서는 같은 정책이 원목에 공격을 60~84틱 연속으로 눌렀다(맨손 원목 파괴 시간이 약 60틱).
- 그래서 "깨질 때까지 누르기"는 STEVE-1에 이미 있고, 목표 조건에 따라 켜지거나 꺼진다고 본다.
- 앞선 학생은 철광석 자료로만 학습했다. 배운 것은 이 경기장의 철광석 출력 보정에 가깝고, 다른 블록으로 옮겨 갈 근거가 없다.

## 2. 목표, 비목표, 실패로 볼 것

**목표**

1. 돌아서기·조준·채굴 단계의 residual을 **철광석이 아닌 여러 블록**으로 학습한다.
2. **철광석은 학습에 한 번도 쓰지 않고**(사용자 결정) 처음 보는 블록으로 평가한다. 철광석에서 나아지면 "다른 블록에도 된다"의 직접 증거가 된다.
3. 성공은 서버 인벤토리로만 판정한다. 개선 지표는 사용자가 정한 대로 시간(쓸데없는 행동)과 성공이다.

**비목표**

- 탐색·접근 학습. 사용자가 잘 된다고 했고, 넓은 장소와 다른 교사가 필요하다.
- 문구 바꾸기(조건 교체 확인). 사용자가 건너뛰었다. 각 블록 문구는 같은 틀("mine {블록}")로 고정한다.
- 영상 인코더(CNN) 학습, 단계 입력 없는 학생 갈래. **(내 결정)** 앞선 실험에서 단계 없는 갈래가 나아지지 않았고, 실행 수를 줄이려고 뺀다.
- 파이프라인 기본 정책 교체. 후보 저장은 채택이 아니다.

**실패로 볼 것 (기술적으로 돌아가도)**

- 철광석 기록(어느 seed든)이 학습 자료에 들어가는 것.
- 평가 실행 중 교사나 규칙이 행동을 보내는 것.
- 학습 블록에서만 나아지고 철광석이 그대로인데 "일반화됐다"고 쓰는 것.
- 성공이 줄었는데 시간이 줄었다고 개선이라 부르는 것.

## 3. 블록과 경기장

경기장은 철광석 경기장(fixture v2 + 돌 곡괭이 지급)을 그대로 쓰고, **철광석 두 개 자리에 대상 블록만 바꿔 넣는다.** 배치·나무·벽·바닥은 같다. 블록 말고는 바뀌는 게 없게 하려는 것이다.

학습 블록 6개 **(내 결정)**. 경기장의 다른 블록(돌·흙·잔디·원목)을 캐서는 얻을 수 없는 아이템이 나오는 블록만 골랐다.
돌 곡괭이를 든 상태의 파괴 시간을 15~60틱으로 섞어서, "N틱 누르기"가 아니라 "깨질 때까지 누르기"를 배우게 한다.

| 블록 | 성공 아이템 | 돌 곡괭이 파괴 시간 | 문구 |
|---|---|---|---|
| coal_ore | coal | 약 23틱 | mine coal ore |
| lapis_ore | lapis_lazuli | 약 23틱 | mine lapis lazuli ore |
| sand | sand | 약 15틱 | mine sand |
| clay | clay_ball | 약 18틱 | mine clay |
| white_wool | white_wool | 약 24틱 | mine white wool |
| oak_planks | oak_planks | 약 60틱 | mine oak planks |
| **iron_ore (평가 전용)** | iron_ore | 약 23틱 | mine iron ore (기존) |

- 조약돌은 뺐다. 벽의 돌을 캐도 조약돌이 나와서 성공 판정이 틀린다.
- 모래는 바로 아래가 돌이라 떨어지지 않는다.
- 문구 임베딩은 기존 `prepare_demo_prompts.py`와 같은 방법(공식 prior, seed 31031)으로 만든다. cond_scale은 철광석과 같은 6이다.

## 4. 교사와 학생

- 교사: 앞선 설계 §4의 hold 방식 그대로. 조준선이 대상 블록 위면 시선 정지 + 공격, 아니면 대상 쪽으로 최대 10도 돌기. 블록 이름만 바뀐다.
- 학생: 앞선 설계 §5의 0 초기화 residual + 단계 one-hot(특권 단계 입력). 블록 정보는 따로 넣지 않는다.
  STEVE-1 잠재 벡터는 각 블록 문구로 조건화된 것이므로, 학생은 "이 문구 아래에서 어떻게 고칠지"를 블록 여러 개에서 배운다.
- 모든 블록이 **하나의 체크포인트**를 함께 쓴다.

## 5. 자료 수집

- seed: 학습 전용 world seed 3개(271828, 314159, 161803). 개발 130363, 최종 seed는 학습에 쓰지 않는다.
- 실행 하나: 대상 블록 1개 수집 단계, 제어 180초, 도구 고정, 감시 없음(앞선 probe와 같음).
- DAgger 3라운드 **(내 결정)**. 라운드마다 블록 6개 × seed 3개 = 18회.

  | 라운드 | 실행 정책 | 샘플링 seed |
  |---|---|---|
  | R0 | 공식 STEVE-1 | 1 |
  | R1 | R0 자료로 학습한 학생 | 2 |
  | R2 | R0–R1 자료로 학습한 학생 | 3 |

- 실행 폴더 이름에 블록을 넣는다(`<블록>-s<seed>-n<n>`). 자료 구축이 블록마다 대상·성공 아이템을 실행 기록에서 읽는다.

## 6. R0 관문 (공식 기준선)

R0가 블록별 기준선 조사를 겸한다. 블록마다 성공 수, 조준 중 공격 비율, 채굴 시도 중 파괴로 끝난 비율을 보고한다.

- **계속 조건 (내 결정):** 공식 STEVE-1의 "파괴로 끝난 시도 비율"이 50% 미만인 블록이 2개 이상이어야 한다.
  모든 블록에서 이미 잘 캐면 교사 정답이 공식 행동과 같아서 고칠 것을 배울 수 없다. 그러면 학습하지 않고 보고한다.

## 7. 학습

앞선 결과 문서의 "다음 학습 제안" 2–3을 반영한다.

- 손실: 정답 행은 BC, 정답 없는 행은 공식 정책과의 KL(계수 10, hold-on과 같음). lr 1e-4, batch 32, 최대 16 epoch, 평균 KL 한도 3.
- **균형 (내 결정):** BC를 (블록, 단계) 묶음별 평균으로 건다. 공식이 실패하는 블록은 실행이 길어 행이 많고, 손 닿는 곳(near)이 정답 행의 대부분이라 묶음별로 맞춘다.
- **보류:** 가장 최근 라운드의 실행 중 블록마다 1개(6개)를 떼어 둔다.
- **수렴:** 보류 NLL이 2 epoch 연속 나아지지 않으면 멈추고 가장 좋았던 epoch로 되돌린다.
- 게임 전 검사: 학습 전 출력 차이 0, 저장/재로드 차이 0, 보류 NLL 감소(기존 검사 그대로).

## 8. 오프라인 관문 (게임 없음, 철광석 개발 비교 전)

철광석 기록은 학습에 쓰지 않지만, 이미 있는 철광석 잠재 벡터(앞선 실험의 학습 seed 공식 실행)로 **학생의 철광석 공격 유지 확률을 미리 볼 수 있다.**

- 잴 것: 철광석 조준·채굴 hold 정답 행에서 학생과 공식의 p_hold(시선 정지 + 공격 확률), 22결정 유지.
- **진행 조건 (내 결정):** 학생의 철광석 채굴 행 평균 p_hold가 공식보다 낮지 않아야 한다. 낮으면 개발 게임 없이 원인을 분석한다.
- 학습 블록 보류 실행의 같은 값도 함께 보고한다.

## 9. 개발 비교 (철광석, seed 130363)

- 갈래 3개 **(내 결정)**: 공식 / 철광석 전용 hold-on 학생(기존 체크포인트) / 여러 블록 학생. 같은 샘플링 seed 1–4로 짝지어 4회씩 = 12회.
- 철광석 경기장 설정은 앞선 실험과 같아야 한다(같은 설정·fixture·계획 파일 내용).

**미리 정하는 판정 (내 결정).** 여러 블록 학생이 "철광석에서 나아졌다"고 쓰려면 셋 다 만족해야 한다.

1. 성공 수가 공식보다 적지 않다.
2. 철광석 채굴 시도 중 파괴로 끝난 비율이 공식의 2배 이상이고, 철광석 전용 학생보다 높다.
3. 성공한 실행의 철광석 단계 게임 시간 중앙값이 공식보다 길지 않다.

하나라도 안 되면 개선이라고 쓰지 않고 상태별 확률·행동으로 분석한다. 표본이 작으므로 관찰로 보고한다.

## 10. 최종 평가

- 개발 판정을 모두 통과할 때만 한다.
- **최종 seed를 지금 미리 정한다: 662607.** 갈래는 공식과 여러 블록 학생, 각 8회(샘플링 seed 21–28).
- 판정은 §9와 같은 세 조건(2번의 "철광석 전용 학생보다" 부분 제외)을 최종 seed에 적용한다.
- 최종 평가가 기준선을 넘을 때만 main 병합을 사용자에게 묻는다.

## 11. 기록과 공개

- 특권 관측(교사, 단계 입력, fixture 좌표, 서버 자세)과 곡괭이 지급(준비 단계)을 보고에 밝힌다.

- 원본 궤적·체크포인트·월드를 보존한다. 결과 폴더(`results/multi-block-20261108/`)는 Git에서 제외한다.

## 12. 위험

- **문구 근거.** 블록마다 같은 틀의 문구를 쓰지만, MineCLIP이 블록 이름을 얼마나 잘 아는지는 블록마다 다르다. R0 조사가 이를 드러낸다.
- **경기장 하나.** 모든 자료가 같은 배치다. 결과는 이 경기장에서의 일반화다.
- **광석 모양 유사성.** 석탄·청금석은 철광석과 질감이 비슷하다. 철광석이 나아져도 "모양이 다른 블록"으로의 일반화는 따로 확인해야 한다. 학습 블록 중 모래·양털·판자가 이 점을 일부 보완한다.
- **회수 단계.** 블록이 부서진 뒤 줍지 않는 문제는 이번 범위 밖이다(교사가 회수 단계에 정답을 붙이지 않는다).

## 13. 구현자에게 맡기는 것

- 블록별 설정·fixture·계획 파일을 만드는 방식(기존 철광석 배치 실행기의 확장 또는 새 실행기). 철광석 설정은 앞선 실험과 내용이 같아야 한다.
- (블록, 단계) 균형 가중치 계산과 최선 epoch 되돌리기의 정확한 구현.
- 블록별 기준선·채굴 시도 집계 스크립트의 위치.
