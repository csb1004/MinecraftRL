# 건축 4차 — 잘못 놓지 않는 건축(신중한 놓기) (2026-11-15 05:30)

- 상태: 사용자 지시(11-15 05시께).
  - "학습 더 필요하다고 판단되는 부분 있으면 진행해. 특히 건축 같은 부분은 잘못 설치하는 것도 문제가 없는 건 아니니까. 집 짓기 같은 건 외관도 중요하니"
  - 세부는 내가 정했다(**(내 결정)**). 게임 전에 이 문서로 자료·순서·판정을 정했다.
- 코드는 브랜치 `build-careful`에서 만들고, `jump-map`에 로컬 병합해 돌린다. main 병합과 push는 하지 않는다.
- 앞선 결과: [건축 3차 결과](../build-results-2026-11-15.md)(개발·최종 8/8, 가림 점검 회복 확인), [3차 설계](2026-11-15-build-recover-design.md).
- 바꾸지 않는 것:
  - 과업 생성기, 성공 판정(서버 설치 기록이 설계도 칸을 모두 덮음), 시간 제한 60초.
  - 모델(STEVE-1 고정 + adapter만 학습), 단계 5개, 특징 11개.
  - KL 10·balance·patience 2·특징 배율 10, use-coef 1(3차에서 고른 설정).

## 1. 왜 하나 — 3차의 잘못 놓음 (게임 없음)

- 3차 c3-final은 성공했지만 잘못 놓은 블록이 남았다. 개발 3개, 최종 1개, 가림 점검 12개다.
- **깔끔한 성공**은 성공하면서 잘못 놓음이 0인 판이다. 개발 6/8, 최종 7/8, 가림 점검 1/8이었다.
- 집처럼 모양이 중요한 건축에서는 잘못 놓은 블록도 실패에 가깝다.
- 원인을 설치 4행 전 누름과 짝지어 보고, c3-final의 `use` 확률을 CPU로 다시 계산했다. 계산은 각 판의 기록된 잠재값·단계·특징으로 했다.
  1. **조준 단계 누름**(개발 3, 최종 1, 가림 8):
     - 개발·최종에서는 확률 0.007–0.07의 드문 뽑힘이었다. 1개(204 n1)만 0.41이었다.
     - 가림 점검에서는 0.36–0.96으로 높았다. 돌아간 뒤의 낯선 상태에서 정책이 확신을 갖고 눌렀다. 조준 단계 확률을 모두 더하면 15.6으로, 개발의 1.5보다 크다.
  2. **놓기 단계 누름**(가림 4): 확률은 0.85–1.0이었다.
     - 기록된 십자선 칸은 목표를 가리켰다. 하지만 401의 예를 계산하면, 시선이 목표 칸 바닥과 그 너머 칸 바닥의 경계(약 0.01블록)를 스쳤다.
     - 십자선이 면 가장자리에 있으면 기록과 실제 설치가 어긋날 수 있다.

## 2. 신중한 놓기 교사 (`build.teacher = "careful"`) **(내 결정)**

- 3차 회복 교사(`recover`)와 같고, '놓기' 단계 조건만 좁힌다(`CarefulTracker`).
  - 기존 조건: 기록된 십자선 칸·면이 목표 칸에 놓인다.
  - 더하는 조건(`inner_hit`): 클라이언트 눈 위치·yaw·pitch로 그은 직선이 추적 중인 블록들 사이에서 처음 닿는 면에 놓으면 목표 칸에 들어가야 한다.
    또 그 면의 가장자리에서 0.2블록 이상 안쪽(가운데 0.6×0.6)에 닿아야 한다.
- 둘 중 하나라도 아니면 '조준' 단계다. 교사는 보이는 면의 중심 쪽으로 고개를 돌리고 누르지 않는다.
- 놓기 행동(카메라 회전 없이 `use`), 단계 목록, 특징, 회복(`move`)은 3차와 같다.
- **시뮬레이터 점검(게임 아님):** 시드 56개 × 방향 4개 × 2번 = 448판에 카메라 잡음 3도와 15% 쉼을 넣었다.

  | 조건 | 회복 교사 | 신중한 교사 |
  |---|---|---|
  | 가림 없음 | 448/448, 잘못 놓음 0, 결정 중앙값 18 | 448/448, 0, 23 |
  | 첫 칸 앞 가림 | 441/448, 0, 22 | 441/448, 0, 26 |

  시뮬레이터는 설치를 결정 시점 시선으로 계산하므로, 가장자리 문제는 재현하지 못한다. 멈추지 않는지만 확인했다.

## 3. 학습 자료 **(내 결정)**

- **d4-r0-3:** 1–3차 학습 수집 R0·R1·R2·R3 48판을 신중한 교사로 다시 라벨링한다. 검증 판은 R3의 c111·c112(n4)다. 이걸로 c4-a를 학습한다.
- **R4 수집(c4-a):**
  - 학습 과업 101–112, 샘플링 5(처음 씀), 12판.
  - 가림 학습 과업 8개, 샘플링 1, 8판. 504, 506, 507, 514, 518, 527, 533, 538이다(학습 seed 회전, `occluded_train` 모드).
    - 고른 규칙은 가림 점검과 같다. 501부터 차례로 보며 첫 칸 앞이 비어 있고, 설계도·가림 칸이 앞서 고른 것과 겹치지 않는 첫 8개다.
  - 가림 상태에서 학생이 확신을 갖고 누르던 결정에 '누르지 말고 보이는 면 중심을 조준'이라는 라벨이 붙는다.
- **d4-r0-4:** R0–R4 68판이다. 검증 판은 R4의 c111·c112(n5)다. 이걸로 c4-final을 학습한다.
- 가림 점검(seed 707106, 과업 401–431)의 게임은 학습에 쓰지 않는다.

## 4. 순서와 판정 (먼저 정함)

배치 폴더는 `results/build4-20261115/`, 실행 스크립트는 `launch/build4.sh`다. 한 번에 게임 하나씩 돈다. 게임과 학습 전에는 GPU가 2150MiB 이상 비기를 기다린다.

1. **교사 점검(준비용, 정책 결과 아님):** 학습 과업 12판과 가림 학습 과업 8판이다. 20판 중 18판 이상 성공하지 못하면 멈춘다.
2. **d4-r0-3 → c4-a → R4(20판) → d4-r0-4 → c4-final.**
3. **개발(dev4, seed 302585, 처음 씀):** 일반 과업 601–608과 가림 과업 705, 710, 712, 718, 726, 735, 736, 742를 샘플링 1로 돈다. 갈래마다 16판이다.
   - c4-final은 신중한 교사 fixture로 돈다.
   - c3-final(3차, 바꾸지 않음)은 자기가 학습한 회복 교사 fixture로 돈다.
   - 공식은 개발에서 돌리지 않고 최종에서 돌린다.
     - 지금까지 건축 게임 36판에서 모두 실패했다. R0 12판, 1차 개발 8판, 3차 최종 8판, 가림 점검 8판이다.
   - **판정:** c4-final의 깔끔한 성공 수가 c3-final보다 많고, c4-final의 성공 수가 c3-final보다 2 이상 적지 않으면 통과한다.
4. **최종(final4, seed 866025, 처음 씀, 개발 통과 때만):** 일반 과업 801–808과 가림 과업 901, 902, 911, 921, 923, 928, 934, 945를 샘플링 1로 돈다.
   - c4-final, c3-final, 공식 각 16판이다. 공식은 신중한 교사 fixture로 돈다(공식은 단계 입력을 쓰지 않는다).
   - **판정:** 개발 판정 조건을 모두 만족하고, 다음도 만족하면 통과한다.
     - c4-final 성공 수가 공식보다 많다.
     - c4-final 성공 수가 8/16 이상이다.

## 5. 밝혀 둘 점

- **특권 입력:** 학습과 평가 모두 설계도, 클라이언트 자세·십자선, 서버 설치 기록으로 단계·특징을 계산한다.
  - 4차에서는 '놓기' 단계가 클라이언트 자세로 그은 직선과 추적 중인 블록으로도 계산된다.
  - 공식 정책은 이 입력이 없다.
- 두 정책은 서로 다른 fixture(교사 이름)로 돈다. 단계 입력의 정의가 정책마다 다르기 때문이다(각자 학습한 정의). 성공과 잘못 놓음은 같은 서버 기록으로 센다.
- 이 학생은 LLM vocabulary에 넣지 않는다.
