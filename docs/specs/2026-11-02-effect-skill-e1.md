# E1: 검증 가능한 결과를 연결하는 RM → 스킬 → RL

상태: 구현 및 개발 검증 대상. U1/U2와 연구 명세의 4단계 방향은 유지한다.

## 문제와 선택

U2에서는 목표 3개 중 실제 2개를 얻어도 최종 목표 보상이 0이었다. 계약 전달 오류는
발견하지 못했지만 추가 단계 조건의 영향은 작았다. 이번에는 최종 목표와 별개인
**검증 가능한 결과 스킬**을 실행 및 학습 단위로 만든다. 특정 좌표/나무 배치에 대한
스크립트를 추가하지 않는다. CNN/CLIP의 결함이나 개선 성능을 선험적으로 단정하지 않는다.

## 계약

- 상위 `goal_spec_v1`은 대상, 최종 수량, 우선순위, 의존성과 성공 판정의 소유자다.
- 하위 `effect_skill_v1` 요청은 상위 목표 해시/ID/개정, 대상 항목, 활성화 당시 기준,
  다음에 넘어야 할 실제 인벤토리 최고치, 증거 종류, 스킬 ID를 포함한다.
- 현재 지원 결과는 `inventory_above_credited_peak` 하나다. 탐색/접근/채굴/회수는 기존
  고정 관측 단계이며 키 입력 단위의 새 RM으로 만들지 않는다. 미지원 결과는 거부한다.
- 스킬 성공은 요청 이후 실제 서버 인벤토리가 요청된 최고치를 초과할 때만 발생한다.
  한 행동으로 여러 개를 얻으면 한 스킬 성공, 최고치는 실제 수량까지 전진한다.
  버리기/재획득은 이전 최고치를 넘지 않으면 추가 보상이 없다.
- 상위 목표가 끝나지 않았으면 같은 목표에서 새 요청을 만든다. 상위 완료/전환은
  기존 큐가 판단한다. 새 목표의 시작 인벤토리를 다시 기준으로 삼는다.
- 요청은 행동 전에 고정한다. 결과는 실제 dispatch 이후에만 기록한다.
  `skill_reward/skill_terminal`과 원래 `reward/terminal`은 별도다. 원래 성공 통계를 바꾸지 않는다.
- 요청의 필요 증가량과 최고치 정보는 실제 정책/가치 입력에 연결한다. 최종 목표 조건과
  임베딩 계약은 U1 규칙을 유지한다. 이번 변경은 임베딩이나 공식 backbone을 변경하지 않는다.

## 실행과 학습 경계

기존 저장 시작 월드/STOP/관측기/commit-only recurrent 경로를 재사용하는 명시적 opt-in이다.
별도 scope/checkpoint/context schema로 S2/R1 자료 혼입을 막는다. 검증된 새 train 자료만
학습한다. PPO 확률/가치 재현, 부모 정책 일치, 공식 motor 보존, 유한 손실을 검사한다.
GAE는 스킬 성공/환경 종결에서 끊으며, 미완료 제한 종료에는 실제 다음 상태 bootstrap을 쓴다.
실패/STOP/개발 자료를 성공 학습 자료로 재분류하지 않는다.

`skill-events.jsonl`과 궤적에는 요청/확정 결과 및 근거를 기록한다. 향후 LLM은 같은 목표
계약을 작성하고, 모니터/SQL/competence 모델은 이 기록을 소비할 수 있다. 이 구성요소들이
이미 구현됐다고 주장하지 않는다. 현재 값은 privileged 고정 관측이며 영상 전용 조건이 아니다.

## 검증

반례: 부분 달성, 수량 급증, 버리기/재획득, 목표 전환, 요청 후 재개정, 잘못된 결과/증거,
내부 스킬 종료 뒤 GAE 누출, 미확정 행동, 취소 자료, 이전 checkpoint, 관측 누출.
기존 R1/S2/U1/STOP 회귀 검사와 새 실제 학습/개발 실행을 분리해 기록한다.
새 조건을 고정한 뒤 작은 실제 pilot를 수행한다. 결과에 따라 재시도하여 성공률을 높이지 않는다.
조건부 adapter 형태는 기존 R1을 재사용한다. 구조 변경과 보상 변경에 더해 새 FiLM 구조까지
동시에 바꾸면 원인 분리가 어려우므로 이번에는 추가하지 않는다.

유료 API/Colab/게시/기존 자료 삭제/모델 승격은 이 작업에 포함하지 않는다.

## 고정 개발 pilot (2026-11-03 실행)

`results/effect-skill-e1-20261102/plan.json`의 새 14회. train은 기존 train 시작 월드에서
원목/흙 pickup 각 1회와 자연 수집 수량 3 각 1회, 총 4회이며 E1 초기 정책으로 새로 수집한다.
그 자료만으로 PPO 1개 후보를 만들고, 초기/후보 각각 개발 5회에서 비교한다.
개발 시드는 81112001/003/007/009/013, 조건은 원목3/흙3/원목1→흙1/흙1→원목1/원목1이다.
회당 제어 시간 ≤180초, pickup ≤400행동, 자연 수집 ≤1200행동.
종료/실패/제한은 모두 보존하며 결과에 따른 성공 재시도를 하지 않는다.
원본 인벤토리/서버 tick 대조 후에만 학습하며, 실제 STOP은 성능 표본과 별도로 1회 확인한다.
기존 개발 월드 재사용이므로 독립 최종 평가가 아니며 소규모 결과로 일반화/개선을 확정하지 않는다.
