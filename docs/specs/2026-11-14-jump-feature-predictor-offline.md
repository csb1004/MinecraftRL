# 점프 v2 특권 입력을 화면 latent로 예측하기 — 오프라인 점검 설계 (2026-11-14)

- 상태: 사용자 지시(11/14 "계속해줘. 중간에 멈추지 말고 네 판단에 필요하다고 판단되면 해"). 세부는 내가 정했다. **(내 결정)**
- 앞선 결과: [점프 v2 결과](../jump-direction-results-2026-11-14.md). j2-final은 개발 7/8, 최종 8/8이었다.
  하지만 단계 one-hot과 방향 특징 7개를 코스 좌표로 계산해 평가 때도 넣었다.
- 이 점검은 게임을 쓰지 않는다. 채굴 v2 배치가 게임을 쓰는 동안 CPU 2스레드, 낮은 우선순위로 돌린다.

## 1. 질문

STEVE-1 latent(2048칸, 프레임 기억 포함)만으로 단계와 방향 특징을 충분히 맞힐 수 있나?
맞힐 수 있으면 "예측기 + j2-final"을 특권 입력 없이 게임에서 시험할 가치가 있다.

## 2. 자료 (학습·개발·최종 분리)

- 자료는 `results/jump-20261114/data/j2-r0-4.pt` 하나다(학습 코스 101–112, v1 R0–R2와 v2 R3–R4의 60판). 코스 단위로 나눈다.
  - 학습: 코스 101–108의 모든 라운드.
  - 검증(조기 종료): 코스 109–110.
  - 시험: 코스 111–112. 기준 3(헤드 확률)은 그중 R4 코스 111·112 행만 쓴다. j2-final이 학습하지 않은 행이다.
- **개발·최종 코스 실행은 쓰지 않는다.** 처음에는 개발 실행을 시험 자료로 쓰려 했다.
  그런데 자료 생성기가 학습 seed가 아닌 실행을 거부했다(`seed 130363 is not a training seed`). 이 보호 장치는 우회하지 않는다.
  덕분에 개발·최종 코스는 나중의 게임 시험에 깨끗하게 남는다.
- 대상 행: 단계가 turn·run·edge·air인 행(goal·fallen 행은 특징이 0이고 라벨이 없다).

## 3. 예측기

- 입력: 지금 결정의 cond latent. 변형 B는 같은 실행의 직전 8개 결정 latent 평균을 이어 붙인다(기억 보강).
- 출력: 단계 4종 분류 + 특징 7개 회귀(`sin_yaw`, `cos_yaw`는 단위 원으로 정규화, `gap2`는 확률).
- 모델: 2048(또는 4096) → 256 → 11 MLP, dropout 0.1, Adam 1e-3, 검증 손실이 5 epoch 안 내려가면 멈춤. seed 0.

## 4. 판단 기준 (실행 전에 정함)

시험 행(코스 111–112)에서 셋을 모두 넘으면 "예측기 + j2-final" 게임 시험을 계획한다(블록 놓기 배치 뒤, 판정은 그때 미리 정함).

1. 단계 정확도 ≥ 0.85.
2. 다음 발판이 화면 밖(시선과 35도 이상)인 행에서 도는 방향(예측 `sin_yaw` 부호)이 맞는 비율 ≥ 0.80.
3. j2-final 헤드에 예측 입력을 넣었을 때, 교사 라벨 기준 세 확률(라벨 쪽으로 돌기, edge 행 점프, 라벨이 달릴 때 달리기)이
   참 입력 때보다 각각 0.10 넘게 떨어지지 않는다.

못 넘으면 결과만 기록하고, 무엇이 모자란지(단계, 화면 밖 방향, 틈 크기)를 다음 설계의 근거로 쓴다.

## 5. 결과 (11-14 04:50, 기준 셋 모두 불통과)

실행: `results/jump-20261114/analysis/feature_predictor.py`(CPU 2스레드, nice 19). 결과 `feature-predictor.json`, 로그 `feature-predictor.log`.
행 수는 학습 4437, 검증 1181, 시험 1365(그중 R4 코스 111·112 108행)이다.
첫 실행에는 출력 순서 버그가 있었다(`gap2`가 확률이 아니었음). 고친 뒤 다시 돌린 값만 적는다.

- 이 108행에는 교사가 점프를 누른 행이 없어 점프 확률은 잴 수 없었다.
- 기준 3: 도는 확률이 0.24–0.27 떨어져 불통과다. 단계 예측만 바꾸면 거의 그대로이고, 손실은 방향 특징에서 나온다.

**해석.** 이 자료 크기(학습 코스 8개)에서 STEVE-1 latent에는 다음 발판의 좌우 방향이 거의 담겨 있지 않다. 화면 안(15도 미만)에서도 0.61–0.69다.
latent는 다음 행동을 고르기 위한 표현이지 물체 위치 표현이 아니라는 뜻으로 읽는다.
그래서 "예측기 + j2-final" 게임 시험은 하지 않는다. 특권 입력 없이 점프 코스를 건너려면 다른 입력이 필요하다.
예를 들어 프레임에서 직접 발판을 찾는 시각 모듈(연구 방향 11/7의 CNN 동시 학습)이나, 실제 맵에서도 얻을 수 있는 경로 표지 같은 것이다.
