## 0. 요약

- **왜:** LOGO 판정식은 고정 관측 위의 등록된 사실만 쓸 수 있다. "벽 4면, 높이 3"은 쓸 수 있지만, "이런 모양의 집"이나 사진 속 집은 판정식으로 다 옮기기 어렵다. 이 한계를 임베딩으로 넘는다(사용자).
- **무엇:** 지식을 임베딩으로 읽는 별도 가치 함수 Q_KB를 둔다. STEVE-1, MineCLIP, 공식 행동 헤드는 건드리지 않는다(사용자).
- **어떻게 고르나 (사용자 방향: 지식이 끌고 간다):**
  - Q_KB가 가장 높은 후보를 고른다.
  - 단, 과제 성공 가능성이 τ 이상이고 가드 1–4를 통과한 후보 안에서만 고른다.
  - 과제와 안전은 거부권만 가진다. τ를 낮출수록 지식이 세게 끈다.
- **어디에 먼저 쓰나 (내 결정):**
  1. 하위 목표 선택(RM 단계 수준): 다음에 무엇을, 어디에 지을지
  2. 헤드 학습 가중치(AWR)
  3. 매 틱 행동 재선택: 보류
- **지식 표현:** 사진 임베딩은 배경에 휘둘린다(사용자 지적). 블록 구조를 원점과 방향을 맞춰 임베딩하는 것을 추천한다. 지식을 설계도로 얻을 수 있는지에 달렸다(D-K3).
- **지식을 썼는지 판정:** 절대 점수 대신 같은 seed에서 지식만 바꿔 넣고 결과 차이를 본다. 배경 차이도 함께 없어진다.
- **MineCLIP fine-tune은 하지 않는다 (내 판단):** STEVE-1이 목표를 잘못 읽게 되고, CLIP 계열이 개수·관계·순서를 잘 담지 못한다(§2.1).
- **남은 결정:** D-K1 지식의 역할, D-K2 학습 신호, D-K3 지식 출처, D-K4 MineCLIP 오프라인 탐침(§10).

## 2. 검토한 길

### 2.1 MineCLIP에 지식을 넣어 fine-tune (버림, 내 판단)

- **담을 수 있는 것이 좁다.**
  - MineCLIP은 16프레임 영상과 자막을 맞춘 대조학습 모델이고, 결과는 512차원 벡터 하나다. 문장은 77토큰까지다.
  - 짧은 시각 행동과 대상("나무를 벤다", "돌집 앞에 서 있다")은 잘 담는다.
  - 개수·크기(5×5, 높이 3), 공간 관계(문은 남쪽), 순서(바닥 다음 벽), 부정, 선행 조건은 CLIP 계열이 공통으로 약하다(Yuksekgonul 외 2023).
  - 16프레임 안에 보이지 않는 지식은 대조학습으로 배울 근거가 없다.
- **STEVE-1이 깨진다.** STEVE-1은 MineCLIP 영상 임베딩을 목표로 받도록 학습됐다. 영상 쪽을 바꾸면 임베딩 공간이 움직여서 본체를 다시 학습해야 한다.
- **자료가 모자랄 것 같다.** (영상, 지식 문장) 쌍이 많이 필요하다. 지금 궤적 수로는 모자랄 것으로 보지만 세어 보지는 않았다.
- **남기는 선택지:**
  - prior만 "명령 + 지식 → 목표 영상 임베딩"으로 다시 학습한다. STEVE-1은 깨지지 않지만, 모양·재료처럼 눈에 보이는 지식에만 효과를 기대할 수 있다.
  - 오프라인 탐침으로 먼저 확인한다(D-K4, §8 K0).
- 이 판단은 논문과 CLIP 계열의 알려진 성질에 근거한다. 우리 MineCLIP으로 재 보지는 않았다.

### 2.2 두 Q의 합 (첫 제안, 주의점만 남김)

- argmax(Q_task + λ·Q_KB)로 고르는 방식이다.
- **합의 함정:** 두 Q를 각자 자기 최적 정책 기준(Q-learning의 max)으로 배우면, 합이 합친 보상의 실제 가치와 달라진다. 실제로 행동하는 정책 기준(SARSA 꼴)으로 배워야 한다(Russell & Zimdars 2003; Hybrid Reward Architecture, van Seijen 외 2017).
- **크기 맞추기:** 두 어드밴티지의 크기가 다르면 합이 사실상 한쪽만 따른다. 비중 λ·|A_KB| ÷ |A_task|를 기록한다.
- 합 방식의 주의점은 §3.4의 AWR 가중치에 그대로 적용된다.

### 2.3 과제 우선, 지식은 동점 깨기 (버림, 사용자 판단)

- 과제 Q로 최선과 ε 이내인 행동들 안에서만 Q_KB가 고르는 사전식 선택이다.
- 지식이 과제를 망가뜨릴 수는 없지만, 지식이 동점일 때 순서만 정한다. 사용자 판단대로 "첨가" 수준이라 버린다.

### 2.4 지식이 끌고, 과제와 가드가 거부 (채택, 사용자 방향)

- 지식이 고르고, 과제와 안전 쪽은 거부권만 가진다(§3.2).
- 통제하기 쉬운 이유:
  - 행동을 지식으로 설명할 수 있다.
  - 지식을 고치면 행동이 바뀐다. 사람이 쥘 수 있는 손잡이가 생긴다.
  - 실패했을 때 지식이 틀렸는지 실행이 틀렸는지 나눠 볼 수 있다(§5).
- 대가는 지식이 틀리면 정책도 같이 틀린다는 점이다. §5의 장치로 다룬다.
- 비슷한 구조로 SayCan(Ahn 외 2022)이 있다. LLM이 고른 "유용한가"와 가치 함수의 "할 수 있나"를 곱해서 둘 다 높을 때만 고른다.

## 3. 구조

### 3.1 망 셋 (내 결정)

| 망 | 입력 | 출력 | 쓰는 때 | 등급 |
|---|---|---|---|---|
| 실행용 Q_KB | 상태 s, 하위 목표 후보 g, 지식 임베딩 k | 지식 부합 가치 | 실행 중 선택(§3.2) | 화면·지시·센서만 |
| 과제 성공 예측 V_task | 상태 s, 하위 목표 후보 g, 상위 목표 | 이 후보로 상위 목표를 이룰 확률 | 실행 중 거부권(§3.2) | 화면·지시·센서만 |
| 학습용 Q_KB critic | 위 입력 + 오라클 | 지식 부합 가치 | 헤드 학습 가중치(§3.4) | 오라클 허용, 학습 프로세스 안에서만 |

- **상태 s:**
  - STEVE-1 latent(화면)
  - 본 지도에서 뽑은 지은 블록 격자(센서 등급, 11-19 §2.4). 집 모양은 화면보다 블록 격자가 정확하다.
  - 인벤토리, RM 단계
- **지식 임베딩 k:** 지시 등급이다. MineCLIP 공간과 맞출 필요가 없다. 구조 인코더(§4.2)나 문장 임베딩을 쓴다.
- **V_task를 따로 두는 이유:** 11-19 §5.3의 critic은 오라클을 읽고 학습 프로세스에서만 쓴다. 실행 중 거부권에는 쓸 수 없다. 그래서 센서 등급만 읽는 성공 예측기를 따로 둔다.
- 셋 다 작은 망이다. STEVE-1과 헤드 옆에 붙고, 본체는 고정이다.
- 실행용 Q_KB와 V_task는 앙상블(예: 5개)로 둔다. 의견 차이를 불확실성으로 쓴다.

### 3.2 선택 규칙 (실행 중)

1. **후보:** RM이 지금 허용하는 하위 목표들이다. 실전 자격을 통과한 기술만 후보가 된다(AGENTS.md, 11-18 §8).
2. **가드:** 가드 1–4(11-19 §2.5)에 걸리는 후보는 뺀다. 가드는 Q 값과 상관없이 먼저 적용한다.
3. **과제 거부권:** V_task(s, g) < τ인 후보는 뺀다.
4. **지식 선택:** 남은 후보 중 w(k)·Q_KB(s, g, k)가 가장 큰 것을 고른다.
   - w(k)는 지식 신뢰도다 **(내 결정)**: `supported` 1, `proposed` 0.5, `disputed`·`retracted` 0.
   - 앙상블 의견 차이가 정한 값보다 크면 지식 선택을 쓰지 않고 RM 기본 순서를 따른다. 이 결정을 "지식 보류"로 기록한다.
5. **남는 후보가 없으면:** hold하고 느린 판단(11-18 §4.5)으로 넘긴다. 스크립트 행동으로 대신하지 않는다(AGENTS.md).

- τ는 개발 seed에서 정한다. 최종 seed는 한 번만 쓴다.
- **기록 (매 결정):** 후보 목록, 각 후보의 가드·거부 결과, Q_KB와 V_task 값(앙상블 평균·편차), 고른 후보, RM 기본 순서였다면 고를 후보, KB revision.

### 3.3 학습 신호 (D-K2)

- 임베딩은 지식을 표현할 뿐이다. Q_KB가 무엇을 맞히도록 배울지는 학습 신호가 정한다. 판정식으로 못 쓰는 지식에서는 이것이 설계의 핵심이다.
- **후보 A, 성공 예시:**
  - 지식에 맞는 완성 결과(블록 격자)를 예시로 모은다.
  - "이 상태에서 이 하위 목표를 고르면 그런 결과에 닿을 확률"을 Q로 배운다. 보상 함수 없이 예시만으로 Q를 배우는 방법이 있다(RCE, Eysenbach 외 2021).
  - 설계도로 지식을 얻으면 예시를 자동으로 만들 수 있다. 사진이면 사람이 지어야 한다.
- **후보 B, LLM·VLM 판정:**
  - 결과 화면이나 구조 요약을 보고 지식에 얼마나 맞는지 점수를 매긴다.
  - 유료 호출(`--allow-paid`)이고, 판정에 잡음이 있고, 판정기를 속이는 방향으로 악용될 수 있다.
- **함께 쓰는 C, 판정식:** 판정식으로 쓸 수 있는 부분(문 개수, 높이, 벽 4면)은 지금처럼 판정식 보상으로 둔다. 임베딩 쪽은 그 밖의 부분만 맡는다.
- **규칙:**
  - 학습 목표 값은 심판(서버 설치 기록·NBT)으로 계산한다(D-S1). 본 지도는 실행 입력에만 쓴다.
  - Q_KB는 §3.2의 실제 선택 규칙 기준으로 배운다(§2.2 합의 함정).
  - 평가는 학습 신호와 다른 판정으로 한다(§6.6).

### 3.4 헤드 학습 가중치 (둘째 자리)

- 11-18 L2의 AWR 꼴 가중치를 exp((A_task + λ·A_KB) / β)로 매기고, 헤드만 갱신한다.
- A_KB는 학습용 Q_KB critic에서 나온다. 11-19 §5.3 critic과 같은 격리 규칙을 따른다. 학습 프로세스에서만 만들고, actor 프로세스는 불러오지 않는다.
- D-S2 기본안(L2부터 critic)이 정해졌으므로, 이 자리는 L2 이후에 쓸 수 있다.
- 비중 λ·|A_KB| ÷ |A_task|를 기록한다.

### 3.5 매 틱 행동 재선택 (보류)

- STEVE-1이 낸 후보 행동 몇 개 중에서 고르는 방식이다. 정책 분포 안에서만 고르니 안전하다.
- 틱 단위 Q는 배우기 가장 어렵고, 본 적 없는 행동에서 과대평가된다. 보수적 Q(CQL 등)가 필요하다.
- K2 결과를 본 뒤에 다시 정한다.

## 4. 지식 표현

### 4.1 사진의 문제 (사용자 지적)

- CLIP 계열 이미지 임베딩은 장면 전체(바이옴, 하늘, 조명, 시간, 시점, 거리)를 담는다.
- 같은 집도 배경이 다르면 다른 집보다 더 멀게 나올 수 있다.

### 4.2 블록 구조 임베딩 (추천)

- **정규화:** 블록 격자를 원점으로 옮기고, 네 방향 회전 중 기준 방향으로 맞춘다. 재료는 범주로 묶는다(예: 판자류, 돌류) **(내 결정)**.
- **같은 공간에서 비교:**
  - 지식: 설계도 또는 KB 구조 템플릿
  - 실행 중 결과: 본 지도(센서)
  - 평가 결과: 서버 설치 기록·NBT(심판)
- **인코더:** 작은 3D 합성곱 또는 점 집합 인코더다. 처음부터 배경이 들어가지 않는다.
- **학습 (게임 없이 가능):**
  - 같은 구조를 옮기고 돌린 것은 같다고 가르친다.
  - 일부만 지은 구조와 완성 구조를 가깝게 둔다. 그래야 짓는 도중에도 진척을 잴 수 있다.
  - 설계도를 생성기로 만들어 쓴다. 건축 과제의 생성기(`build_task.py:33`)를 출발점으로 쓸 수 있다.

### 4.3 사진만 있을 때

- **정규 렌더:** 사진 속 구조와 결과 구조를 둘 다 빈 월드에 다시 지어, 같은 카메라와 조명으로 찍고 임베딩한다. 평가에만 쓸 수 있고, 실행 중 입력으로는 못 쓴다.
- **배경 불변 학습:** 같은 구조를 여러 바이옴에서 찍은 쌍을 같다고 가르치는 대조학습이다. 일이 가장 크다.
- 사진에서 구조를 복원하는 것은 이 설계 범위 밖이다. 인식 모듈은 빼기로 했다(11-18 §8).

### 4.4 KB에 넣는 형태 (코드 변경, 내 결정)

- 새 관계 `structure_template`를 더한다. 값은 원점 기준 블록 목록, 재료 범주, 문·창 같은 기능 칸 표시다.
- 원점 기준이라 위치 특정 지식이 아니다. "위치 특정 지식은 KB에 넣지 않는다"(11-18 §4.5)와 맞는다.
- 조건 키, 근거, 상태 기록은 지금 저장소를 그대로 쓴다. 근거가 `llm_assertion`뿐인 템플릿은 `proposed`로 시작한다.
- 템플릿은 지시 등급이다. 짓는 위치(원점)는 시작 자세 기준으로 정한다.

## 5. 지식이 틀렸을 때

- **거부권:** 가드 1–4와 τ가 지식이 과제와 안전을 망가뜨리는 것을 막는다.
- **KB 반박 연결:**
  - 지식대로 골랐는데 서버 판정으로 실패하면, 그 판을 `game_observation` 근거로 KB에 남긴다.
  - 같은 지식으로 정한 횟수 넘게 실패하면 `disputed`로 내린다 **(내 결정)**. w(k)가 0이 되어 그 지식은 선택에 쓰이지 않는다.
  - 지식이 철회되면 그 지식으로 고른 구간을 학습에서 빼거나 다시 판정한다(11-18 §4.5 오염 방지).
- **지식 오류와 실행 실패 나누기:**
  - 같은 seed에서 지식 없이(RM 기본 순서) 같은 하위 목표를 해냈는데 지식을 넣으면 실패한다면, 지식 쪽 실패로 분류한다.
  - 지식이 있든 없든 그 하위 목표에서 실패하면 실행(헤드) 쪽 실패로 분류한다.
- **보고:** "지식대로 했는데 실패한 경우"를 따로 센다.

## 6. 평가

### 6.1 결과가 지식을 따랐나 (서버 판정)

| 지표 | 정의 | 집 예시 | 쓰임 |
|---|---|---|---|
| 조건 충족률 | KB 정의를 판정식 묶음으로 바꿔 충족한 비율(가중합) | 벽 4면, 높이 3, 문 1개, 지붕 빈틈 0 | 보상 가능 |
| 모양 일치도 F1 | 위치와 네 방향 회전 중 가장 잘 맞는 배치에서 칸 단위 F1 | 틀 밖 블록과 빠진 블록 모두 감점 | 평가 전용 |
| 편집 거리 | 틀과 같아지려면 더 놓거나 캐야 할 블록 수 ÷ 틀 칸 수 | 0이면 완벽 | 평가 전용 |
| 기능 검사 | 실제로 집 구실을 하나 | 문 말고는 안이 밖과 막혔나(flood fill), 문으로 들어가 설 수 있나 | 평가 전용 |

- 보상에 넣는 값과 평가하는 값을 나눈다. 같으면 정책이 판정식의 빈틈을 파도 알아챌 수 없다(예: 판정식은 통과하는 구멍 난 벽).

### 6.2 지식을 썼나: 지식 바꿔 넣기 (사용자 지적에 대한 답)

- 같은 seed, 즉 같은 지형과 배경에서 지식만 A, B, 없음으로 바꿔 돌린다. 결과 차이는 지식에서만 나오고, 배경 문제도 같이 없어진다.
- **구별 정확도:** 지식 A로 지은 결과가 B보다 A에 가깝고, B로 지은 결과가 A보다 B에 가까운 비율.
- **지식 효과 크기:** 지식 없음에 비해 A를 줬을 때 결과가 A에 얼마나 더 가까워졌나.
- 거리는 §4.2 구조 임베딩 공간에서 잰다. 판정식으로 쓸 수 있는 부분은 판정식으로 보조한다.
- 정책에 무작위성이 있으니 seed마다 여러 판 돌린다. 개발 seed에서만 한다.

### 6.3 Q_KB가 결정을 얼마나 바꿨나

- **개입률:** 지식 선택이 RM 기본 순서와 다른 후보를 고른 비율.
- **유익 개입률:** 결정이 바뀐 경우 중 결과가 나아진 비율. 저장한 상태에서 두 후보로 각각 이어 돌려 비교한다. 비용이 커서 표본만 쓴다.
- **거부율:** 가드와 τ가 Q_KB 최선 후보를 막은 비율. 너무 높으면 지식이 과제와 자주 부딪친다는 뜻이다.
- **지식 보류율:** 불확실성 때문에 지식 선택을 쓰지 않은 비율.

### 6.4 τ 곡선

- τ를 바꿔 가며 "과제 성공률 대 조건 충족률" 곡선을 그린다. 지식을 세게 끌수록 과제 성공이 떨어지기 시작하는 지점이 보인다.
- τ는 개발 seed로 정한다.

### 6.5 지식이 학습을 도왔나 (D-K1이 (나)일 때 핵심, (가)에서도 보조)

- 전이학습 표준 지표(Taylor & Stone 2009): 학습 0판 성공률, 정한 성공률까지 걸린 판 수, 학습 곡선 아래 면적, 최종 성능.

### 6.6 일반화와 악용

- **처음 보는 형태:** 재학습 없이 새 템플릿만 넣고 조건 충족률과 구별 정확도를 잰다. 높으면 지식을 읽는 것이고, 낮으면 학습한 모양을 외운 것이다.
- **틀린 지식:** 불가능하거나 일부 틀린 템플릿을 넣고 과제 성공률 하락과, §5의 반박으로 몇 판 만에 회복하는지 잰다.
- **악용 감시:** 보상에 넣은 값(조건 충족률, 학습 신호 점수)은 오르는데 평가 전용 검사(F1, 기능 검사)가 떨어지면 악용으로 본다. 11-18 §4.6과 같은 구조다.
- **학습 신호와 다른 판정:** VLM 점수로 배웠다면 사람 평가로 확인한다.
- **판정식 한계를 넘었는지 보이기:**
  - 판정식으로 쓸 수 있는 지식에서는 판정식 방식과 비슷한 결과가 나오는지 검산한다.
  - 판정식으로 쓸 수 없는 지식에서는 사람 평가로 더 나은지 본다.

### 6.7 판정 규칙

- 성공은 서버 상태·인벤토리·NBT로만 판정한다.
- 통과 수치는 실행 전에 기록한다. 과제 성공률은 지식 없음 조건과 공식 프롬프트 이상이어야 한다.
- 학습·개발·최종 seed를 나눈다.

## 7. 누출과 등급

- 실행용 Q_KB와 V_task는 11-19 §6의 타입 경계를 따른다. `SensorFrame`, 지시, KB만 받는다.
- import 검사: actor 프로세스가 학습용 Q_KB critic 모듈을 import하면 실패하는 단위 검사를 둔다.
- 반사실 검사: 오라클(가려진 블록, fixture의 안 보이는 부분, seed)만 바꾸면 실행용 Q_KB와 V_task 출력이 같아야 한다.
- 행 기록 등급 태그: 지식 임베딩은 지시, 본 지도 격자는 센서, 학습 목표는 심판으로 단다.

## 9. 지키는 규칙과 다른 문서

- **지키는 규칙:**
  - STEVE-1, MineCLIP, 공식 행동 헤드는 고정이다.
  - 성공은 서버 기록으로만 판정한다.
  - 실전 자격을 통과하지 않은 기술은 후보와 LLM 실행 vocabulary에 넣지 않는다.
  - 유료 호출은 `--allow-paid`일 때만 쓴다.
  - 후보가 없으면 hold하고 보고한다. 스크립트 행동으로 대신하지 않는다.
  - 완료한 실험의 결과·체크포인트·해시·`source-at-game`은 고치지 않는다.
- **다른 문서:**
  - 11-18 설계의 관련 문서 목록에 이 문서 링크를 더했다.
  - 요약계획서와 사이트 입력문은 고치지 않는다. 이 설계는 계획서의 "LLM 판정식 보상"과 "지식 저장소"를 넓히는 내용이다.

## 10. 사용자가 정할 일

- **D-K1 지식의 역할:**
  - 기본안 (가): 지식이 목표의 일부다. "그 모양이어야 한다". 최적 정책이 바뀌고, 반영률을 최대화한다. 사용자의 "반영 정도를 평가해서 최대화"와 "지식에 끌려다니는 편"에 맞는다.
  - 대안 (나): 지식은 힌트다. Q_KB를 상태만의 잠재 함수로 두면 최적 정책은 그대로이고 학습 속도만 바뀐다(Ng 외 1999; Wiewiora 2003). 주 지표는 §6.5다.
- **D-K2 학습 신호:**
  - 기본안: 성공 예시(A)와 판정식(C). 설계도로 예시를 자동 생성할 수 있고 유료 호출이 없다.
  - 대안: LLM·VLM 판정(B)을 더한다. 유료이고 판정기 악용 감시가 더 필요하다.
- **D-K3 지식 출처:**
  - 기본안: 설계도(블록 좌표). 구조 임베딩(§4.2)을 바로 쓸 수 있다.
  - 대안: 사진. 정규 렌더(평가 전용)와 배경 불변 학습(§4.3)이 필요하고, 실행 중 입력으로는 쓰기 어렵다.
- **D-K4 MineCLIP 오프라인 탐침:**
  - 기본안: 해 본다. 게임과 학습 없이 MineCLIP 가중치만 쓴다. §2.1의 판단을 우리 모델로 확인한다.
    1. 글 구분력: 지식만 다른 문장들("집을 지어", "5×5 돌집, 문은 남쪽", "3×3 나무집, 문은 북쪽")의 임베딩 유사도
    2. 명령 보존: 명령만 넣은 임베딩과 "명령 + 지식" 임베딩의 유사도, 녹화 클립에서 명령에 맞는 장면을 찾는 정확도
    3. 영상 구분력: 결과 모양이 다른 건축 판 클립에서 맞는 지식 문장을 골라내는지
  - 대안: 하지 않고 "지식은 하위 목표 분해와 Q_KB로"로 바로 정한다.

**내가 정한 것 (확인 부탁):**
- 첫 적용 자리를 하위 목표 선택으로 두고, 매 틱 재선택은 보류(§0, §3.5)
- 실행용 Q_KB, 센서 등급 과제 성공 예측 V_task, 학습용 Q_KB critic의 세 망 구조(§3.1)

- 구조 정규화와 재료 범주(§4.2), KB 새 관계 `structure_template`(§4.4)

- 지난 건축 판은 서버 기록 결과 격자만 학습 목표로 쓰기(§8)
- 센서 건축 헤드 전의 K1–K2 결과는 R 조건으로 따로 표기(§8)
