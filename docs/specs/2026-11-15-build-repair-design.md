# 건축 5차 — 잘못 놓인 블록 치우기 (2026-11-15 12:10)

- 상태: 사용자 지시(11-15 05시께)에 따른 학습이다. 세부는 내가 정했다(**(내 결정)**). 게임 전에 이 문서로 과업, 순서, 판정을 정했다.
  - 지시: "학습 더 필요하다고 판단되는 부분 있으면 진행해. 특히 건축 같은 부분은 잘못 설치하는 것도 문제가 없는 건 아니니까. 집 짓기 같은 건 외관도 중요하니"
- 코드는 브랜치 `build-repair`에서 만들고 `jump-map`에 로컬 병합해서 돌린다. main 병합과 push는 하지 않는다.
- 앞선 결과:
  - [4차 결과](../build4-results-2026-11-15.md): c4-final 개발 16/16(잘못 놓음 0), 최종 16/16(깔끔한 성공 14)
  - [크기 점검 결과](../build-large-results-2026-11-15.md): 6–16칸 8/8, 깔끔한 성공 7, 잘못 놓은 1개가 둘레 가운데 빈칸에 남음
  - [최소 요구 능력과 빈틈](2026-11-15-minimum-capability-gaps.md) §3-4: "잘못 놓은 블록 치우기(부수기 단계)"

## 1. 왜 하나

- 4차 정책은 40판에서 블록 3개를 잘못 놓았다. 한 번 놓으면 그대로 남는다. 집이면 벽 옆이나 빈칸에 튀어나온 블록이 겉모습을 망친다.
- 잘못 놓기를 더 줄이는 것만으로는 0이 되지 않는다. 원인이 무엇이든 끝 상태를 설계도와 같게 만드는 능력이 필요하다.
- 그래서 정책에 **치우기**를 더한다. 설계도 밖 블록이 보이면 곡괭이로 바꿔 부수고, 다시 조약돌로 바꿔 짓는다.
- 성공 기준도 바꾼다. 설계도를 다 채우고, **설계도 밖 블록이 하나도 남지 않아야** 성공이다.

## 2. 과업 **(내 결정)**

- 모듈은 `minecraftrl.build_repair`다. `repair_build(id)`는 기존 생성기(`build_task.generate_build`)의 설계도에 **잘못 놓인 블록**(이하 '군더더기')을 더한다.
  - 군더더기 수는 `id % 3`(0, 1, 2개)이다. 그래서 과업 셋 중 하나는 군더더기가 없다. 짓기 실력이 줄지 않았는지도 함께 본다.
  - 위치는 설계도 바닥 칸의 앞뒤좌우 칸 중에서 고른다. 설계도 칸, 시작 칸, 시험장 밖은 뺀다.
  - 블록은 조약돌이다. 정책이 잘못 놓는 블록과 같다. fixture가 게임 시작 때 놓는다.
- fixture는 조약돌 32개(1번 칸)와 돌 곡괭이 1개(2번 칸)를 준다. 손에는 처음에 조약돌을 든다.
- 과업 번호와 world seed(모두 처음 씀):

  | 모드 | 과업 | world seed |
  |---|---|---|
  | `repair_train` | 1101–1112 | 학습 seed 271828, 314159, 161803 |
  | `repair_dev` | 1201–1208 | 414213 |
  | `repair_final` | 1301–1308 | 236067 |

- 시간 제한(60초), 시험장, 성공 판정 방식은 기존 건축과 같다. 성공 판정만 위처럼 넓힌다.

## 3. 단계 계약 ([과업 분해 원칙](../task-decomposition.md))

- 단계: `reach`, `move`, `aim`, `place`, **`dig`**, `done`. 단축키 칸 바꾸기는 단계가 아니라 하위 행동이다.
- 진입 조건과 증거(모두 특권 입력, 공식 정책에는 없음):
  - 서버 설치 기록과 서버 파괴 기록(`demo_destroys`, 마지막 파괴 칸)으로 블록 상태를 추적한다.
  - 군더더기 = fixture 군더더기 + 설계도 밖 설치. 남은 군더더기가 있으면 가장 가까운 것을 목표로 삼는다.
    - 사거리(4.5) 안에서 그 블록의 면이 보이면 `dig`다. 아니면 그 면이 보이는 자리로 `reach`/`move`한다(3차 교사의 자리 찾기와 같다).
  - 군더더기가 없으면 4차(신중한 놓기)와 같은 단계다.
  - 손에 든 물건은 서버의 선택 아이템(`server_selected_item`)으로 안다. 화면 아래 단축키 칸에도 보인다.
- 완료 조건:
  - `dig`: 서버 파괴 기록이 그 칸을 지웠을 때다. 공격 입력만으로는 끝나지 않는다.
  - 과업: 설계도 칸이 모두 서버 기록상 차 있고, 군더더기가 하나도 없을 때다.
  - 정책이 설계도 블록을 부수면 그 칸은 다시 빈칸이 되어 다시 놓아야 한다.
- 교사(`repair`, 4차 신중한 교사에 더함):
  - `dig`에서 곡괭이를 들지 않았으면 2번 칸을 누르고, 보이는 면 가운데로 돈다.
  - 곡괭이를 들었으면, 눈에서 그은 직선이 그 블록 면 가장자리에서 0.2 안쪽에 닿을 때 회전 없이 공격한다. 아니면 면 가운데로 돈다.
  - 한 번 공격을 시작하면 직선이 그 블록 어디에 닿든 공격을 이어간다. 마인크래프트는 공격을 떼면 부수던 진행이 사라지기 때문이다.
  - 다른 단계에서 조약돌을 들지 않았으면 1번 칸을 누르고, 그 행에서는 `use`를 누르지 않는다.
- 정책 입력: 단계 one-hot(6개)과 특징 12개. 특징은 4차의 11개에 '곡괭이를 듦'(0/1)을 더한 것이다.
  - `dig`에서 목표 방향 특징은 군더더기 블록 가운데, 면 특징은 보이는 면 가운데를 가리킨다.
  - 단계 수와 특징 수가 바뀌므로 헤드를 새로 학습한다(adapter만, STEVE-1은 고정).
- 행동 잠금: 건축 게임은 정책의 단축키, 버리기, 인벤토리 키를 막아 왔다(`policy_tool_lock`).
  - 이 과업에서는 1번과 2번 칸만 풀어 준다(`policy_tool_allowed`). 버리기, 인벤토리, 3–9번 칸은 그대로 막는다.
  - 공식 정책도 같은 설정으로 돈다.
- 중단: 기존과 같다. STOP 뒤에는 정책 행동이 없고, 입력을 해제하고 PID를 정리한다.
- 보고: 판마다 남은 군더더기, 치운 수, 설계도 블록을 부순 수, 잘못 놓음, 파괴 기록 누락 수를 남긴다.

## 4. 시뮬레이터 점검 (게임 아님)

  - 단축키 칸, 손에 든 물건, 곡괭이로 같은 블록을 15결정(1결정 = 1틱) 이어서 공격하면 부서지는 것을 흉내 낸다. 돌 곡괭이로 조약돌을 부수는 시간이 15틱이다.
- 과업 1101–1112 × 시작 방향 4개(48판) 결과:

  - 잘못 누름 10%와 잡음 3도에서도 성공하고, 자기 실수도 치운다.

## 5. 순서와 판정 (먼저 정함)

- 배치 폴더는 `results/build5-20261115/`, 실행 스크립트는 `launch/build5.sh`다. 한 번에 게임 하나씩, GPU가 2150MiB 이상 빌 때 돈다.

- 학습 과업의 world seed는 `(id / 3) % 3`으로 돌린다(271828, 314159, 161803). 군더더기 수(`id % 3`)와 seed가 겹치지 않게 하려는 것이다.
- 성공은 모든 갈래를 `scripts/score_build_repair.py`로 센다. 기록(서버 설치·파괴)을 치우기 규칙으로 다시 돌려, 유효한 판 중 설계도가 차 있고 군더더기가 없는 판을 센다.

1. **교사 점검(준비용):** 치우기 교사로 1101–1112를 1번씩 돈다. 11/12 이상 성공하지 못하면 학습 없이 멈춘다.
2. **p5-a:** 4차까지의 학습판 68개(R0–R4)를 치우기 교사로 다시 라벨링해 학습한다. 설정은 4차와 같다(KL 10, balance, patience 2, 특징 배율 10, use-coef 1).
   - 검증(holdout)은 4차 c4-final과 같은 R4 c111·c112 n5 판이다.
3. **R5:** p5-a로 1101–1112를 샘플링 1, 2로 돈다(24판). **p5-b**를 R0–R5로 학습한다. 검증은 R5 c1111·c1112 n2 판이다.
4. **R6:** p5-b로 같은 과업을 샘플링 3으로 돈다(12판). **p5-final**을 R0–R6으로 학습한다. 검증은 R6 c1111·c1112 n3 판이다.
5. **개발(seed 414213, 1201–1208):** p5-final과 공식 정책.
   - **개발 판정:** p5-final 성공 ≥ 5/8이고 공식보다 많으면 최종으로 간다. 아니면 "치우기 추가 학습 필요"로 기록하고 멈춘다.
6. **최종(seed 236067, 1301–1308):** p5-final, 공식, c4-final(참고).
   - c4-final은 치우기 단계가 없다. 4차 fixture(신중한 교사)로 돌고, 군더더기는 fixture 블록으로 같은 자리에 둔다. fixture가 다르므로 배치 폴더를 따로 쓴다.
     c4-final 게임은 설계도를 다 채우면 끝난다. 성공은 같은 치우기 규칙으로 기록에서 센다.
   - **최종 판정:** p5-final 성공 ≥ 5/8이고, 공식보다 많고, c4-final보다 많아야 "치우기 학습 확인"이다.

## 6. 밝혀 둘 점

- 특권 입력: 설계도, 클라이언트 자세·십자선, 서버 설치·파괴 기록, 서버 선택 아이템, 직선 시선 계산으로 단계와 특징을 계산한다. 공식 정책은 이 입력이 없다.
- 이 과업에서는 정책의 1·2번 단축키를 풀어 준다. 4차까지의 건축 게임과 행동 잠금 조건이 다르다.
- 학습 과업의 성공은 평가가 아니다. 이 학생은 LLM vocabulary에 넣지 않는다.
- 군더더기는 fixture가 놓은 블록이다. 정책이 실제로 잘못 놓은 블록을 치우는 것은 판마다 따로 센다.
