## 확인된 제어 문제와 수정

실제 live 실행의 탐색200전이는 전부 search, 원목0이었다. 런타임은 이 결과를
`assess_attempt`에 전달하지 않고 시간만으로 wood에 복귀했다. 이후577전이도 search였다.
이 경로를 실패 판정과 연결한다. 현재 target이 있으며 같은 target에 접근했거나
없던 target을 발견한 경우, 또는 현재 mine/collect인 경우만 수집으로 인계한다.
이동량·과거에 잠시 보인 target·예산 종료 자체는 재개 근거가 아니다.
상위 wood RM/인벤토리 완료 조건/보상/신경망 행동/기억은 보존한다.
복구 실패·관측 불신·허용된 요청 소진 후 재정체는 종료하고 입력을 해제한다.
실패 판정은 실행된 구간/원래 목표/요청 ID와 함께 별도 영수증과 이벤트로 남긴다.
기존 단독 GoalRecoveryController 진단 계약은 유지하고 계획 인계 컨트롤러만 수정한다.

회귀 검사: 무진전200tick, 이동만 있음, target 상실, 현재 상호작용, 재획득,
30초 예산, 목표 완료/STOP 우선, 대기/중단 후 전송0, 호출 추가0.
고정 응답의 새 corner 실제 실행 최대1회/180초로 제어 연결을 확인한다.
정체가 없어 인계되지 않으면 미검증으로 기록하며 성공으로 대체하지 않는다.

## 하위 정책 원인 후보: BC 유지 손실

현재 `teacher NLL + KL(parent || candidate)`의 KL계수1은 교사와 부모가
충돌하는 각 categorical head에서 교사 확률 약1/2을 선호한다.
독립 상태의 수식이며 모델 확률 상한이나 개발 실패의 확정 원인은 아니다.
예측: 계수를0.1로 줄이면 같은 훈련 상태의 첫 교사 행동 NLL/회전 확률이
기존계수1보다 개선된다. 개발 상태에서도 개선되는지는 별도 관측한다.

`train_coverage_anchor_ablation.py`로 1회 실행: 기존 masked 부모, 같은
10836프레임/2565개 train 교사 정답, seed9612, lr5e-6, 같은662갱신/순서,
유효128입력 burn-in/8프레임, value 동결. 변경 변수는 KL계수1→0.1뿐이다.
개발619정답은 측정 전용. live/fixed 복구 평가 궤적은 학습에 쓰지 않는다.
임베딩은 기존 wood 유지. 탐색 prompt 변경·RM 단계 추가와 섞지 않는다.
개발 첫 회전 최소0.5%, NLL/계속 행동과 기존 strict gate를 그대로 측정한다.
미통과 시 게임 입장을 낮추거나 기본 정책을 승격하지 않는다.
통과 시 전체 영상 replay 일치 확인 후 별도 명세로 개발 게임을 진행한다.
이 대조는 새 PPO나 강화학습 성능 개선 증명이 아니다.
