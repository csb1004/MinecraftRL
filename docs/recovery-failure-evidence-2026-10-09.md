# 실패 근거에서 LLM·상위 플래너로의 연결

사용자 추가 지시: 실패/정체 판정을 충분히 검증하고 LLM의 탈출 계획을 상위 플래너와 하위 정책에
연결한다. 기존 목표 RM을 삭제하지 않고 진행도·완료 근거를 보존한다. 현재 실행 중인 고정 대조는
변경하지 않고, 새 판정은 보존된 실제 기록에 먼저 적용한다.

## 판정 경계

`StallDetector`의 탐색400tick·접근200tick·채굴400tick·회수200tick과 목표 진전800tick 상한을
그대로 사용한다. 개별 반복 행동이나 보상 평탄만으로 실패를 판정하지 않는다. 그래프 순환은
실제 반복의 근거이며 경로가 불가능하다는 증명이 아니다. 관측 누락·오래된 tick은 정책 실패와 분리한다.

`recovery_evidence.py`는 새 보상/감지기를 추가하지 않고 기존 감지와 실제 서버 관측을 플래너용으로
해석한다. 정체 의심은 재계획 후보이며 `task_impossible=false`, `execution_authorized=false`이다.
현재 `wood_server_mining`은 서버의 원목 채굴 대상 활성 여부다. 손상량 센서는 없으므로 반복 채굴을
진행이나 실패로 단정하지 않고 `mining_damage_unmeasured`를 명시한다. 블록 경도·통행 가능 지도도
측정하지 않는다. 실험용 fixture 구조는 LLM 관측 사실에 넣지 않는다.

실제 복구 구간의 획득, 같은 대상에 대한 접근 진전, 상호작용 기회, 이동/회전을 구분한다.
mine/collect는 원래 목표로 인계할 근거이며 완료가 아니다. 이동·회전만으로 복구 성공을 선언하지 않는다.
200tick 소진 시 실제 진전 유무와 함께 재계획 후보를 남긴다. 전체 제어 예산 소진·STOP·관측 오류·목표 완료는
새 요청 후보를 억제한다. 복구가 실행되지 않은 경우는 실패 표본에 넣지 않는다.

## 계층별 책임

감지기는 정체 시점·대상·실제 진전·반복·관측 한계를 제공한다. LLM은 이 근거와 실패 이력을 보고
탈출 하위 목표를 제안한다. 상위 플래너/검증기는 목표와 우선순위, 유효한 skill, 전제 조건, 남은
시간과 재시도 예산을 검사한다. 하위 정책은 실제 행동을 생성한다. 결과는 다시 서버 증거로 판정한다.

기존 `ReplanGuard`의 stale 응답·STOP·완료·예산·중복 실패·미지원 skill 거부를 유지한다.
목표 조건 전환은 현재 opt-in 진단이다. 이를 검증된 ‘우회’ skill로 등록하거나 LLM의 실행 vocabulary를
늘리지 않았다. 실제 대조의 정체 순간에는 입력 중립/실행 세대가 증명되지 않으므로 오프라인 변환기가
그 증거를 만들어 넣지 않는다. 실제 LLM 호출과 실시간 요청 대기는 아직 연결하지 않았다.

기존 기록의 새 증거는 `results/goal-recovery-comparison-20261009/planner-evidence/`에 보존한다.
이 자료는 실게임 성과를 늘리지 않는 읽기 전용 분석이며 실제 호출0/새 행동0이다.

## 유료 호출 전 준비

`recovery_draft.py`와 준비/실행 스크립트는 기록된 첫 corner 쌍의 정체 시점만으로 제안을 검사한다.
현재 제공하는 선택지는 이미 구현한 일회 임베딩 전환을 사용하는 `explore_then_resume`과
`remain_paused`다. 방향 지정·경로 탐색을 구현한 것처럼 제공하지 않는다. 이 제한된 개발용 선택지는
실행 capability 레지스트리에 추가되지 않으며 모든 제안은 `execution_authorized=false`다.

실제 비교와 별도 취소 검사를 끝낸 뒤 입력/프롬프트/코드 hash를 고정한다. 두 입력에는 이후 획득량이나
정답을 넣지 않는다. 앞서 프로젝트에서 사용한 `gpt-5.3-codex` 식별자, 최대2호출, 호출당1024출력token,
20초timeout, 재시도0의 제안 품질 smoke test를 준비한다. 실패한 호출도 예산을 소비한다.
기본 실행은 호출을 거부하며 기존 유료 호출 승인의 소진된 한도를 재사용하지 않는다.
준비 이후 사용자 추가 승인으로 [실제 원격 LLM2회](recovery-draft-api-validation-2026-10-09.md)를 완료했다.
두 응답은 탐색 후 원래 목표 복귀를 제안했고 계약 검사를 통과했다. 실제 원격 호출은2회로 종료했다.
정체와 완료 근거가 모순되면 완료를 우선해 호출 전에 거부하도록 추가 보강했다.
실시간 계획 대기/중립 전이/dispatch 연결과 다중 RM 우선순위 스케줄러는 후속 범위다.
