## 연구 방향: competence와 모델 기반 계획

사용자가 실행 중 제기한 우려는 타당한 설계 점검 항목이다. 현재 R1은 **고정 RM + 목표 조건부 정책 + 보정층의 model-free PPO**다. 학습된 환경 전이 모델, 그 모델 안에서의 계획 탐색, 자동 competence 기반 과제 선택이나 LLM 호출은 이 실행에 없다. RM의 진행 상태 전이는 환경의 행동 결과 예측 모델과 다르다.

후속 방향으로는 다음을 제안한다. **아직 구현한 기능이 아니다.**

1. 현재 관측과 이력에서 스킬 실행 후 상태 변화·성공 가능성·소요 시간·불확실성을 예측한다. 같은 RM 상태라도 실제 장면은 다르므로 RM 상태 번호만 입력으로 사용하지 않는다.
2. 예측 모델 안에서 후보 계획을 제한된 예산으로 비교하고 실제 환경에서는 선택한 스킬을 실행한다. 실제 결과로 모델과 RL을 갱신한다. 스킬 단위 결과 모델은 [SkiMo](https://proceedings.mlr.press/v205/shi23a.html)가 참고가 된다.
3. 목표 달성에 필요한 능력 중 연습으로 개선될 가능성이 있는 부분에 학습을 배분한다. 쉬운 스킬만 반복하거나 모르는 스킬을 불가능으로 확정하지 않도록 한다. [Practice Makes Perfect](https://arxiv.org/abs/2402.15025)는 능력 추정과 연습 선택을 계획에 결합하는 참고 연구다.
4. 관측 오류·예측 모델 오류·불가능한 계획·실행 능력 부족·환경 장애를 구분한다. 모든 실패를 행동 정책 재학습으로 처리하지 않는다. 능력 추정에는 정책 버전을 붙여 이전 정책의 성공률이 새 정책에 잘못 적용되지 않게 한다.
5. 같은 초기 정책과 데이터/계산 예산으로 고정 커리큘럼, competence 기반 과제 선택, 결과 예측 계획 추가를 비교한다. 계획기를 끈 상태의 학습 후 성능과 정책을 고정한 계획기 성능도 분리해, 계획기의 도움과 RL에 남은 능력을 구별한다.

Competence progress는 학습할 목표의 선택 기준이고, [Moerland 등의 설명에서 two-phase exploration](https://arxiv.org/pdf/2006.16712)은 모델 내 탐색과 실제 환경의 행동 선택을 구분한다. 단순히 학습을 두 번 한다는 뜻은 아니다. 사용자가 염두에 둔 정확한 논문명은 확인되지 않았다.

STEVE-1은 교체 가능한 초기 정책으로 다루는 것이 적절하다. 본체를 계속 고정하면 새 표현/기억/행동을 학습하는 범위에 한계가 있지만, 계획기 추가만으로 그 한계가 해결되지는 않는다. 이번 기준 비교를 마친 뒤 추가 STEVE-1 전용 문장/학습률 탐색을 자동으로 이어가지 않는다. 고정 관측 계약, 충분한 실전 자료, 모델 오차와 정책 퇴행 검증이 다음 설계에도 필요하다.

실행 시 계획은 현재 가능한 방법을 선택하고, 학습 시 계획은 어떤 부족한 능력을 연습할지 선택한다. 후자에는 현재 성공률뿐 아니라 최근의 개선 정도, 최종 과업과의 관련성, 실행 비용을 함께 사용해야 한다. 데이터가 없는 상황은 성공률 0으로 단정하지 않고 미확인으로 남긴다. 이는 이번 실험의 두 학습 라운드와 다른 구분이다.

최소 후속 검증에서는 먼저 고정된 관측으로 스킬 결과 예측이 단순 성공률 기준보다 도움이 되는지와 불확실성이 맞는지 확인한다. 그다음 정책을 고정한 계획 비교, 같은 예산의 학습 과제 선택 비교, 계획기를 제거한 정책 평가를 순서대로 분리한다. 현재의 18개 학습 에피소드만으로 충분한 결과 모델을 만들 수 있다고 가정하지 않는다. 학습/개발 분리와 정책 버전 기록을 유지하고, 현재 개발 자료를 학습에 사용하면 새 평가 월드를 마련해야 한다.

LLM은 검증 가능한 RM/학습 요청을 제안하고, RM은 목표·순서·보상을 정의하며, 결과 모델과 계획기는 실행 가능성과 연습 선택을 돕는다. 실제 RL 업데이트와 퇴행 검사를 통과한 정책만 실행 후보가 된다. LLM의 주장만으로 모델의 전이나 성공 판정 근거를 확정하지 않는다. 이 제안은 기존의 RM+RL → LLM 작성 RM → 이상 감지/피드백 학습 → SQL 지식 확장이라는 연구 순서와 원문 명세를 대체하지 않는다.
