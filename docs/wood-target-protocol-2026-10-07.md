# 원목 채굴 대상 교정 — 사전 검증 조건

범위는 원목 잠금 대상과 실제 서버 채굴 대상의 불일치다. 접근 정체 복구·아이템 entity 추적·
새 학습은 별도 단위다. 이전 개발 자료를 학습하지 않고 최종 평가 시드를 사용하지 않는다.

가설: 처음 시야 ray로 잠근 원목과 다른 원목을 캐면 기존 RM은 접근으로 남을 수 있다.
기존 로그의 공격 입력+클라이언트 hit는 실제 채굴의 확증이 아니므로, 서버
PlayerInteractionManager의 진행 중 채굴(지연 완료 처리 포함)을 읽어 독립적으로 검증한다.
관측은 기존 recorder의 게임 스레드 snapshot 경계에서 읽고 행동을 삽입하지 않는다.

기존 wood_* 관측과 v1/v2 보상은 보존한다. 병렬 wood_v3_* 추적은 서버가 받아들여 처리 중인
살아 있는 플레이어의 원목 채굴 좌표로 잠금을 바꾼다. 시점을 돌리는 것만으로 바꾸지 않는다.
해당 블록이 사라지면 기존 40tick 파괴 위치 회수 근사를 유지한다. 다른 원목을 실제로 캐기
시작하면 새 채굴 의도가 회수 의도보다 우선한다. 즉시 파괴되어 snapshot에 진행 상태가
남지 않는 경우의 채굴 이벤트 추적과 실제 드롭 위치는 이번 구현 범위가 아니다.

wood-potential-v3는 새 센서를 사용하는 별도 조건이다. 보상식·성공 인벤토리·실패 비용·
gamma·시간 비용·6차원 문맥은 v2와 같다. mine은 접근 가능한 채굴 준비 또는 서버 진행 중
채굴이며 파괴 성공을 뜻하지 않는다. v2 head를 v3로 실행할 때 source_checkpoint_reward_mode를
기록하고 호환 로드하되, v3 조건에서 학습된 정책으로 해석하지 않는다. 기본 sparse는 유지한다.

검증 순서: 단위 회귀/분리 JAR 빌드 → 같은 흙 벽 시험장/같은 v2 checkpoint의 v2 실행에서
두 센서 동시 기록 → v3 실행에서 RM/actor/value 실제 연결 감사 → v3 실제 사망 종료 회귀.
각 제어 최대180초, eval만 사용, optimizer 갱신0. 실행 중 오류는 무효로 보존한다.

통과 기준: 서버가 원목을 처리 중인 모든 snapshot에서 새 목표 좌표가 해당 좌표와 같고 mine으로
판정됨, 기존 센서 불일치가 같은 실제 경로에서 재현됨, 새 목표 파괴 후 회수 또는 즉시 획득,
실제 인벤토리 획득 확인, 보상/입력 원시 재계산 일치, 이후 행동0·입력 해제·소유 PID0.
가설 재현이 안 되면 성공으로 덮지 않고 추가 진단 이유를 기록한다. 게임 종료와 테스트 통과를
학습 성능 개선으로 해석하지 않는다.
