# 미완료 목표 우선순위 검증

상태: 승인된 기능 구현 및 Windows/WSL 소프트웨어 검증 완료.
실제 Minecraft 게임·추가 학습·유료 API·Colab·GitHub 작업은 실행하지 않았다.
[설계 계약과 명령](goal-aging.md), [고정 범위](goal-aging-plan-2026-10-15.md).

## 구현과 확인한 동작

- 영구 목표 ID와 기존 버전/실패 이력을 유지하고 미완료 시간에 따라 우선순위 상승.
- 최대 실행 가능 대기 초과 시 새 고우선순위 목표에 계속 밀리지 않고 실제 서비스 구간 배정.
- 선행 작업에 긴급도 상속, 동률 시 대기와 원래 하위 우선순위 보존.
- 짧은 선택/재계획/우선순위 변경으로 대기와 정체 이력을 초기화하지 않음.
- 실제 RM 노드 선택 및 LLM packet의 scheduling 문맥에 연결. 보상 객체는 변경하지 않음.
- 명시적 다중 수집 세션에서 여러 목표 완료까지 같은 환경 유지, 목표 전환 때 입력 해제.
- 추론 중 pause/우선순위 변경/STOP 뒤 이전 행동 폐기.
- 월드 ID가 같은 schema4 복원만 허용하며 목표를 자동 실행하지 않음.
- 정체 목표는 blocked로 보존하고 다른 준비된 목표를 선택. resume 후 실패 기록 유지.
- PowerShell 명령 제출→JSON 검증 경로를 실제 임시 디렉터리에서 검사.

테스트 시나리오의 `dirt,dirt,dirt,wood` 순서는 제어된 시계와 가짜 환경의 실제 세션 루프
결과다. 높은 우선순위 목표가 끝나기 전에 오래된 목표로 전환함을 확인하는 소프트웨어 증거이며
학습 정책의 게임 행동/인벤토리 성과로 세지 않는다.

## 재현 후 수정

첫 장부7검사, 다중 목표5검사, RM 입력/선택2검사는 구현 전 실패를 확인했다.
후속 `review-red.log`의3실패는 다음과 같다.

1. 선행 작업60초가 상위 목표의 직접 정체60초로 오인됨 → direct_service_s 분리.
2. 상위 우선순위 상속으로 형제 작업의 원래 순서 소실 → 자체 우선순위 동률 비교.
3. PowerShell이 새 enqueue/reprioritize 명령을 거부 → 제출 스크립트와 WSL 실행 옵션 연결.

별도 오류 주입에서 시간 회계 예외가 finally cleanup을 건너뛰는 문제를 확인했다.
회계 실패를 기록하고 입력 해제/환경 종료를 계속하도록 수정했다.
resume으로 마지막 failure 필드를 해제해도 누적 실패 기록을 보존하도록 보완했다.
마지막 복원 검사에서 완료 목표만 있는 세션이 새 요청 전에 종료되는 것을 재현했다.
동일 월드에서 다음 명시적 요청을 기다린 뒤 정상 처리하도록 수정했다.

## 한계와 후속

aging 설정의 실제 게임 효율, 장기 다중 목표 완료율, LLM의 추가 효과는 미검증이다.
기본 CNN/이동 정책/보상은 그대로여서 기존 벽 접근 실패를 해결했다고 주장하지 않는다.
현재 다중 목표는 지원된 수집 과업이며 일반 대화의 복수 목표 자동 확정이나 임의 RM 실행기가 아니다.
다중 세션은 정체 목표를 자동으로 LLM에 재의뢰하지 않고 기존 실패 기록과 명시적 재개 경계를 유지한다.
다음 실게임은 별도 개발 조건에서 대기 시간, 실제 서비스, 전환 횟수, 서버 획득량,
중단 후 입력·소유 프로세스 정리를 함께 측정해야 한다. 기존 완료 배치를 다시 돌리지 않는다.
