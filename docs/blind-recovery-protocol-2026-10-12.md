# 정체 후 복구와 벽 정보 제거 비교

사용자 승인: 기존 벽 환경에서 정체 후 탈출 검사, 결과를 GitHub에 1차 정리해 업로드.
기존 연구 명세/부모/가중치/RM/원본 실험을 보존한다. 새 유료 API/학습/최종5시드 사용0.

## 고정 조건과 판정

2026-10-10 첫 후보 far/corner의 실제 정체 당시 위치·수평 시선을 기존 개발 벽 환경의
새 복사본 시작점에 적용한다. pitch는 기존 fixture의 -13도, 기억은 새 episode 초기화다.
이전 실행의 완전한 상태 복원이 아니며 준비 중 정책 행동/성공 표본은0이다.
현재 실행에서도 기존 StallDetector가 실제 정체를 검출한 뒤에만 복구한다.
정체 전 완료/종료는 복구 미실행이며 분모에서 제외한다.

두 월드 × 다음 두 조건, 각1회. world seed104761, sampling12021/12022(조건 간 동일),
전체 제어180초, 복구400행동/60초. 동일 보강 nav checkpoint f1dee801…/부모473142f….
샘플링/도착반경0.35/높이차1.5/원래 RM과 STOP 계약은 그대로다. 실패 기준을 사후 완화하지 않는다.

1. `fixture`: 기존 벽 끝을 아는 경유점 공급. 정보 제공 대조군이다.
2. `visit_memory`: 월드 구조/벽 끝/출구/나무 좌표를 받지 않는 일반 탐색 기준선.
   현재 위치·yaw, 실제 방문한2블록 구역, 이전 후보 실패만 사용한다.
   정체 시 바라보던 방향보다 옆/뒤의 새 방향을 우선한다. 이후 방문 비용과 방향 연속성으로
   3블록 떨어진 후보를 고른다. 미관측 후보는 통행 가능 경로로 선언하지 않는다.
   후보100행동 또는40행동 동안 거리0.25블록 개선 없음이면 실패 이력을 남기고 다른 후보를 고른다.
   실제 후보3개 도달 시 원래 수집으로 복귀한다. 후보 생성 최대8개/기존 전체 복구 예산 유지.

좌표·방위는 privileged server다. 기존 root RM 문맥과 종료/인벤토리 계측도 유지한다.
따라서 이 조건은 **벽 정답 정보 제거**이며 영상 전용/F3/LLM 플래닝 조건이 아니다.
상위 후보 선택은 명시적 규칙 기준선이고 모든 게임 키·마우스 행동은 신경망이 샘플한다.

판정은 (a) 정체 지점에서3블록 이상 이탈한 후2블록 밖에서20전이 유지,
(b) 알려진 장벽 반대편 통과, (c) 실제 원목 획득으로 분리한다.
벽 구조를 읽는 (b)의 판정기는 게임 종료 후에만 실행하며 정책/탐색기에 피드백하지 않는다.
판정 구현은 첫3블록 도달 이후의20전이를 검사한다. 장벽의 반대편은 episode 출발 쪽의
반대이며 몸 반경0.3을 포함해 x>=8.3을 요구한다. root가 이미 횡단한 쪽에서 정체를 감지했다면
`already_on_far_side_at_stall`로 분리하고 복구의 새 횡단 성공/실패 분모에 넣지 않는다.
root prefix의 화면/행동 차이를 대조한다. 달라지면 인과 성능 향상으로 해석하지 않는다.
추론/전체 주기 중앙값·95백분위, GPU 메모리, 거리·도달·실패 원인,STOP/키/PID를 기록한다.
