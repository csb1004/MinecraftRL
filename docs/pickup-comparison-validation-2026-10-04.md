# 실패 월드 복구: 짧은 문구와 공식 문구의 실제 비교

## 결론

실패 직후 저장된 **같은 월드의 복사본**에서 기존 짧은 문구는 5/5,
공식 평가 문구는 4/5로 흙 획득에 성공했다. 문구를 공식 버전으로 바꿀 이점은
확인되지 않아 **기본값 `short`를 유지한다.**

기존 정책으로 저장·프로세스 재시작·새 조건 샘플링·재개 후 수집이 가능함을 확인했다.
같은 프로세스에서 정책 상태만 초기화하는 효과를 분리한 실험은 아니다. 일반적인
줍기 능력, 모든 정체의 해소, 자동 복구 성공률을 입증하지 않는다.
이전 60초 무획득 실패 기록도 그대로 유지한다.

## 변경과 검증

- STEVE-1 문구 비교용 `--steve-prompt-profile short|official`을 추가했다.
  기본값, guidance=6.0, 가중치, 실제 인벤토리 기반 RM 판정은 유지했다.
- 실제 문구와 조건 embedding SHA256을 policy reset 이벤트에 기록한다.
- 프로젝트 내부의 `--world-store-root`를 추가해 각 실험을 별도 복사본에서 실행한다.
  슬롯 이름을 유지해 같은 플레이어 UUID로 복원하며 원래 저장소는 덮어쓰지 않는다.
- 한 번에 10회를 실행하는 비교 도구와 미실행/기술 오류/정책 미완료를 구분하는
  집계 도구를 추가했다. [옵션·재현 명령](policy-prompt-profiles.md).

새 옵션의 실패 검사를 먼저 확인한 뒤 구현했다. WSL 회귀 검사에서 기존 호출자가
새 CLI 속성을 갖고 있지 않은 오류 4개가 드러나 기본값 호환 처리를 수정했다.
최종 Windows 99개 중 95개 통과/4개 Linux 전용 제외(1.679초), WSL 99개 통과
(28.732초). 프로젝트 밖 저장소 거부 및 두 실행/집계 스크립트 구문도 확인했다.
사용자 순차 실행 지침에 따라 자체 검토했으며 독립 에이전트 리뷰는 아니다.

## 고정 조건

- 실행 폴더: `results/pickup-comparison-20261004T034711716036Z/`.
- 원본 슬롯: `failure-20261004T032512557525Z`, 원본 세대:
  `3b2f51efcf7c4bbe8edfee14623eb5db`.
- 기존 STEVE-1/MineRL 환경, GTX 1060 3GB, 드라이버 560.94.
  시작 전 사용 443 / 여유 2523 MiB.
- 기존 난수 시드 5개 × 두 문구 = 10회. **서로 다른 지형 5개가 아니다.**
  Python/NumPy/Torch/환경 초기 시드를 설정하되 저장 월드는 동일하다.
- 두 문구 순서를 시드마다 번갈아 적용했다. 실행당 제어 상한 180초,
  목표 dirt 1개, 무획득 60초면 paused/저장/종료.
- `short`: `collect dirt`.
- `official`: 고정된 upstream paper_prompts.py의 dirt 문구.
  source commit: `903b244796322f4d0073a8f62c05f51eac3aed52`.
- 실행기는 기존 과업에 구조화된 resume 명령을 발행했다. 유료 API 호출 0회이며
  이번 비교는 자연어 LLM 정확도 검사가 아니다.

## 결과

시간은 resume acknowledgment부터 실제 인벤토리 완료 이벤트까지다.
실패는 60.025초의 무획득 감지이며 성공 시간으로 환산하지 않는다.

| 시드 | short: 획득 / step / 완료(초) | official: 획득 / step / 완료(초) |
|---:|---|---|
| 104729 | 흙 1 / 57 / 9.713 | 흙 2 / 233 / 31.773 |
| 130363 | 흙 1 / 94 / 15.584 | 흙 1 / 106 / 17.033 |
| 155921 | 흙 1 / 33 / 7.364 | 흙 1 / 48 / 9.150 |
| 196613 | 흙 1 / 32 / 7.492 | 흙 1 / 48 / 9.317 |
| 262147 | 흙 1 / 115 / 17.867 | 흙 0 / 384 / no_progress |

두 조건 모두 계획 5, 실제 실행 5, 기술 오류 0, 미실행 0이다. official의 1회
무획득은 정책 미완료로 기록했다. 이 시행은 밀 씨앗 1개만 얻었고, 목표 흙은 0개였다.
목표와 무관한 아이템을 성공으로 인정하지 않았다. 마지막 100개 행동 중 attack은 38개,
이동/점프는 35개여서 이전 실패의 공격 100/100 반복과 완전히 같은 패턴은 아니다.
`official-262147/run/frames/000384.png` 및 전체 관측/행동 로그를 보존했다.

원시 session status는 성공 9회 `task_completed`, 정체 후 종료 1회 `cancelled`다.
비교 도구의 `completed=true`는 **계획한 10회의 실행 완료**를 뜻하며 10/10 수집 성공을
뜻하지 않는다. 정책 결과는 profile별 5/5와 4/5로 별도 집계한다.

## 원본 보존 및 제어 확인

- 10회 모두 실제 복원 인벤토리 일치. 위치 차이는 각각 약 0.086013블록으로 기존
  허용 오차 2블록 이내였다. 비트 단위로 동일한 물리 진행을 주장하지 않는다.
- profile별 조건 embedding 해시 5개가 각각 달랐다. 실제 조건 문구와 guidance를
  이벤트에서 검사했다. 요청한 수집 목표 자체는 모두 dirt 1개다.
- 재개 acknowledgment 전 정책 dispatch 0회. 모든 STOP 및 마지막 정체 이후
  정책 dispatch 0회. 입력 해제와 월드 저장 모두 성공.
- 각 시행의 소유 자식 잔존 0개, 종료 후 별도 프로젝트 Python/Java 조회도 0개.
- 원본 current pointer 바이트, manifest와 world.zip 해시 유지 확인. STOP 다시 잠금.
- 추가 API 0회, 기존 프로젝트 누적 37회 유지. Colab/전역 환경 변경 없음.

## 해석과 다음 범위

같은 실패 후 상태에서 기존 정책을 새로 시작해도 목표를 달성할 수 있었다.
공식 문구는 성공률 개선을 보이지 않았고, 두 조건 모두 성공한 네 시드에서는
기존 문구 쪽 완료 시간이 짧았다. 한 월드의 5쌍 관측이므로 일반적인 문구 우열이나
통계적 효과를 주장하지 않는다. 기본 설정을 바꿀 근거가 없어 그대로 유지했다.

이전 실패 실행은 흙을 캐기 전 상태에서 시작했고, 이번 비교는 실패 후 저장한
상태에서 시작했다. 따라서 이전 실패와 이번 성공을 문구/hidden-state 하나의
인과 효과로 해석할 수 없다. 프로세스 재시작·prior 재샘플링·물리 재개가 함께 있다.

자동 재시도를 추가하거나 새 줍기 motor skill이 완성됐다고 보고하지 않는다.
다음 검증 대상은 같은 세션에서 목표·획득량을 유지한 제한된 정책 재초기화가
도움이 되는지다. 이번 10회는 완료했으며 같은 묶음을 추가 반복하지 않았다.
