# 수집 정체 감지와 복구

세션은 실제 목표 아이템 순증가의 최고치가 기본 60초 동안 늘지 않으면 과업을
`paused`로 바꾼다. `no_progress`는 **획득 증가를 관측하지 못했다**는 뜻이다.
자원 부재, 길 막힘, 적 출현 등의 원인을 식별한 것은 아니다.

## 감지와 제어

- `session --no-progress-s 60`으로 설정한다. 유효 범위는 0 초과 180초 이하다.
  설정값은 세션 summary에 기록한다. `episode`/기존 정책 벤치마크에는 적용하지 않는다.
- 실행 중의 경과 시간으로 측정한다. 일시정지·복원 대기 시간은 새 시도에 포함하지 않는다.
  모델/환경 초기 로딩은 제외하며, 활성 정책 조건 설정·추론·환경 제어 시간은 포함한다.
- 현재 단계의 순증가 최고치가 늘면 시간을 새로 측정한다. 잃은 아이템을 같은 수량까지
  다시 얻는 것으로 감지 시간을 무한히 연장하지 않는다.
- 추론 전후에 검사한다. 정체가 확인되면 revision 증가 → paused 체크포인트 → 입력 해제
  → `task_no_progress` 이벤트를 기록한다. 이미 계산한 정책 행동은 전달하지 않는다.
- STOP과 들어온 명령을 먼저 검사한다. 오래된 revision을 담은 요청은 거부한다.
- 실제 이벤트에는 감지 시간, 임계값, 관측 번호와 과업 상태가 남는다.
  summary에는 `no_progress_s`, `no_progress_events`가 남는다.

## 복구

정체는 전체 과업을 완료하거나 취소하지 않는다. 완료한 단계와 활성 단계 baseline,
실제 진행도, 남은 계획을 보존한다. 대화 콘솔의 현재 과업에도 failure 근거를 전달한다.

1. 같은 목표를 계속 시도하려면 기존 `resume` 확인 절차를 사용한다. 기존 baseline은
   유지하고 감지 시간을 다시 시작한다. 무제한 자동 재시도는 하지 않는다.
2. 목표를 바꾸려면 기존 `modify` 또는 `modify_plan`을 확인한다. 일시정지 상태를
   유지하며 새 목표의 baseline을 현재 인벤토리에서 잡는다. 이후 별도로 재개한다.
3. 중단하려면 `cancel` 또는 STOP을 사용한다.

실패 근거는 schema 3 체크포인트와 저장 월드에 함께 보존한다. schema 1/2를 계속 읽으며
실패 정보가 없는 일반 과업은 기존 schema를 쓴다. 재개/수정 이후 현재 failure 필드는
제거하지만 이전 감지 이벤트와 저장 세대는 남는다. schema 3 파일을 이전 코드로
되돌려 읽는 것은 지원하지 않는다.

이번 단계는 관측 기반 중단 및 **명시적으로 수정한 계획의 실행**이다. LLM의 자동
원인 진단이나 자율적인 대안 탐색·새 스킬 선택은 구현하지 않았다. 기본 60초 값의
오탐률·최적성은 평가되지 않았으며 탐색이 오래 걸리는 정책에는 성급한 중단일 수 있다.

## 한 번에 실제 검증

Windows PowerShell의 프로젝트 폴더에서 실행한다. 프로젝트 Python 경로는 해당
프로세스에만 설정하며 API 키나 유료 호출은 필요하지 않다.

```powershell
$env:PYTHONPATH = Join-Path (Get-Location) 'src'
python scripts/run_failure_recovery_acceptance.py
```

STOP이 잠겨 있어야 시작한다. 고유한 검사 슬롯에서 5초 임계값으로 실제 정책의 정체를
유도하고 저장·종료한다. 두 번째 프로세스는 실패 상태를 복원하고 흙 1개 계획으로
교체한 뒤 명시적으로 재개한다. 구간당 제어 상한은 180초이며 자동 재시도는 없다.
종료 시 STOP을 다시 잠그고 원시 이벤트, GPU/시간 측정, 저장·프로세스 정리 근거와
acceptance.json을 `results/failure-recovery-<UTC>/`에 보존한다.

이 검사의 유도된 정체는 자연 실패율에 넣지 않는다. 기존의 실제 취소/STOP 회귀와
합성 테스트도 각각 별도 근거로 유지한다.
