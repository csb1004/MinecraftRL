# 공통 이동 정책의 RM 통합 전 확인 사항

2026-10-19 정적 코드 점검. 실제 통합 실험 결과가 아니며 현재 진행 중인 평가의
실행 코드와 정책은 변경하지 않았다.

## 확인한 실행 계약 차이

독립 이동 평가는 `navigation_trial.py`에서 `delivered_mode`를 명시하여 실제 전달
행동의 최빈값을 선택하고, 도착 조건을 12틱 연속 유지해야 성공으로 판정한다.
학습되지 않은 개발 월드에서 이 조건으로 측정한 결과만 보고한다.

현재 `rm_navigation.py`의 waypoint 실행은 `GoalRecoveryController.act`를 통해
`RLPolicy.act`를 호출한다. 여기서는 `pi_head.sample(..., deterministic=False)`를
사용하며 `NavigationSwitch.sample`도 원래 head의 표본추출을 전달한다.
도착은 commit에서 단일 `arrived(...)` 판정으로 종료한다. 이미 도착한 노드를
건너뛰는 경로도 별도로 존재한다.

새 v4 정책의 부모·목표 임베딩 해시 검사, client 관측 및 root_context_mode 정보는
통합 로더가 지원한다. 이는 가중치를 읽는 호환성 확인이며 행동 선택과 종료 계약이
같다는 증거는 아니다. 목표별 잔여 틱 예산과 목표 전환 시 기억 유지도 함께 확인해야 한다.

목표의 높이에도 차이가 있다. `AdaptiveRoute`와 `ExplorationRoute`는 현재 위치와
같은 y의 수평3블록 후보를 만들고, RM 입력 검증도 같은 높이를 요구한다.
이 후보의 지형은 unknown이며, 자연 이동 평가의 미리 확인한3차원 목표와 다르다.
도착 유지12틱만 연결하면 해결된다고 가정할 수 없다. 실제 지면 높이를 확인할 수 있는
목표인지, 높이를 모르는 수평 탐색 목표인지 구분하여 정책 입력과 완료 계약을 검증해야 한다.
현재 도착 허용 높이 오차1.5블록을 정밀 도착 판정으로 바꿀 때 이 차이를 숨기지 않는다.

## 채택 전 검증할 상태 변화

1. 선택한 이동 정책을 RM에 연결했을 때 명시한 행동 선택 방식이 실제 전달 행동,
   기록된 행동 확률 및 감사의 재현 결과와 일치한다.
2. 도착 유지 조건을 충족한 경우에만 이동 노드가 완료되고, 루트 목표와 기존 미완료
   목표는 보존된다. 이미 만족한 노드의 처리도 별도 규칙과 증거를 갖는다.
3. 이동이 끝나거나 실패하면 다음 스킬로 넘어가되 루트 정책의 표본추출과 기억을
   의도 없이 변경하지 않는다. STOP 이후 전달 행동0, 입력 해제, 소유 PID 정리를 확인한다.

결정적 실행을 도입한다면 행동의 실제 확률은 해당 선택 규칙을 반영해야 한다.
원래 제안 분포의 확률을 실제 전달 행동 확률로 대신 쓰거나, 결정적 평가 궤적을
그대로 on-policy PPO 자료로 넣지 않는다. 기본 정책 승격 전 별도 고정 통합 조건으로
검증하며 현재 자연 지형 실패를 제어 규칙 변경으로 숨기지 않는다.

현재 c91 및94e999는 별도 stochastic 근거리 정지 진입 조건도 충족하지 못했다.
따라서 독립 delivered_mode 평가의 통과를 기존 RM 표본추출 경로의 통과로 해석할 수 없다.
