# 연속 복구 시연의 기억층 BC 결과 — 2026-10-08

학습·체크포인트·전체 추론 연결과 실제 진단4회까지 완료했다. 기억층 학습은 행동을 바꿨지만
긴 벽 우회는 해결하지 못했다. 기본 정책을 유지한다.

[최초 프로토콜](temporal-bc-protocol-2026-10-08.md),
[학습 후 추가한 진단 조건](temporal-bc-diagnostic-protocol-2026-10-08.md).
기존 RM/보상/기본 정책과 연구 명세는 유지한다. LLM 재계획이나 RM 우선순위 전환을 구현한
결과가 아니다. 이번 추가 학습은 **행동 복제(BC)**이며 PPO 갱신은 없다.

## 구현과 데이터

동결된 앞쪽 CNN/목표 결합/기억블록의 순차 입력을 캐시하고 마지막 기억블록을 학습한다.
매8프레임 창 앞의 기억은 episode 시작부터 현재 가중치로 다시 계산한다. 앞부분은 no-grad,
창 안은 기억을 detach하지 않는다. 행동 label, 관측 순서, 실제 RM6 입력을 유지하며 episode
경계를 넘지 않는다. 8프레임은 gradient 범위이지 모델이 기억하는 전체 과거의 길이가 아니다.
게임에서 한 전이는 서버1tick이므로 8전이는 명목상0.4초다. 실제 제어 시간은 별도 측정한다.

기존 교사6 train/2 development의2037전이(train1436/dev601)를 사용했다. 원본 frame/action/
관측 연속성/해시/분할을 검사했다. 교사는 privileged scripted 시연이며 학생의 성공 표본이 아니다.
현재 학생도 영상/고정 embedding에 privileged RM6을 더하므로 영상 전용 조건과 구분한다.
최종5시드와 개발/평가 게임 궤적을 학습에 사용하지 않았다. 기존 완료 학습을 재실행하지 않았다.

새 `temporal_bc.py`와 학습기, 기존 teacher 추출기의 `--cache-temporal`, 마지막 기억블록 위치/
개수/가중치를 포함한 체크포인트, `RLPolicy` 실제 로더/출처 기록을 연결했다. 로드 전 모든
backbone tensor의 키/shape/dtype/유한성을 검사하며 일부만 바뀐 상태를 남기지 않는다.
기억층·표현층 후보의 기존 head-only PPO 재개는 거부한다. value 가중치는 보존하지만 표현이
달라져 value 출력까지 같다고 주장하지 않는다.

## 같은 자료·순서의 학습 결과

같은 gap 부모/wood embedding/CFG6, 8프레임 창182개, seed9602,1epoch, AdamW lr5e-7,
KL계수1, gradient clip1. 두 조건 합계364 optimizer 갱신이다. 기억층의 추가 gradient 진단은
가중치를 갱신하지 않았다. 창마다 현재 가중치로 과거 기억을 재계산하므로 이전 optimizer 시점의
기억 캐시를 이어 쓰지 않는다. 전체 episode BPTT나 전체 모델 미세조정으로 해석하지 않는다.

## 실제 추론 경로와 gate 판정

저장된 두 후보를 원본 전체 정책에 로드하고 개발 시연281프레임씩을 순차 추론했다.
캐시를 사용하는 학습 경로와 특징/기억/행동 log-prob 오차가 모두0이다.
[최종 대조](../results/temporal-bc-runtime-20261008-v2/report.json).
첫 검사는 CPU에서 모델을 만들면서 upstream 전역 기본 장치도 CPU로 설정해, GPU 이동 뒤
초기 기억이 CPU에 생기는 검사기 오류로 중단했다. 초기 기억을 명시적으로 GPU로 옮기도록
수정했다. [원본 오류](../results/temporal-bc-runtime-20261008/report.json)는 보존했다.
학습/모델 가중치 오류나 Minecraft 실패 표본으로 세지 않는다.

기억층 후보는 개발 행동 예측 손실이 줄었지만 train KL=.060300이 최초 상한.03을 넘었다.
따라서 [엄격 기준 배치](../results/temporal-bc-comparison-20261008/experiment.json)는4조건
**미실행**으로 남겼다. 그 분모에 성공/실패를 넣지 않는다. 학습률을 추가 탐색하거나 gate를
통과로 고치지 않았다.

별도 진단은 개발 결과를 확인한 뒤 정했으며 KL 상한을 적용하지 않는다. 유한성/개발 NLL/
저장 복원/전체 추론 일치/STOP 요구는 유지한다. 후보를 기본 정책으로 승격하지 않는다.
이 선택은 작은 정책 변화만 허용하는 기준이 유용한 BC 변경까지 제한하는지 실제 게임에서
확인하기 위한 탐색이며 독립 최종 평가가 아니다.

## 실패 해석과 다음 단위

기억층이 업데이트되지 않거나 추론에서 빠진 문제는 이번 검사에서 배제했다. 그러나 손실 감소가
우회 능력으로 이어지지는 않았다. [교사 행동 집계](../results/temporal-bc-features-20261008/label-audit.json)에서
train1436행동 중 이동이 포함된 정답은674개였다. 따라서 단순히 이동 정답이 전혀 없다는
설명도 맞지 않는다. 충분한 상태 범위를 포함한다는 뜻은 아니며, 반복 공격에 빠진 학생의
방문 상태와 교사 시연의 차이·8프레임 gradient 제한·동결 prefix·짧은 학습량의 영향을 아직
분리하지 못했다. 어느 하나를 유일한 원인으로 단정하지 않는다.

다음 검증 단위는 **훈련 월드에서 학생이 실제로 정체한 상태의 교정 시연**이다. 정체→후퇴/
방향 전환→통로 진입→재접근의 관측/정답 행동을 보강하고 분리된 개발 자료로 확인해야 한다.
이번 개발/평가 궤적을 train으로 바꾸거나 실패 행동을 정답으로 복제하지 않는다.
새 우회 skill을 실행 vocabulary에 등록하거나 기본 정책으로 승격하지 않는다.
