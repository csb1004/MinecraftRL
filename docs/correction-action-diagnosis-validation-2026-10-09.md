# 교정 행동 예측 분석 결과 — 2026-10-09

관측된 병목은 정체 상태에서 첫 복구 회전을 시작하는 부분이다. 교사가 먼저 회전한 뒤의
기록된 화면에서는 부모와 후보 모두 필요한 회전 방향에 높은 확률을 주지만, 회전하기 전에는
공격을 계속하려는 확률이 높다. 전체 개발 손실 감소만으로 이 시작 행동의 개선을 판단하면 안 된다.
이는 보존된 소규모 자료의 예측 진단이며 자율 우회 성공이나 학습 실패의 유일한 원인 규명이 아니다.

## 실행 범위와 재현

[사전 조건](correction-action-diagnosis-protocol-2026-10-09.md)과
[인계 경유점 정정](correction-action-diagnosis-clarification-2026-10-09.md)을 적용했다.
Windows DESKTOP-V0HJPC2의 실제 프로젝트에서 PowerShell을 사용하고, GPU 추론은
WSL Ubuntu-24.04의 기존 격리 환경으로 실행했다. 새 게임·정책 행동·optimizer 갱신·실제 LLM·Colab은 모두 0이다.
`results/STOP`은 해제하지 않았고 분석 중 매 프레임 원래 해시를 확인했다.

- 원본 교정 6시연의 전체 4,961프레임을 각 모델의 마지막 기억층·표현층·actor로 순서대로 재생했다.
  train 4시연/교사 정답 1,005개, development 2시연/619개이며 학생·중립 3,337프레임은 문맥 전용이다.
- 부모는 `temporal-bc-temporal-20261008/checkpoint.pt`, 후보는
  `masked-correction-training-20261009/checkpoint.pt`다. 후보에 부모의 최종 기억 특징을 넣어 비교하지 않았다.
- 공식 버튼 8,641개와 카메라 121개의 확률을 합산했다. 정답 yaw 부호 확률에는 카메라 활성 gate를 포함한다.
  회전 방향의 부호가 맞는 명령 확률이며, 정확한 회전량·충돌 회피·실제 탈출 성공 확률은 아니다.
- 두 모델 합계 9,922개의 프레임 예측을 보존했다. 기존 긴 벽 2게임의 3,199전이에는
  각 실행 자신의 actor만 적용했고, 기록된 행동 log-prob 재현 오차는 모두 0이었다.
- 전체 NLL은 기존 학습 보고서와 최대 4.31e-9 차이로 일치했다. 부모 특징 재현 오차 0,
  원본·체크포인트·명세·실행 코드 해시 보존을 확인했다.
- 분석 시간 344.26초, PyTorch peak allocated 328.54 MiB/reserved 356 MiB다.
  이는 캐시를 사용하는 오프라인 분석 자원이며 전체 게임 추론 VRAM이나 제어 지연이 아니다.

## 첫 회전이 평균에 가려져 있었다

각 개발 시연에서 교사에게 인계된 첫 관측의 명령 확률이다. 정답 행동은 공격을 멈추고 회전하는 것이다.
여기서 부모와 후보는 같은 기록된 문맥을 각각 자신의 기억층으로 재생했다.

| 개발 시연 | 정답 방향 회전: 부모 | 정답 방향 회전: 후보 | 후보 공격 확률 | 첫 행동 NLL: 부모 → 후보 |
|---|---:|---:|---:|---:|
| far | 0.809390% | 0.511039% | 99.887550% | 21.603312 → 21.667406 |
| corner | 0.000309% | 0.000235% | 99.944192% | 20.716233 → 20.772565 |

두 경우 모두 첫 정답 행동의 NLL이 악화됐고, 정답 방향으로 회전할 확률도 줄었다.
far의 후보 이동 명령 확률 75.36%에는 벽을 향한 전진도 포함하므로 탈출 확률로 해석할 수 없다.

반면 교사가 이미 1·2·3번 행동한 뒤의 기록된 관측에서 후보의 정답 방향 회전 확률은 다음과 같다.

| 개발 시연 | 교사 행동 1회 이후 | 2회 이후 | 3회 이후 |
|---|---:|---:|---:|
| far | 42.84% | 83.95% | 88.99% |
| corner | 28.11% | 80.51% | 95.77% |

이는 교사가 바꿔 놓은 화면과 그에 따른 기억 상태에서의 예측이다. 학생이 실제로 첫 행동을
실행하거나 이후 경로를 자율적으로 완수한 결과가 아니다. 부모도 이 이후 구간의 회전 예측은 이미 높았다.
첫 8교사 프레임의 평균 정답 방향 확률은 73.4364% → 73.5008%, top1은 둘 다 75%여서
첫 프레임의 낮은 확률을 감춘다. 첫 프레임 상세 검사는 사전 지정 first8 창 내부의 후속 분석이다.

## 구간별 손실과 자료 구성

개발 시연 전체 교사 NLL은 1.901921 → 1.690696으로 감소했지만, 감소량의 70.41%가
통로 횡단·나무 재접근에서 발생했다. 전체 손실을 낮추는 학습과 정체를 벗어나는 첫 행동의 학습은
이 자료에서 같은 결과를 내지 않았다.

| 교사 구간 | 개발 정답 수 | 부모 NLL | 후보 NLL |
|---|---:|---:|---:|
| 재배치 | 44 | 3.431026 | 3.263928 |
| 통로 접근 | 97 | 1.483482 | 1.284280 |
| 통로 횡단 | 66 | 3.043251 | 2.511609 |
| 나무 재접근 | 81 | 3.339915 | 2.636569 |
| 채굴 | 175 | 1.276572 | 1.233855 |
| 밑동 제거 | 142 | 0.600339 | 0.574142 |
| 회수 | 14 | 7.313604 | 7.255117 |

훈련 자료에서 각 시연의 첫 교사 행동은 총 4개로 1,005개 정답의 0.398%다.
네 훈련 시작점에서도 학습 후 정답 방향 회전 확률이 감소했다. 단순한 개발 세계 일반화 문제로만
볼 수 없다. 다만 표본 수·손실 가중·1 epoch·KL 제한·8프레임 역전파·기억 표현의 영향을
각각 분리한 실험은 아직 하지 않았다. 가중치만 늘리면 해결된다는 결론도 이 분석으로는 낼 수 없다.

별도 `collect` 구간은 훈련 정답 0개, 개발 14개다. 훈련 시연은 앞선 단계에서 이미 획득해 끝났다.
회수 구간의 높은 개발 NLL은 이런 자료 범위와 함께 봐야 하며, 해당 14프레임을 훈련으로 옮기지 않는다.

## 실제 긴 벽 실패 로그와의 연결

이번에는 새 게임을 실행하지 않고 [앞선 실제 대조](masked-correction-bc-validation-2026-10-09.md)의
로그를 분석했다. 후보가 닫힌 모서리에 있는 **행동 전 위치**로 분류한 1,143전이는 다음과 같다.

| 지표 | 후보 닫힌 모서리 구간 |
|---|---:|
| 평균 공격 명령 확률 | 99.858071% |
| 실제 공격 명령 비율 | 100% |
| 평균 이동 명령 확률 | 0.070160% |
| 실제 이동 명령 비율 | 0% |
| 평균 카메라 활성 확률 | 0.343317% |

부모의 복구 단계 이후 1,316전이도 평균 공격 확률 99.95503%, 실제 공격 100%, 실제 이동 0%였다.
기록된 행동 log-prob가 자신의 저장된 actor로 정확히 재현되므로, 이 구간의 공격 고착을
후보 가중치가 실행에 반영되지 않은 현상으로 설명할 근거는 없다.

앞선 경로 보고서의 후보 정체 **1,144전이**는 **행동 후 위치** 기준이다. 이번의 행동 전 기준과는
모서리로 진입한 경계 전이 1개가 다르다. 같은 실제 전이를 서로 다른 시점으로 분류한 차이이며
서버 관측 개수가 누락되거나 모델이 다른 개수로 인식한 결과가 아니다.

## 분석기 교정과 검사

초기 경유점 복원기는 첫 z를 3.5로 고정했다. 원래 교사는 정체 감지 뒤 중립 입력을 거쳐
인계 시점의 z를 사용했으므로, train-104743-far의 frame 467에서 행동 대조가 즉시 실패했다.
실제 canonical z는 3.1508192341791528이었다. 잘못된 가정으로 분석을 계속하지 않았다.

최초 코드와 오류는 `results/correction-action-diagnosis-precheck-20261009/`에 보존했다.
원본 `handoffs[].waypoints`와 실제 인계 위치를 검증하는 방식으로 수정한 뒤 6시연의 교사 행동을
모두 대조했다. GPU 분석은 이 교정 후 실행했다. 시연·행동 라벨·체크포인트 자체를 수정하지 않았다.

신규 검사 8개가 Windows와 WSL에서 각각 통과했고 구문 검사도 통과했다.
경유점 경계·mirror 방향·실제 인계 z·행동 불일치·불완전 경로·학생 정답 주입 거부·카메라 gate·
누락 지표의 분모를 확인했다. 기존 전체 회귀 검사를 이번에 다시 실행했다고 주장하지 않는다.
사용자 지침에 따라 서브에이전트 없이 재사용·정확성·계산량을 순차 검토했다.
두 결과 그래프를 직접 열어 축·단위·표시 범위를 확인했다.

종료 확인에서 고정 소스 59개·결과 4개·그래프 2개의 해시가 일치했다. 프로젝트에 해당하는
Windows/WSL Python·Java 잔여 프로세스는 0, GPU 사용률 0%/장치 메모리 323 MiB,
STOP 내용·해시는 처음과 동일했다. 종료 점검 때 WSL은 `firefly`의 systemd 사용자 세션
시작 경고를 냈지만 프로세스 조회는 exit 0으로 완료됐다. 시스템 설정은 변경하지 않았다.

## 다음 실행 단위

다음 단위는 **정체 관측에서 스스로 복구 행동을 시작해 접근이 회복되는지**를 확인하는
시작 구간 중심 BC다. 기존 상위 RM을 지우거나 개별 키 입력을 새 RM 단계로 만들지 않는다.

1. 실제 교사 정답이 있는 시작 구간의 표집/손실 비중을 명시적으로 분리한다. 학생 반복 행동에
   허구의 회전 정답을 붙이지 않는다. 학생 prefix는 실제 순서의 문맥으로 유지한다.
2. 첫 행동·첫 8프레임·지속 이동·통로 횡단을 별도 지표로 둔다. 전체 NLL 개선만으로
   실제 게임 평가의 통과를 선언하지 않는다. 훈련 시작점이 4개뿐인 한계 때문에 같은 자료의
   단순 반복은 과적합 진단으로 한정하고, 필요하면 훈련 월드의 서로 다른 정체 상태에서 실제 교정 정답을 보강한다.
3. 기존 계속 이동/채굴 행동을 함께 보존하고, 후보·갱신 예산·중단 기준을 실행 전에 고정한다.
   비교는 별도 개발 세계에서 학생 자신의 첫 회전→정체 이탈→통로 통과→서버 인벤토리 획득으로 판정한다.
4. 이번 개발 시연·평가 궤적은 훈련에 사용하지 않는다. 최종 5시드는 그대로 보존한다.
   강제 scripted 회전으로 정책 실패를 가리거나 미검증 우회 skill을 LLM vocabulary에 추가하지 않는다.

이번 완료 범위는 분석기와 보존 자료의 오프라인 진단이다. 시작 구간 중심 학습과 그 실제 게임 검증은
아직 미실행이며 성공/실패 표본에 포함하지 않는다. 기본 정책·연구 명세·원본 월드·체크포인트는 유지한다.
