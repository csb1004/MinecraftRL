# 같은 프로세스 재초기화 실험 결과

## 결론

고정 시드 5회 모두 재시도 없이 실제 흙 1개를 획득했다. 자연 무획득 정체가 0회여서
**실게임에서 재초기화의 복구 효과는 미검증**이다. 복구 성공률을 5/5 또는 0/5로
계산하지 않는다. 재시도 대상 표본 자체가 0개다. 일반 세션의 자동 재시도는 켜지 않았다.

기존 resume은 같은 정책 객체의 recurrent state와 text prior embedding을 다시
초기화한다. 이 경로에 worker PID 기록을 추가했고, 실험기만 자연 정체 뒤 최대 한 번
resume하도록 만들었다. 부분 획득량·이미 완료한 앞 단계·현재 목표 보존과 한 번의
예산은 합성 검사로 확인했다. 이 합성 검사를 실제 정책 복구 성공으로 간주하지 않는다.

## 실행 조건과 결과

[사전 조건](inplace-recovery-plan.md)에 따라 이전 실패 시행 시작 상태인 슬롯
`failure-20261004T032512557525Z`의 세대 `1c1415241ad44a81b6e89a1943472bf0`을
각 시행의 격리 저장소에 복사했다. 직전 문구 비교의 세대 `3b2f51efcf7c4bbe8edfee14623eb5db`와
다르다. 원본 current pointer와 선택 세대 manifest/zip 해시는 그대로 유지됐다.

STEVE-1, `collect dirt`, guidance 6.0, 목표 dirt 1개, 자연 정체 기준 60초,
재시도 포함 제어 상한 180초를 적용했다. 같은 저장 월드의 5개 난수 시드이며 서로
다른 지형이 아니다. 최초 paused 원목 계획을 흙 1개로 수정한 뒤 명시적으로 재개했다.
실행 환경은 Windows/WSL Ubuntu-24.04 및 GTX 1060 3GB다.

## 제어 검사와 증거

모든 시행에서 복원 인벤토리 일치, 환경 reset 1회, episode 시작 1회, 최초 policy reset
1회, 최초 resume 전 및 STOP acknowledgment 후 dispatch 0회, 중립 입력 해제,
월드 저장, 소유 자식 프로세스 종료를 확인했다. **정체 이후 pause→retry 구간은
이번 실게임에서 발생하지 않았다.** 실제 재시도 시 PID 유지·과업 보존·조건 재샘플링
검사는 도구에 준비됐지만 이번 데이터로 통과했다고 주장하지 않는다.

- Windows: 101개 중 97개 통과, Linux 전용 4개 제외, 1.778초.
- WSL: 101개 통과, 27.588초.
- 새 검사 2개는 실패 확인 후 통과시켰다. 실행/분석 스크립트 구문 검사 통과.
- 종료 후 읽기 전용 WSL 검사에서 프로젝트 관련 Python/Java 잔존 0개.
- `results/STOP` 유지. 추가 API 0회, 기존 누적 37회 유지. Colab 연결 없음.
- 연구 명세 SHA256:
  `4af3ad00c5bab9b9d08b2e23fe768e140944118aa85cf412c45a67bb032275ad`.

원시 결과: `results/inplace-recovery-20261004T044053480648Z/`의 `experiment.json`,
`analysis.json`, 각 시드의 `run/events.jsonl`, `run/summary.json`, 프레임과 격리 월드.
검사 로그는 `results/inplace-recovery-{red,green,windows,wsl}.log`, 종료 확인은
`results/inplace-recovery-process-check.json`에 보존했다.

## 재현과 후속 경계

프로젝트 PowerShell에서 STOP이 있는 상태로 다음 명령을 실행한다. 실행기는 STOP을
이번 결과 폴더로 보존 이동하고, 새 STOP 요청을 전달하며 종료 시 다시 잠근다.

```powershell
$env:PYTHONPATH='src'
python scripts/run_inplace_recovery.py
python scripts/analyze_inplace_recovery.py results/inplace-recovery-<실행시각>
```

기본 short/60초/명시적 resume는 유지한다. 같은 5회 묶음을 정체가 나올 때까지
무제한 반복하지 않는다. 후속에는 실제 사용 중 새 자연 정체가 발생했을 때 이 도구의
한 번 재개 경로와 증거를 수집할 수 있다. 강제 정체 fixture를 별도로 쓰더라도
제어 경로 검사로 구분해야 한다. 추후 복구가 관측돼도 무재초기화 대조군 없이 인과적
개선을 주장하지 않으며, recurrent state와 prior 재샘플링의 효과도 분리되지 않는다.
