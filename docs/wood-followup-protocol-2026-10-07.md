# v2 후속 검증: 실제 실행·경로 비용·개발 세계

사용자 승인 범위에서 이전 남은 검증을 이어간다. 원본 연구 명세·최종5시드는 유지한다.
학습된 v2 checkpoint는 `results/wood-shaping-v2-training-20261007/checkpoint.pt`,
부모는 `results/rl-batch-20261005T040215634778Z/training-retry-1/checkpoint.pt`다.

## 순서와 판정

1. 최신 v2 실제 개발 월드2000003 실행. 원목 획득134tick/23.577초로 연결은 성공했으나
   과거86tick보다 길다. 같은 초기 픽셀·반복 조건이 아니므로 인과 효과를 단정하지 않는다.
2. 원본 ZIP을 보존한 채 단일 청크 상부에 별도 시험장을 만든다. nbtlib2.0.4/numpy1.26.4는
   `.runtime/fixture-tools`에만 설치. 원본 NBT/region/ZIP을 수정하지 않고 새 파일을 만든다.
   마지막 region sector의 패딩이 없는 유효 저장 파일은 복사 시 패딩을 추가한다.
3. 긴 우회로의 흙 벽과 짧은 우회로의 돌 벽을 만든다. 두 배치에서 명시적 scripted probe로
   파괴/우회 양 경로의 실제 원목 획득까지 tick을 측정한다. 판정은 실제 측정값으로 한다.
   이 제어는 준비·진단용이며 정책 실패의 대체 성공으로 세지 않는다.
4. 부모/v2를 같은 배치에서 각1회 최대180초로 실행한다. 선택 경로·벽 통과·획득/실패를 기록한다.
5. 기존 개발5시드2100011/2100023/2100037/2100041/2100059의 동일 저장 ZIP에서 부모/v2를
   각1회 최대180초로 실행한다. 양쪽 모두 v2 관측·head 입력 형식을 사용한다.
   성공률, 획득 tick/제어시간, GPU/추론/전체주기, 초기 상태·픽셀 차이를 함께 기록한다.
6. 별도 불붙은 시험 플레이어의 명시적 noop 진단으로 실제 environment_done과 v2 실패 비용을 확인한다.
   입력 해제가 불가능한 done 경로는 기존 계약에 따라 별도 결과로 기록한다. 정책 과업 표본이 아니다.

학습 업데이트0인 고정 체크포인트 비교다. 각 world에 반복1회인 탐색적 검증이며 통계적 일반화는 주장하지 않는다.
기술 실패·초기화 중단·미실행은 과업 실패로 세지 않는다. STOP 이후 새 행동0 및 소유 PID 정리를 원시 로그로 감사한다.
시험장이 복원/이동에 실패하면 비용 비교는 미검증으로 남기고 준비 문제부터 수정한다.
성능 개선을 확인하지 못하면 기본 정책을 유지하고, 새 데이터의 학습 투입과4조건 학습 ablation은
성공/실패/복구 데이터 분리와 동일 behavior 조건을 먼저 확보한 뒤 수행한다. 기존 개발 평가 데이터는 학습하지 않는다.

## 앞으로의 과업 분해

사용자의 일반화 요청은 [상위 목표·skill 내부 단계 계약](task-decomposition.md)에 기록하고
AGENTS.md에서 후속 작업이 이를 읽도록 연결했다. 미지원 목표를 LLM 실행 schema에 임의 추가하지 않는다.

자료: [nbtlib 공식 저장 파일 API](https://vberlier.github.io/nbtlib/files/).

준비 진단의 최초 파괴 경로는 벽과 원목을 파괴했지만 밑동 앞에서 정지해180초 회수 실패했다.
`rl-eval-104729-20261007T041331833104Z`를 보존한다. 시험 스크립트가 파괴 뒤에도 같은 좌표를
공격한 원인이며, 확인된 목표 소실 뒤 밑동을 넘어 회수하는 단계로 수정했다. 학습 정책 표본이 아니다.
비용 진단에서 실제 획득이 확인되지 않으면 배치를 중단하고 원인부터 수정한다.
블록 경도/채굴 시간은 설치된1.16.5 `Blocks.java`, `AbstractBlock.java` 구현을 확인하며
실제 probe 소요 tick으로 비교한다. 다른 Minecraft 버전/서버로 일반화하지 않는다.
