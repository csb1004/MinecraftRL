# 공통 이동 입력과 사람 자료 연결 계약

사용자가 승인한 공통 스킬 학습의 입력 계약이다. v6 이후 별도 후보에 구현·학습했고 아래에 진행 이력을 남긴다.
연구 명세/상위 목표/RM 우선순위나 기존 원목 actor를 바꾸는 설계가 아니다.

## 문제와 결정

현재 이동 head는 실제 시각/기억2048채널에 나무 수집용 상위RM6채널을 붙여 받는다.
공식 사람 영상에는 이 연구의 RM 상태가 없다. 이를 임의로 search/approach라고 만들면
관측하지 않은 상태를 정답으로 주게 된다. 반대로 공통 이동은 대상이 나무인지 작업대인지보다
현재 장면과 실행 가능한 상대 목표/움직임이 필요하다.

후속의 별도 후보에서는 **navigation head에서 상위RM6채널을 구조적으로 사용하지 않는 조건**을
검사한다. 이를 unknown=0이라는 RM 상태로 해석하지 않는다. 실제 상위RM은 그대로 목표와
우선순위를 관리하고 원본 로그/원목 actor 입력에도 보존한다. 이동 내부의 상대 방향·거리·높이·
pitch·직전 움직임·남은 예산은 학습/실행 입력으로 계속 사용한다.

기존 모델/기본 입력은 유지하고 새 checkpoint 버전에 `root_context_mode`를 반드시 명시한다.
관측된6채널을 사용하는 과거 모델은 같은 수치로 복원돼야 한다. 새로운 ignored 조건은
RM6값을 바꿔도 navigation logits이 같아야 하고, goal이 없는 root 실행은 원래 입력을 사용해야 한다.
기존 head의 입력 함수가 달라지는 것이므로 단순히 가중치 학습만의 효과라고 보고하지 않는다.
모델 변경 전에 현재 v6의 수집/학습/감사를 모두 끝내고 source를 보존한다.

## 사람의 이동에서 쓸 수 있는 목표

사람의 의도는 녹화에 없으므로 미래 기록 위치를 **사후 이동 참고점**으로 붙인 것임을 명시한다.
입력은 현재 frame의 영상/기록 pose와 지정한 참고점으로 구성한다. 미래 화면을 현재 영상 입력에
넣지 않는다. 미관측 상위RM·실제 성공·접지·안전성을 생성하지 않는다.

임의의2초 끝점을 안정 정지 목표로 취급하지 않는다. 우선 먼 참고점으로 이동하는 감독만
검토하고, 끝점 근처와 시작 직전 움직임을 복원할 수 없는 첫 frame은 loss에서 제외한다.
끝점이 공중/물/위험 지형일 가능성이 있으면 별도 상태로 보존하며 일반 육지 도착 자료로 넣지 않는다.
현재 기존120frame feature cache에는 goal/RM=null, loss_eligible=false가 남아 있다.
이 파일을 소급해서 완성된 학습 자료로 표시하지 않는다.

새 목표/마스크는 별도 sidecar에 원본 frame·pose·입력·video/JSONL/특징 SHA를 연결한다.
인간의 실제 행동은 불변이고 상대 목표를 사후 부여했다는 사실을 별도로 기록한다.
원본 recording 단위 train/development 분할을 유지하고 PPO 데이터로 사용하지 않는다.

## 구현·검증 순서

1. 현재 v6 완료 결과와 실제 이동 개선을 우선 판단한다.
2. RM 사용 여부의 버전/학습/실행/감사 계약을 작은 별도 후보로 구현한다. 과거 checkpoint 수치 동일,
   ignored 조건의 RM 불변성, root 경로 보존, 잘못된 metadata 거부를 확인한다.
3. 목표를 붙일 수 있는 사람 구간을 실제 화면/pose/행동/시점 근거로 선정하고, 미충족 구간은 제외한다.
   이미 성공한64frame encoder 재현 검사는 특징 계보 근거이며 목표 정답 검증의 대체가 아니다.
4. 같은 로컬 자료로 입력 계약 변경의 영향을 먼저 비교한다. 이후 소량의 사람 이동 BC를 섞는 별도
   조건을 실행한다. 입력 변경과 사람 자료 추가를 동시에 적용한 효과를 단일 원인으로 주장하지 않는다.
5. 기존 평지 이동·정지를 회귀 평가하고 별도 자연 지형의 목표 접근을 실제 실행한다.
   교사/스크립트 성공, 영상 label 일치, 체크포인트 로드를 학습 정책의 실제 도착으로 세지 않는다.

자연 지형의 낙하 회피/장애물 판단은 영상을 필요로 한다. 이 계약은 시각 채널을 제거하는 설계가
아니며, 모르는 RM 정보를 제거해 실제 시각/목표 자료를 공통 이동 학습에 연결하기 위한 것이다.

## 격리 준비 검사 — 18:06

`results/common-navigation-root-context-preparation-20261017/navigation_model_staged.py`에만 구현했다.
실제 운영 모듈/학습/게임 코드는 아직 변경하지 않았다. ignored 조건은 RM6열을 linear 연산에서
제외해2048시각 특징만 받아도 되며, 기존2054입력의 RM값을 바꿔도 navigation 출력이 같다.
root 경로와 과거 checkpoint의 출력은 그대로다. 명시적 v3 계약이 없으면 ignored 입력을 거부한다.

Windows/WSL 각15검사를 통과했다. 첫 WSL 검사에서는 RM 없는 입력의 tensor stride 차이로
수치가 달랐고, ignored 분기에서 영상/목표를 contiguous로 통일한 뒤 비트 단위 동일성을 확인했다.
첫 실패 로그도 보존한다. 이것은 모델 입력 구현 검사이며 실제 이동 성공은 아니다.

사람 후보120frame 중 기준 위치의 높이가 계속 바뀌는40frame 구간은 제외했다. 나머지 두 구간에서
첫 frame과 참고점1블록 이내를 제외해 train36행동/development35행동의 사후 상대 목표를 제안했다.
`human-reference-proposal.json`은 `training_ready=false`, 원본 행동/feature 불변이며, 실제 사람 의도·
접지·안전·정지·도착을 관측했다고 표시하지 않는다. 아직 사람 가중치 학습0이다.

## 실제 코드 연결과 사람 자료 검증 — 18:27

18:14부터 RM 입력 분리 v3를 실제 코드에 연결하고 [같은 로컬 자료의 별도 학습](common-navigation-root-context-2026-10-17.md)을
진행 중이다. 위18:06 문단의 격리 상태는 당시 기록이며 현재 상태와 구분한다.

사람 참고점의 독립 재현은 train36/development35개 행동 모두 통과했다. Windows/WSL 삼각함수의
최대 차이1.11e-16을 측정한 뒤 허용오차1e-12로 비교하고, 학습 입력에는 원본 sidecar 값을 그대로
쓴다. 해시·정확한 행동 사상·split·clip 경계·목표 위치·원본 불변성은 엄격 비교한다. 첫 실패 로그는 보존했다.
`configs/common-human-navigation-bc-pilot-v1.json`과 `human-reference-qualification.json`에서 복원한다.

혼합 학습 코드/감사는 아직 격리된 준비 파일에 있다. 사람 loss10%·로컬90%, 원본36개를 복제해
독립 표본처럼 세지 않는 조건이다. 별도 사람 모니터35개는 gradient에서 제외한다. 순수 함수5검사와
실제 사람/로컬 특징을 사용한 CPU 역전파 검사를 통과했다. 혼합해도 로컬 log probability 오차0,
사람 loss에서 유한한 gradient가 생기며 optimizer0·가중치/root 불변이다. 이는 자료→손실 경로의 검사다.
아직 사람 자료 학습이나 실제 이동 성능 향상은 없다. 현재 실행의 소스가 바뀌지 않도록 로컬 실험과
감사를 완료한 뒤 혼합 코드를 실제 학습기에 연결한다.
