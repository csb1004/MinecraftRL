# 넓은 지식 탐색과 상호작용 중심의 개선 요청

2026-10-25 사용자 보완. 지식 검색을 현재 과업의 전제조건에만 제한하지 않는다. 상호작용은
검색/학습 중에도 유지한다. 후속 사용자 합의에 따라 같은 페르소나·공유 맥락의 LLM이 한 응답에
자연어 대화와 구조화된 개선 판단을 함께 출력한다. 프로그램이 이를 검증하며 별도 2차 변환 LLM은
기본 경로에서 제외한다. 독립된 페르소나들이 사용자 의도를 따로 결정하는 구조를 피한다.
이 문서는 요구와 추천 계약이며 구현/게임/학습/API 실행 결과가 아니다.

후속 사용자 제약에 따라 실사용 관측기는 고정한다. learning_request는 관측기를 바꾸지 않고
검증된 목표 조건·연습 분포·보상/평가와 RL 갱신으로 연결한다.
[지식→정책 학습 계약](knowledge-to-policy-learning-2026-10-25.md)을 함께 따른다.

이전의 '자연어 응답 후 2차 LLM 변환'은 검토했던 대안이다. 현재 합의는 한 의사결정 응답을
대화와 시스템 처리에 함께 사용하는 방식이다. 같은 모델 이름/페르소나만 공유하는 별도 호출과
구분하며, 실제 RL 정책과의 의미/행동 일치는 별도 검증한다.

## 검색과 지식 수용 범위

수집/제작 외에도 몹의 변환, 날씨와 환경 효과, 생태/상호작용, 위험, 공간/차원 규칙, 플레이
관습/문화, 사용자와의 대화에서 생긴 질문을 검색 대상으로 허용한다. 현재 실행 중인 목표에
직접 필요하지 않아도 관련 지식을 저장할 수 있다. 기본 분류에 없는 내용도 근거 원문과 함께
후보로 보존한다. 관습/개인 선호를 보편적인 게임 물리 규칙과 동일하게 취급하지 않는다.

검색 계기는 사용자 질문/호기심, 새로운 관측, 설명되지 않는 사건, 기존 지식의 충돌,
위험 가능성, 현재/후속 과업이다. 중복·호출/시간 예산을 두고 실행 가능한 주제 목록을 곧
지식 검색 허용 목록으로 사용하지 않는다. 지식 수용 범위와 자동 행동/보상/학습 범위를 구분한다.

정형 자료 변환과 문서 검색을 병행한다. 출처 원문/버전/확인 시각을 보관하고 LLM이 필요 부분을
`대상 + 사건/관계 + 적용 조건 + 예상 결과 + 예외 + 근거`로 추출한다. 관측에 연결되지 않은
새 개념은 설명/질의에 사용할 수 있지만 실행 또는 보상의 확정 판정으로 바로 사용하지 않는다.
서로 다른 버전/환경의 주장이나 반대 근거는 보존하고 기존 비단조 수정 절차로 처리한다.

사용자 예시인 돼지의 번개 변환은 로컬 Minecraft 1.16.5 소스
`.runtime/steve1/lib/python3.10/site-packages/minerl/MCP-Reborn/src/main/java/net/minecraft/entity/passive/PigEntity.java:205`
에서 확인했다. 번개 처리 시 난이도가 PEACEFUL이 아닌 경우 ZOMBIFIED_PIGLIN을 생성하는
분기가 있다. 이는 소스 확인이며 이번에 실제 번개 실험을 수행했다는 뜻은 아니다.
이 지식만으로 현재 관측한 좀비화 피글린의 출현 원인을 번개로 확정하지 않는다.

## 하나의 상호작용·판단 맥락

상호작용 LLM은 사용자 발화, 현재 목표, 페르소나/선호, 대화 요약/최근 대화, 관측 사건,
검색 근거, 현재 정책 능력의 같은 버전 상태를 사용해 응답과 필요한 판단을 함께 만든다.
모델 버전과 페르소나/목표/KB/정책 revision을 각 요청에 기록한다. 사용자에게는 구조화된 응답의
자연어 대화 부분만 보여준다. 검색 결과나 학습 완료를 기다려 모든 대화를 막지 않는다.
확인되지 않은 사실은 불확실성을 밝히고, 검색 후 새 근거가 생기면 응답/판단을 갱신한다.

상황 감시/VLM은 관측과 이상 후보를 전달하고 검색 작업자는 근거를 가져온다. 이 작업자들이
별도 페르소나나 독립적인 최종 사용자 의도를 만들지 않는다. 사용자 발화가 없는 사건도 같은
판단 맥락에서 처리하며 모든 내부 사건을 사용자에게 발화할 필요는 없다. 대화 요청이 긴
백그라운드 추론 뒤에 무한 대기하지 않도록 우선순위와 오래된 요청의 취소/통합을 둔다.

LLM 입력은 원래 사용자 발화·목표·관측·검색 근거와 필요한 대화 기억이다. 친근한 답변 문장만
보고 별도 의도를 재추측하지 않는다. 출력은 자연어 reply와 상황 판단, 지식 후보, 추가 확인,
계획 변경, 학습 요청으로 구분한다. 필요한 판단 요약은 의도/근거/불확실성만 담으며 비공개
추론 과정 전체를 요구하지 않는다. 필요 없는 후보는 null/빈 목록으로 남긴다. 내부 관측 사건에는
사용자 발화가 없어도 되며, 매 사건마다 대화 메시지나 학습 요청을 강제로 생성하지 않는다.

## 단일 응답과 프로그램 검증 계약

| 출력 | 보존할 내용 |
|---|---|
| 사용자 응답 | 같은 페르소나의 자연어 reply. 판단/실행 상태와 모순되지 않아야 함 |
| 원문 연결 | 사용자/에이전트 발화 ID, 근거 문장, 관측/검색 항목 ID |
| 대화 의도 | 질문·정보·선호·제안·실행 요청·수정·취소를 구별 |
| 상황 판단/추가 확인 | 관측 사실, 경쟁 가설, 모르는 항목, 가설을 구별할 다음 확인 |
| 지식 후보 | 일반 규칙, 현재 사건의 가설, 출처, 적용 맥락과 불확실성 |
| 계획 후보 | 기존 root goal ID와 revision, 하위 목표/우선순위, 적용한 선호 |
| 학습 후보 | 원인 가설, 부족한 능력, 필요한 확인/연습 조건, 보류 사유 |
| 일관성 | persona/KB/policy revision, 원문과의 충돌/누락/지원 여부 |

파서와 검증기는 별도 성격을 갖는 의사결정자가 아니다. 형식/필수 필드/근거 ID/지원 기능/목표
revision을 검사하고 새로운 목표·확정 지식·학습 필요성을 추가하지 않는다. 부정, 수량,
미래/가정 표현, 불확실성, 제안을 보존해야 한다. 형식 준수 자체가 사실성이나 답변과 요청의
일치를 보장하지 않으며, 프로그램만으로 모든 의미 충돌을 검출할 수 있다고 가정하지 않는다.
불일치나 모호함은 후보 적용을 보류하고 같은 판단 맥락에 반환한다. 형식 오류를 임의의 실행
명령으로 복구하지 않는다. 재판단 횟수는 제한한다. 이미 승인된 목표/범위는 유지하며 새 형식을
쓴다는 이유로 사용자 승인을 매번 다시 요구하지 않는다.

Task Commitment Layer와 실행 가능성/보상/자원 검증기는 그대로 필요하다. 에이전트가 자기
답변에서 '해볼게'라고 말한 것 자체를 사용자 실행 승인으로 사용하지 않는다. 단순한 게임 지식
질문을 번개 소환·동물 변환 실험 요청으로 바꾸지 않는다. STOP은 LLM 생성/검증 완료를 기다리지 않는다.
기본 경로는 응답 파싱/필수 검증 후 reply와 후보를 각 처리 경로로 전달한다. 준비/후보 상태를
실행/학습 완료로 표현하지 않는다. 긴 검색/학습은 비동기로 분리하며 단일 판단 응답이라는 이유로
게임 제어 루프를 막지 않는다. 실제 응답 지연과 대화 품질은 구현 후 측정한다.

## 예시와 피드백

관측으로 번개를 보지 못했는데 사용자가 돼지 변환 이유를 물으면, reply는 검색한 일반
변환 규칙을 설명하면서 이번 사건의 원인은 미확정이라고 구분한다. 같은 응답 안에서 다음을 분리한다.

- 일반 지식: 적용 조건이 있는 돼지의 번개 변환 규칙. 출처에 근거한 항목.
- 현재 사건: 번개가 원인이라는 가설. 직접 관측하지 않았다면 확인되지 않음.
- 사용자 의도: 질문/정보 교환. 새로운 실행 요청 아님.
- 개선 후보: 현재 관측/능력에 근거가 있을 때만 필요한 확인 또는 학습 후보 생성.

판단과 말투는 같은 페르소나/선호를 따르며 행동 성향에 적용할 선호는 명시적으로 전달한다.
페르소나는 사실의 진위나 사용자 최종 성공 기준을 바꾸지 않는다. 기존 RM과 목표 이력도 보존한다.
실행/학습 결과는 같은 사건·발화·목표 ID로 상호작용 LLM에 돌아가 다음 응답과 능력 지식을 갱신한다.
중간에 목표가 취소되거나 revision이 바뀌면 늦은 판단/학습 결과를 현재 행동에 그대로 적용하지 않는다.

출력 형식이 자연어와 JSON으로 다른 것 자체는 불일치의 증거가 아니다. 같은 모델/페르소나를
사용해도 의미 보존이나 실제 정책 학습은 자동 보장되지 않는다. 부정/농담/정보 질문/제안/명령을
구분하는 출력 검사, 근거 없는 추가 주장/목표 검사, 오래된 결과 차단, 실제 행동/학습 결과와
발화의 일치 여부를 평가한다. '말한 의도 → 생성한 요청 → 실제 결과'의 추적으로 동기화를 검증한다.

## 현재 코드와의 차이

`src/minecraftrl/semantic.py`의 기존 prompt는 semantic planner를 persona와 분리하며
현재 실행 vocabulary도 제한돼 있다. 이는 위 요구를 이미 구현했다는 뜻이 아니다. 새 단일 응답
계약을 도입할 때 기존 목표 승인·수정·취소 검증을 보존하고 구현 범위/테스트를 다시 정해야 한다.
이번에는 설계 문서만 변경했다. 원문 `research-spec.md`, 게임 환경과 STOP은 유지한다.
