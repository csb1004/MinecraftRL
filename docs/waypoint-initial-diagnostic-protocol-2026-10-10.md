# 경유점 skill 미호출 뒤 초기 상태 진단

보강 후보의 정체 기반 far/corner 게임은 원래 root가 원목1개씩 얻어 종료했다.
각각717/1028전이지만 이동 행동0이다. 해당 두 게임은 경유점 성공/실패 표본이 아니다.
정체 발생 여부와 별도로 실제 목표 추종을 확인하기 위해 다음 조건을 추가한다.

- 보강 checkpoint `f1dee801…`를 그대로 사용한다. 새 학습/체크포인트 선택/API는0이다.
- 같은 개발 far/corner 월드와 sampling9922/9923, 각1회다. 원본/앞선 결과를 덮어쓰지 않는다.
  출력은 `results/waypoint-initial-validation-20261010/{far,corner}`다.
- 명시적 `--rl-waypoint-start initial`에서 첫 정책 행동 전 fixture 경유점을 공급한다.
  정체 감지를 가장하지 않는다. `diagnostic_route_start`와 시작 방식/출처를 기록한다.
- 행동은 보강 신경망이 샘플한다. 교사 접두 행동/직접 키 override는 없다.
  초기 신경망 기억에서 출발하므로 정체 이후 기억 분포의 복구 검사와 구분한다.
- 기존400이동행동/60초, 전체180초, 서버 도달0.35블록/높이차1.5, route 후 원래 root 복귀,
  root RM/STOP/입력 해제/소유 PID 정리 계약을 유지한다.
- 알려진 경로·privileged 좌표/방위 조건이며, 성공해도 자연 지도 탐험이나 정체 복구의
  일반화로 해석하지 않는다. 실패해도 임계값/키 입력을 바꾸지 않고 실제 궤적을 기록한다.

시작 경계와 미지원 CLI 조합 검사에서 의도한2실패를 먼저 확인했다. 최소 구현 과정의 잘못된
검증 함수 삽입도 회귀 검사가 잡아 실행 전 수정했다. 최종 관련13개 Windows 검사 통과.
실행 당시 소스는 각 게임 폴더에 보존한다.
