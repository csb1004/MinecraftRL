# 같은 상태에서 상대 목표에 따라 행동을 바꾸는 공통 이동 학습

목표는 특정 저장본의 정답 경로가 아니라 상대 목표에 따라 접근·방향 전환·정지를 선택하는
공통 가중치를 학습하는 것이다. 원목 정책과 원문 연구 목표, 실제 성공/STOP 계약은 유지한다.

앞선 두 비교는 각각704갱신을 완료했지만 둘 다 사전 offline 선택 기준에 미달했다.
거리 scale16은 가까운 목표의 비이동 확률을 개선하지 못했고, delivered BC는 먼 목표의
전진도 줄였다. 단순 정지 빈도 증가로는 부족했다. 학습 정지 정답451개 중 정면5도 이내16개,
그중 거의 정지한 경우4개라는 coverage 편향을 확인했다.

기존 자료를 반복하는 방법은 이 상관관계를 유지한다. 소수 정면 정지 표본만 복제하는 방법은
그 장면에 과적합할 수 있다. 기존 교사 질의에 **같은 실제 상태의 다양한 상대 목표**를 추가하여
목표와 화면 맥락의 상관관계를 줄이는 방법을 선택한다. 이것은 기존 BC 자료 생성 흐름의 확장이다.

## 자료 계약

- 감사된 현재 입력 train A/B/C만 사용한다. 각 실행의 접지 확인 상태 중 순서가 고정된12개를
  고르게 선택한다. development와 예약 final에서 gradient 자료를 만들지 않는다.
- 현재 시선을 기준으로 상대 방위 -170/-135/-45/-8/0/8/45/135/170도,
  거리0.10/0.18/0.60/1.50/3.00블록을 사용한다. 현재 위치와 목표 모두 기존 교사가 다루는
  볼록한 평지 내부여야 한다. 중심점뿐 아니라 폭0.6블록인 몸 전체가 차지하는 블록 열이
  x1..6,z1..14 안에 있어야 한다. 같은 방위에 적어도 하나의 거리0.6 이상 목표가 없으면 그 방위는 제외한다.
- 현재 위치·시선·관측 시점·직전 이동량은 실제 값이다. 목표만 별도 조건으로 바꾼다.
  해당 상태에서 원래 실제 실행한 action/logp/goal/owner/features는 고치지 않는다.
  새 가상 목표의 계획 예산은100틱으로 명시한다. 정확히180도의 좌우 동률은 제외해
  부동소수점 부호에 따른 교사 정답 모호성을 피한다. 실제 원래 목표의 남은 예산은 보존한다.
- 별도 `bc_motion_goal`과 `bc_action`, 원본 row/새 목표/좌표 출처/질의 코드 해시를 보존한다.
  공식 action mapper로 정답을 만들고 독립 감사에서 좌표·목표·정답을 재생한다.
- 가상 목표 질의는 실제 궤적, 성공 횟수 또는 PPO 자료가 아니다. 완주/보상/value를 만들어 붙이지 않는다.
  원래 RM 이력과 LLM 실행 vocabulary도 바꾸지 않는다.

## 학습 및 검사

초기 actor는 기존 v3 `584e7cf507a9ce4376f542f46269660fc40fc9f900e3878f425bc9f727066fb1`이다.
root/value는 동결한다. residual distance scale16은 함수 보존 변환 후 실제 전 입력 오차0을 확인한다.
BC는 실제 전달 명령 확률을 사용하고, 기존 실제 상태 질의와 새 목표 질의를 함께 학습한다.
학습률1e-4,16epoch,batch32,KL 한도3,난수14101이다. 자료 수에 따른 실제 갱신 수를 보고한다.
이 단계는 자료와 최적화 조건을 결합한 후속이며 단일 변경의 인과 효과라고 주장하지 않는다.

기존 별도 monitor254개는 gradient에서 제외한다. 기존 적합성 검사를 통과한4개 train 상태의
거리 반사실 검사는 진단으로만 쓴다. 실제 게임 전 조건은 평균 가까운 목표 비이동 확률≥0.85,
먼 목표 전진 확률≥0.40, 먼/가까운 목표 전진 차이≥0.20, monitor delivered NLL≤기준의1.05배다.
미달이면 실제 성공을 가정하지 않고 학습/자료를 분석한다. 체크포인트·로그는 보존한다.

통과하면 canonical/current-pose 기준과 새 후보를 같은 개발2월드/초기 화면·기억/코드/JAR에서
새로 비교한다. seed17479,client pose,12틱 안정 도착,6목표/실행,제어≤180초를 유지한다.
최소10/12 안정 도착·월드별 비악화·총 도착 증가 또는 동률에서 행동 감소,
STOP 이후0·해제·소유PID 종료 및 확률 재생 감사를 요구한다. 최종 시드는 여전히 미사용이다.

## 준비 오류 수정과 새 실행

첫 `results/common-navigation-goal-variation-20261017` 시도는 중심점 범위만 검사하여 몸이 벽과
겹치는 목표46개를 포함했다. 학습 중 추가 검사로 발견해 소유 진단 STOP을 걸었다.
2epoch/최소182 optimizer step이 실행됐지만 저장 checkpoint는 없고 이 시도 전체를 제외했다.
중간 epoch 갱신 수는 이전 중단 로그에 없어 정확히 추정하지 않는다. 이후 학습기는 중단 시
현재 optimizer 갱신 수도 저장한다. 원본 실패·로그·STOP은 보존한다.

수정 후에는 원본 시작 ZIP을 SHA로 바인딩하고 NBT의 실제 기반암 바닥/몸이 차지할 빈 공간,
생존 모드/몹 생성 없음과 전 구간 인벤토리0을 직접 확인했다. 수확 카운터0만으로 모든 블록
변경이 없었다고 추론하지 않는다. 상태 선택36개는 같고, 정답은487+506+462=1,455개다.
기존 실제 상태 정답1,384개를 더한 총2,839개를 사용한다. 이전4개 거리 진단 상태도 NBT 몸폭
검사를 통과했다. `goal-query-domain-preflight.json`과 `body-safe-distance-probe-geometry.json`이 근거다.

`configs/common-navigation-goal-variation-v1-retry1.json`은 별도 출력
`results/common-navigation-goal-variation-20261017-retry1`을 사용한다. 실패 가중치를 이어받지 않고
원래 v3에서 다시 시작한다. 소유 STOP도 기록된 SHA가 그대로일 때만 보존·재무장한다.

## 첫 정상 학습과 추가 고정 라운드

retry1은2,839정답/1,424 optimizer update를450.125초에 완료했다. 실제 정답1,384개와
가상 목표1,455개를 모두 재생 감사했고,3,093입력의 초기 변환 오차0/root·value 보존/reload0이다.
checkpoint는 `fa51381e646cf04b8d298b192795f4102c7afdf6336581591bea356ead8aa08a`다.
monitor delivered NLL은 기준2.6828→1.9686이다.

거리 진단은 가까운 목표 전진0.2702/비이동0.7298,먼 목표 전진0.3823으로 방향 관계가
정상화됐지만 사전 세 행동 gate는 미달했다. 실제 게임0이며 게임 실패 표본으로 계산하지 않았다.
원본 `selection.json`의 eligible=false는 바꾸지 않는다.

학습 손실이 계속 감소하고 KL guard에 닿지 않았으므로 같은 조건·자료에서 추가16epoch를
별도 v2 라운드로 실행한다. 시작 가중치는 위 retry1이며 Adam 상태는 새로 시작한다.
따라서 한 optimizer의 중단 없는32epoch와 동일한 실험이라고 주장하지 않는다.
`configs/common-navigation-goal-variation-v2.json`과 별도 출력에 기록하고 실제 검사 기준은 유지한다.

v2는 추가1,424갱신 뒤 가까운 비이동0.8035/먼 전진0.5178/거리 차이0.3214,
monitor 실제 명령 NLL1.4777이다. 모든 자료·원본/value·reload 감사는 통과했지만
정지0.85 조건은 미달하여 `eligible=false`를 보존했다. 신규 실게임0이다.
checkpoint는 `3fce7fa00938a7a024b38c13a2de2a9fef97571b2e33b63e8cb695db679a714f`다.

손실과 거리 구분이 함께 개선되어 같은 자료·조건의 별도 v3 16epoch를 이어간다.
`configs/common-navigation-goal-variation-v3.json`에 source와 SHA를 고정하고 Adam은 새로 시작한다.
기준을 낮추거나 개발 게임의 실패를 합성 정답으로 대체하지 않는다. 이 반복 선택에 사용한
monitor와 거리 진단은 개발용이며 최종 일반화 표본이 아니다. v3가 사전 기준을 통과하면
준비된 2개발 월드의 실제 새 대조4개를 실행한다.

v3도1,424갱신·정답 감사·원본/value 보존·reload0을 통과했다. checkpoint는
`41e6e20c12cd62ad68b9de232350315653cce195c0258b5578cbf8f5bd94cc85`다.
가까운 비이동0.8432/먼 전진0.5738/monitor 실제 명령 NLL1.3852지만 사전 정지0.85는
미달했다. 반올림하여 통과시키지 않고 원래 false를 보존했다. 정상 세 라운드는 총4,272갱신이며
가중치 학습 결과일 뿐, 이 목표 질의 자료 후보의 실제 게임 실행은 아직0이다.

`configs/common-navigation-goal-variation-v4.json`은 위 v3에서 같은16epoch/새 Adam을 실행한다.
통과 시 기존 launcher의 학습·정답 감사·체크포인트 SHA·STOP 검사를 거쳐 새 실제 대조4개를
이어 실행한다. 거리 진단과 monitor에 반복 적응한 후보이므로 이 둘을 최종 평가로 해석하지 않는다.

## 상위 RM 문맥의 범위

`rm-context-coverage.json`으로 원본 train1,419전이의 실제 여섯 RM 입력을 확인했다.
search428/approach991이며 mine/collect/complete는 없었다. 별도 monitor266전이는 모두approach다.
이는 원본 전이의 범위이며 BC로 채택한1,384정답이나 독립 성공 표본 수와 다르다.
이번 가상 목표 질의는 그 실제 문맥을 보존한다. 이 결과만으로 모든 상위 과업/단계에서
동일한 이동 능력이 나온다고 주장하지 않는다. 후속 공통 스킬 전이에서는 다른 실행 가능한
상위 단계에서의 문맥 의존성도 분리 검사해야 한다. 사람 자료에 미관측 RM 문맥을 실제 관측처럼
만들어 붙이지 않는다.

v3의 `root-context-sensitivity.json`은 같은4개 train 화면·목표에서 상위 단계5종과
상위 거리0/0.5/1을 가정해 입력 민감도만 검사했다. 근거리 전진 확률 범위는 상태별 평균0.0292,
최대0.0540, 원거리는 평균0.0403/최대0.0632였다. 잠재 버튼 head의 원래 문맥 대비 최대TV는
0.0524였다. 이 가정들은 실제 동시에 관측된 상태가 아니므로 채굴/수집 단계의 실행 성능이나
RM 불변성을 입증하지 않는다. 새 선택 gate로 사용하지 않고 원본 자료·상위 RM은 유지했다.
