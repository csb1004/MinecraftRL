## 실행 조건과 결과

로컬 Windows/WSL, GTX1060 3GB에서 기존 v2 checkpoint에 v4 RM 문맥을 연결했다.
훈련104743/104759·중간 단계·별도 평가2000003/2000029의 독립 ZIP6개를 만들었다.
실제 실행은 짧은 벽 훈련4회뿐이다. 영상/순환 backbone은 고정하고 전체 물리 행동 공간을
유지했다. privileged 서버 RM 문맥 조건이며 영상 전용 조건으로 해석하지 않는다.
직접 우회 행동, API 대체, scripted 교사는 사용하지 않았다.

## 실패 근거와 해석

![실제 서버 이동 경로](../results/recovery-curriculum-20261007/server-paths.png)

그림은 반사 배치를 공통 방향으로 정규화한 실제 서버 위치다. 회색은 파괴 불가 벽,
갈색은 원목, 노란 표시는 RM 재탐색 진입이다.

모든 실행의 최대 x는 벽 앞6.7블록에서 멈췄다. 행동의92.4–97.5%는 직전 서버 ray가
bedrock 벽 좌표를 가리킬 때의 공격이었다. 반사 배치 첫 실행은 통로 쪽 z여유 기준4.3을
넘었지만 벽 뒤로 진행하지 못했다. 나머지는 그 여유 기준에도 도달하지 못했다.
이는 공격 표적/이동 경로의 관측 결과이며, 모든 행동을 충돌 물리의 단일 원인으로 설명하지 않는다.
[경로·행동 감사](../results/recovery-curriculum-20261007/route-audit.json).

RM 재탐색 활성 관측은 각각1127/1333/1327/1500개이고 실제 actor/value 양 CFG 입력과
로그가 일치했다. 그러나 행동 복구로 이어지지 않았다. 이전 고정features 개입에서 문맥의
행동 분포 영향이 매우 작았고, 이번에도 성공적인 우회 전이가 없었다. 단순히 벽 길이를 줄이고
같은 정책을 반복 실행하는 것만으로 성공 경험을 얻을 수 있다는 가정은 이 소규모 조건에서 충족되지 않았다.
정책 표현 능력, 탐색 부족, 학습량 부족의 기여도를 분리한 결과는 아니다.

PPO 업데이트0, 후보 checkpoint 없음, 중간 벽 훈련/긴 벽 부모·후보 평가/새 문맥 개입 비교는
미실행이다. 이는 이번 프로토콜의 성공 경험 확보 기준에 따른 것이며, 실패 궤적은 원본 그대로
훈련 split에 보존했다. 실패 궤적으로는 학습 자체가 불가능하다는 주장도 아니다.
최종5시드와 기본 정책은 유지했다.

## 다음 작업 단위

**우회 성공 경험 확보 → 동일 behavior 학습 → 별도 세계 복구 평가**로 나눈다.

다음 수집에서는 통로 진입에 가까운 초기 배치부터 시작해 원래 정체 위치로 확장하고,
세계 seed와 정책 sampling seed를 분리해 반복 탐색 조건을 명시해야 한다.
평가 자료를 훈련으로 옮기거나 scripted 우회를 정책 성공으로 바꾸지 않는다.
정체 전에 통과한 경험과 정체 후 복구 경험도 분리한다.
