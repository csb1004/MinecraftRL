# 이상 판단에서 실제 RL 개선까지 — 병목 해결 제안

2026-10-25. 사용자 요청에 대한 구체적인 해결안이다. 구현/실험 결과가 아니며 게임·학습 STOP을 유지한다.
Minecraft 1.16.5, 공식 STEVE-1 초기값, RL 중심 연구, 다양한 학습 조건과 별도 평가 조건을 유지한다.
전체 KB 구축이나 기존 BC 정책 완성을 선행 조건으로 두지 않는다.

후속 사용자 보완으로 **학습 중에도 본 게임 플레이 유지**가 필수다. 자세한
[병행 확인·연습·학습 구조](continuous-play-learning-2026-10-25.md)를 따른다.
이전의 수집/학습 교대 운영 제안은 최종 운영 요구를 충족하지 않으며 아래에 수정했다.

추가 사용자 조건: **실사용 관측기는 고정**한다. 지식은 기존 목표 조건과 검증된 연습/보상 계약을
거쳐 정책 학습으로 연결한다. [고정 관측기와 지식→정책 연결](knowledge-to-policy-learning-2026-10-25.md)을
따르며 새로운 사건마다 관측기를 수정하는 방식은 사용하지 않는다.

## 다음 핵심 병목: 이상 근거에서 실행 가능한 학습 과제로

단일 LLM이 대화와 개선 후보를 한 응답에 생성하는 방식은 사용자와 합의했다.
[단일 응답 계약](unified-interaction-knowledge-2026-10-25.md)을 따른다. 이는 설계 결정이며
구현 완료나 의미/행동 동기화의 실증이 아니다. 다음 우선순위는 이상을 실제 학습 필요성으로
연결하는 진단이다. 반복 자체로는 잘못된 지식, 실행/관측 장애, 계획 오류, 수행 능력 부족을
구별하지 못한다. STEVE-1에 자연어 지시를 전달하는 것과 실제 RL 개선 요청을 실행하는 것도 다르다.

현재 `stall_detection.py`는 단계별 무진전/반복/경로 순환의 근거를 내보내고, docstring도 이를
재계획 후보로 제한한다. 임의 세계 지식에 기반한 의미/원인 진단기가 이미 구현됐다고 보지 않는다.
`semantic.py`도 기존 제한된 의도/목표 해석 경로이며 새 학습 요청 컴파일러가 아니다.
이는 코드와 설계 검토에 따른 우선순위이며 새 실행에서 측정한 처리량 병목은 아니다.

다음으로 필요한 공통 증거 단위는 최근 관측 묶음, 실제 전달 행동, 현재 목표/정책 버전,
적용 조건이 있는 기대 변화, 실제 변화, 관측 출처/시각/누락, 경쟁 가설이다. 기대 변화는
검색/KB 또는 경험에서 가져오되 관측 사실과 분리한다. unknown은 정상적인 결과이며 새 지식에
관측 연결이 없다고 거짓으로 처리하지 않는다. 서버 정답은 별도 평가 라벨이며 영상 전용 입력과 섞지 않는다.

작은 개발 확인에서는 겉으로 비슷한 정체를 만드는 다른 원인과 정상 우회/채굴을 구분한다.
관측 유효성, 전제조건, 기존 동결 정책에서 계획만 바꾼 결과 등 필요한 근거를 한정된 예산에서
확인한다. 모든 원인을 완벽히 증명할 때까지 기다리는 구조도 피하고 근거 부족은 보류한다.
필요한 능력·연습 조건·실제 성공 판정에 연결된 경우에만 학습 후보를 실행 가능한 요청으로 채택한다.
판정/초기화 기능이 없는 새로운 지식은 KB에 보존하고 미지원 항목을 반환한다. 실사용 관측기에
새 항목을 추가해 우회하지 않는다.

검증은 이상 오탐/미탐, 원인별 혼동, 판단 보류율, 불필요한 학습 요청, 감지/판단 지연을
함께 기록한다. 보류만 하는 시스템이 좋은 점수를 받지 않도록 판단 가능한 사례의 처리율도 보고한다.
후속 병목은 그 요청이 공식 정책의 실제 RL 개선으로 이어지고 기존 능력을 보존하는지다.
구현 착수 시에는 아래 권장 순서대로 고정 요청으로 학습 경로를 먼저 검증하고 자동 진단을 연결한다.

## 1. 실패 원인 진단

감시자는 최근 관측·실제 전달 행동·목표·기대 변화·관측 품질을 모아 사건을 만든다. LLM에는
확정 실패 원인 대신 경쟁 가설과 그 가설을 구별할 수 있는 관측을 요청한다.

| 원인 후보 | 구별할 근거/확인 | 대응 |
|---|---|---|
| 관측/실행 장애 | 관측 나이, tick/sequence, 전달 여부, 가능한 경우 별도 정답 관측과 비교 | 복구/추가 관측. 자동 학습 표본 제외 |
| 지식/전제 오류 | 적용 버전, 도구/재료/접근 조건, 출처 충돌 | 검색·전제 확인·비단조 수정 |
| 계획 오류 | 동결 정책에서 하위 목표나 순서만 바꾼 제한된 진단 | 재계획 효과를 별도로 기록 |
| 수행 능력 부족 | 전제와 관측이 유효한 조건에서도 반복적으로 실제 목표 미달 | 학습 후보 생성 |
| 근거 부족/복합 원인 | 여러 설명이 남거나 검증할 관측을 얻을 수 없음 | unknown 유지, 제한된 추가 확인 |

정체 이벤트 외 정기 의미 평가도 유지한다. 화면 의미를 담당하는 모델/표현은 별도로 검증한다.
개발 단계에는 서버 상태를 정답 라벨로 쓸 수 있지만 영상 전용 조건의 평가자 입력에 몰래 넣지 않는다.
가중치를 고정하고 한 조건만 바꾸는 진단은 인과 가설의 근거이며 인과성의 확정 증명은 아니다.
진단 실험 횟수/시간을 제한하고 정상 우회·채굴·로딩을 포함한 사례로 오탐/미탐/판단 보류율을 측정한다.
LLM이 출력한 신뢰도 숫자를 보정된 확률처럼 취급하지 않는다.

## 2. 공통 학습 요청과 검증기

LLM은 아래 항목을 구조화해 제안하고, 검증기가 현재 지원하는 관측/판정/초기화/학습 범위에 연결한다.
필수 항목이 미지원이면 부족한 항목을 반환한다. 자연어 skill 이름을 만들었다고 실행 가능해지지 않는다.

| 항목 | 내용 |
|---|---|
| 목적/근거 | root goal, 학습할 공통 능력, 원인 가설, 근거 사건/지식 ID |
| 조건/입력 | 적용 조건, 정책에 주는 목표·관측, 관측 권한, unknown 처리 |
| 실제 성공 | 서버 상태/인벤토리 등 독립 판정 ID, 측정 창, 중복 획득 처리 |
| 연습 분포 | 시작 조건·변화시킬 요소·학습 seed 목록, 제외할 개발/평가 조건 |
| 학습 목적 | 과업 보상, 선택적 shaping 후보, 비용, 종료/시간 초과 의미 |
| 갱신 계약 | 공식 초기값/현 정책 버전, 갱신 층, 알고리즘 설정, 제어 시간 단위 |
| 예산/중단 | 상호작용·업데이트·시간·자원 상한, 중복 요청 키, 진전 없는 경우 재진단 |
| 검증/채택 | 개발 평가와 보존 과업, 효과/퇴행 허용 기준, 최종 평가와의 분리 |

초기에는 작은 관측/판정 요소를 조합해 여러 과업에 재사용한다. 지원되지 않는 새 개념은 근거와
함께 보류하고 미지원 사유를 반환한다. 필요한 관측 연결의 개발은 별도 버전/실험 조건으로만
다루며 실사용 중 관측기를 바꾸지 않는다. 최종 목표 RM과 성공 판정은 LLM이 임의로 바꾸지 못한다.
LLM은 연습 조건/하위 목표/보상 후보를 선택하며 배치별 KB·RM·보상·정책 버전을 고정한다.

## 3. 공식 STEVE-1에서 실제 갱신 경로 만들기

첫 알고리즘 후보는 PPO와 value head다. 공식 가중치를 불변 보존하고 후보 정책의 제한된 층을
갱신한다. 초기 head 중심 경로는 작은 공학 검증으로 사용하며 최종 학습 범위를 head에 고정하지 않는다.
보상·경험·최적화 경로가 유효한데도 개선되지 않으면 표현 부족을 포함해 재진단하고 마지막 층/순환
블록 일부 또는 adapter 후보를 별도로 비교한다. adapter도 활성값 메모리를 없애지 않으며 3GiB 적합성을
보장하지 않는다. 과업마다 별도 전용 정책을 무조건 만드는 대신 공유 정책/조건부 입력을 우선한다.

검증 순서:
1. 미갱신 후보가 동일 입력·목표·순환 상태에서 공식 추론 경로와 일치하는지 확인한다.
2. 실제 전달 행동의 정규화된 확률, guidance 설정, 순환 상태, 정책 버전을 궤적에 보존한다.
3. 유한 gradient, 허용 층만 변경, 변경 후 실제 행동/획득 변화가 있는지 각각 확인한다.
4. 실제 보상 개선과 별도 조건의 성공률을 평가한다. loss 감소나 체크포인트 변경만으로 성공이라 하지 않는다.

head만 학습하면 동결 특징을 재사용할 수 있지만, 순환부를 갱신하면 순차 입력과 reset/burn-in을
처리해야 한다. 예전 특징 캐시만으로 새 순환부의 PPO 갱신이 올바르다고 가정하지 않는다.
행동 수, 서버 tick, 현실 시간을 구별하고 할인율과 shaping의 시간 단위를 맞춘다.
PPO에는 현재 수집 정책의 유효한 rollout을 사용한다. 오래된 궤적을 일반 PPO 배치에 섞지 않는다.
작은 업데이트와 검증된 기준 정책에 대한 KL 제약을 후보로 사용하되 실제 능력 보존을 별도로 평가한다.

## 4. 유용한 경험과 보상

준비된 시작 상태에서 선행 조건을 갖춘 연습 → 거리/시선/배치/도구 조건 변화 → 선행 단계가 포함된
과업으로 확장한다. 초기 상태를 준비한 개입은 기록하고 원래 과업의 자율 성공으로 계산하지 않는다.
훈련 조건 선택은 최근 성공/실패 근거를 이용하되 하나의 좌표·배치만 반복하지 않는다.
정상 수행과 실패 사례를 모두 모으고 정해진 예산에서 성공 경험이 없으면 원인을 다시 검토한다.

최종 보상은 실제 획득/완료 상태로 판정한다. 중간 보상이 필요하면 RM 진행 증거와 연결한
potential-based shaping을 후보로 삼는다: `F = gamma^delta_t * Phi(next) - Phi(current)`.
기준 시간 단위, 같은 할인율, 고정 potential, 종료/시간 초과 처리를 맞춰야 한다. 부분 관측,
동적 KB, 근사 상태에서는 고전 이론의 정책 불변성을 자동 보장하지 않는다. 같은 상태 순환이나
버렸다 다시 줍기로 보상이 늘어나는지 점검한다. 시간 비용 자체는 목적을 바꿀 수 있어 별도 설정으로 고정한다.
보상 합계와 실제 성공을 분리하고 shaping만 개선되면 채택하지 않는다.

## 5. 자원과 실시간 실행

- 게임 소유자는 한 개다. 빠른 감시 스레드는 불변 관측을 읽고 LLM/DB 완료를 기다리지 않는다.
- 의미 평가·검색은 비동기로 수행하고 중복 요청과 오래된 응답을 제거한다. STOP은 별도 경로다.
- 본 게임은 검증된 정책으로 계속 플레이하고, 별도 연습 환경/learner가 후보를 학습한다. 같은 GPU의 병행 적합성은 실측한다.
- 초기 PPO 학습 경험은 별도 연습 환경에서 후보의 배치별 정책으로 수집한다. 본 게임의 오래된 정책 데이터를 그대로 섞지 않는다.
- 배포 정책과 후보를 분리하고 후보 상태 준비 후 행동 경계에서 전환한다. 준비 중에는 기존 정책을 유지하며 변경된 순환부의 상태를 검증한다.
- 감지 지연, 원인 판단 시간, 학습 완료 시간, 추가 경험량을 각각 기록한다. 실시간 감시가 즉시 능력 습득을 뜻하지 않는다.

OOM 또는 예산 초과가 관측되면 로그를 남기고 배치/시퀀스/갱신 범위를 검토한다. 로컬에서 의미 있는
학습 범위가 불가능하면 동일 실험을 다른 자원에서 재현할 준비를 하되 유료 자원/실제 Colab 연결은
이번 제안으로 실행하지 않는다. 학습이 끝날 때까지 위험 대응을 미루지 않는다.

## 6. 학습 효과, 망각, 지식 수정

계획만 개선된 경우와 정책 능력 개선을 구분하기 위해 두 수준을 측정한다.
- 정책 수준: 같은 목표 프롬프트·도움 조건에서 전후 가중치를 비교한다. 학습 중 교정 힌트는 평가에서 제거한다.
- 시스템 수준: 공식 동결 정책, LLM 재계획만, 고정 규칙으로 학습 선택, LLM으로 학습 선택을 비교한다.
  관측·검색 권한과 최대 경험/계산 예산을 맞추고 실제 사용량도 보고한다.

개발 조건에서 채택 기준과 허용 퇴행을 정하고 최종 평가 전에 고정한다. 학습하지 않은 seed뿐 아니라
배치/조건 조합도 분리하고 여러 반복과 불확실성을 보고한다. 작은 파일럿의 개선을 일반화 증명으로 삼지 않는다.
최종 평가 결과를 보고 반복 튜닝하지 않는다. 결과가 불확실하면 이전 정책을 유지한다.
과거 능력 보존은 별도 학습용 연습 과업과 평가용 보존 과업을 분리한다. 새 정책으로 기존 과업도
다시 수집해 RL 학습에 섞을 수 있다. 보존용 증류/replay는 별도 보조 목적을 명시하고 PPO와 혼동하지 않는다.

LLM으로 되돌릴 결과는 원인 가설, 변경한 학습 조건, 전후 성공/실패, 경험량, 적용 범위, 정책 버전이다.
학습 실패도 돌려주고 같은 원인의 중복 요청에는 예산/재호출 제한을 둔다. KB 근거가 철회되면
의존 계획/학습 작업을 재검토하고 관련 정책을 재평가한다. KB 수정 자체를 정책의 망각/교정으로 간주하지 않는다.
공개 지식을 검색한 효과와 새로운 조건에 대한 정책 적응을 별도 결과로 정의한다.

## 권장 실행 순서와 완료 근거

1. 공식 초기값의 미갱신 동등성·실제 rollout·학습 데이터·자원 측정. 이것은 구현 검증이다.
2. 고정된 공통 학습 요청으로 다양한 조건에서 RL 전후 비교와 능력 보존 확인. 개선되지 않으면 이 지점에서 재진단한다.
3. 관측 → 경쟁 가설 → 제한된 확인 → 같은 학습 요청 생성에 LLM을 연결하고, 학습 요청 정확성과 결과를 평가한다.
4. 필요한 검색/지식 추출·철회를 추가해 잘못되거나 부족한 지식이 있는 조건으로 확장한다.
5. 설정과 예산을 고정한 비교 실험으로 각 구성 요소의 효과를 분리한다.

가장 먼저 확인할 것은 작은 KB의 크기가 아니라 공식 정책에서 제한된 추가 RL이 새 조건의 실제
성공을 개선할 수 있는지다. 이 순서는 장기 목표를 축소하지 않고 구성 요소 실패를 구별하기 위한 것이다.
