# 새 개발세계 고정 비교 — 2026-10-07

사용자 ‘그래 진행해줘’에 따라 이전 할인률 후보의 새 개발세계 비교를 실행한다. 중간 보상·학습·기본 모델·전역 설정·최종 평가 시드는 바꾸지 않는다. 준비 전에 고정한 조건이며 결과에 맞춰 수정하지 않는다.

- 새 개발 시드: **2100011, 2100023, 2100037, 2100041, 2100059**. 기존 학습16세계·개발2세계·최종5시드와 겹치지 않는다. 이전 결과 폴더/명세에 같은 시드가 없는 것을 확인했다. 산림 여부·난이도를 보고 교체하지 않는다.
- 조건: 부모78회 `parent`, 동일 학습량 γ=.99/λ=.95 `control`, 후보 γ=.999/λ=.95 `candidate`. 모두 지난 배치의 immutable checkpoint이며 이번 optimizer 업데이트0이다.
- 각 세계는20중립tick으로 한 번 준비·저장하고 세 정책이 같은 ZIP을 복원한다. 복원 후 기존60중립tick·1행동=1서버tick·서버 첫 원목 획득+1·즉시 종료를 유지한다.
- **5세계×3정책×2반복=30회**, 제어 시간 각각 최대180초. 준비5회는 정책 평가/성공률에 포함하지 않는다. 세 정책 순서는 세계 index를 기준으로 순환 이동하고 두 번째 반복에서 뒤집는다. 세계 순서는 첫 반복 정순/둘째 역순이다. 목록을 runner가 실행 전 JSON으로 저장한다.
- 초기 서버 위치·시선·시간·생명·인벤토리·순환 상태·sampling seed·embedding 동일성을 확인한다. 픽셀 차이는 기록하되 좋은 프레임을 고르려고 재시작하지 않는다. 전 시행의 VRAM·추론/제어주기 중앙값/p95·획득량·실패 원인·중단/입력 해제/PID 정리를 기록한다.
- 모든 평가는 학습 제외. 기술 실패와 유효한180초 미획득/환경 종료를 구분한다. 시간 초과의 bootstrap은 저장되지만 이번에는 학습하지 않으므로 성과 지표를 바꾸지 않는다. 실제 미획득은 이번 제한시간 과업의 미달성으로 보고한다.
- 0행동 preflight에서 Java/nvidia-smi의 일시 실패만 원본 로그를 보존하고1회 재시도한다. 해시·소스·초기 세계 불일치나 새 수동 STOP은 재시도하지 않는다. 준비 실패·실제 기술 실패는 남은 계획을 숨기지 않고 미실행으로 기록한다. 수정이 필요하면 원인을 먼저 분석하고 변경/제외 근거를 별도 기록한다.

일차 지표는 조건별 성공수/유효 시행수(정상 완료 시각10회)와 세계별2회 결과다. 이차는 성공 시 제어시간, 유효 미획득이면180초를 부여한 제한 시간 점수의 평균이다. 기술 실패·미실행은 이 평균/성공률에 넣지 않고 별도 표시한다. 성공 tick은 성공 시행에 한한 값이라고 표시하며 빠른 실패를 빠른 성공으로 취급하지 않는다.

후속 후보 유지 판단 기준:30회 모두 유효, 후보가 각 세계에서 양쪽 대조보다 성공수가 적지 않음, 평균 제한 시간 점수가 양쪽 대조보다 각각10% 이상 낮음, 세계별 제한 시간 평균이 양쪽 대조보다 모두 낮은 세계가5개 중3개 이상. 이 기준을 통과해도5개 개발세계뿐이므로 일반화 입증이나 기본 정책 자동 승격은 하지 않는다. 미통과하면 이전 한 세계의 단축을 일반 개선으로 취급하지 않는다.

시행 후 원시 감사, 원본/체크포인트/명세 해시, STOP 유지·잔존 프로젝트 프로세스0을 확인하고 보고서를 갱신한다. 유료 자원·Colab 연결·GitHub 공개는 하지 않는다. 최종 시드3000017/3000029/3000047/3000061/3000073은 미실행으로 보존한다.
