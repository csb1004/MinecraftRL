# 같은 월드 이어하기의 정책 기억

개발 시드104761의 retention/2에서 회차 시작 뒤 원목 설치 소비가 재발했다.
직전 retention/1의840개 실제 추론 화면을 먼저 재생한 고정 화면 비교에서,
다음 회차 첫64화면의 평균 use 확률은 초기화12.499%→기억 유지3.168%였다.
고정 화면의 출력 비교이며 실제 반사실적 수집 성공은 아니다.

같은 월드/같은 목표 revision을 이어가는 명시적 opt-in으로 RNN cache와 Torch 난수 상태를 보존한다.
최초 파일이 없는 기존 저장본은 초기화하고 새 회차 종료부터 기억을 저장한다.
공식 영상 목표 조건에서 먼저 검증하며 텍스트 prior 재표집이나 다른 모델에 적용하지 않는다.

- 월드 정상 저장 후 같은 불변 세대에 `policy-memory.npz`를 함께 넣고 manifest에서 해시로 묶는다.
- 모델/소스/실행 dtype 구조, world_id, task_id/revision/goal, root embedding/guidance를 확인한다.
- 목표가 바뀌면 명시적으로 초기화한다. 모델/파일 손상은 복원 오류로 차단한다.
- 신경망 상태와 Torch CPU/CUDA RNG만 복원한다. 키, 카메라, 재고, 위치, 게임 RNG를 대신 조작하지 않는다.
- STOP 이후에는 직전에 계산된 상태를 저장할 뿐 새 추론/정책 행동을 보내지 않는다.
- world load의 중립 tick 공백은 남는다. 비트 단위 물리 연속성이나 독립 평가 표본으로 해석하지 않는다.
- 원본 checkpoint/실패 기록/목표 수량을 유지한다. 추가 가중치 학습·유료 호출0.

실제 첫 적용은 최신43원목/22흙 저장본 ea600be62fdb4901ab7e92e9ebcc3c8b에서 시작한다.
그 저장본에는 정책 기억 파일이 없으므로 첫 회차는 cold start이며, 이후 회차의 복원부터 효과를 검증한다.
중단된 탐험13틱/3.157초와 남은187틱/26.843초는 기존 복구 계약을 그대로 따른다.

실제 검증을 완료했다. memory/0에서 처음 저장한 뒤 memory/1·2 및 memory-resume/0·1에서
직전 파일/기억 SHA와 같은 상태가 복원됐다. 정상5회3800행동으로43→45→50→54→60→64원목,
최종 흙25개였다. memory/3은 호스트 재시작으로 준비 중 끊겨 이 집계에서 제외한다.
5회 모두 STOP 뒤 새 추론/행동0, 서버 키0, 소유 PID0이며 목표 완료 뒤 추가 추론/행동도0이다.
Windows739(717통과·22제외), 최종 관련7/WSL72검사, 실제 GPU의 다음 행동/RNN 완전 동일 복원도 확인했다.

`results/goal-completion-20261016-preparation/goal-completion-audit.json`에 실제 근거가 있다.
고정된 live cold 대조가 없으므로 순증가를 기억 유지의 인과 효과로 해석하지 않는다.
