# 판자 회수 직후 정지·저장 검증

**후속 원인 감사 정정:** 이 문서의 “성공 관측 뒤 추가 행동 0회”는 인벤토리와 제작 통계가
모두 갖춰진 witness 이후를 뜻한다. 인벤토리 판자 4개를 처음 관측한 시점부터 세면 성공
3회 모두 정책 행동이 4회 더 있었다(104729: 263→267, 155921: 45→49, 196613: 338→342).
서버 통계 지연까지 정책을 계속 실행한 경계 문제를 후속 수정 대상으로 확인했다.
원자료 재계산: results/craft-rm-cause-audit.json. [수정·검증 조건](craft-recovery-plan.md).

실제 STEVE-1 시행 5회 중 3회가 원목 1개 소비·판자 4개 회수·제작 통계 4 증가를
충족했다. 세 시행 모두 해당 관측 직후 정책을 멈췄으며, 저장된 level.dat와 playerdata에도
판자 4개가 남았다. 전체 과업 성공은 **3/5**, 회수 성공 사례의 저장 보존은 **3/3**이다.
나머지 2회는 회수 기준에 도달하지 못했다. 기술 오류 0, 미실행 0, 추가 API 0회다.

## 조건과 변경

[사전 계획](craft-retention-plan.md)에 따라 기존 자연 수집 원목 1개·흙 1개의 저장 세대
`sequence-20261004T025836469371Z/28222939e73444be84ba333eedf2d4d8`를 매번 복사했다.
같은 월드의 고정 난수 시드 5개이며 서로 다른 지형 5개는 아니다. STEVE-1 가중치,
guidance 6, `craft wooden planks`, 제어 예산 180초를 유지했다. Windows/WSL,
GTX 1060 3GB의 로컬 결과다. 재료 지급·API 제작·정책 대체는 없다.

`run_episode`에 선택적 완료 검사를 추가하고 별도 craft-probe에서만 사용한다.
관측 증거가 충족되면 target_reached로 정지해 다음 추론·정책 dispatch를 막는다.
그 뒤 중립 입력, 필요한 경우 GUI 닫기, 월드 저장과 자식 프로세스 종료를 수행한다.
일반 대화/RM에는 제작 목표를 아직 연결하지 않았다.

## 실제 결과

최종 인벤토리의 흙 1개는 모든 시행에서 유지됐으며 표에서는 생략한다.
회수 시간은 episode_started부터 성공 관측까지이며 초기화·종료 정리는 별도다.

| 시드 | 정책 steps | 판자 최대 | 회수 시간(초) | 종료 상태 | 저장된 물품 |
|---|---:|---:|---:|---|---|
| 104729 | 267 | 4 | 50.640 | target_reached | 판자 4 |
| 130363 | 1486 | 0 | 미달 | time_limit | 없음 |
| 155921 | 49 | 4 | 20.724 | target_reached | 판자 4 |
| 196613 | 342 | 4 | 53.825 | target_reached | 판자 4 |
| 262147 | 1501 | 3 | 미달 | time_limit | 판자 1, 버튼 1, 막대기 4 |

제작 통계는 모두 판자 4 증가했으나 인벤토리 회수와 같지 않다. 130363은 판자 4개를
인벤토리에서 관측하지 못했고 버튼 제작 통계가 4 증가했다. 262147은 최대 판자 3개만
관측됐고 버튼 1·막대기 4의 추가 제작 통계가 있었다. 정확한 커서/칸별 이동 원인은
현재 자동 관측만으로 확정하지 않는다. 이 두 시행을 정지 제어 성공 때문에 과업 성공으로
계산하지 않는다. 예산 종료 시각은 180.047/180.040초로, 진행 중 추론이 끝난 뒤
행동을 폐기했다. 각각 추론 횟수가 dispatch보다 1회 많다.

성공한 3회는 witness step과 최종 step이 같고 이후 새 추론·정책 행동이 0회다.
196613은 성공 시 GUI가 열려 있었으며 종료 정리로 닫은 뒤에도 판자 4개를 보존했다.
모든 시행에서 저장 NBT의 아이템별 슬롯 합계가 정리 후 관측과 일치한다.
커서 아이템 자체는 직접 관측하지 못해 cursor_item_verified=false를 유지한다.

[이전 무정지 실험](crafting-validation-2026-10-04.md)은 중간 회수 3/5, 최종 판자 4개
보존 0/5였다. 이번에는 회수 뒤 추가 제작을 차단한 사례를 확인했다. 다만 게임 실행이
완전히 결정적이지 않아 시드별 경로와 시각은 달랐으며, 소규모 전후 비교로 일반적인
성공률 향상이나 회수 이전 실패의 해결을 주장하지 않는다.

시행별 중앙값 / p95이며 단위는 ms다.

| 104729 | 43.011 / 52.224 | 112.339 / 134.052 | 2771 |
| 130363 | 43.239 / 52.630 | 108.212 / 120.948 | 2771 |
| 155921 | 44.690 / 54.779 | 127.544 / 158.486 | 2776 |

Torch peak allocated 2097.686–2098.717 MiB, reserved 2144 MiB다. 장치 peak는 다른
프로세스도 포함하는 샘플이며 순간 peak를 놓칠 수 있다. 각 시행 입력 해제·GUI 닫기·저장,
STOP acknowledgment 후 정책 dispatch 0회, 소유 자식 프로세스 종료를 확인했다.
최종 WSL 프로젝트 Python/Java 잔존 0개, results/STOP 유지, 원본 월드 해시·pointer 유지다.

Windows 검사는 총 114개 중 110개 통과·Linux 전용 4개 제외, WSL 114개 통과다.
완료 콜백 검사에서 실패를 먼저 확인한 뒤 구현했고, 정리 정보 누락 시 보고 오류를
피하도록 보완한 후 관련 6개도 재검사했다. WSL 검사 시작 시 systemd 사용자 세션 경고가
있었지만 검사와 이후 실게임 실행은 완료됐다. 독립 에이전트 리뷰는 수행하지 않았다.

## 재현 및 증거

PowerShell에서 `$env:PYTHONPATH='src'` 설정 후
`python scripts/run_crafting_probe.py --stop-on-success`를 사용한다.
직전 종료 결과를 검토하고 STOP이 유지된 상태에서 실행한다. 실험기가 기존 STOP을
결과 폴더에 보존 이동해 재무장하며 종료 시 다시 STOP을 설정한다.
실험 출력은 `results/craft-retention-20261004T060008002436Z/`의 experiment.json,
analysis.json, saved-inventory-check.json과 시행별 events.jsonl, summary.json,
craft-cleanup.json, saved-nbt.json이다. 테스트 로그는 results/craft-retention-*.log다.
최종 프로세스 점검은 results/craft-retention-process-check.json에 남겼다.
연구 명세 SHA256은 `4af3ad00c5bab9b9d08b2e23fe768e140944118aa85cf412c45a67bb032275ad`다.

남은 과제는 회수 이전 실패 분석, 막대기·작업대의 독립 목표 검증, 재료 예산과
선행 조건을 가진 제작 과업 연결이다. 3×3 제작이나 일반 제작 능력은 아직 검증하지 않았다.
