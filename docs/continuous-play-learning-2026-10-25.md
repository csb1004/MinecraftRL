# 플레이를 유지하는 확인·연습·추가 학습

2026-10-25 사용자 보완: 사람처럼 플레이하는 것이 목표이므로 추가 학습 중에도 본 게임의
행동은 이어가야 한다. 이전 해결안의 '제어 중단 → 학습 → 재개'는 이 운영 요구를 충족하지 않는다.
이는 운영 구조의 요구 수정이며 지금 게임/학습을 재개하라는 명령으로 해석하지 않는다. STOP 유지.

## 작은 확인의 세 가지 방식

1. 관측만으로 확인: 최근 화면/행동/목표와 허용된 상태 관측을 비동기로 대조한다. 입력이 전달됐는지,
   대상이 보이는지, 관측이 오래됐는지, 예상 변화가 생겼는지 확인한다. 모르면 unknown으로 남긴다.
2. 플레이에 포함하는 확인: 필요한 경우 시선 확인·재접근·인벤토리 확인 등 지원되는 관측 행동을
   상위 계획에 제안한다. 실제 입력은 기존 제어 소유자와 정책을 통해서만 전달한다. 정책이 수행하지
   못하는 확인 동작을 스크립트로 몰래 대체하지 않는다. 실제 플레이를 통해 확인한 근거로 기록한다.
3. 별도 환경에서 확인: 조건을 바꾸는 반복 실험이나 위험한 시도는 독립된 Minecraft 1.16.5
   연습 프로세스에서 한다. 본 게임의 아이템/위치/월드를 바꾸지 않고 비교 조건을 준비한다.

세 번째 방식은 실제 게임 엔진으로 하는 시뮬레이션이다. 저장된 영상만 다시 보는 것은 새로운
행동의 결과를 알려주지 않으며, LLM의 예상 결과도 실제 환경 피드백을 대신하지 않는다.
학습된 world model은 초기 필수 요소로 두지 않는다.

## 본 게임과 연습 환경

본 게임은 검증된 정책 버전으로 계속 진행하면서 관측/행동/결과를 발행한다. 막힌 원래 행동을
무한 반복하게 하지 않고 지원되는 범위에서 추가 관측·우회·다른 하위 목표를 선택한다.
STOP, 실제 위험, 사용자 명령에 따른 중단은 플레이 지속 요구보다 우선한다.

감시자/LLM은 본 게임의 근거와 필요한 검색을 이용해 진단/연습 요청을 만든다. 별도 연습기는
전제조건을 통제한 여러 배치에서 후보 정책의 경험을 수집하고 learner가 갱신한다. evaluator는
연습에 쓰지 않은 조건과 능력 보존 과업을 확인한다. 학습 실패/대기 중에도 배포 정책은 계속 실행한다.

최신 요구에 따라 감시 근거와 검색 결과의 판단은 상호작용 LLM의 같은 맥락으로 들어가며,
한 응답에 자연어 대화와 진단/연습 요청을 함께 생성하고 프로그램이 검증한다. 별도 2차 LLM
변환은 기본 경로에 두지 않는다. 검색·검증·학습 중에도 자연어
상호작용은 유지한다. [상호작용 계약](unified-interaction-knowledge-2026-10-25.md) 참조.

초기에는 본 게임과 관련된 조건의 연습 월드를 사용한다. 정확한 동일 순간 복제는 별도 과제다.
현재 `world_store.py`와 월드 지속성 경로는 정상 save-and-quit 이후 저장을 전제로 하며,
살아 있는 월드를 일관되게 즉시 복제하는 기능이 아니다. 플레이 중 저장 파일을 단순 복사하면
시점이 섞일 수 있다. 향후 live snapshot에는 서버 tick 경계의 일관된 상태 수집, 독립 저장/로딩,
현재 상태와 복제 상태의 검증이 필요하고 저장 과정의 지연도 측정해야 한다.

지형/인벤토리를 복원해도 RNG, 진행 중 행동, GUI, 동적 entity, 정책의 순환 상태까지 동일함을
보장하지 않는다. 화면으로 안 보이는 구조를 임의로 채운 연습은 가설 기반 근사 환경이며,
그 결과로 본 게임 실패의 원인을 확정하지 않는다. 학습/진단용 privileged 정보는 별도 표기한다.

## 학습 데이터와 알고리즘

운영 정책과 학습 후보가 동시에 존재하므로 버전 차이가 생긴다. 각 궤적에 정책·목표·KB·보상
버전, 행동 확률, 시각, 관측 출처, 본 게임/연습 환경 구분을 붙인다. 본 게임에서 오래된 정책이
계속 모은 데이터를 최신 학습 후보의 일반 PPO 자료로 무조건 사용하지 않는다.

초기 제안은 별도 연습 환경이 학습 후보의 배치별 정책으로 새 경험을 모으고 PPO로 갱신하는 방식이다.
본 게임 로그는 진단과 연습 조건 선택에 사용한다. 이 구성은 별도 환경을 이용한 추가 학습이며
본 게임 경험만으로 즉시 온라인 학습한다고 보고하지 않는다.

본 게임의 비동기 경험을 지속적으로 직접 학습에 쓰는 경로를 추가하면 정책 지연에 대한 보정과
재사용 범위를 명시해야 한다. IMPALA의 actor/learner 분리와 V-trace는 참고 후보이며 STEVE-1에
그대로 적용되는 완성품이 아니다. 변경한 순환부에는 과거 hidden state의 적합성도 검토해야 한다.
본 게임·연습 환경·평가 환경의 모든 경험과 계산 시간을 비용에 포함하고 성공 표본은 구분한다.

## 플레이를 멈추지 않는 정책 전환

실행 중인 모델 객체를 learner가 직접 수정하지 않는다. 검증된 후보를 준비한 뒤 하나의 행동
dispatch 경계에서 배포 버전 포인터를 바꾸는 방식을 검토한다. 모델 준비 중에는 기존 정책이 계속 실행한다.
후보 준비와 전환이 제어 지연을 늘리지 않는지는 실제 검증해야 한다. 준비가 안 되면 전환을 미룬다.

같은 encoder/순환부를 유지하고 head만 바꾸는 경우에도 입력/상태 계약을 확인한다. 순환부가
바뀌면 최근 관측·목표·reset 이력으로 새 후보 상태를 준비하는 방법 또는 자연스러운 초기화
경계를 검토한다. 제한된 이력으로 복원한 상태를 전체 과거의 정확한 재현이라고 간주하지 않는다.
현재 관측 시점에 후보가 따라오지 못했거나 자원이 부족하면 이전 정책을 유지한다.
새 행동 소유자를 만들지 않고 전환 전후 tick, 정책 버전, 입력 상태와 STOP 순서를 기록한다.

## 자원과 검증

이번 읽기 전용 `nvidia-smi` 결과는 GTX 1060 3GB, 총3072MiB/사용430MiB/여유2536MiB였다.
게임/학습 미실행 시점 값이며 병행 실행 가능성의 증거가 아니다. 멀티스레드만으로 메모리나
연산량이 늘어나지 않는다. 본 게임 추론을 우선하고 학습·연습은 독립 프로세스에서 예산을 제한한다.

같은 PC에서는 작은 head의 CPU 학습 또는 제한된 GPU 학습을 후보로 실측할 수 있지만,
CPU 학습은 속도/표현 한계가 있고 별도 Minecraft 렌더링/추론 비용까지 사라지지는 않는다.
넓은 가중치 범위와 별도 연습기의 병행에는 별도 GPU/머신이 필요할 수 있다. 추가 자원 사용은
실제 병목을 측정한 뒤 판단하며 이번에는 설치·유료 사용·Colab 연결을 하지 않는다.

핵심 검증은 학습 없는 본 게임과 학습 병행 중 본 게임의 제어 주기 p50/p95/p99, 긴 지연,
행동 공백, 메모리, 큐 지연을 비교하고, 후보 준비/적용 중 중복 입력·STOP 위반이 없는지 확인하는 것이다.
계산 간섭으로 제어 기준을 넘으면 학습 작업을 늦추거나 중단하며 본 게임을 학습 때문에 정지시키지 않는다.
지연 목표는 현실 시간으로 측정한다. MineRL의 동기식 step이 천천히 진행돼도 성공했다는 이유만으로
사람처럼 실시간 플레이한다고 주장하지 않는다. 학습 효과와 자연스러운 행동은 별도 평가 항목이다.

## 근거와 현재 상태

병행 실행 구조를 갖추더라도 자원 외의 병목이 남는다. 화면과 기호의 연결이 틀리면 진단이 틀리고,
근사 연습 환경의 개선이 본 게임으로 전이되지 않을 수 있다. RL에 충분한 경험/보상이 없거나
갱신 범위가 부족하면 후보가 개선되지 않으며, 새 능력 학습이 기존 능력을 훼손할 수 있다.
정책 지연·순환 상태·동적 목표와 적용 시점도 검증해야 한다. 제안 구조를 이 문제들의 해결 완료로
해석하지 않는다. [KB 구축안](rl-primary-monitor-discussion-2026-10-25.md)과 실제 학습 검증을 별도로 진행한다.

- Actor/learner 분리와 정책 지연 보정: https://proceedings.mlr.press/v80/espeholt18a.html
- 현재 저장 기능의 한계: [월드 저장과 재개](world-persistence.md), `src/minecraftrl/world_store.py`.

이 문서는 요구 수정과 권장 구현안이다. 별도 연습기·비동기 learner·플레이 중 정책 전환·live snapshot은
이번에 구현하거나 검증하지 않았다. 게임/학습/API0, 기존 STOP 유지.
