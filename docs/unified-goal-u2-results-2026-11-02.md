단계만 바꾼 입력도 실제 장면에 적합하다는 보장이 없으므로 민감도 검사이지 행동 정답 평가가 아니다.
MineCLIP 목표를 바꿔 원시 encoder를 다시 실행한 검사는 하지 않았다.

## 어디에서 막혔는가

**1. 올바른 목표를 받아도 접근·재탐색이 끊긴다.**

원목 3개의 기존 형식 실행은 실제 파괴 2회·획득 2개 뒤 600tick 동안 진전이 없었다.
전체 단계는 탐색 712, 접근 65, 채굴 294, 회수 39행동이었다. 마지막까지 목표 수량 3과 진행량 2,
나무를 찾으라는 문구가 유지됐으며 인벤토리 보상 합은 0이었다. 목표 전달 누락의 증거는 없다.

원목→흙의 통합 실행은 탐색 342, 접근 598행동 뒤 종료됐다. 실제 원목 파괴·획득은 0이다.
마지막 상태는 대상 알려짐=true, 도달 가능=false였다. 지형을 파며 흙 5개를 얻었지만
그 행동은 원목 접근으로 이어지지 않았다. 화면과 서버 기록으로 확인되는 실패 지점은 접근이며,
시각 표현·경로 선택·조건 활용 중 어떤 부분의 인과적 결함인지는 추가 대조가 필요하다.

**2. 회수 단계와 실제 행동의 결합이 약하다.**

마지막 통합 실행에서는 325/392/466/533번째 행동에 원목 파괴가 발생했다.
RM이 회수 단계인 동안에도 추가 채굴이 이어졌고, 첫 파괴에서 **220tick 후인 545번째**에
원목 2개를 주웠다. 결과적으로 성공했지만 즉시 회수하지 않고 총 4개를 파괴한 경로였다.
현재 collection의 접근·채굴·회수는 같은 root 임베딩을 공유하고 추가 단계 tensor로 구분한다.
이 구조와 작은 조건 민감도는 회수 제어를 더 조사할 근거다. 문구를 분리하는 것만으로 해결된다는
보장은 없으며, 이전 R1에서도 pickup 조건과 adapter 학습의 일반적인 개선은 확인되지 않았다.

**3. 상위 완료 보상만으로는 공통 하위 능력을 학습하기 어렵다.**

현재 상위 수량 목표가 끝날 때 일회성 보상 1을 준다. 원목 2개까지 얻었어도 3개 목표에 실패하면
전체 보상 합은 0이다. 이번에는 학습하지 않았으므로 보상 설계가 실제 업데이트를 망쳤다고 주장하지 않는다.
다만 하위의 유효한 획득 경험과 전체 목표 실패를 분리해 학습할 필요가 있다.
이동·버튼 횟수에 임의의 보너스를 늘리는 방식보다는 검증 가능한 결과를 단위로 삼아야 한다.

**4. 비교 실험의 변동과 수집 처리량이 학습 효율을 제한한다.**

시작 위치·방향·시각/tick·인벤토리는 5쌍 모두 같았지만 첫 화면은 **1/5쌍만 정확히 같았다**.
나머지 화면의 다른 픽셀 비율은 0.00434~0.94054%였다. 첫 화면이 같은 쌍도 4번째 화면에서
파괴 입자 차이가 생기고 9번째 행동부터 달라졌다. 서로 성공/실패가 뒤집힌 두 조건 모두
화면 차이가 행동 차이보다 먼저였다. 동일 시드만으로 인과적 성능 비교가 충분히 통제되지는 않았다.

10회 실제 제어 시간 합은 **825.55초(13.76분)**다. 4,941행동은 게임 내 247.05초에 해당한다.
재무장부터 마지막 STOP/배치 종료까지는 **65.99분**으로, 모델·게임 준비/종료와 감사 시간도 포함한다.
아래는 각 실행에서 구한 통계의 범위이며 전체 행동을 합친 percentile이 아니다.

| 측정 | 실행별 중앙값 범위 | 실행별 p95 범위 |
|---|---:|---:|
| 정책 추론 | 51.94~58.28ms | 61.70~68.92ms |
| 전체 제어 주기 | 146.16~164.39ms | 189.72~241.17ms |

PNG 기록 중앙값은 31.45~41.75ms, 환경 처리 중앙값은 46.88~53.71ms다.
매 실행 모델·게임을 새로 준비하고 종료하는 비용과 Windows/WSL 사이 대용량 로그 읽기 비용도 있었다.
새 이벤트 세부 분석은 기존 Windows 격리 Python의 stdlib로 읽어 후처리했다. 정책 실행 조건은 바꾸지 않았다.
장치 전체 사용량의 샘플 peak는 2,874MiB, torch allocation peak는 1,915MiB였다.
장치 측정은 다른 프로세스까지 포함한다. OOM은 없었지만 전체 backbone 학습의 메모리 여유를 검증한 것은 아니다.

## 권장 개선 순서와 판정 기준

| 우선순위 | 개선 | 통과를 어떻게 판단할 것인가 |
|---|---|---|
| 1 | 공통 스킬 학습 기준과 비교 시작 상태를 고정한다. S2에도 검증된 저장 시작 상태를 연결하고 동일 정책 반복(A/A)으로 변동을 측정한다. 평지·단차·가림·회수·목표 전환을 자원 종류와 교차한다. | 초기 상태 복원과 STOP 보존, 같은 정책 자체의 변동량을 보고. 개발 seed를 새 train 자료로 재사용하지 않는다. |
| 2 | 상위 RM의 수량/순서를 유지하면서 내부 `접근 → 상호작용 → 결과 회수`를 공통 결과 단위로 학습한다. 예: 실제 상호작용 결과 발생과 실제 인벤토리 증가를 구분하고, 하위 완료가 상위 완료를 대체하지 않게 한다. | 별도 train 세계에서 새 경험으로 RL 업데이트. 새로운 지형·대상 배치의 접근/회수 성공과 전체 목표 성능이 함께 개선되어야 한다. 버리기·재줍기·중복 보상 반례 포함. |
| 3 | 동일 계약의 현재 목적·진행·대상 정보를 정책이 실제로 사용할 수 있게 학습한다. 조건별 적절한 행동이 실제로 다른 장면을 포함하고, 목표 전환과 회수 경험을 충분히 수집한다. 먼저 현 구조에서 측정한 뒤 필요할 때 context와 영상/기억이 상호작용하는 adapter를 비교한다. | 동결 정책 대조와 새 정책 대조를 분리. 조건 민감도 증가만으로 채택하지 않고 실제 인벤토리 성과와 기존 수집 능력 유지로 판단한다. 전체 backbone 해제는 별도 메모리 실측 후 결정한다. |
| 4 | 성공·실패·소요 시간·불확실성을 같은 상태 변화 계약으로 축적하고 competence에 따라 연습을 배분한다. 자료가 쌓이면 작은 스킬 결과 모델을 검증한 뒤 계획에 사용한다. | 예측의 보정·미관측 상황 불확실성을 검사. 계획기를 꺼도 새 정책이 나아졌는지 평가해, 쉬운 과제 선택과 RL 능력 향상을 구분한다. |
| 병행 | 모델/환경 준비의 재사용, 제한된 비동기 기록 큐 등을 별도 성능 조건에서 검증한다. | 의미가 같은 1tick 행동·완료 판정·원본 기록·STOP를 유지하면서 제어/수집 시간이 줄어야 한다. 임의 frame skip으로 행동 의미를 바꾸지 않는다. |

추천은 **통합 계약을 유지하고 공통 스킬 학습과 조건 활용을 먼저 강화한 뒤, 검증된 스킬 결과를
계획·학습 선택에 연결하는 것**이다. 특정 벽/나무 좌표에 대한 스크립트나 성공한 문구를 더 붙이는 방향으로
확장하지 않는다. 관측기와 허용 입력은 고정하고, 대상 위치를 모르는 조건에 서버 좌표를 몰래 추가하지 않는다.
여기서 제안한 개선은 아직 구현/학습/성능 검증한 것이 아니다.

STEVE-1은 사전학습 행동 정책을 MineCLIP latent 목표에 맞춰 조정하고 텍스트 prior를 학습한 구조다.
이번 명시적 RM context의 활용도가 그 사전학습과 같다고 가정할 수 없다.
[STEVE-1 원문](https://arxiv.org/abs/2306.00937).
스킬 결과를 예측해 계획하는 방향과 competence/개선 가능성에 따라 연습을 고르는 방향은 각각
[SkiMo](https://proceedings.mlr.press/v205/shi23a.html),
[Practice Makes Perfect](https://arxiv.org/abs/2402.15025)를 참고할 수 있다.
이 논문들의 로봇/시뮬레이션 결과가 Minecraft에서의 효과를 보장하는 것은 아니며, 위 제안은 프로젝트 적용 추론이다.

## 종료와 재현 자료

별도 실제 STOP는 canonical 원목64, 10행동 뒤 요청했다. 요청 가시화/ack 이후 dispatch는 각각 **0/0**,
입력 해제 확인·held keys 0·잔존 소유 PID 0, 정상 취소 worker exit 2였다. 실제 중단을 성능 표본에 넣지 않았다.
요청 가시화부터 ack는 약 46ms, 요청 시작부터의 상한은 약 120ms인 단일 측정이며 최악 지연 보장이 아니다.
일부 upstream 종료 로그에 kill timeout 경고가 있었지만 최종 소유 PID 정리는 확인됐다.
모든 게임/학습 실행은 종료했고 STOP를 유지한다.

자료는 `results/unified-goal-u2-20261102`에 있다. `plan.json`, 명령별 JSON/로그, `work.json`,
`source-at-game`, 각 `events.jsonl`/PNG/summary/trajectory, `analysis.json`, `event-detail.json`,
`contract-analysis.json`, `stop-probe-audit.json`, `driver-completion.json`, `completion.json`을 보존한다.
Git HEAD만으로 재현하지 말고 dirty tree의 실제 실행 소스 snapshot과 해시를 사용한다.
완료한 배치를 다시 실행하지 않는다. 원문 연구 명세·공식 모델·관측기·과거 실험은 유지했고,
기존 4단계 연구 방향을 변경하지 않았다.
