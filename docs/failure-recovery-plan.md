# 수집 정체 감지와 명시적 복구

기존 순차 RM의 다음 개발인 실패·재계획 처리를 진행한다. 연구 명세 4.5–4.7의
관측 기반 상태와 기존 pause/modify_plan/resume 계약을 유지한다.

1. 실제 목표 인벤토리 순증가의 최고치가 60초 동안 늘지 않으면 no_progress로
   일시정지한다. 수치는 세션 옵션으로 조절하며 자원 부재나 경로 막힘으로 추정하지 않는다.
2. 추론 전후에 검사하고 입력을 해제한다. 자동 재시도/목표 변경/API 대체 없이
   새 revision과 실패 근거를 기록한다. 기존 확인은 무효화한다.
3. 실패 이유와 완료 단계/획득량을 저장·복원한다. 명시적 resume은 baseline을
   유지하고 새 관측 시간을 시작한다. 기존 modify_plan으로 남은 계획을 교체한다.
4. 가짜 시계/환경으로 진행·손실·일시정지·오래 걸리는 추론·명령 경쟁을 검사한다.
   회귀 검사를 묶어서 실행한 뒤 실제 STEVE-1에서 짧은 검사 한도로 정체를 유도하고
   수정/재개/취소와 행동 차단을 검사한다. 유도된 정체를 자연 실패율로 계산하지 않는다.

추가 유료 API 호출 없음. 기존 연구 명세 및 정책 벤치마크는 변경하지 않는다.
새 스킬이나 일반 분기 RM의 설계는 이 단계에 포함되지 않는다.

## 실행 기록

- Ruling: 기존 디렉터리에서 순차 실행하며 자체 검토한다. Git 저장소/분리 작업공간을
  새로 만들거나 하위 에이전트를 사용하지 않는다(사용자 경로 및 순차 실행 지침).
- 공유 계약: TaskState의 실패 revision/체크포인트 → runtime 입력 해제 → 대화 현재
  과업 갱신 → 기존 resume/modify_plan. schema 1/2 읽기 호환을 유지한다.
- Ruling: 정체는 자원 부재의 증거가 아니므로 no_progress만 기록한다. 자동 재시도는
  하지 않는다. 잘못된 임계값은 성급한 pause를 만들 수 있어 설정값과 근거를 남긴다.
- 완료: 최초 4개 실패 → 구현 후 통과, 보강 2개 포함 최종 Windows 91/4 skip,
  WSL 95/95. 감지·저장·복원·명시적 계획 교체/재개의 실제 제어 계약 통과.
- 실제 결과: 재계획한 흙 1개는 60초 동안 0개로 실패. acceptance=false를 보존하고
  제어 증거와 분리했다. API 제어 대체나 무단 자동 재시도 없음.
- Final review: 사용자 순차 실행 지침에 따라 자체 검토. 취소 경합, schema 1/2 호환,
  schema 3 단일/계획 과업 및 손상 입력, paused 수정, 이전 확인 무효화, STOP 순서를
  확인했다. 독립 리뷰는 아니며 새 스킬의 복구 성공은 이 단계의 미해결 정책 과제다.
