후속 상태: 첫 수집의 교사가0/6 안정 도착에 실패해 다음 단계를 중단했다. 새 학습은0이며
이 배치는 자동 재시작하지 않는다. [위치 입력의 시점 불일치 진단·교정](common-navigation-pose-alignment-2026-10-17.md)을
먼저 진행한다. 아래 replay/monitor 계획은 원래 서버 입력 조건의 기록이며 클라이언트 조건에 적용하지 않는다.

현재 이동 후보는 다양한 출발/목표에서 실제 도착했지만, 도착 순간에도 0.10–0.27블록/틱 움직였다.
`results/common-navigation-distill-20261017-retry1/arrival-motion-diagnostic.json`이 근거다.
반경 진입 즉시 종료하는 기존 과업에는 정지 상태의 교사 경험도 거의 없다. 다음 단위는 같은 이동
인터페이스와 행동 공간에서 감속 후 위치를 유지하는 것이다. 별도 저장본 전용 스킬을 만들지 않는다.

## 실행 전 고정할 조건

- 시작 후보는 v3 `584e7cf507a9ce4376f542f46269660fc40fc9f900e3878f425bc9f727066fb1`.
  기존 원목 actor/본체/value를 동결하며 이동 residual/projection만 BC 갱신한다.
- 학습용 3개 출발 조건, 각 6개 무작위 목표. 기존 train seed 104729/104743/104759를 사용한다.
  이동 3–6블록과 정밀 접근 0.65–1.3블록을 번갈아 사용하고 시작 방향/대칭도 바꾼다.
- `correction` 모드에서 학생 최대 60틱, 미완료 시 입력 해제 후 명시적 좌표 교사 최대 100틱.
  원본 행동/소유자/logp를 보존하고 학생 방문 상태의 별도 정답 질의와 실제 교사 구간을 BC에 사용한다.
  교사 도착을 학생 성공으로 세지 않는다. 총 행동 상한 966틱, 제어 예산 175초/실측 180초 이하.
- 기존 train 10실행의 정답을 replay하고 같은 별도 development 교사 자료로 loss를 관찰한다.
  개발 실행과 최종 평가 시드는 gradient에 넣지 않는다.
- BC 학습률 1e-4 / 16 epoch / KL 한도 3 / batch 32. 실제 보존 갱신·root 보존·reload를 확인한다.
  새 자료량을 포함한 학습 프로세스 상한은 1,800초이며 게임 제어 시간 상한과 구분한다.

## 도착의 새 검사

기존 도착 기준은 기본값으로 그대로 둔다. 이번 명시적 조건에서는 실제 서버의 연속 **12틱** 동안
수평 목표 거리 ≤0.35블록, 수평 이동량 ≤0.03블록/틱, 수직 이동량 ≤0.01블록/틱,
목표 높이 오차 ≤0.05블록, GUI 닫힘을 모두 요구한다. 기준을 벗어나면 누적을 0으로 초기화한다.
새 목표 및 학생→교사 전환에서도 누적을 승계하지 않는다. 초기 위치가 목표 안이라는 이유만으로
무행동 성공을 인정하지 않고 실제 연속 관측이 있어야 완료한다.

정지 상태는 새 RM 단계/행동이 아니다. 기존 수치 목표와 직전 이동량 입력이 감속 판단에 쓰이고,
연속 유지 횟수는 완료 검증의 상태다. 원래 navigation reward의 성공은 이 조건을 충족할 때만 1회 준다.
거리 potential과 시간 비용은 유지하고 별도의 제자리 보상은 추가하지 않는다.
기존 1틱 도착 결과와 새 12틱 안정 도착 결과는 직접 합산하지 않는다.
