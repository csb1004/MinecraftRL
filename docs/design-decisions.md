# 설계 결정 및 변경 기록

## 2026-10-07 후속 과업의 단계 계약

사용자가 이후 과업도 원목의 탐색/접근/채굴/회수처럼 검증 가능한 상태 변화 단위로
나누도록 요청했다. 상위 목표 RM과 skill 내부 RM을 구분하고, 진입/완료의 실제 증거,
실패·복구, 정책 입력, 보상, 중단 경계를 함께 정의한다. 이미 충족된 단계는 건너뛸 수 있다.
개별 키 입력을 단계로 늘리거나 미지원 제작/이동 과업을 실행 가능하다고 선언하지 않는다.
[공통 계약과 과업별 현재 범위](task-decomposition.md)를 루트 AGENTS.md에서 참조한다.
장기 연구 목표와 원문20개 항목은 유지한다.

## 2026-10-07 원목 내부 단계와 거리·틱 보상

사용자가 승인한 탐색/접근/채굴/수집 분해와 거리 변화·틱 비용을 `wood-potential-v1`
선택 조건으로 추가했다. 기존 sparse 조건은 보존한다. 총이동거리가 아닌 잠근 목표까지의
거리와 RM 상태로 bounded potential을 계산한다. 서버 중심 ray로 확인한 목표와
정규화 거리/단계가 actor·value head에 전달되므로 이 조건은 영상 전용 정책과 구분되는
privileged context 실험이다. 좌표와 게임 조작 API를 행동 생성에 직접 사용하지 않는다.
새 head 입력 열은 0으로 초기화하며 영상/recurrent backbone은 고정한다.
수집 단계의 거리는 실제 item entity 대신 파괴 위치를 사용하므로 아이템 추적 완성으로
해석하지 않는다. 실제 획득은 서버 인벤토리만 인정한다. [고정 조건](wood-shaping-protocol-2026-10-07.md).

시간 비용의 할인 반환값 점검에서 v1이 늦은 성공보다 조기 실패를 선호할 수 있음을 확인했다.
v1 원본을 보존하고 v2에서 실제 환경 실패 종료에만 -1을 추가했다. 사용자 STOP/기술 오류와
시간 제한 truncation에는 적용하지 않는다. 같은 초기 상태에서 성공/실패 반환값 순서를
수식·단위 테스트로 확인했다. 신규 실험에는 v2를 사용하되 기본 sparse/정책 승격은 유지한다.

## 2026-10-06 확대 RL 배치와 종료 후처리 경계

승인된8시드×2회 수집 및2시드×전후3회 검증을 완료했다. 영상·순환 backbone 고정과 기존 행동/보상 정의를 유지하고, 누적78회 연구 checkpoint에서394회 추가 갱신했다. 검증 개선 근거가 없어 기본 정책은 유지한다. 과제나 hyperparameter를 평가 결과에 맞춰 다시 조정하지 않았다. [실제 결과](rl-expanded-validation-2026-10-06.md).

실제180초 미획득 시행에서 게임 close와 tensor 저장/worker 종료가 기존10초 종료 유예를 함께 소비해 감독기 SIGTERM이 발생했다. 입력 해제·환경 close 이후의 명시적 marker에 한해 최대60초 후처리를 허용하고 수동 STOP 및 유예 만료 강제 정리는 유지한다. 최종 supervisor 실패는 tensor 내용과 무관하게 학습에서 거부한다. 원본 실패를 보존하고 정확히1회 재실행했으며, 별도35초 실게임 시간 초과에서도 정상 저장·종료와 이후 행동0을 확인했다. 원래180초 궤적 전체를 다시 재현했다는 주장은 하지 않는다. [고정 조건·원인](rl-expanded-protocol-2026-10-06.md).

## 2026-10-05 첫 RL 범위

최초 실행은 STEVE-1 영상·순환 backbone을 고정한 행동 출력층과 새 가치함수 PPO로 한정했다. 실제 전달 행동의 정규화 CFG 확률과 frozen feature를 저장해 동일한 출력층 계산을 재현한다. 전체 모델 학습으로 해석하지 않는다. 학습·평가 분할을 강제하며 평가 시 체크포인트를 변경하지 않는다. 실제20회 업데이트와5쌍 결과 및 초기 상태 재현성 한계는 [검증 기록](rl-pilot-validation-2026-10-05.md)에 보존한다. 장기 연구 명세는 변경하지 않는다.

기준: 사용자가 제공한 승인 계획과 `research-spec.md`의 20개 항목. 2026-10-03.

## 연구 목표와 실행 순서

최종 목표는 지속적 embodied companion agent이며 장기 과업, 인간다움, 사회적 상호작용, ablation 평가를 유지한다. 철 장비와 네더는 장기 목표 예시다. 첫 통합 완료 조건은 따라오기, 지정 위치 이동, 귀환, 나무·돌 수집, 기본 제작 중 대화·수정·취소·일시 중단·재개가 작동하는 것이다.

원문 17절의 단계는 보존한다. 추가 합의에 따라 Stage 5의 **공개 사전학습 정책 실행 가능성 검증**을 인프라 완성보다 앞에 둔다. 대규모 사전학습 재현은 이번 범위가 아니다. API 봇을 먼저 완성한 뒤 정책을 미루지 않는다.

중간 레시피의 커밋은 다음 의존 작업을 허용하지만, 전체 요청(기본: 곡괭이1·도끼1)의
완료는 새 행동 권한을 회수한다. 결과 미리보기·커서 물품·서버 인벤토리·저장 NBT를
구분하고 작업대 배치도 서버 블록 및 저장 청크로 확인한다. 읽기 전용 서버 관측은
게임 스레드에서 발행한 스냅샷으로 전달한다. [실험 범위](workshop-protocol.md).
이는 연구 명세10절의 결정적 제작 보조이며 학습 정책/RL 성과로 계산하지 않는다.
제작의 모든 기능을 완성할 때까지 RL을 미루지 않고, 이번 검증 다음 연구 단계는
채집 보상 연결과 첫 실제 가중치 갱신이다. [첫 RL 전환 기준](first-rl-stage.md).

2026-10-04 조합 실패 분석에서 **정책을 더 실행해도 되는 조건**과 **과업을 최종 완료로
인정하는 조건**을 분리했다. 기존 craft-probe는 수집 RM 밖의 실험 경로였고 인벤토리와
늦은 제작 통계를 동시에 기다리는 동안 추가 행동이 나갔다. 조합 실험의 수정 조건은
crafting → recovering → completed/failed다. 실제 물품을 관측하면 제작 정책 권한을
회수하고, 서버 인벤토리·커서·통계를 확인한 뒤 종료한다. 클라이언트 예측만으로 완료를
인정하지 않으며 저장 NBT 불일치도 성공으로 계산하지 않는다. 일반 대화/RM 제작 지원을
추가한 것은 아니다. [근본 원인과 관측 근거](craft-rm-root-cause.md).

2026-10-04 실패 월드의 5쌍 실제 비교에서 short 5/5, official 4/5였으므로 기본
문구는 short를 유지한다. official과 격리 world-store-root는 재현 실험용 옵션이다.
저장·재시작 효과와 같은 세션 내 정책 재초기화 효과를 구분하며 자동 재시도 경계는
변경하지 않았다. 상세: pickup-comparison-validation-2026-10-04.md.

2026-10-04 후속 단계는 인벤토리 순증가의 정체를 no_progress로 기록하고 paused로
보존하는 경로다. 기본 60초는 조절 가능한 초기값이며 원인 진단이나 최적 임계값이 아니다.
자동 목표 변경/무한 재시도 없이 기존 명시적 resume/modify_plan으로 복구한다.
실제 재개 후에도 흙 획득이 없었던 실패를 보존했다. 상세: failure-recovery.md.

2026-10-04 추천안 A 승인 후 첫 RM 구현은 최대 8단계의 선형 wood/dirt 수집으로
한정했다. 단계별 실제 순증가, 완료 이력, revision, 현재/남은 단계 수정, paused 복원을
검증했다. 일반 그래프·분기·새 스킬을 이 묶음에 억지로 포함하지 않는다. 이는 연구
축소가 아니라 기존 정책으로 실행 상태 경계를 먼저 완성한 것이다. 상세: sequence-rm.md.

Dialogue/Persona LLM → Task Commitment → RM Compiler/Validator → RM Runtime → Planner/Replanning → Policy/API Skill → Minecraft 관측 검증.

- LLM은 의미 해석과 응답을 제공하되 task 최종 등록 및 완료 판정 권한을 갖지 않는다.
- CHAT/QUESTION/INFORMATION/PREFERENCE/PROPOSAL/REQUEST/MODIFY/CANCEL을 구분한다. 일시 중단/재개는 명시적 실행 제어 이벤트로 추가한다.
- RM은 실제 게임 관측으로만 진행한다. 원문의 이벤트 예시 이름 차이는 추후 canonical vocabulary와 alias 검증으로 해결하며 원문은 수정하지 않는다.
- 대화와 행동은 비동기 처리한다. 취소·수정 시 이전 task revision의 행동을 폐기하고 입력을 해제한 뒤 새 목표를 실행한다.
- Persona는 대화와 계획 선호에 영향을 주되 목표를 바꾸지 않는다.
- episodic/world/user preference/skill experience memory를 분리한다.
- Human Play Prior(행동)와 Knowledge Base/RAG(문화·밈·관습)를 분리한다.

## 정책 선택과 해석 제한

1. VPT foundation 1x부터 로컬 메모리·속도와 자발적 행동을 측정한다. 자연어 조건을 지원한다고 간주하지 않는다.
2. STEVE-1은 별도 환경·프로세스에서 짧은 나무/흙 수집 지시를 평가한다. 공식 배포는 2x 정책, MineCLIP, text prior가 필요하다. VPT 1x가 맞는다고 STEVE-1도 3GB에 맞는다는 보장은 없다.
3. MineStudio는 후속 실행·학습 환경 후보다. 이번 최초 기준선은 공식 MineRL 계열이다.
4. 화면→키보드/마우스 정책 가중치를 Mineflayer에 직접 넣을 수 없다. Mineflayer는 별도 API skill/관측/연결 후보다.
5. 정책 실패를 API 대체 성공으로 보고하지 않는다. 모든 행동 로그에 controller=policy 또는 api를 기록한다. 본 묶음에는 API 행동 fallback이 없다.
6. 작은 실행 실험은 인간다움·문화 이해의 증거가 아니다.

## 환경 및 경로

최종 프로젝트 경로는 `D:\DATA\Desktop\MinecraftRL`이다. Windows 명령은 PowerShell, 필요한 Linux 실행은 WSL을 사용한다. GitHub 통신은 PowerShell HTTP 또는 Git을 사용하며 gh는 사용하지 않는다. 기존 파일/시스템 환경을 덮어쓰지 않는다.

전달본 작성 당시 연결은 Linux 클라우드 `/workspace`였다. 당시 전체 액세스는 그 머신의 권한이며 사용자 PC 연결이 아니었다. `/workspace/MinecraftRL-delivery/project`는 **전달용 준비본**이었다. 이후 지정 Windows 경로의 실제 설치와 WSL 정책 검증을 완료했다(`local-validation-2026-10-03.md`). 설치 스크립트는 승인 경로만 사용하며 다른 내용의 기존 파일 발견 시 쓰기 전에 중단한다.

전달 당시 사용자 보고 환경: GTX 1060 3GB, 드라이버 560.94, 당시 여유 2521 MiB, RAM 23.9 GiB, Windows Python 3.11, Node/npm/Java/Git, WSL Ubuntu-24.04/docker-desktop. 실제 Windows/WSL 재검증 값과 실험 당시 자원 사용은 위 로컬 검증 문서 및 results에 별도로 보존한다.

OpenAI API는 후속 대화/의미 해석에 사용하고 모델을 설정 가능하게 한다. 키 보유 여부 미확인; 이번 정책 검증에 키는 필요하지 않다. Colab 연결과 유료 자원 사용은 하지 않았다.

## 후속 월드 지속성 요청 (2026-10-04)

사용자가 게임 종료 뒤 동일 월드·인벤토리·과업 재개를 요청했다. `session`에만 저장 슬롯을
적용하며 고정 시드 `episode/suite` 실험은 그대로 둔다. 과업은 실제 복원 관측을 검증한 뒤
paused로 복원하며, 명시적 resume 또는 완료/취소 뒤 새 요청으로만 정책 제어를 시작한다.
원래 MineRL `<Quit/>`의 저장 누락을 실제 재시작 실패와 저장 NBT로 확인했다.
설치 원본 JAR를 보존하고 세션 전용 사본에 저장 완료 처리를 추가한다.
복원 중 새 월드나 API 아이템 지급으로 대체하지 않는다. 상세는 `world-persistence.md` 참조.

2026-10-07 RL 개발세계 준비에서 새 월드 이름이 과거 폴더와 충돌하는 사례를 확인했다.
저장 지원 사본 JAR의 새 월드 생성에 UUID 저장 이름을 추가하고, 경로가 이미 있으면
생성을 거부한다. 기존 게임 RNG 호출과 지형 seed는 유지하며 복원은 기존 ZIP을 그대로 쓴다.
RL 준비·복원은 저장 NBT의 실제 seed도 요청값과 대조한다.
원인·증거·같은 시드 복구 조건은 `rl-horizon-world-collision-2026-10-07.md`에 기록했다.

## 실험 결정

2026-10-04 후속 정체 복구 실험은 자연 정체가 관측된 시행에만 한 번의 명시적 resume를
실험기가 발행하도록 제한했다. 기본 세션의 자동 재시도는 활성화하지 않았다. 실제 5회는
모두 초기 성공으로 정체가 없어 복구 효과가 미검증이다. 같은 조건을 성공 사례가 나올
때까지 반복하지 않으며 초기 성공을 복구 성공으로 계산하지 않는다. 상세는
