# 대화·기억·월드 통합 검사

후속 승인으로 실제 LLM+게임 검사도 수행했다.
[추가 API 5회 및 실게임 결과](live-semantic-world-validation-2026-10-04.md).
아래는 합성 응답 통합 단계 당시 기록이다.

이번 단계는 Responses 요청/응답 어댑터 → 제안 확인 → 실제 STEVE-1 → 저장 →
게임 재시작 → 같은 대화 기억 및 과업 복원을 연결하는 로컬 검사다.
모델 응답만 결정적인 합성 fixture를 사용한다. API 키를 읽지 않고 주입 transport가
고정 응답을 반환하므로 원격 LLM 호출이나 언어 이해 품질 검증이 아니다.
이전 승인된 실제 API 5회에 추가되는 유료 호출은 없다.

## 재현

기존 실행 종료 기록을 확인하고 results/STOP을 고유한 보존 경로로 이동한 다음:

```powershell
.\scripts\Invoke-PolicyProbe.ps1 -Policy steve1 -Operation semantic-world-scenario
```

시나리오는 별도 validation 슬롯을 만든다. 고정 seed 130363, 실행별 제어 시간 상한
180초를 사용한다. 첫 실행에서 흙 64개 과업을 확인하고 실제 흙 2개 이상 획득 후
대화 제안/확인으로 pause, STOP 및 정상 저장한다. 두 번째 실행에서는 동일 월드를
paused로 복원하고 새 확인 후 resume하여 추가 2개 이상 획득 후 저장한다.
64개 목표 완료율을 평가하는 실험이 아니며 의도적 STOP의 raw cancelled/invalid를 보존한다.

검사 항목:

- 합성 과거 대화의 미확정 나무 제안과 선호가 최근 12개 밖으로 밀려난 뒤에도
  출처 있는 분류별 요약으로 어댑터 입력에 전달된다.
- 페르소나 응답에 명령처럼 보이는 문장이 있어도 실행되지 않는다.
- 콘솔을 재생성하면 이전 제안 확인 번호가 무효이며 새 확인이 필요하다.
- 확인 전 1초 대기와 월드 복원 후 명시적 재개 전에는 정책 행동이 없다.
- 진행도는 실제 인벤토리에서 읽고, 과거 대화의 제안으로 목표를 바꾸지 않는다.
- pause/STOP 뒤 새 정책 행동, 입력 해제, 저장 및 자식 프로세스 종료를 확인한다.

## 발견한 중단 경계 문제

SessionDialogue는 부모 폴더 STOP만 확인해 세션 자체 STOP을 놓쳤다. 중첩된 결과
폴더에서는 프로젝트 공통 STOP도 직접 확인하지 못했다. 실패하는 회귀 검사를 먼저
실행하고 세션 STOP 및 명시적 공통 stop_file 검사를 추가했다. CLI는 공통 STOP을
전달하며 실제 시나리오도 같은 경로를 사용한다. 최종 명령 발행 직전 다시 상태를
검사하고, worker의 기존 행동 차단은 별도로 유지한다.

## 실제 실행 결과

Windows DESKTOP-V0HJPC2 / WSL Ubuntu-24.04 / GTX 1060 3GB에서
`results/semantic-world-scenario-20261004T013043802327Z`의 두 실행을 완료했다.
별도 슬롯은 `validation-20261004T013043802327Z`다.

| 항목 | 최초 수집·저장 | 복원·재개·저장 |
|---|---:|---:|
| 실제 흙 인벤토리 | 0 → 2 | 2 → 4 |
| 정책 step | 511 | 252 |
| 제어 시간(초) | 67.869 | 33.707 |
| 종료 처리(초) | 5.163 | 4.817 |
| 추론 중앙값 / p95(ms) | 42.976 / 52.771 | 42.484 / 51.462 |
| 제어 주기 중앙값 / p95(ms) | 118.699 / 143.130 | 114.172 / 144.933 |
| 전체 GPU 관측 peak(MiB) | 2789 | 2779 |
| PyTorch allocated / reserved peak(MiB) | 2098.717 / 2144 | 2098.717 / 2144 |
| 준비 완료 → 새 확인 수락(초) | 2.877 | 1.819 |
| 확인 전 / pause 후 / STOP 후 정책 행동 | 0 / 0 / 0 | 0 / 0 / 0 |

복원 관측은 흙 2개·씨앗 1개와 위치 차이 0블록으로 일치했다. 과업 revision 1,
흙 64개 목표, progress 2 및 paused 상태를 새 콘솔이 읽었다. 새 확인으로 resume한
뒤 progress 4에서 다시 pause하고 저장했다. 두 번 모두 neutral_command_sent,
소유 자식 잔존 0개다. 별도 전체 프로젝트 프로세스 조회에서도 잔존 0개였다.
현재 STOP은 다시 잠겨 있으며 실행 중인 게임은 없다.

두 단계 각각 합성 transport 응답 5회, 총 10회다. 원격 모델 API 호출은 0회다.
요약 전달·미확정 제안 비실행·옛 확인 번호 거부·페르소나 출력 비실행은 각 단계
`dialogue-acceptance.json`과 `fixture-payloads.json`에 기록했다. 전 구간 이벤트를
다시 검사한 결과는 `integrated-evidence.json`, 원본 요약은 `acceptance.json`이다.
검사 보조 스크립트의 Windows 기본 cp949 읽기 오류는 UTF-8 명시 후 재실행했다.
실게임 결과나 정책 실패가 아니며 원본 이벤트는 변경하지 않았다.

WSL 테스트 75개 통과(27.181초), Windows 71개 통과/4개 Linux 전용 제외(1.374초).
PowerShell 및 WSL shell 구문 검사 통과. 로그는 results의
`semantic-world-wsl-tests.log`, `semantic-world-windows-tests.log`에 보존했다.
연구 명세 원문 SHA256은 기존 값과 동일하다.

## 남은 검증

다음 실험은 실제 LLM 응답으로 같은 제어 흐름을 검증하는 것이다. 이전 유료 호출
승인 5회는 이미 소진했으므로 이번에는 수행하지 않았다. 준비된 시나리오를 이용해
수집 요청의 의미 해석, 명료화, 미래 제안의 비실행, 과업 문맥 참조 및 관측에 맞는
페르소나 응답을 별도 승인된 호출 예산 안에서 검사해야 한다.
개인 MyWife 기록 연결, 긴 대화에서의 추론 정확도, 일반적인 장기 목표 유지,
최신 Bukkit 서버 호환성은 여전히 미검증이다. 이 고정 응답 검사를 실제 LLM의
목표 유지 능력이나 일반적인 RM 완성으로 해석하지 않는다.
