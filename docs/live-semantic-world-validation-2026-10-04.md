# 실제 LLM·기억·STEVE-1·월드 복원 통합

사용자의 추가 실행 승인 후 실제 OpenAI Responses 호출을 최대 5회로 제한하여
로컬 실게임과 연결했다. 5회 모두 completed 응답 및 로컬 처리를 마쳤다.
실게임의 실행·확인·복원·재개 경계는 통과했으나, 미래 제안의 세부분류는 기대한
TASK_PROPOSAL 대신 CHAT이었다. 전체 의미 해석 품질이 완벽하다는 결과가 아니다.

  실제 게임 과업 상태를 사용했다. 키와 요청 헤더는 결과에 기록하지 않았다.

### 분류 차이의 원인 검토

현재 PLANNER는 미래 제안을 TASK_REQUEST로 만들지 말라고 지시하지만, 미래 제안을
반드시 TASK_PROPOSAL로 분류하라는 개별 라벨 정의는 제공하지 않는다. CHAT과
TASK_PROPOSAL의 구분 지침이 불충분한 것이 가능한 원인이다. 단일 응답으로
모델 내부 원인을 확정할 수 없다. 이번에는 관측 라벨을 덮어쓰거나 성공으로
재분류하지 않았다. 이 발화는 현재 기억에서 context로 저장되므로, 장기 기억의
미확정 제안 분류도 엄밀히는 보완 대상이다. 라벨 정의와 대조 발화 평가를 보완하고
별도 승인된 호출로 재검증해야 한다. 실행 권한은 어떤 대화 기억에도 부여하지 않는다.

확인하여 실행했다. 수집·재개 제안의 내용은 실험기가 기대값과 검사한 뒤 확인했으며,

pause는 기존 제한 한국어 문법으로 처리해 API를 쓰지 않았다.

두 실행 모두 neutral_command_sent, 정상 월드 저장, 소유 자식 잔존 0개다.
마지막 별도 WSL 프로세스 조회에서도 프로젝트 Python/Java 잔존 0개였다.
STOP을 다시 잠갔다. 의도적 STOP의 원본 cancelled / execution_valid=false / worker
exit 2는 그대로 보존하며 일반 정책 성공률 표본에 합치지 않는다.
