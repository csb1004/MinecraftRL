# 공통 이동 입력의 시점 정합성 수정

12틱 감속·정지 수집 첫 실행에서 학생 0/6, 좌표 교사도 0/6이었다.
`results/common-navigation-settled-20261017/collect-train-a/run`의 966행동은 정상 실행 및
STOP/입력 해제/PID 감사를 통과했지만, 정지 시연 품질이 낮아 `training-exclusion.json`으로
학습에서 제외했다. 원본을 보존하고 다음 수집 전에 진단용 STOP을 걸었다. 학습 갱신은 0이다.

## 원인과 수정 범위

현재 실패와 과거 독립 실행 3개의 이동 관측 947개에서 서버 X/Z는 정확히 4틱 전의
클라이언트 X/Z와 같았다. 화면/시선은 현재인데 목표 거리/이동 속도에는 이전 위치를 넣었다.
전진 해제 직후 클라이언트 속도는 즉시 감소한다. 키 해제 실패와는 구분한다.
정지 중에는 좌표 패킷 갱신이 더 드물 수 있으므로 모든 관측에 고정 4틱이라고 일반화하지 않는다.
근거는 `results/common-navigation-settled-preparation-20261017/pose-lag-diagnostic.json`이다.

기존 recorder 경계에서 클라이언트 위치·tick·접지 여부를 읽기 전용으로 추가했다.
새 명시적 `pose_source=client` 조건만 현재 시점의 목표 벡터/이동량/교사 입력을 사용한다.
서버 상태와 원본 행동은 그대로 저장한다. 안정 도착은 양쪽 위치와 접지가 연속 12틱 기준을
만족해야 하며 최종 성공 증거는 서버를 계속 포함한다. 게임 물리와 네트워크 동작은 변경하지 않는다.
기존 기본값 `server`와 과거 기록의 의미는 보존한다.

클라이언트 관측 누락/비정상 tick은 조용히 서버 값으로 대체하지 않고 중단한다.
서로 다른 입력 시점의 학습 자료 혼합도 거부한다. 과거 서버 입력 모델의 가중치는 명시적
warm start로 쓸 수 있으나 예전 replay/개발 label monitor는 새 클라이언트 자료에 섞지 않는다.

## 실제 교정 검사

`results/common-navigation-client-calibration-20261017/calibration.json`에 기존과 같은
시작 월드/목표/모델/난수를 고정했다. 학생 60틱 뒤 교사 100틱, 6목표, 연속 안정 도착 12틱이다.
학습 없이 입력 시점 수정의 효과를 먼저 검사한다. 교사 5/6 이상 안정 도착, 양측 tick 증분 1,
STOP 뒤 새 행동 0/키 0/소유 PID 0을 통과해야 새 시연 수집을 진행한다.
교사 결과는 학생 또는 학습 개선 성공으로 세지 않는다. JAR 관측 필드가 달라졌으므로
이전 실행과 코드/JAR가 완전히 같다는 주장도 하지 않는다.

Windows 전체 843검사(818통과/25제외)를 확인했다. WSL 관련 검사와 새 JAR 컴파일 및
실제 교정 실행 결과는 아직 확인 중이다. 직접 빌드 첫 시도는 격리 환경 PATH 없이 호출해
`javac`를 찾지 못했다. 게임 런처와 동일한 micromamba 환경으로 다시 검증한다.

후속: WSL 관련45검사와 새 JAR 컴파일 통과. 새 JAR SHA는
`dac9a1c9cb6b0a7d848559cd7f55d88f7d5bd89db4bad4d5ed35cf8fe9a530a2`이며 upstream 해시 불변이다.
실제 교정은 **학생2/6·교사4/4 완료**, 총6목표가12틱 안정 도착했다. 450행동/54.723초,
양측 tick 증분1, 실제 전달 행동/확률/value/보상 재생 오차0, STOP 뒤0/키0/소유PID0을 확인했다.
이전과 같은 모델/월드/목표/난수/초기 위치·화면·기억·conditioning이다. 새 가중치 갱신은0이다.
`calibration-verification.json`에 근거를 보존했다.
