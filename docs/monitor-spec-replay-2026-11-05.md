## 요약

1. **재생은 실시간 감지기와 같다.** 기록된 정체 이벤트 47개(개발 10, 평가 37)가 모두 같은 단계, 같은 종류로 ±2초 안에 다시 나왔다.
2. **시간 초과 8단계 중 7개를 감지했다.**
   - 6개는 정체 신호로 단계 시작 46–72초에 감지했다. 철은 `repeated_cycle` 3개, 원목은 `no_progress` 3개다.
   - 1개는 조약돌 시간 기준(40초)으로 감지했다.
   - 놓친 1개는 단계 시작 21초 만에 실행 상한(900초)이 온 경우다.
3. **정체 신호에서 나온 오탐은 0개다.** 오탐은 여유 20%에서 26개, 50%에서 14개, 100%에서 9개이고, 모두 시간 기준에서 나왔다.

5. **'찾음' 판정이 약하다.** 조준선이 대상에 처음 닿은 순간을 찾음으로 본다. 그 뒤 수백 초 동안 다시 찾는 단계가 많았고, 이것이 탐색형 오탐 16개의 원인이다.

### 오탐 내역 (여유 0.2, 26개)

- **제작 8개.** 개발 기록이 5회뿐이고, 규칙 스킬의 실제 소요 시간이 배치마다 달랐다.

  - 돌 곡괭이: 개발 최악 3.5초라 점검은 4.2초다. 평가 12회 가운데 3회가 4.9–9.2초였다.
- **탐색형 '찾은 뒤' 16개** (철 11, 원목 5).
  - 철은 단계 시작 0.3–275초에 조준선이 처음 닿았고, 단계는 189–783초에 끝났다.

    - 철 7개: 지식이 없는 채로 철광석을 쳤다(`guard_unknown`).
    - 원목 5개: 보호 블록을 계속 쳤다(`guard_violation_persistent` 등).
  - 즉 '찾은 뒤' 시계가 잠깐 본 순간부터 돌기 시작해, 실제로는 탐색 시간을 다시 재고 있었다.

## 다음에 고칠 것 (M3 전, 새 평가 seed로 확인)

1. **정체 감지기 침묵.** 목표 예산 만료(`no_goal_progress`)가 위치 정체나 반복 같은 다른 사유를 가리지 않게 한다.

4. 명세나 기준을 고치면 새 버전 번호와 새 출력 폴더를 쓴다. 이번 평가 기록에 맞춘 값은 같은 기록으로 평가하지 않는다.
