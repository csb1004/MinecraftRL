# 오래된 목표의 실행 우선순위

2026-10-15 사용자 승인에 따라 미완료 목표를 오래 방치하지 않도록 상위 실행 순서를 조정한다.
하위 RL 보상, 완료 조건, 정책 가중치는 변경하지 않는다. [구현 범위](goal-aging-plan-2026-10-15.md).

## 시간과 선택 규칙

`PriorityLedger`는 시스템 시계를 직접 읽지 않는다. 실행기가 활성 세션 경과 시간과
실제 행동이 전달된 제어 주기 시간을 구분해서 제공한다.

| 항목 | 의미 |
|---|---|
| age_s | 미완료 목표의 활성 세션 누적 시간. 실행·대기·막힘 동안 증가 |
| wait_s | 실행 가능한 자신/선행 작업에 서비스가 배정되지 않은 누적 시간 |
| service_s | 자신의 직접 실행과 자신을 위한 선행 작업의 실행 시간 |
| direct_service_s | 목표 자체의 실제 실행 시간. 정체 판정은 이 값과 진행도 high-water를 사용 |
| service_credit_s | 한 서비스 구간을 채우기 전까지 보존하는 실행 시간 |

사용자 pause, 완료, 취소 상태에는 시간이 누적되지 않는다. 프로세스 종료·복원 대기 시간도
세지 않는다. 실패로 blocked인 목표의 age는 유지·증가하지만 강제 실행하지 않는다.
플래너 응답 대기는 활성 시간에는 포함되며 행동 서비스로 인정하지 않는다.

초기 설정은 다음과 같다. 실제 게임 최적값을 검증한 것은 아니다.

- 기본 중요도: 정수0–100.
- 미완료 가중치: 30초당5점, 최대30점.
- 명시적 `deadline_s`: 생성 후 활성 세션 시간의 마감. 마감 전30초부터 최대30점.
  실제 시각(UTC) 마감은 아직 지원하지 않는다. 마감이 없으면 이 가중치는0이다.
- 실행 가능한 상태의 대기가60초를 넘으면 점수와 별개로 오래 기다린 후보부터 서비스 배정.
- 실제 서비스10초를 채우기 전에는 가능한 한 현재 목표를 유지한다. 단순 선택은 서비스가 아니다.
  짧게 선택했다가 바꿔도 대기는 초기화하지 않고 누적 서비스가 구간을 채웠을 때만 초기화한다.
- 선행 작업은 의존 목표의 우선순위와 대기 긴급도를 상속한다. 상속 점수가 같으면
  대기 시간과 자신의 원래 우선순위로 비교한다.

60초는 안전한 선택 시점에서 재배정할 기준이다. 진행 중인 환경 호출을 강제 중단하는
실시간 마감 보장이 아니다. RM 하위 스킬은 기존 완료·예산·실패 인계 시점에서 선택한다.
STOP/명시적 pause/취소/완료, 의존 조건, 지원 executor와 기존 실패 방법 차단을 우회하지 않는다.
실행 불가능한 목표의 성공 또는 유한 시간 완료를 보장하지 않는다.

## 실제 연결

`RMPlanScheduler`는 원래 목표와 하위 계획에 같은 장부를 사용한다. 원래 RM·진행도·이전
제안은 보존하며, 새 계획의 노드 이름·설명·우선순위가 달라져도 동일한 방법의 시간은 보존한다.
다른 waypoint 슬롯이라도 동일한 executor 인자면 같은 방법으로 취급한다.
완료했던 방법을 새 상황에서 다시 제안할 때는 새 시도 시간으로 구분하고 상위 목표의 age는 유지한다.
LLM 입력 `scheduling`에 시간·설정·점수와 실행 권한 없음이 포함된다.
LLM 출력으로 이 시간이나 실제 완료를 덮어쓰는 필드는 없다.

기존 과업 세션에는 `--task-priorities` / PowerShell `-TaskPriorities`로 명시적 다중 목표
모드를 추가했다. 지원된 wood/dirt 수집 목표와 기존 순차 수집 계획만 실행한다.
일반 대화에서 복수 약속을 자동 확정하거나 임의 RM을 컴파일하는 기능은 추가하지 않았다.
이 세션과 연구용 단일 wood RM 복구 경로는 같은 우선순위 모듈을 사용하지만 별도 실행기다.

예시 실행 명령(검증 문서의 예시이며 이 명령으로 실제 게임을 실행한 것은 아님):

```powershell
.\scripts\Invoke-PolicyProbe.ps1 -Policy steve1 -Operation session -TaskPriorities -WorldSlot priority-dev -Seconds 180
.\scripts\Send-TaskCommand.ps1 -SessionPath $sessionPath -Operation enqueue -TaskId wood -Goal wood -Count 2 -Priority 20
.\scripts\Send-TaskCommand.ps1 -SessionPath $sessionPath -Operation enqueue -TaskId dirt -Goal dirt -Count 2 -Priority 80 -DependsOn wood
.\scripts\Send-TaskCommand.ps1 -SessionPath $sessionPath -Operation reprioritize -TaskId wood -ExpectedRevision 1 -Priority 60
```

`$sessionPath`에는 실행기가 출력한 프로젝트 results 아래 세션 경로를 사용한다.
기존 STOP 파일이 있으면 실행/명령 스크립트가 거부한다. 자동 해제 기능은 추가하지 않았다.
enqueue는 새 고유 ID만 허용하며 완료/취소 ID를 재사용할 수 없다. reprioritize는 revision을
검사하고 증가시키되 목표 내용·완료 기준·진행도·시간·정체 이력을 초기화하지 않는다.
명시적 modify는 기존 버전을 남긴다. pause/resume/cancel은 지정한 목표에 적용되며
다른 실행 가능한 목표는 계속될 수 있다. 전체 중단은 기존 STOP 경계를 사용한다.

완료는 기존 규칙대로 해당 목표 수락/수정 당시 인벤토리 baseline 대비 실제 순증가다.
동일 자원 목표끼리 아이템을 배타적으로 할당하는 재고 예약 시스템은 아니다.
목표 전환 때 입력을 해제하고 최신 관측을 사용하며 STEVE-1 조건/기억을 재설정한다.
추론 중 새 명령은 세대를 무효화하여 이전 추론 행동을 폐기한다.

## 저장·실패·검증 경계

다중 목표 체크포인트 schema4는 개별 TaskState, 우선순위 장부, 이전 버전, 실패 기록을
월드 ID와 함께 보존한다. 기존 schema1–3 월드도 명시적 모드에서 가져올 수 있다.
복원 시 실행 중 목표는 모두 paused가 되어 명시적 resume을 기다린다.
resume은 마지막 failure 표시를 해제해도 누적 failure history를 지우지 않는다.
64개 목표, 목표별32개 수정 이력/실패 기록의 한도가 있으며 이력을 조용히 버리지 않는다.

정체 시간은 해당 목표 자체의 직접 실행과 서버 인벤토리 진전에 연결한다.
목표 A를 위해 선행 목표 B를 수행한 시간만으로 A가 정체했다고 판정하지 않는다.
다중 수집 세션은 정체 목표를 보관하고 다른 가능한 목표로 전환한다. 자동 LLM 재시도는
이 세션에 새로 추가하지 않았으며, 기존 RM 복구 실행기의 실패→재계획 연결은 유지한다.

자동화 검사는 인공 관측/제어된 시계를 이용한 소프트웨어 검증이다.
새 정책의 실제 Minecraft 성과, 다중 목표 장기 완료율, 실제 API 효과와 구분한다.
