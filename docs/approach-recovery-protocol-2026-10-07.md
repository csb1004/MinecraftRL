# 접근 정체 감지와 재탐색 입력 — 검증 조건

목표는 정체 관측→목표 재검토/재탐색→실제 접근 회복이다. 각 단계의 확인 여부를 분리한다.
학습되지 않은 재탐색 입력을 넣었다는 이유로 복구 능력이 생겼다고 주장하지 않는다.

원래2100059 실패 정책은 sparse 부모에서 확장된 zero 문맥 열을 사용했다. 그 실패를 RM의
거리 포화만으로 설명할 수 없다. 기존 거리 입력은16블록에서 포화하지만 정체 감지에는 서버의
원시 거리를 사용한다. 이번에는 포화 거리 보상식까지 동시에 변경하지 않는다.

wood-potential-v4는 기존 v3 센서/보상식/6차원 입력을 유지하고, 같은 목표에 접근 중인 연속
200tick(명목10초)의 각 위치 축 범위≤2블록, 창 시작 대비 최단 거리 개선<.5블록이면 정체
후보로 기록한다. ‘접근 불가능’의 증명은 아니다. 이동 중인 우회·mine/collect는 이 판정에서 제외한다.
센서는 기존 v3 목표를 보존하고, 활성 복구 RM은 그 잠금에 대한 접근 입력을 search/거리0으로
잠시 무시한다. 새로운 물리 행동·LLM 명령·메모리 초기화·API 길찾기를 주입하지 않는다.

복구 해제 증거는 진입보다1블록 이상 가까워짐, 새로운 원목 대상, 채굴 준비, 회수 또는 종료다.
새 좌표만 확인한 경우를 실제 획득 성공과 구분한다. 성공/사망이 항상 우선하며 보상 보너스는
추가하지 않는다. 잠재함수 변경과 시간/실패 비용은 기존 식을 따른다. STOP/오류 학습 제외 유지.

단위 경계·왕복 보상·종료 검사를 먼저 한다. 이전 정체 로그의 legacy 센서를 대입한 검사는
오프라인 반사실적 진단으로만 표시하고 v3 실제 실행이라고 세지 않는다. 최근 v3 센서가 있는
정상 수집2개에서 불필요한 경보를 확인한다.

실제 조건은 기존 원목 시험장의 벽 재질만 bedrock으로 바꾼 별도 ZIP이다. z=14 우회로가
있으며 원본 월드들은 보존한다. 준비용 detour script로 도달 가능성을 확인하되 정책 성공과
분리한다. 같은 v2 checkpoint를 v3/v4에 각1회,180초 한도로 실행해 입력 변경 효과와 한계를
확인한다. 시작 상태/픽셀 비교·서버 획득·GPU/추론/제어 주기·중단/정리를 기록한다.
v4의 사망 경계는 기존 death 월드에서 별도1회 확인한다. 전부eval, optimizer 갱신0.

통과 기준을 나눈다: 감지/입력 연결은 실제 진입과 원시 보상·feature 감사, 행동 복구는 진입
이후의 실제 접근 회복 및 원목 획득이다. 진입 없이 바로 획득하면 복구 검증 표본으로 삼지 않는다.
180초 미획득은 정책 실패로 남긴다. 실패를 script로 대신 완료하지 않으며 기본 정책을 승격하지 않는다.
검증 데이터는 학습하지 않고, 복구 학습이 필요하면 별도 훈련용 세계와 수집 조건을 다음 단위로 둔다.
