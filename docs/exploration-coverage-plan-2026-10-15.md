# 방문 경로를 사용하는 제한된 탐험 보강

사용자 재개 요청과 별도 탐험 방법 추가 요청에 따라 수행한다. 기존 미방문 우선·지정 장소
재방문 허용 합의를 유지하며, 새 RM/모터 vocabulary를 만들지 않는다.

1. corner의 저장 궤적 감사만 재개한다. 이전 게임/실패 로그/중지 기록은 보존한다.
   WSL 시작, Python 진입, torch import/파일 load를 구분하고 소유 감사 프로세스만 제한한다.
2. 기존 RM 경유점 후보의 탐험 점수에 목적지뿐 아니라 후보 경로의 미방문 칸·관측된
   방향별 통과 횟수를 반영한다. 후보 직선은 가정일 뿐이며 통행 가능성은 계속 unknown이다.
   새로운 보상을 추가하거나 방문 자체를 원래 과업 성공으로 세지 않는다.
3. 기존 `visited` 전략을 유지하고 명시적 `coverage` 옵션으로 연결한다. 현재 네 개의
   바인딩된3블록 경유점과 학습 이동 head를 그대로 사용한다. 도착/실패 영수증과 별도로
   실제 새 칸·새 방향 통과 수를 저장하고 다음 계획에 제공한다. return/resource 목적에는
   미방문 우선 가중치를 적용하지 않는다. 실제 집 복귀 executor의 구현을 주장하지 않는다.
4. 미방문 선택·회귀/실패/관측 범위·STOP/완료 우선·실제10차원 입력의 회귀를 검사한다.
   저장된 far/corner 입력에서 선택 차이를 재생하고, 새 개발 far/corner 각1회로 실행한다.
   seed104761/sampling14031,180초,최대2고정 계획,각100tick/20초,API/optimizer0.
   개발 배치 간 prefix가 다르면 인과 개선으로 해석하지 않는다.
5. 이동 정밀도 보강은 별도 [근거리 준비안](near-navigation-plan-2026-10-15.md)을 따른다.
   개발 궤적을 훈련에 섞지 않고, 탐험과 이동 성능의 영향을 구분한다.

성공 기준: 실제 계획 선택과 모터 입력 연결, 원래 RM·기억·STOP 유지, 신규 방문/도착/목표
확보/인벤토리 획득의 별도 기록이다. 소규모 탐험 결과를 우회 일반화나 인간다움으로 해석하지 않는다.
기존 가중치/명세/월드/최종5시드를 보존하며 기본 전략을 자동 승격하지 않는다.

## 관측 근거에 따른 후속 단위

두 `coverage` 게임을 종료·감사한 뒤 추가 단위를 고정했다. 저장 월드 NBT의 외벽을
평가 전용으로 확인하니 기존 실패3건 중2건의 도착 반경이 내부 이동 영역과 겹치지 않았다.
이 정보를 런타임에 넘기지 않는다. 실제 이동 명령의 반복 실패만으로 방향을 의심한다.

- `coverage_motion`: 최근24행동 중 같은 방향·같은 위치 근처의 저이동 명령12개가
  모이면 국소 막힘 가설을 기록한다. 점프/짧은 회전으로 증거를 즉시 지우지 않는다.
  실제 횡단은 가설을 철회하고 다른 층의 관측은 합치지 않는다.
- 현재 목표 방향과 일치하는 새 증거가 있을 때만 조기 실패로 종료하고 재계획한다.
  STOP·실제 도착·원래 과업 완료를 우선한다. 실패 원시 관측을 독립 재구성해 감사한다.
- 저장56이동구간 재생: 완료33구간 경보0, 실패23구간 중3검출. 실패 전체를 벽으로
  분류하지 않으며, 자료 내 관측이라 일반화 입증은 아니다.
- 이 감지→다음 계획을 검사하는 **새 corner 게임1회**를 별도
  `results/exploration-motion-20261015`에 실행한다. 같은 seed/가중치/180초,
  고정 요청 최대3회다. 이전2회 제한과 달라 성능의 인과 대조로 쓰지 않는다.
- 근거리 BC 실행기는 별도로 준비했으며, 탐험 방향의 실행 가능성 문제를 먼저 다룬다.
