# 정체 시 목표 조건의 영향 진단 — 2026-10-09

현재 coverage BC 결과를 보기 전에 후속 진단 조건을 고정한다. coverage 후보가 기존에 고정한
실제 게임 입장 기준을 통과하지 못할 때만 실행한다. 통과하면 우선 계획된 게임 비교를 완료한다.
학습 횟수나 입장 기준을 이 진단 때문에 변경하지 않는다.

현재 정책은 정체 상태에서도 같은 `collect wood` 임베딩을 사용한다. 이 조건이 공격 반복을 강화할
가능성을 검사하되 원인이라고 미리 결론 내리지 않는다. 공식 STEVE-1 로컬 소스
`external/steve1/steve1/run_agent/paper_prompts.py`의 탐색 문구는 `go explore`이다.
이 문구의 존재 자체는 탐색·우회 능력의 검증이 아니다.

## 통제 조건

- 완료/감사된 coverage 후보 하나를 고정한다. optimizer 갱신·새 게임·행동 전송은0이다.
- 같은13개 시연(train11/development2)의 실제 첫 교사 입력 및 이후7개 관측을 사용한다.
  학생 prefix·중립은 원본 wood 조건으로 전체 replay한 뒤, 같은 기억 상태에서 조건별 분기를 시작한다.
- 원래 저장된 wood 임베딩은 별도 baseline으로 유지한다. 새 wood=`collect wood`, explore=`go explore`를
  로컬 MineCLIP+공식 VAE prior로 생성한다. API/LLM 호출은 없다.
- VAE는 확률적으로 latent를 표집한다. seed9711/9712/9713 각각의 같은 latent를 두 문구에 사용하고
  latent·텍스트 특징·생성 임베딩을 보존한다. 공식 `get_prior_embed`와 동일 seed의 출력 일치도 검사한다.
  원래 저장된 wood와 새 임베딩의 차이는 문구만의 효과가 아니다. 문구 효과는 각 동일 latent의 wood/explore 쌍으로 해석한다.
- 7조건(original wood + 새3 wood + 새3 explore)의 분기마다 원래 기억을 복원하고 같은 영상8개와
  원래 RM context를 사용한다. 이전 분기의 기억이 다음 분기로 새지 않았는지 확인한다.
- 첫 행동의 공격·이동·공격 해제+임의 yaw·공격 해제+교사 yaw 방향·정답 NLL을 기록한다.
  첫8개 평균은 보조 지표로 구분해 첫 행동의 희박한 확률을 가리지 않는다.
- baseline 첫 행동 지표는 완료된 coverage 학습의 전체 replay 결과와 일치해야 한다.
  모든 프레임/가중치/조건 소스를 hash로 확인하며 연구 명세·기본 정책·최종5시드는 보존한다.

이 결과는 기록된 관측에 대한 조건 변화의 영향이다. 후속7관측은 교사가 만든 화면이므로 새 정책의
자율 rollout·복구 성공·획득 성공·reward 개선으로 세지 않는다. 같은 목적으로 통계적 일반화도 주장하지 않는다.
개발 자료는 여기서도 학습 정답으로 쓰지 않는다. 행동이 살아나더라도 실제 조건 전환과 wood 목표로의
복귀는 별도 실행 계약/실험이 필요하다. LLM vocabulary나 자동 우선순위 실행을 이 검사만으로 추가하지 않는다.
