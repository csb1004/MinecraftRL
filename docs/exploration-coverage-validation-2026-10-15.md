# 경로 방문 기반 탐험과 관측 기반 막힘 복구

사용자 재개 요청 뒤 [고정 범위](exploration-coverage-plan-2026-10-15.md)를 수행했다.
**탐험 후보의 우선순위와 조기 실패→재계획 연결은 확인했지만, 원목 획득과 우회 일반화는 미해결이다.**
이번 새 게임은 coverage far/corner 2회와 coverage_motion corner 1회다. 이전 RM 연결 2게임은
저장 궤적 감사만 완료했으며 재실행하지 않았다. 새 API 호출·RL optimizer 갱신은 0이다.
별도 근거리 BC 수집/학습은 [독립된 단위](near-navigation-plan-2026-10-15.md)로 분리한다.

## 추가한 방법

기존 공간 기억의 목적지 방문 횟수에 더해, 후보 경로의 미방문 칸과 실제 관측된 방향별
통과 횟수를 점수에 반영한다. 현재 네 개의 상대 경유점과 학습된 이동 정책을 사용한다.
후보 직선을 따라가는 가상 표본은 통행 가능한 지도나 실제 방문으로 저장하지 않는다.
실제 새 방문/연결 수는 실행 종료 때 서버 좌표로 다시 계산해 다음 계획의 근거로 전달한다.
귀환/자원 목적에는 새 장소 선호를 적용하지 않는다. 실제 집 복귀 executor 검증은 별도다.

`--rl-navigation-strategy coverage` 또는 `coverage_motion`으로 명시적으로 선택한다.
기본 `visited`는 유지한다. LLM에 전달되는 기존 waypoint context에 근거를 연결했지만,
이번 게임은 고정 플래너로 실행했으므로 LLM 추가 효과를 주장하지 않는다.
새 방문 보상을 추가하거나 방문 자체를 상위 RM 완료로 판정하지 않는다.

## 실제 결과

새 칸은 이동 skill 실행 중 처음 관측된 2×4×2 블록 공간 단위다. 단순 이동 거리와 다르다.
도착 분모는 실제 실행한 경유점만 포함한다. 미실행 접근/root 노드는 실패 표본에 넣지 않는다.

| 조건 | 실제 전이 | 이동 도착 | 이동 중 새 칸 | 후속 단계 | 원목 |
|---|---:|---:|---:|---|---:|
| 이전 visited / far | 1,004 | 0/2 | 2 | 미실행 | 0 |
| 이전 visited / corner | 1,052 | 1/2 | 1 | 찾기 100행동 실패 | 0 |
| 새 coverage / far | 1,033 | 1/2 | 4 | 찾기 100행동 실패 | 0 |
| 새 coverage / corner | 1,004 | 0/2 | 0 | 미실행 | 0 |
| 새 coverage_motion / corner | 1,193 | 1/3 | 3 | 찾기 70행동 완료→접근 100행동 실패 | 0 |

세 새 게임 3,230전이의 저장 행동확률 오차는 모두 0이었다. 실제 이동/하위 단계·보상·원래 RM 보존과
STOP 뒤 추론/전송 0, 입력 해제 후 키 0, 남은 소유 PID 0을 원시 기록에서 검증했다.
모두 계획 횟수 제한에서 `planning_paused`, worker exit 2, `execution_valid=false`로 끝났다.
이는 제한된 인계 진단이며 정상 완료한 원목 평가 에피소드로 집계하지 않는다. runtime error는 없었다.

초기 화면은 같은 월드의 이전 게임과 같지만, 복구 전 root 행동이 이미 달랐다. 또 motion 후속은
고정 계획 상한을 2회에서 3회로 늘린 별도 진단이다. 위 차이는 인과 성능 개선이나 성공률 추정이 아니다.
관측 출처는 privileged server이며 영상만으로 탐험한 결과로 해석하지 않는다.

## 확인한 병목과 수정 근거

1. **목표가 검증 월드의 내부 이동 영역 밖으로 나갔다.** 원본 ZIP의 NBT에서 외벽을 평가 전용으로 확인했다.
   이전 실패 3건 중 2건, coverage 실패 3건 모두 도착 반경이 외벽 안 플레이어 중심 영역과 겹치지 않았다.
   motion의 첫 두 목표도 같은 필요조건을 만족하지 못했다. 이 지도/벽 정보는 정책 입력에 전달하지 않았다.
   반경이 내부와 겹치는 다른 목표도 통로가 열려 있다는 보장은 아니다.
2. **기존 연속 저이동 감지가 점프·회전에 끊겼다.** 최근 24행동 중 같은 방향·같은 위치 근처의
   저이동 명령 12개를 모으도록 선택적 감지를 추가했다. 실제 횡단은 가설을 철회한다.
   지형을 확정하지 않고 `blocked_direction_suspected`로 기록한다. 저장 56구간 재생에서는
   완료 33구간 경보 0, 실패 23구간 중 3검출이었다. 다른 자료의 오탐/미탐 성능은 미검증이다.
3. **실제 새 게임에서 감지→대안 실행이 이어졌다.** motion 첫 이동은 82행동째 증거 12개로 조기 종료했다.
   둘째 이동은 100행동을 소진했고, 셋째는 35행동 만에 도착했다. 이어 나무 발견은 완료했으나,
   접근은 실패했다. 원래 과업 재개는 미실행이며 더 넓은 탐험·우회 능력이 완성된 것은 아니다.
4. **근거리 정밀 제어는 별도 문제다.** 이전 far 첫 목표는 내부 도달 조건을 만족하면서도
   0.369블록까지 접근 후 재이탈했다. 이 부분을 별도 train 교정/BC로 다루며 개발 궤적은 학습하지 않는다.

현재 남은 핵심은 실행 가능한 국소 목표를 더 잘 고르는 능력, 실패 근거의 누적/반증,
발견한 나무까지 실제로 돌아가 접근하는 행동이다. 계획 횟수나 할인률만 늘린다고 해결됐다고 볼 수 없다.

세 게임 PyTorch peak allocated 1,915.00 MiB, reserved 2,126 MiB.
장치 표본은 다른 프로세스를 포함하고 짧은 peak를 놓칠 수 있다. OOM은 관측되지 않았다.
Windows 616검사 중 595통과·21제외, WSL 관련 30검사 통과. 합성 검사를 게임 성공에 포함하지 않는다.
실게임 후 다른 층의 횡단이 아래층 막힘 가설을 잘못 철회하는 경계를 추가 재현·수정했다.
관련 47검사 통과 및 실제 motion 1,193전이/요청 3건의 막힘 기록·후보 허용 여부 재생 일치를 확인했다.
`floor-red.log`, `floor-green.log`, `floor-replay.json`에 보존하며 새로운 게임 성과로 세지 않는다.
이어 실제 이동이 재개된 현재 행동에 과거 증거만으로 새 경보를 만드는 경계를 재현·수정했다.
관련 48검사 통과, 같은 실게임 요청/막힘 기록/후보/이동 영수증 3개 모두 원래 결과와 일치했다.
`recovered-motion-red.log`, `recovered-motion-green.log`, `motion-guard-replay.json`을 확인한다.
마지막 변경 후 WSL감지9검사도 통과했다. 별도 학습 후속까지 끝낸 뒤 Windows/WSL 프로젝트 프로세스0,
STOP유지와 명세해시불변을 [종료 검증](reports/2026-10-15/local-work-closure.json)에 기록했다.

이전 corner 감사는 중립 임베딩 검사 수정 후 새 wrapper로 62.641초에 완료했다.
원래 180초 timeout과 재개 첫 helper import 오류는 보존했다. warm cache·CPU thread·실행 경로가
함께 달라졌으므로 원래 timeout의 단일 원인은 확정하지 않는다.
