# 순차 수집 RM 구현 묶음

사용자 승인: 추천안 A, 추가 API 호출 최대 30회(실패 포함), 단계별 재승인 없이
구현→로컬 검사→실게임 통합 검증→보고. 기존 연구 목표는 유지한다.

- 기존 단일 과업/저장 형식을 읽으며, 순차 과업은 1–8개의 wood/dirt 수집 단계로 제한한다.
- 단계별 완료는 진입 시 인벤토리 baseline 대비 실제 순증가로만 판정한다.
- 완료 단계, 활성 단계, 남은 단계를 명시적으로 저장한다. 단계 전환은 revision을 올린다.
- 현재 단계 수정은 baseline을 새로 잡고 뒤 단계를 유지한다. 남은 계획 교체는 완료 이력을 유지한다.
- pause/cancel은 전체 순차 과업에 적용한다. 복원 시 running은 paused가 된다.
- 중립 입력 해제 후 다음 정책으로 전환하며 오래된 명령/확인은 거부한다.
- 단일 과업 API는 유지하고 계획 명령과 LLM 단계 표현만 추가한다. 일반 그래프·분기·제작은 별도다.

검증: 상태/검증기/저장 호환/관측/중단/대화 회귀를 먼저 통과시킨 뒤, 한 번의
종합 실행으로 실제 나무→흙, 현재 단계 수정, 중간 저장·복원·재개, 취소를 검사한다.
모델 해석·합성 검사·실게임 결과는 구분하고 수집 실패는 실제 결과로 보존한다.
유료 호출은 묶음 공통 영속 예산으로 제한한다. 실패 항목만 수정 후 재검사한다.
