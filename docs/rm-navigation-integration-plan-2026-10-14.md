# RM 계획과 경유점 실행 통합

사용자 승인: 공통 스킬 연결 → 실패 원인/실행 결과 통합 → 이력을 사용하는 재계획.
원문 RM·완료 기준·가중치·원본 실험 유지. 새 API 호출 없이 계약/실제 기록 재생부터 검사한다.

## 실행 단위와 완료 조건

1. 경유점 실행 계약: 현재 관측에서 생성한 최대4개 후보를 동일 신경망 executor의
   매개변수가 고정된 capability로 등록한다. 시작 위치/목표/가중치/도착 판정/예산을 묶는다.
   RM의 기존 노드 schema를 유지하며 후보 이름을 바꾸어 중복 검사를 우회하지 못하게 한다.
2. 실행 결과: 실제 도달/부분 이동/중단/미실행/관측 불명 구분, 방향 정렬/정밀 도착/
   막힘 의심은 수치 근거와 함께 기록한다. 실패 원인은 가설이며 벽 정답을 공급하지 않는다.
3. 계획 연결: 기존 RM scheduler와 신경망 subgoal controller 아래 이동 head를 연결한다.
   이전 계획과 성공 영수증 보존, 현재 요청과 관측에 묶인 후보만 실행한다.
   과거 실패와 같은 출발 부근/방향/방법은 새 후보 이름이나 작은 좌표 변경으로 재시도하지 않는다.
   STOP/시간 종료는 차단 근거로 쓰지 않는다. 실제 접근 상태 변화는 재검토 근거다.
4. 검증: 계약/실패 분류/STOP/이력 회귀 RED→GREEN, 기존 전체 검사, WSL 관련 검사,
   보존된 실제 경유점 궤적의 분류 및 요청 재생. 가능하면 새 고정 응답 로컬 게임1회와
   저장 행동 확률/RM/STOP 감사. 고정 응답을 실제 LLM 성과로 세지 않는다.

## 구현 결정

- Ruling: 프로젝트 경로를 유지하며 `codex/rm-navigation-feedback` 브랜치에서 작업한다.
  사용자 지침상 다른 worktree에 프로젝트를 만들지 않는다. 기존 미커밋 변경과 실행 소스는 보존한다.
- Ruling: 사용자의 서브에이전트 금지에 따라 구현/최종 리뷰는 주 실행 흐름에서 순차 수행한다.
- Ruling: 새 자유 좌표 생성 schema 대신 `navigate_waypoint_0..3` capability 인스턴스를 사용한다.
  네 이름은 하나의 학습 executor에 목표를 묶은 별칭이며 중복 판정에서는 별칭을 무시한다.
  현재 관측에서 바인딩한 후보 밖의 경로는 실행 가능하다고 주장하지 않는다.
- Ruling: 유료 후보 선택 배치는 이미 종료됐다. 이번 통합 검사는 무료 하네스/저장 자료/고정 응답을
  사용하고 실제 API 호출을 자동 추가하지 않는다. 실제 LLM 통합 실행 성능은 별도 미검증으로 남긴다.

## 실행 기록

- 시작: 현재 566검사/WSL28·6게임4,814전이 완료 상태를 보존했다. 기존 완료 배치 재실행0.
- 경유점 계약·RM 연결·재계획 이력·STOP·오래된 좌표 거부를 구현했다. 관련 51검사 통과,
  CLI 제한 포함 WSL 58검사 통과. 새 CLI 검사를 기존 함수 중간에 넣은 검사 배치 오류를 수정해
  Windows 전체 검사를 다시 진행한다. 제품 실행 오류와 구분한다.
- 실제 기존 6게임4,814전이 중 이동1,000전이/17구간 재생: 도달2, 중단5, 실패10.
  실패는 정렬2/정밀도달4/막힘의심1/미해결3. 원본 기록 변경0, 새 게임 성과가 아니다.
- 게임 실행 전 고정: 개발 far 월드, seed104761/sampling14031, 제어180초,
  고정 응답 최대2회/지연1초, 이동·접근 각각 최대100행동/20초, 새 게임1회.
  실행기는 `scripts/run_rm_navigation_validation.py`, 결과는 `results/rm-navigation-integration-20261014/game-v1`.
  첫 경유점은 규칙 최저비용 후보, 다음 접근→root. 정체 미발생이면 복구 미호출로 남긴다.
  기존 root 관측(나무 목표 좌표 포함)을 쓰므로 후보 전용 정보 조건과 동등 비교하지 않는다.
- game-v1 완료:932전이, 첫 이동100행동 실패→이력 포함 재계획→둘째 이동28행동/0.2076블록 도달.
  나무 목표가 unknown인데 고정 검사용 계획에 찾기 단계가 없어 `approach_requires_known_target`으로
  멈췄다. 실제 LLM 실패가 아니다.928신경망+중립4행동, logp0오차·RM/STOP/키/PID 감사 통과.
- 자기 검토에서 이미 도달한 경유점의0행동 결과가 별도 영수증 파일에 빠지는 경우를 재현·수정했다.
  이어 실제 unknown 상태에 대해 찾기→접근을 생략한 고정 계획 문제를 재현했다.
  고정 계획을 이동→locate_wood→approach_wood→root로 보완한다. 이미 알려진 목표의 찾기는
  기존0행동 완료 처리로 생략하며, 사용자 목표/RM/보상/완료 임계값은 유지한다.
- Ruling: 이 수정의 실제 분기를 확인하기 위해 game-v2를 새 결과 경로에서1회만 실행한다.
  개발 월드/가중치/seed/제어180초/최대2요청은 그대로, 각 임시 skill20초/100행동.
  기존 game-v1·이전6게임을 덮어쓰거나 다시 완료 집계하지 않는다. 실행 전 소스/조건을 새로 저장한다.
  초기 화면/행동이 달라질 수 있어 전후 인과 성능 비교로 쓰지 않으며 미호출이면 그대로 남긴다.
- 추가 자기 검토: 합법적인 DAG의 노드 목록이 실행 순서와 반대일 때 마지막 실패 대신
  오래된 성공을 읽어 재계획이 깨지는 오류를 재현했다. 배열 마지막 항목 대신 실제 종료
  sequence가 가장 큰 결과를 선택하도록 수정했다. 관련45검사 통과 후 game-v2 시작.
  Windows 전체581검사는 이 수정 직전에 통과(21제외)했으며 최종582검사는 종료 후 확인한다.
- 완료: game-v2는1,004전이 후 요청 예산으로 종료했다. 두 이동은 각각 미해결/정밀 도착 실패이며,
  찾기·접근·root 재개는 실행되지 않았다. 가장 가까운 거리는0.508블록으로 도착 기준0.35를 넘었다.
  두 새 게임1,936전이의 저장 행동 확률·RM·STOP 감사를 통과했으며 원목 획득은 모두0이다.
  최종 Windows582검사 중561통과·21제외, WSL 관련61검사 통과. 원문·가중치·원본 궤적 해시와
  game-v2 실행 소스 일치를 확인했다. STOP 뒤 새 행동·남은 입력·소유 프로세스는0이다.
  실제 API 호출·optimizer 갱신·Colab 연결·업로드0. 이번 연결 검증을 완료하며 추가 게임은 실행하지 않는다.
