# 정체 근거·실패 이력·재계획 검증 계약

승인된 후속 단위: 그래프 정체 이벤트를 실패 이력과 typed proposal 검증에 연결한다.
기존 `TaskState`/RM과 완료 증거를 복사해 참조하며 변경하지 않는다. 단순 재시도로 baseline을
새로 만들거나 목표를 취소/재생성하지 않는다. 다중 RM 우선순위 스케줄러·실제 LLM 호출·정책
집행·우회 skill 학습은 이 계약 검사와 구분한다.

## 범위와 구현 단위

1. 실제 서버 관측의 작은 snapshot: world/episode, 실제 task ID/revision(있을 때만), 실행 세대,
   관측 번호·tick·제어 경과 시간, 목표, 실제 인벤토리/대상/위치 구역/선택 도구/생존 여부.
   실험 fixture의 정답 경로·장벽 재질이나 과거 대화를 최신 사실로 넣지 않는다.
2. 실패 이력은 별도 원자적 sidecar에 저장한다. world/episode/목표, skill와 정책 버전, 관련
   관측 사실의 동일성을 비교한다. 문장/시각/yaw/미세 위치 변화만으로 실패 이력을 우회하지 않는다.
   로드 후 요청 예산과 소비된 응답도 보존한다. Windows/WSL 동시 작성은 지원하지 않는다.
3. 요청당 응답1회, session당 요청3회로 제한한다. 요청 발급 때 예산을 소비하므로 timeout이나
   잘못된 응답도 비용에서 빠지지 않는다. 전체180초 내 남은 시간과 skill별 예산을 검사한다.
4. 제안은 request ID, skill ID, 정확한 인자, 제한 시간/tick, 근거 event ID, 짧은 이유만 받는다.
   임의 코드/키 입력, 목표 완료 선언, 보상 변경, RM 수정, 숨은 목표 변경은 받지 않는다.
5. 적용 전 현재 world/episode/task ID·revision·실행 세대, 과업 상태, 관련 전제, 관측 신선도,
   STOP/사용자 pause/cancel, 입력 해제 근거를 다시 확인한다. 단순 관측 번호 증가만으로 stale
   처리하지 않고 관련 사실이 달라졌는지 확인한다. 완결된/대체된 과업은 재개하지 않는다.
6. 현재 RL 조건의 실제 capability는 같은 정책/embedding으로 `collect_wood` 실행이다.
   특정 나무 지정·좌/우 우회는 아직 연결되지 않아 미지원으로 거부한다. 교사/API 제어로 대체하지 않는다.

## 검증

- fake provider의 정상·형식 오류·근거 누락·지원 skill 부족·동일 실패·관련 사실 변화·예산 초과,
  늦은 응답·pause→resume 세대 변경·STOP·완료·취소·revision 변경·입력 미해제·저장 복원 검사.
- 기존 TaskState의 여러 단계 완료 증거와 현재 진행도를 검사 전후 비교한다. 유효 제안도
  **검증 승인**일 뿐이며 이 모듈은 행동을 보내지 않는다. 실제 스케줄러 통합을 완료했다고 세지 않는다.
- 기존 graph-stall v3의 실제 정체5event/4궤적을 새 산출물에서 읽기 전용으로 검사한다.
  RL 기록에 없는 task ID/revision/입력 해제 사실을 만들지 않는다. 가상의 제안은 실제 LLM 응답과
  구분한다. 유효 경로는 합성 경계 검사로만 확인하고 실게임 성공으로 세지 않는다.
- 정상10참고궤적에는 정체 요청0, 최종5시드·원본 로그/모델·STOP·연구명세 보존.

성공 기준은 잘못된 재계획의 거부·실패/요청 이력 보존·기존 RM 불변·출처 명시다.
실제 복구 성능은 연속 시연의 기억층 학습과 이후 실제 planner 대조에서 별도로 검증한다.
