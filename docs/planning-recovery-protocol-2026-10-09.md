# 계획 대기와 일회 조건 전환 연결 — 2026-10-09

승인된 로컬 실행 범위에서 진행한다. API 추가 호출0, 학습0, 최종5시드 미사용.
이 단위는 LLM의 성능 평가가 아니라 고정 제안 공급자를 사용한 실제 실행 연결 검사다.
원래 원목 RM·체크포인트·기억을 유지한다. 임시 탐색 선택은 opt-in 진단 capability로만 연결한다.

1. 기존 StallDetector 최초 정체 뒤 다음 행동을 중립 입력으로 보내고 서버 held_key_count=0을 확인한다.
2. 중립 입력도1tick 전이이며 RM·순환 기억·화면·보상을 기록한다. 정책 표본/학습 정답은 아니다.
3. 실행 세대·월드·episode·원래 목표·현재 관측·실패 근거를 묶어 요청을1회만 발급한다.
4. 계획 대기 중 게임 입력/정책 추론은0이다. STOP와 전체180초 제한을50ms 이하 간격으로 검사한다.
5. 응답 후 중립1tick으로 서버 관측을 갱신한다. 목표 완료/STOP 우선, stale·전제 변경·입력 미해제 거부.
6. 로컬 검증 통과 때만 같은 신경망의 탐색 조건으로 전환한다. 최대200tick 또는30초, 먼저 도달한 한도에 복귀한다.
7. 실제 wood 상호작용 기회가 생기면 조기 복귀하며 실제 인벤토리+1만 목표 완료다. 최대 개입1회.

공급자는 로컬 고정 explore_then_resume 또는 remain_paused 응답과 명시적 지연을 사용한다.
유료 API 선택지는 CLI에 추가하지 않는다. 공급자 예외/잘못된 응답/20초 대기 만료 시 추가 행동 없이
planning_paused로 에피소드를 정리한다. 복구 실패를 API 키 조작/교사 경로로 대체하지 않는다.
호출 대기20초와 복구30초를 확보하지 못하면 새 요청을 보내지 않는다. 중립/대기 시간도180초에 포함한다.

검사: 실제 runtime·RLEnvironment·RM·StallDetector·ReplanGuard를 사용하는 합성 통합에서
중립 전이/메모리, 정상 복귀, STOP/완료/관측 변화/만료/중복 응답/재시도 차단을 검증한다.
이후 기존 corner 개발 월드(seed104761), 고정 checkpoint
`results/onset-coverage-training-20261009/checkpoint.pt`와 원래 wood/explore9711 임베딩으로
고정 응답5초 대기 실제1회(sampling9731), 대기 중 STOP 실제1회(sampling9732)를 각각 실행한다.
실제 두 번째 실행은 성능 분모에서 제외한다. 완료된 기존6게임은 재실행하지 않는다.
정체가 발생하지 않으면 해당 인계 검사는 미실행으로 기록하고 성공/실패로 세지 않는다.

실제 관측/인벤토리·전이·RM/head 확률·키 해제·소유PID·제어시간·지연·GPU 메모리를 감사한다.
대기/중립이 없는 이전 조건과 동일한 행동 궤적 또는 인과 대조라고 주장하지 않는다.
오류는 원본을 보존하고 원인 수정 후 필요한 조건만 별도 기술 시도로 재검사한다.
