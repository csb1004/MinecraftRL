실행 전 고정한 조건이다. 기존 연구 목표 및 대화/RM의 미지원 제작 범위는 유지한다.
정책은 STEVE-1, 공식 MineRL 계열 1.16.5, 관측용 패치와 명시적 커서 회수 보조를 사용한다.
모델에는 픽셀만 전달하며 조합 API나 아이템 지급은 사용하지 않는다.

- 원본: craft-recovery-20261004T071020156492Z/104729의 최종 저장 세대.
  판자4·흙1을 저장 NBT로 확인하고, 각 시드마다 독립 복제한다. 원본 해시/포인터를 보존한다.
- 막대기 조건: `craft sticks`, 판자2 소비→막대기4, 판자2 잔량.
  고정 프롬프트에는 수량을 넣지 않았다. 정확 수량/잔량은 제어기의 사전 판정 조건이며,
  초과 제작을 언어 수량 지시의 이해 실패로 단정하지 않는다. 목표 아이템 제작·저장 여부도
  별도 보조 지표로 기록하되 정확 예산 성공률의 기준은 바꾸지 않는다.
- 작업대 조건: `craft a crafting table`, 판자4 소비→작업대1.
- 각 조건 configs/experiment.json의 고정 시드5개, 제어 시간 최대180초.
  두 조건 사이 자원은 공유하지 않는다. 각각 조건부 제작 능력 검사이며 연속 기술 트리 성공은 아니다.
- 실제 결과 아이템이 인벤토리/커서/입력 칸에 관측되면 즉시 정책을 정지한다.
  결과 미리보기 슬롯은 수량에 포함하지 않는다. 입력 해제·회수는 별도 제어로 기록한다.
- 성공은 정확한 소비·생산 수량, 제작 통계 증가, 빈 커서, 닫힌 GUI, 서버 확정,
  최종 저장 NBT 일치가 필요하다. 목표 관측 뒤 새 추론/정책 전달0 및 자식 프로세스 정리를 확인한다.
- 추론 중앙값/p95, 전체 제어 주기, GPU 메모리, 결과/잔량, 실패 위치를 기록한다.
  통계 지연으로 정책 witness가 없더라도 최종 보조 포함 성공과 구분해 기록한다.
- 목표 미생성은 정책 실패로 기록한다. 기술 오류가 발생하면 배치를 멈추고 원인을 조사한다.
  초기화 실패/취소/미실행을 정책 성공·실패 표본에 넣지 않는다. 수정 후 조건은 별도 보존한다.

전체 회귀 테스트, Java 컴파일은 실게임 성공의 증거가 아니다. 실제 실행 결과는 별도 문서에 기록한다.
