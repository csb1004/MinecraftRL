# 공개 모방 데이터 보완 — 2026-10-08

후속 실행: [FindCave 시연 BC 학습·실제 비교 결과](bc-navigation-validation-2026-10-08.md).
별도194MB 자료의 BC는 실행 완료했지만 긴 벽 개선은 미입증이다. 아래 첫 VPT 샘플은
계속 호환성 probe로 보존하며 해당 샘플을 학습했다고 해석하지 않는다.

## 방향

모든 과업을 작은 시험장에서 처음부터 RL로 배우는 방식은 채택하지 않는다.
현재 VPT/STEVE-1의 사전학습 행동을 기반으로 공개 사람 시연을 활용하고,
실패가 집중되는 복구 구간만 추가 수집·미세조정한다. RM 단위는 성공 판정과
목표 유지의 단위이지 각각 독립 모델을 처음부터 학습해야 한다는 뜻이 아니다.

`사전학습 정책 → 관련 사람 시연 BC → 소규모 목표/복구 RL → 분리 평가`를 작업 방향으로 둔다.
이는 장기 연구 범위 축소가 아니며 새 학습 성능이 입증됐다는 뜻도 아니다.

### BC 선택 기준 보완 — 사용자 추가 합의, 2026-10-08

사용자는 과업에 적합하면 단순 BC를 선택해도 된다고 했다. 우선 목표 조건과 시간 문맥을
유지하는 BC를 비교 기준으로 삼되, 현재 공개 샘플에 우회 전문가 행동이 있다는 가정은 하지 않는다.
위 BC→RL 순서는 장기 방향이며 모든 skill에 추가 RL을 의무적으로 적용하는 뜻은 아니다.
분리된 시작 위치/벽 길이/방향에서 실제 통과·획득과 기존 채집 성능을 만족하면 해당 skill은
BC 후보를 사용할 수 있다. BC loss 감소만으로 채택하지 않는다. 수치 채택 기준은 실제 학습 전 고정한다.

현재 우선 병목은 알고리즘 복잡도보다 실패 상태를 포함하는 관련 시연의 확보 여부다.
일반 이동 시연을 더 학습하는 것만으로 정체 복구가 해결된다고 기대하지 않는다.
BC 실패 시 시연 범위·목표 조건·동결된 표현의 한계를 구분한 뒤 복구 시연 추가나 RL을 비교한다.
DAgger는 정책이 방문한 상태에서 전문가의 교정 행동을 받을 수 있어야 하므로,
그 전문가 없이 현재 실패 로그를 재학습하는 것을 DAgger라고 부르지 않는다.
[STEVE-1의 목표 조건 BC](https://arxiv.org/abs/2306.00937),
[DAgger와 순차 예측의 상태 분포 문제](https://proceedings.mlr.press/v15/ross11a.html).

## 학습 연결 계약과 다음 단위

1. 원본 세션 ID로 먼저 train/development 분할한다. 같은 5분 분절의 인접 세션/중복을
   다른 split에 넣지 않는다. 이번 공개 예제는 호환성 probe로 고정하고 평가에 사용하지 않는다.
2. 관측·행동 offset, camera float→bin, hotbar 변화, GUI 커서, 동시 버튼 손실을 확인한다.
   null/GUI 행을 프레임열에서 삭제해 시간 간격과 recurrent context를 바꾸지 않는다.
   GUI 등 제외 구간은 BC loss mask로 처리하되 실제 모델 입력 전 영상 처리도 별도로 구현한다.
3. 이동/접근/회수 구간은 시연 내 상태 변화로 선별하고 출처·근거를 보존한다. 장애물 우회 라벨은
   위치 변화만으로 만들지 않는다. 장애물/통로 근거가 없으면 일반 이동 시연으로만 사용한다.
4. STEVE-1의 hindsight MineCLIP 목표 조건 또는 검증된 구간별 목표를 사용한다.
   모든 시연에 현재 collect wood embedding을 붙이거나 미상 RM 문맥을 search로 채우지 않는다.
   일반 행동 BC를 먼저 적용할 때에는 RM 추가 열을 업데이트하지 않는 별도 조건을 명시한다.
5. BC는 사람 행동의 negative log likelihood, PPO는 실제 수집 정책의 old_logp/advantage를 사용한다.
   외부 시연을 on-policy 궤적으로 위장하지 않는다. 두 손실·표본수·checkpoint 계보를 분리한다.
6. 기존 일반 행동을 보존하는 데이터와 복구 구간을 혼합하되 비율/반복수는 학습 전 고정한다.
   현재 3GB GPU에서는 게임을 종료한 상태에서 특징 추출과 head 학습을 순차 자원 측정한다.
   backbone 전체 학습 가능성은 미검증이며 head-only도 우회 개선을 보장하지 않는다.
7. 짧은 벽에 물리적으로 막힌 출발→중간 벽→개발 긴 벽을 분리한다. 각 단계는 일반화를
   확인할 평가 장치이며 모든 벽 길이에 별도 전문 모델을 만드는 계획이 아니다.
   실제 획득/통과, wall time와 server tick, STOP/키 해제/소유 PID를 보고한다.

실행 가능한 다음 개발 단위는 구간 선별과 목표 조건/시점 검증, 그 다음 작은 BC 후보 학습이다.
LLM planner는 이미 가능한 이동 skill 위에서 목표를 선택하도록 연결한다. 현재 미지원 이동을
planner vocabulary에 넣는 것만으로 구현됐다고 처리하지 않는다.
