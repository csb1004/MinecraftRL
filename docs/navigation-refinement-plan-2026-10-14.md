# 이동 교정·head 비교·짧은 이동 RL

사용자가 승인한 순서: 학생 이탈 상태 교정 → 같은 자료의 head 비교 → 이동 전용 RL → 분리 개발 평가.
이 문서는 실행 전 조건과 진행 기록이다. 원문 연구 명세와 최종 평가5시드는 유지한다.

## 고정 조건

- 기존 train seed104743/104759의 recovery 월드만 optimizer 자료로 사용한다.
  development104761의 far/corner는 검증만 한다. 기존 개발 궤적은 학습하지 않는다.
- 교정 수집은 명시적인 학생→중립→교사 인계다. 실제 학생 상태를32행동까지 관측한 뒤
  같은 목표의 교사 조향을 최대100행동 기록한다. 교사 행동은 공식 action mapping으로
  양자화한 뒤 실제 게임에 전달한다. 학생·중립·교사 소유권, 모든 원본 화면/상태를 보존한다.
- 목표는 알려진 fixture의 빈 왼쪽 공간에서 정방향·역방향·짧은 접근을 포함한다.
  seed별1회/6목표 교정과 별도 개발1회/6목표 교정으로 시작한다. 이는 지형 탐색 평가가 아니다.
- 이동 후보 입력은 기존6개 상대 목표+직전 서버 전이의 몸 기준 이동2개·시선 변화1개·남은
  행동 예산1개다. 1행동은 검증된 서버1tick. 속도는 블록/tick이며 wall-clock 지연과 구분한다.
- 같은 수집 자료로 선형 보정과 작은 비선형 보정 head를 비교한다. 기존 이동 head에서
  동일하게 시작하며, 원래 root/영상/기억 가중치는 동결한다. 현재 도착 반경0.35를 유지한다.
- 이동 RL은 별도 목표 조건 value로 PPO한다. 원래 wood 보상은 그대로 기록하고,
  이동용 보상(도착+1/실제 실패-1, tick비용0.002, gamma0.99, alpha0.2,
  Phi=-min(거리,16)/4)을 별도로 기록한다. 100tick 기한은 입력된 유한 과업의 종료이며
  종료potential0. STOP/전체 시간/환경 중단은 실제 실패로 바꾸지 않는다.
- BC 최대24epoch, seed14101, batch32; 실제 정책 평가당 목표별100tick/전체180초.
  train PPO 최대2게임 수집·4epoch 1배치, 개발은 기존/선형BC/비선형BC/RL 각각2월드1회.
  기술 무효만 원인 수정 후 새 경로로 재시도하며 실패 성능을 숨기기 위해 재실행하지 않는다.
- 성과는 목표별 실행 여부/서버 도착/경로 길이/행동 수/원목 증가/지연/VRAM/STOP로 구분한다.
  초기 상태·화면 차이를 기록한다. 합성 검사/교사 도달/미실행은 학습 정책 성공에서 제외한다.
- API·Colab·GitHub 업로드0. 결과는 results/navigation-refinement-20261014 아래 보존한다.
